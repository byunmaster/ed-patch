# SFC · PC98 기법

SFC(슈퍼패미컴)와 PC-98 한글화에 필요한 기법을 카페 원문에서 추린 레퍼런스다. 두 플랫폼 모두 이 프로젝트의 장기 로드맵 타깃이며, 여기 정리한 내용은 향후 착수 시 참고용이다. SFC 항목은 DQ3(드래곤 퀘스트 3) ROM을 대상으로 한 폰트·포인터 분석, PC-98 항목은 3bpp/1bpp 플레인 그래픽 구조와 폰트·그래픽 편집 기법을 다룬다.

> 출처: hansicgu 카페
> 짝: PC98·DOS 를 더 깊이 판 [`koei-pc98-dos.md`](koei-pc98-dos.md)(koeimod 카페 — 조사 판정 · 폰트 오프셋 계산식 · DOSBox 디버깅).

## SFC

### SFC DQ3 롬 영역 확장 패치 및 각 포인터 주소 정보 (#32031)

- 원문: https://cafe.naver.com/f-e/cafes/16259867/articles/32031
- 도구: HxD(Hex Editor), IPS 패처, 메시지 툴(Shift-JIS 텍스트 → bin 변환)
- 출처 원자료: 일본 앳위키 DQ바이너리 개조 위키 (https://w.atwiki.jp/dq_binary/pages/31.html)

핵심은 SFC DQ3의 ROM 영역 확장 패치와 포인터·주소 자료다.

- **ROM 확장 규모**: 확장 패치 `DQ3_extended_ver1444.ips`를 원본 ROM에 적용하면 크기가 **4,194,304 바이트(4MB) → 6,192,456 바이트**로 약 2MB 늘어난다. 확장 후 ROM을 열어 보면 여기저기 빈 공간(자유 영역)이 많이 확보되어, 늘어난 한글 텍스트나 폰트를 넣을 여유가 생긴다.
- **대사 압축 해제**: 이 확장 패치는 DQ3의 대사 압축까지 해제해 둔 상태라, 텍스트를 평문으로 다루기 쉬워진다(한글화 시 유리한 조건).
- **메시지 삽입 방식**: 제공된 메시지 툴은 텍스트를 bin으로 만든 뒤 Hex Editor로 ROM의 특정 영역부터 덮어씌우는 방식이다. 다만 이 툴은 **Shift-JIS 기반** 텍스트를 bin으로 변환하므로, 한글화하려면 툴이 뽑아내는 바이너리 형식을 참고해 **UTF-8 / EUC-KR → bin 변환 툴을 새로 만들어야 한다.**
- **한계**: 첨부 자료만으로는 한국어화가 바로 되지 않는다. 일본어를 일본어로 개조하는 수준이며, 한국어로 바꾸려면 타일(폰트) 교체 등 별도 작업이 필요하다.

첨부: `DQ_0390_Modified.zip`(앳위키 자료 일부를 구글 번역 포함해 정리한 것 — 확장 패치, 수정 이력, 메시지 툴 포함).

### 비트를 폰트로 출력하기 (SFC DQ3) — 上·中·下 연속 강좌

blackjack 님의 DQ3 분석 강좌(첫/두/세 번째 걸음)를 **프로그래밍 없이 정규표현식 + 엑셀만으로** 따라 푸는 3부작 풀이다. 목표는 ROM의 폰트 비트 데이터를 사람이 눈으로 볼 수 있는 16×16 도트 형태로 재정렬하고, 최종적으로 CrystalTile2에서 폰트로 보이게 만드는 것. DQ3처럼 비트 단위로 뒤섞어 저장한 폰트를 다룰 때의 원리와 흐름을 담는다.

전체 흐름: **hex 추출 → 2진수 변환(上) → 비트 역순·재배치(中) → 16×16 정형화 후 hex 복원·타일 확인(下).**

준비물: HxD(hex 에디터), 정규표현식 지원 에디터(에디트플러스), 엑셀.

#### 비트를 폰트로 출력하기 上 (#32036)

- 원문: https://cafe.naver.com/f-e/cafes/16259867/articles/32036
- 도구: HxD, 에디트플러스(정규식), 엑셀
- 주제: 폰트 영역 hex 추출 → 2진수 변환

1. HxD로 DQ3 ROM을 열고 `Ctrl+G`로 오프셋 **0x10ED3**으로 이동.
2. **0x10ED3 ~ 0x13F24** 범위를 드래그해 복사(이 구간이 폰트 비트 데이터).
3. 에디트플러스에 붙여넣고, 바꾸기(`Ctrl+H`)로 hex 값 사이 **공백(스페이스 1칸)을 전부 제거**.
4. 정규식 바꾸기로 두 글자(=1바이트)씩 개행:
   - 찾을 말 `(..)` / 바꿀 말 `\1\n` / 정규식 체크.
   - `()`는 그룹, `.`은 임의 1글자 → 2글자마다 개행하라는 뜻.
5. 2글자(1바이트)씩 정렬된 상태를 전체 복사.
6. 엑셀에서 A열 **셀 서식을 텍스트**로 지정 후 A1에 붙여넣기(값 손상 방지).
7. B1에 `=hex2bin(a1,8)` — 16진수를 2진수로 변환하되 8자리 미만이면 앞을 0으로 채워 **8비트**로 출력. **12370행까지** 채운다(폰트 데이터 전체 바이트 수).
8. B열 전체를 복사해 메모장에 붙여넣으면 폰트 비트가 8비트 2진수 행으로 나열된다.

즉 이 단계의 산출물은 "1바이트 = 8비트 2진수 한 줄"로 펼쳐진 데이터다.

#### 비트를 폰트로 출력하기 中 (#32044)

- 원문: https://cafe.naver.com/f-e/cafes/16259867/articles/32044
- 도구: 에디트플러스(정규식), 엑셀(필터·정렬)
- 참고: 새항아리 님 GBA 한글화 쌩초보 강좌 9 (https://cafe.naver.com/hansicgu/29377)
- 주제: 비트를 눈에 보이게 치환하고 **역순·재배치**로 도트 순서를 바로잡기

1. 가독성을 위해 `0`을 `□`, `1`을 `■`로 치환(흑백 반전을 원하면 반대로).
2. blackjack 님 설명대로, 이 폰트는 현재 행에 필요한 데이터를 **아래쪽 행에서 끌어와** 써야 하는 구조라 정규식만으로는 해결 불가 → 엑셀 병행.
3. 재배치 핵심 원리: **데이터를 역순으로 배치한 뒤 11글자씩 잘라 다시 역순으로 재배치**한다.
4. 엑셀에서 A열에 1부터 증가하는 자연수, B열에 데이터를 넣고 → **데이터 → 필터 → 숫자 내림차순 정렬**로 B열을 통째로 역순으로 뒤집는다.
5. 역순 B열을 에디트플러스로 옮겨 개행(`\n`)을 모두 제거해 한 줄로 만든다.
6. 11글자 단위로 자르기 전 정렬 보정:
   - 전체 글자 수 = 8글자 × 12370행 = **98960**.
   - 98960 ÷ 11 = 몫 **4** → **맨 앞 4글자를 제거**해야 11로 딱 나눠떨어진다.
7. 앞 4글자를 지운 뒤 `(...........)`(점 11개) → `\1\n`으로 11글자마다 개행.
8. 다시 4~5번(자연수 채번 → 내림차순 정렬 → 개행 제거)을 반복해 한 번 더 역순 재배치.

결과적으로 "역순 → 11글자 절단 → 역순"을 거쳐 도트가 올바른 순서로 재배치된 중간 산출물이 나온다. 세 번째 걸음은 下에서 이어진다.

#### 비트를 폰트로 출력하기 下 (#32048)

- 원문: https://cafe.naver.com/f-e/cafes/16259867/articles/32048
- 도구: 에디트플러스(정규식), 엑셀, HxD, CrystalTile2
- 주제: 16×16 도트로 정형화 → 다시 hex로 복원 → 타일 뷰어로 확인

1. 각 줄 끝에 채움 데이터를 붙이기: 찾을 말 `$`(행 끝) → 바꿀 말 `0000F`. (마지막을 일부러 `0`이 아닌 `F`로 둔 이유는 4번에서 개행 마커로 재활용하기 위함.)
2. 13행마다 사이에 "0 16개 × 3줄"을 넣어야 하므로, 먼저 개행(`\n`)을 모두 제거해 한 줄로 만든다.
3. **13 × 16 = 208글자**마다 개행하고 그 뒤에 0 16개짜리 3줄을 삽입:
   - 에디트플러스는 `{}`(반복 횟수) 문법을 지원하지 않아 `.{208}`를 못 쓴다 → 찾을 말에 점(`.`)을 **208개** 직접 찍는다.
   - 바꿀 말: `\10000000000000000\n0000000000000000\n0000000000000000\n` (그룹 뒤에 0 16개 3줄).
4. 앞서 심어둔 `F`를 `0\n`으로 치환 → 어중간하게 남던 경계가 "0 + 개행"으로 정리된다.
5. 이 시점에서 각 글자가 깔끔한 **16×16** 도트 모양을 갖는다.
6. `□→0`, `■→1`로 되돌리고, 다시 8글자(1바이트) 재정렬을 위해 개행을 전부 제거.
7. `(........)`(점 8개) → `\1\n`으로 8글자마다 개행.
8. 전체 복사.
9. 엑셀 A열을 텍스트 서식으로 두고 붙여넣은 뒤 B1에 `=bin2hex(a1,2)` — 2진수 8비트를 **2자리 hex**로 역변환. 마지막 행까지 채우고 B열 복사.
10. HxD에서 새 파일 → 붙여넣기 → 저장(hex로 복원된 폰트 bin).
11. 그 파일을 **CrystalTile2**로 열면 폰트가 정상적으로 출력된다.

후기: 이런 비트 조작이 필요한 작품은 SFC **데어 랑그릿사**도 마찬가지(비트 조작을 거쳐야 폰트가 제대로 보임). 정규표현식은 한 번 익혀두면 이런 텍스트 가공에 두고두고 유용하다. 반대로, 비트 단위로 뒤섞는 작품은 난도가 높으니 가능하면 피하는 편이 정신건강에 좋다는 게 필자 소감.

## PC98

### [그래픽] PC98 3bpp를 편집해봅시다! (#31753)

- 원문: https://cafe.naver.com/f-e/cafes/16259867/articles/31753
- 도구: 그림판, CrystalTile2, YYCHR, 포토샵(인덱스 유지 가능한 툴)

**기초 이론 — 3bpp 플레인 구조**

- PC-98은 **3bpp** 그래픽을 쓴다. 1비트(1플레인) 그래픽을 **3번 겹쳐(마스킹)** 색을 만든다고 보면 된다. 이 "겹겹이 플레인을 마스킹해 출력"하는 방식은 PC-98 전용이 아니라 z80 시절 아케이드 ROM, NES(FC), PC엔진 스프라이트 등에서 두루 쓰인 유구한 전통 방식이다(원리는 같고 사양만 다름). 아케이드 ROM에 같은 용량 파일이 2~3개씩 있는 것도 이 플레인 구조 때문.
- 16×16 타일 하나 = **256비트**. RAW로 보면 16진수 나열이라 형태를 알 수 없지만, 2진수로 바꿔 **16비트씩 16줄**로 끊으면 한 플레인(1겹)의 도트 그림이 드러난다.
- 1겹·2겹·3겹 세 플레인을 같은 좌표에서 **교차(중첩)**하면 각 픽셀의 3비트 값(0~7)이 정해지고, 그 값이 곧 팔레트 인덱스가 된다 → **3비트 = 8색**.
- 분해와 조립은 역순: hex → 2진수 → 16×16 플레인 3장 분리 → 중첩해 팔레트 인덱스 산출 → 색 적용. 전용 툴이 없거나 미지의 데이터 형식이어도, 콘솔의 비디오 출력 사양만 알면 이 방식으로 데이터를 읽어낼 수 있다.

**PC-98 그래픽 수정 실전 (CrystalTile2 ↔ YYCHR ↔ 포토샵)**

핵심 아이디어: 3bpp 플레인 데이터를 툴이 다룰 수 있는 4bpp 타일로 옮겨 편집한 뒤 되돌린다.

1. CrystalTile2로 그래픽 파일을 연다. 16×16·4타일 구성이면 **너비 16 / 높이 16 / 단색 1bpp**로 설정해 데이터를 찾는다. 3bpp는 3겹이므로 가로 칸 수를 ×2(6칸)로 맞춘다(Shift + 좌우 키로 칸 수 조정).
2. 수정할 그래픽 영역을 복사한다.
3. 새 파일을 만들고 타일 모드로 진입, 같은 1bpp 설정에 이번엔 **가로 8칸**으로 맞추고 붙여넣는다.
4. 데이터를 규정된 배치로 정렬하되 **4번째 칸은 반드시 비워 둔다**(팔레트 혼선 방지 — 3플레인 + 빈 1플레인).
5. 팔레트 데이터를 내보내고 파일을 저장한다.
6. YYCHR로 그 파일을 열어 Format을 **4BPP PCE(SG)**로 설정, 저장했던 팔레트를 불러온 뒤 `File → Save Bitmap(F9)`로 비트맵 저장.
7. CrystalTile2로 돌아와 새 파일 → 타일 모드에서 **너비 8 / 높이 8 / N64·MD 4bpp**, 16칸 설정. (다른 4bpp는 무방하나 **SNES 4bpp 모드는 쓰지 말 것** — 2bpp만 출력되는 버그.)
8. YYCHR 비트맵을 붙여넣고 `도구 → 타일 압축도구(P)`로 타일 조각을 맞춰 BMP로 내보낸다.
9. 내보낸 BMP를 그림으로 수정하고, 가져오기(I)로 다시 불러와 변경된 타일 데이터를 복사.
10. 포토샵에서 YYCHR가 저장한 BMP를 열어 수정 타일을 붙여넣고, **OS/2 형식 BMP**로 저장(안 그러면 YYCHR에서 인덱스 에러).
11. YYCHR `File → Open Bitmap and paste(F8)`로 저장한 BMP를 불러와 저장.
12. CrystalTile2로 수정 파일을 열어 확인 → 원래 배치로 원복 → 변경 그래픽을 복사해 원본 파일 해당 위치에 붙여넣고 저장하면 완료.

메모: 단발 작업은 툴 제작 없이 위 왕복으로 가능하지만, 연속 작업이라면 pal(팔레트)을 인덱스 참고용으로 두고 BMP 수정본을 변환하는 전용 프로그램을 만드는 편이 낫다. (댓글 정보: 일부 PC-98 게임은 대사를 LZW/LS11 등으로 압축하거나, 한자만 S-JIS 전각·나머지는 반각 카타카나로 저장 후 출력 시 전각 히라가나로 변환하는 등 용량 절약 기법을 쓴다. 대항해시대1의 `OEgrp.dat`처럼 팔레트 1024바이트를 앞에 두고 오프셋 0x400부터 스크립트 언어팩처럼 RLE 그래픽을 처리하는 사례도 있음.)

🔴 **위 강좌들의 전제를 확인하고 쓴다.** anxdiet·NDC·Pachy98 은 전부 **디스크에 파일 시스템이
있는 게임**을 상정한다(FAT 를 열어 `.EXE`·`.MES` 를 꺼낸다). 팔콤 영웅전설 PC-98 은 **FAT 도
디렉터리도 없이** 로더가 섹터를 직접 읽으므로 그 절차가 **첫 단계부터 안 돈다.**
「PC-98 이니까 이 강좌대로」가 아니라 **그 게임이 파일 시스템을 쓰나부터** 본다.
우리 쪽 측정법과 대응은 [`our-findings.md`](our-findings.md) 의 「레트로 PC 는 글꼴이 본체
ROM 이다」·「PC-98 배포는 포맷 동물원」 두 절.
