## 1. 완성형에서 종성을 판정한다 — 조사 처리

싱글바이트/완성형만 쓰는 게임에서 **조사(을/를·이/가·으로/로)** 를 맞추려면 앞 글자의 종성을
알아야 하는데, EUC-KR·CP949 는 유니코드처럼 산술로 안 떨어진다. 카페의 결론은 둘로 갈린다.

- **유니코드로 계산할 수 있을 때** — `(코드 − 0xAC00) % 28` 이 곧 종성 인덱스다.
  0 이면 받침이 없고, **5 면 `ㄹ` 받침**이다. 초성·중성까지 쪼개려면
  `초성=((코드−0xAC00)/28)/21`, `중성=((코드−0xAC00)/28)%21`, 합칠 땐 역산.
- **완성형 코드만 손에 있을 때** — 산술이 없으니 **표를 미리 뽑아 둔다.** 초성 바이트별로
  「종성 없는 글자」와 「`ㄹ` 종성 글자」의 하위 바이트 배열을 만들어 두고 이진 탐색으로 본다
  (C 소스 공개). 배열 25줄 × 8~16개 규모다.
- ⚠ **`ㄹ` 받침을 따로 두는 이유** — 「삽으**로**」와 「화살**로**」처럼 `ㄹ` 받침은 받침 없는
  글자와 **같은 쪽**으로 붙는다. 종성 유무만 보면 여기서 틀린다.
  ([#317](https://cafe.naver.com/f-e/cafes/28702069/articles/317) ·
  [#321](https://cafe.naver.com/f-e/cafes/28702069/articles/321) ·
  [#319](https://cafe.naver.com/f-e/cafes/28702069/articles/319))

> 우리 쪽 대응물은 `shared/text/`의 조사 처리와 ps1-ed1+2 의 **런타임 조사 훅**이다.
> 다른 점은 우리가 **런타임에** 고르고, 저쪽은 **빌드 때** 문안에 박는다는 것.

## 2. 문자코드 → 폰트 오프셋 계산식

폰트를 통째로 갈아끼울 때 매번 다시 유도하게 되는 식이라 그대로 옮겨 둔다.
전제는 **한 글자 32바이트(16×16 1bpp)** 의 고정 길이 폰트다.

- **SJIS** — 상·하위 바이트에서 `0x81`·`0x40` 을 빼고, 상위가 `0x1E` 를 넘으면 `0x40`(코드
  공백 구간)을 더 뺀다. 하위가 `0x3F` 이상이면 `XX7F` 자리가 비어 있으니 1 을 뺀다.
  상위 한 칸당 `0xBC` 글자, 반각 영역 `0x70` 을 더한 뒤 32 를 곱한다.
- **EUC-KR(완성형)** — 첫 코드가 `0xA1A1` 이라 둘 다 `0xA1` 을 빼고, 한글과 한자 사이의
  빈 구간(`0xC9XX`)을 상위가 넘어서면 1 을 뺀다. 나머지는 같은 꼴.
- ⚠ 두 식의 공통점이 요점이다 — **문자표의 「구멍」을 빼 주지 않으면 전 구간이 한 칸씩
  밀린다.** 밀린 폰트는 「비슷하지만 다른 글자」로 나와서 눈으로 잘 안 잡힌다.
  ([#436](https://cafe.naver.com/f-e/cafes/28702069/articles/436))

## 3. 폰트 자원과 만드는 법

- **PC98 용 16×16 한글 비트맵** — BISCO 와 얇은둥근모. 기존 BISCO 는 글자가 **옆 칸을
  침범**하는 자리가 있어 고쳐 올린 것이 정본이다.
  ([#732](https://cafe.naver.com/f-e/cafes/28702069/articles/732))
- **TTF/TTC → CP949 비트맵 뽑기** — `ttf2fnt.py`. CP949 범위를 16×16 1bpp 로 렌더해
  **1bpp BMP + 바이너리 + 오프셋 tbl** 을 같이 뱉는다. tbl 이 나온다는 게 중요하다 —
  위 §2 계산식을 안 쓰고 표로 갈 수 있다.
  ([#599](https://cafe.naver.com/f-e/cafes/28702069/articles/599))
- **폰트 시트 재배치** — PC98 에뮬용 BMP 폰트는 글자가 **세로로** 이어 붙어 있어서 손으로
  붙이기가 고약하다. 94자씩 세로로 잘라 잇는 스크립트를 쓴다.
  ([#547](https://cafe.naver.com/f-e/cafes/28702069/articles/547))

## 4. 칸이 모자랄 때 — 글자를 칸에 우겨넣는다

이름·지명처럼 **바이트 수가 원본에 묶인** 자리에서 쓰는 수법. 우리가 ED1 이름창에서 겪은
것과 같은 문제다.

- **전각 4글자를 3칸(48픽셀)에** — 두 글자씩 24×16 으로 그려 놓고 폭을 줄여 이어 붙인다.
  입력은 이름 목록 텍스트 하나, 출력은 폰트 시트에 붙일 덩어리.
  ([#685](https://cafe.naver.com/f-e/cafes/28702069/articles/685))
- **전각 3 + 반각 1 이 전각 3 보다 낫다** — 7바이트 칸이면 전각 3글자(48픽셀)로 끝내는 대신
  반각 한 자리를 더 끌어와 **56픽셀**을 쓴다. 같은 글자 수라도 가독성이 올라간다.
  ([#547](https://cafe.naver.com/f-e/cafes/28702069/articles/547))
- ⚠ 반대로 **전각 2칸에 4글자**를 넣을 거면 그냥 **반각 폰트**를 쓰는 게 맞다 — 우겨넣기는
  칸이 애매하게 모자랄 때만 이득이다.

## 5. 「길이가 넘었나」를 자동으로 본다

- **대사 길이 초과 검사기** — 원본 실행파일과 번역 텍스트를 같이 읽어 **원문보다 길어진 줄**만
  뽑는다. 짝으로 **오프셋으로 대사를 자동 입력하는 도구**가 있다(검사 → 반영이 한 벌).
  ([#115](https://cafe.naver.com/f-e/cafes/28702069/articles/115) ·
  [#114](https://cafe.naver.com/f-e/cafes/28702069/articles/114))

> 우리 `build.py:check_screen_gates` 와 같은 계열이다. **조용히 탈락하는 것**을 게이트로

## 6. 조립식 문장 — 조각을 이어 붙이는 게임의 대비책

코에이 게임은 「{인물}이 {행동}했다」처럼 **문장을 조각으로 들고 런타임에 잇는다.** 조각
하나를 자연스럽게 고치면 **그 조각을 같이 쓰는 다른 문장이 깨진다.**

- 대사를 **메모리 주소를 키로 하는 사전**으로 관리하고, 이어지는 조각들의 주소를 **간선**으로
  적어 둔다. 명사가 여러 개 들어오는 자리는 코드 대신 `{인물명}`·`{개간,치수,…}` 처럼
  후보를 적는다.
- 그러면 조각 하나를 키로 넣어 **그 조각이 등장하는 모든 문장**을 뽑아 볼 수 있다.
  고칠 자리가 눈에 보인다.
  ([#717](https://cafe.naver.com/f-e/cafes/28702069/articles/717))

> ⚠ 우리도 같은 함정이 있다 — ED1 의 `%c` 인자 주입·`chain`/`subs`. 저쪽이 **그래프로
> 역인덱스를 만든다**는 게 우리에게 없는 부분이다.

## 7. DOS·PC98 디버깅

- **데이터 블록의 시작점을 찾는 요령** — MS Run-Time Library 로 빌드된 실행파일은 코드 블록과
  데이터 블록이 갈리고, **컴파일러 버전 문자열이 나오는 그 줄이 데이터 시작점**이다.
  어셈 코드는 데이터 블록에 안 들어간다. 데이터 블록만 떼어 내면 어셈이 참조하는 오프셋을
  쉽게 추린다.
  ([#98](https://cafe.naver.com/f-e/cafes/28702069/articles/98))
- **어셈 코드를 텍스트로 뽑아서 본다** — W32Dasm(윈10 에서는 보안 정책에 막혀 VirtualBox 의
  XP 에서 돌린다) 으로 디스어셈블 → 프로젝트/주석 저장 → `.alf` 를 `.asm` 으로 바꿔
  구문 강조 되는 편집기로 연다. 주소를 찾을 땐 **검색어 앞에 공백을 하나 더** 넣어야
  어셈 주소가 같이 걸리지 않는다.
  ([#85](https://cafe.naver.com/f-e/cafes/28702069/articles/85))
- **DOSBox 디버그 빌드** — 디버그 버전에서 `Alt+Pause` 로 디버거 창이 뜬다(레지스터·데이터·
  명령어·파일 영역). 소스에서 직접 빌드하는 절차도 정리돼 있다(VS2017 + SDL 1.2.15).
  ([#40](https://cafe.naver.com/f-e/cafes/28702069/articles/40) ·
  [#42](https://cafe.naver.com/f-e/cafes/28702069/articles/42))
- 🔴 **파일이 읽히는 순간을 잡는 법** — DOSBox 자체를 디버깅하면 게임의 어셈이 안 보인다.
  대신 **치트엔진으로 dosbox_debug.exe 에 붙어** 파일 앞부분 바이트열(0x20 정도, 팔레트가
  섞이면 더 넓게)로 스캔해 **데이터 브레이크포인트**를 건다. 걸리면 게임 창에서 `Alt+Break`,
  치트엔진 쪽 BP 를 풀고 `F9` — 그 데이터를 만진 **직후 명령**에서 멈춘다.
  ⚠ **CPU 사이클을 1000 이하로 낮춰 두고** 해야 접근 지점 가까이에서 선다(`Ctrl+F11`).
  ([#58](https://cafe.naver.com/f-e/cafes/28702069/articles/58))
- **SoftICE** — VirtualBox + MS-DOS 6.22 + SoftICE 2.80 이미지. 게임 실행 중 `Ctrl+D`.
  ([#86](https://cafe.naver.com/f-e/cafes/28702069/articles/86))
- **IDA 세그먼트 읽기** — `.text` 코드 / `.data` 변수 / `.rdata` 상수·읽기 전용 / `.idata` DLL.
  **공간이 모자라면 `.rdata` 의 참조 없는 자리(XREF 주석이 안 붙은 곳)를 코드 케이브로** 쓴다.
  ([#172](https://cafe.naver.com/f-e/cafes/28702069/articles/172))

  일본어(shiftjis.tbl)·한글(작업용 tbl)을 그 자리에서 읽는다. `Ctrl+G` 주소 이동,
