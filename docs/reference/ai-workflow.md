# AI 활용 한글화 워크플로

레트로/콘솔 게임 한글화에 AI(Claude·ChatGPT/Codex·Gemini·로컬 VLM)를 실전 투입한 카페 글들을 워크플로·기법 중심으로 정리한 레퍼런스. 번역 프롬프트 설계, OCR로 폰트 테이블 만들기, AI에게 압축/치트/리버싱을 시키는 접근, 파라트랜즈+Gemini 같은 파이프라인, 그리고 emucap 등 에코시스템 도구까지 "재사용 가능한 형태"로 뽑았다. 우리 프로젝트(에이신 덴세츠 KR)가 곧 AI 주도 한글화라 절차와 프롬프트 **구조**를 자세히 남기되, **남의 글·프롬프트 본문은 옮기지 않는다**(공개 레포 — 루트 CLAUDE.md 「저작권」). 여기 있는 건 전부 우리 말로 다시 쓴 요약과 원문 링크이고, 원문 사본은 로컬 `docs/reference/_inventory/prompts/`(gitignore, 커밋 안 함)에만 둔다.

> 출처: 한글화하는 사람들의 모임(hansicgu) 카페

## 번역/프롬프트

### 제가 사용한 AI 스튜디오 프롬프트 (#32631)

- 원문: https://cafe.naver.com/f-e/cafes/16259867/articles/32631
- 도구: Google AI Studio (Gemini)
- 대상: 「두근두근 마녀신판 PLUS」 시나리오 번역

서브컬처 게임 대사 번역용 시스템 프롬프트의 실전 예시. 핵심은 (1) 역할 부여 (2) 누락 금지·태그 보존 절대규칙 (3) 게임 엔진 제약을 반영한 출력 형식(줄 길이·최대 줄 수) (4) 캐릭터별 말투 사전을 한 프롬프트에 모두 박아 넣는 것. 재사용 시 태그 이름과 칸 수/줄 수만 게임에 맞게 바꾸면 된다.

프롬프트의 구조(우리 말로 요약):

- **역할 부여**: 일본 서브컬처 게임 시나리오 전문 번역가로 지정하고, 아래 세 절을 숙지한 뒤 번역하라고
  못 박는다.
- **절대 규칙(일곱)**: 누락 금지가 최우선(반복 문장·짧은 감탄사·전각 공백·빈 줄까지) · 이름/종결 태그
  보존 · 일본식 부호 보존 · 딱딱한 직역투 배제 · 원문 호칭 보존 · 번역문만 출력 · 긴 파일은 나눠서
  끝까지.
- **출력 형식·줄바꿈 제약**: 줄바꿈과 빈 줄 위치를 원문과 1:1로 맞춘다 · **줄 길이를 칸으로 정의**
  (글자 1칸, 공백·쉼표·마침표 0.5칸, 한 줄 18칸) · 이름 줄 + 본문 최대 줄 수를 태그 꼴로 명시하고
  넘치면 압축 · 특정 태그가 있으면 예외.
- **캐릭터 말투 사전**: 등장인물마다 성격 한 줄 + 1인칭·호칭·어미·특유 표현을 적어 둔다.
- 원문 보관: `docs/reference/_inventory/prompts/hansicgu-32631.md` (로컬 전용, 커밋 안 함) ·
  원문 https://cafe.naver.com/f-e/cafes/16259867/articles/32631

- 댓글에서 나온 중요한 보강: 무작정 "규칙 다 지켰는지 반복 체크해"는 효과가 적다. 반복으로 품질을 올리는 **랄프 패턴**의 핵심은 "매 반복이 이전 세션의 잘못된 선입견에 오염되지 않은 **새 세션**이어야 한다"는 것. 즉 재검수는 새 컨텍스트에서 원문부터 다시 읽게 해야 한다.
- Gemini가 지정 프롬프트를 무시하기 일쑤라는 현장 불만도 함께 기록됨(모델 준수도 편차 주의).

### 구글 AI 스튜디오 사용해보기 (#32090)

- 원문: https://cafe.naver.com/f-e/cafes/16259867/articles/32090
- 도구: Google AI Studio (https://aistudio.google.com/), Gemini(무료, 유료 API 전환 가능)

AI Studio 사용 절차(Playground → 분야 선택 → 모델 선택 → 채팅) 안내 + 우측 **System instructions**에 넣는 영한 문학 번역 프롬프트를 공유. 영→한 번역에서 "번역투 제거·재구성"을 강제하는 시스템 프롬프트로 재사용 가치가 높다.

프롬프트의 구조(우리 말로 요약):

- **역할·목표**: 영→한 문학 번역가. 의미·어조·감정의 무게를 한국어로 **재구성**해 처음부터 한국어로
  쓴 글처럼 읽히게 한다.
- **핵심 지침 넷**: ① 문장 구조 — 원문 구조를 버리고 긴 문장을 짧게 끊는다 ② 감정 몰입 — 은유·감각
  묘사는 직역보다 환기되는 느낌, 의성·의태어 활용 ③ 번역투 회피 — 분명한 주어 생략, 수동→능동
  ④ 리듬·어조 — 문장 길이 변주, 서술과 대사의 말씨를 가른다.
- **주석 규칙**: 문화 레퍼런스·관용구·모호한 표현은 본문은 자연스럽게, 원뜻과 선택 이유는 별도 주석
  칸으로 뺀다.
- 원문 보관: `docs/reference/_inventory/prompts/hansicgu-32090.md` (로컬 전용, 커밋 안 함) ·
  원문 https://cafe.naver.com/f-e/cafes/16259867/articles/32090

### chatgpt 무료 사용자도 한번에 끝낼 수 있는 NSW 번역 지시사항 (#33044)

- 원문: https://cafe.naver.com/f-e/cafes/16259867/articles/33044
- 도구: ChatGPT/Codex(5.5~5.6, sol xhigh 추론), NxFileViewer 3.0.2, nstool
- 대상: Nintendo Switch(NSP/XCI) 타이틀 — 「마이테츠」, 「FLOWERS」, 「Q.U.L.I.A.」 등

이 글의 알짜는 첨부된 **작업 지침 MD 2종**이다. Codex 같은 에이전트에 이 지침을 읽히고 "번역 진행, 중단 금지, PDCA 적용"만 지시하면 추출→번역→검수→패키징을 한 턴 안에 자율 수행하게 만드는 하네스. 우리 프로젝트의 표준 폴더/게이트 설계에 그대로 참고할 만하다.

한 줄 트리거 프롬프트의 구조(우리 말로 요약): 목표 지정 명령으로 **지침 MD 경로**와 대상 게임을 주고,
① 모든 절차가 끝날 때까지 중단 금지 ② 사용자가 멈추라 하기 전엔 스스로 멈추지 말 것
③ PDCA(계획→실행→검증→개선→재진행)를 돌릴 것 — 세 가지만 덧붙인다. 지침은 파일에 두고 프롬프트는
「그 파일을 읽고 끝까지 가라」만 말하는 분리가 요점이다.
(원문 보관: `docs/reference/_inventory/prompts/hansicgu-33044.md` — 로컬 전용, 커밋 안 함)

첨부 지침 두 개(작업 지침 · 번역 워크플로)에서 가져갈 원칙(우리 말로 압축):

- **격리와 원본 불변** — 타이틀마다 작업 칸을 따로 두고, 추출한 원본은 읽기 전용, 빌드는 매번 깨끗한 원본에서 다시 만든다.
  추출·검증은 문서화된 CLI 로만 하고, 안 되면 「막힘」으로 기록한다.
- **안정 키 매니페스트** — 원문↔번역을 행 번호가 아니라 리소스 ID·오프셋으로 잇고, 상태값을 한 벌로 통일한다.
  일본어가 기준이고 영어는 보조, 한 줄만 떼어 번역하지 않으며 제어 토큰은 원형대로 둔다.
- **배치 + 병합 게이트** — 장면 단위 배치(경계엔 병합하지 않는 문맥 줄을 겹쳐 준다)로 번역하고, 출력은 자동 검사
  (행 누락·토큰 개수·화면 폭·잔존 원문)를 통과한 것만 병합한다. 2차 검수는 1차를 믿지 않는 **새 배치**로 원문부터.
- **실기 시험은 한 번에 한 종류씩** — 폰트 → 시스템 → 시나리오 → … 순으로 더해 실패 원인을 가른다.
- ⚠ 숫자·형식명이 문맥에 따라 인물 이름일 수 있다 — 용어집에 문맥 판별 규칙을 적는다.
(항목별 요약 원본도 같은 보관 파일에 있다: `docs/reference/_inventory/prompts/hansicgu-33044.md`)

### [오픈소스] 파라트랜즈 + Gemini 고퀄리티 기계번역 (#31931)

- 원문: https://cafe.naver.com/f-e/cafes/16259867/articles/31931
- 도구: PARAGEM (https://github.com/Ftoaster/PARAGEM), Paratranz API, Gemini API(무료)

Paratranz 프로젝트를 웹 UI에서 열어 Gemini로 배치 기계번역하는 파이프라인. 재사용 포인트:

- **파이프라인**: Paratranz API 키 + Gemini API 키 입력 → 파일 목록 로드 → 미번역/번역완료/검토 단계 선택 → **한 번에 20개씩 배치 번역** → AI가 **2개 옵션 동시 제시** → 선택 또는 직접 편집 → 저장/검토.
- **품질 관리**: 웹에서 실시간 용어집 관리로 동일 용어 일관성 유지. 지명/코스명 등 고유명사 자연스러운 한글 음차.
- **협업**: 다중 사용자 세션 잠금(5분 미활동 자동 해제). 다중 사용자 시 서버 호스팅(포트포워딩/클라우드) 필요.
- 설정: `translator_config.json`에 Paratranz 프로젝트 ID, `run_web_translator.bat` 실행 시 패키지 자동 설치·브라우저 자동 실행.
- **주의**: Gemini 무료 플랜 gemini-2.5-flash-lite는 1,500회/일 제한.

### 번역에 도움이 되는 AI 사용법 논의 (#31628)

- 원문: https://cafe.naver.com/f-e/cafes/16259867/articles/31628
- 도구: ChatGPT, Gemini 등(검수·윤문 보조)

"딸깍 한 방 번역"이 아니라 **검수·윤문 보조**로 AI를 쓰는 워크플로 논의. 재사용 가능한 절차:

1. 원문을 AI에 넣어 캐릭터별 특성·말투를 먼저 분석시킨다("이 텍스트의 캐릭터를 분석하고 특성·말투를 예상 분석해").
2. 진행한 번역이 캐릭터 특성·말투에 맞는지 검토시킨다.
3. 영어 원문의 말장난(wordplay)만 따로 뽑고 번역+번역 이유를 받는다.
4. 말장난은 사람이 별도로 현지화한다.
5. 오타를 찾고 원 번역 ↔ 추천 수정본을 비교시킨다.

현장 합의(댓글): AI 초벌·비교·검수는 긍정적이나 어감·어투는 결국 손번역. 텍스트만으로는 오역이 나므로(장면 미확인) **초벌 번역 → 전체 흐름 파악 → role·말투·고유명사 직접 재정의 → 다시 AI 번역**이 실전에서 가장 쓸 만했다는 다수 의견. AI가 자체 "예의 바른 표현/도덕 지침"을 사용자 지시보다 우선해 지시를 벗어나는 문제도 지적됨.

### 치타맨 3 오프닝 AI 한글화 (#32506)

- 원문: https://cafe.naver.com/f-e/cafes/16259867/articles/32506
- 도구: AI 번역(모델 미명시), 그림판(수기 보정)

### AI와 함께 도전하는 NES RPG 한글화 — 폰트 문제와 해결 (#33067)

- 원문: https://cafe.naver.com/f-e/cafes/16259867/articles/33067
- 도구: Codex·Claude(첨부 `NES_RPG_한글화_가이드.md`를 작업 지침으로), emucap, 갈무리 8×8 폰트(M8x8.ttf)
- 첨부: `NES_RPG_한글화_가이드.md`(Codex/Claude 공용 지침), `M8x8.ttf`(AI에 미리 주면 작업 가속)

NES는 한 화면 동시 타일 수가 제한적이라 2,350자 완성형 한글이 큰 난관. 정리된 해결 방향:

- **CHR 뱅크 전환**: CHR-ROM 확장 후 한글 폰트를 여러 CHR 뱅크에 분할, 대사/장면에 맞는 폰트 뱅크를 선택 전환.
- **매퍼 이식**: 원본 매퍼를 MMC3/MMC5로 이식·확장해 CHR-RAM 동적 폰트 로딩, 또는 MMC5 **Extended Attribute Mode**(ExRAM 확장 속성으로 8×8 타일마다 CHR 뱅크 지정 → 여러 폰트 뱅크의 한글을 한 화면에 혼용). 단 MMC5 이식은 호환성 문제로 안정화가 어렵고 토큰 소모가 큼(미해결 영역으로 남김).
- 댓글의 실전 매퍼 선택 사례: 「가챠폰전사4」는 원본 MMC3(매퍼4, PRG 256KB+CHR 256KB)를 **매퍼 12(Huang-1)** 로 교체. MMC3 클론 + CHR 확장 레지스터(`$4132`) 하나만 추가된 칩이라 **게임 코드를 하나도 안 고치고**(기존 뱅크 전환/NMI/스캔라인 IRQ 그대로) `$4132`에 0/1 쓰는 스텁만으로 CHR 256KB→512KB, 늘어난 절반에 한글 폰트 뱅크를 넣음. → 매퍼 선택 기준: "최소 침습으로 폰트 공간만 배로".
- **emucap 워크플로 팁**(댓글): 초기에 메모리 덤프 떠서 주는 방식이 제일 삽질. emucap MCP 도입 후 일사천리. 단 처음부터 다 맡기지 말고, 문제 지점까지 사람이 진행→세이브스테이트 저장→스샷 찍고 "이 지점 세이브1에 있고 스샷 여기 있으니 네가 해"라고 넘기는 게 효율적.
- **AI용 폰트 소스**: https://font.emulog.app/#fonts (댓글 추천)

### AI를 활용한 OCR로 폰트테이블 한자처리 강좌 (#31997)

- 원문: https://cafe.naver.com/f-e/cafes/16259867/articles/31997
- 도구: 크리스탈타일2(폰트 추출), Python, **로컬**: LM Studio + Qwen3-VL-8B(Q8_0) / **API**: Gemini 2.5 Flash-Lite. 첨부 스크립트 `ocr_with_lmstudio.py`, `ocr_with_gemini.py`
- 대상: GBC 「김전일」 — 한자 1,159자 폰트 테이블

순서 뒤죽박죽에 한자만 잔뜩 쓰는 게임의 폰트 테이블을 눈대중 대조하는 대신, **각 글자 이미지를 VLM으로 OCR해 테이블(CSV)을 자동 생성**하는 절차. 재사용 절차:

1. **전처리**: 크리스탈타일2에서 폰트 이미지를 추출하고 Python으로 글자당 개별 이미지로 분리(예: 16×16, 1,159장). `font_output/0000.bmp, 0001.bmp ...`
2. **백엔드 선택**:
   - 로컬 — LM Studio 설치 → Mission Control에서 비전 모델(Qwen3-VL-8B) 다운로드(양자화 Q8_0 등) → Ctrl+L로 로드 → Running. VRAM 확보 필요(테스트: 5060Ti 16GB), 또는 RAM 넉넉한 Apple M 시리즈(MLX). 연산 PC를 서버로 분리해 노트북에서 붙여도 됨.
   - API — `pip install google-generativeai google-api-core pillow tqdm`, `DEFAULT_MODEL=gemini-2.5-flash-lite`, `DEFAULT_API_KEY`에 AI Studio 발급 키.
3. **프롬프트 수정**: 스크립트의 `build_default_prompt` 함수만 자기 폰트에 맞게 손본다. 동작 원리는 "프롬프트 + 이미지 base64를 모델에 던지고 반환값을 수집"이 전부(직접 모델 학습 아님).
4. **실행**: 로컬 Qwen 약 전체 3분, Gemini 약 한 장당 4초. 결과는 `ocr_results_*.csv`. (Gemini 429 = 무료분 만료, 잠시 후 재시도.)
5. **육안 재검수**: 틀린 부분이 있으므로 사람이 최종 대조.

- 참고: 글자 크기가 8×8로 내려가면 인식률이 떨어질 수 있음(프롬프트로 보완 시도).

### 비트 변환이 필요한 폰트 처리 (#32564)

- 원문: https://cafe.naver.com/f-e/cafes/16259867/articles/32564
- 도구: no$gba(메모리 덤프), 크리스탈타일2, ChatGPT(알고리즘 역추론). 첨부 `encodeFont.bin`/`decodeFont.bin`/`s1~s4.bin`
- 대상: GBA 「환성신 저스티라이저」 — 12×16 폰트, 1bpp→4bpp 변환 저장

폰트가 뷰어에서 찌그러져 나오고 실제 저장 포맷이 특이(1bpp를 읽어 그림자 처리하며 GBA 4bpp로 변환)할 때, **인코딩 알고리즘 자체를 AI에게 역추론시키는** 접근. 재사용 절차:

1. 게임을 대사 나오는 지점까지 진행 후 바이너리 덤프 → 크리스탈타일2로 실제 저장된 글자 데이터 확인(포맷·크기 파악).
2. **정답 페어를 만든다**: 특정 글자(예 `か`)의 원본 저장 데이터(`s1.bin`)와, 16×16 1bpp 환경에서 사람이 한 점 한 점 정확히 찍어 만든 "정답 글자" 데이터(`s2.bin`)를 준비. 한 글자 크기 0x20이면 헥스에서 0x20 범위 지정 → 우클릭 → 이미지 내보내기로 저장. **단 한 픽셀도 틀리면 분석 실패**.
3. 글자 하나로는 알고리즘이 안 잡히므로 두 번째 글자(`た`)의 원본/정답 페어도 추가.
4. AI에게 "이 원본 데이터가 이 정답 글자로 인코딩되는 규칙을 알아내라"고 의뢰 → 첫 답변은 무시, 두 번째 글자 페어까지 준 뒤의 답변에서 알고리즘 도출(작성자는 단 두 명령으로 성공).
5. 도출된 알고리즘으로 디코딩/인코딩 함수 작성 → 한글 폰트 삽입.

- 참고 블로그(DQ군, 비트 변환 방식): https://blog.naver.com/devilucifer/221992990193

### AI를 이용한 LZSS 재압축 함수 구현 (#31634)

- 원문: https://cafe.naver.com/f-e/cafes/16259867/articles/31634
- 도구: OpenAI o3, Google Gemini 2.5 Pro(코드 생성)
- 대상: 「마나케미아」의 자체 변형 LZSS(`LZR\x00` 헤더) 압축 파일(.tim2 그래픽)

한글화 그래픽을 재삽입할 때 원본 여유 공간을 초과 → **더 높은 압축률의 재압축 함수를 AI에게 구현시킨** 사례. 핵심 접근: 헤더/사이즈 같은 세세한 건 빼고, **압축 포맷의 flag/데이터 구조만 자연어로 정확히 명세**해 던진다. 프롬프트의 구조(우리 말로 요약):

- **목표**: 언어(Python)와 우선순위를 못 박는다 — 속도는 버리고 **압축률 최우선**.
- **출력 꼴**: flag 열 + 데이터 열 두 갈래.
- **flag 네 종류의 해제 의미**: 리터럴 1바이트 · 길이 지정 리터럴 열 · 바이트 런(한 값을 n번) ·
  LZ 매치(두 바이트에서 12비트 거리 + 4비트 길이를 뽑아 윈도우에서 복사). 비트 배치까지 적는다.
- **요청**: 바이트열을 받아 위 두 열을 내는 압축 함수.
- 원문 보관: `docs/reference/_inventory/prompts/hansicgu-31634.md` (로컬 전용, 커밋 안 함) ·
  원문 https://cafe.naver.com/f-e/cafes/16259867/articles/31634

결과: o3는 1차에 원본보다도 압축률이 나쁘고, 2차엔 아예 깨진 압축(해제 오류). **Gemini 2.5 Pro는 한 번에** 동적 계획법(DP) 기반 최적 파싱 함수를 내놓아 원본 대비 유의미하게 개선(예: `0x892`→`0x72c`). 실전 운용 팁: **속도가 느리므로** 사람이 만든 빠른 함수로 일단 압축하고, **여유 공간을 초과하는 파일(전체의 ~20%)에만** Gemini 함수를 적용. 그래픽은 자주 안 바뀌므로 결과를 캐싱. 헤더 포맷(`LZR\x00` + 크기 필드들)은 사람이 뒤에 맞춰 붙임.

### AI를 활용한 디버그메뉴 살리는 팁 (#32668)

- 원문: https://cafe.naver.com/f-e/cafes/16259867/articles/32668
- 도구: Ghidra(디컴파일), 메모리 덤프, 치트(cheat/pnach), 메인 Claude Opus + 서브 Gemini Flash API + 로컬 Gemma. 첨부 예: `ULJS00354.ini`(PSP), `SLPS-25601_*.pnach`(PS2)
- 대상: 검수용으로 죽어 있는 디버그 메뉴 복원 — PSP 「초전자포」, GBA 「엔젤릭레이어」, NDS 「키라링 레볼루션」, PS2 「우에키의 법칙」 등

한글화 검수 시 특정 챕터/테스트룸으로 건너뛰려고 개발용 디버그 모드를 되살리는 기법. **전제**: 별도 빌드로 분리된 게 아니라 **진입점만 누락된** 경우여야 한다(롬 곳곳의 `debug`/`test`/`デバッグ` 문자열이 단서). 재사용 절차:

1. 암호 해제한 실행 바이너리 또는 메모리 덤프를 뜬다.
2. Ghidra로 올려 디컴파일 함수에서 디버그 관련 함수·분기를 찾고 **주소를 기록**.
3. 그 주소·첨부파일을 근거로 AI에게 질문 → 호출부를 찾게 하거나, 호출부가 없으면 **치트로 특정 키 조합에 그 함수를 호출**하게 만들거나, **NPC 스크립트 호출을 디버그 NPC로 바꿔치기**.

AI 대화 패턴(재사용 가능, 우리 말로 요약):

- **호출점 없는 디버그 함수**: 기종·문자열 주소를 밝히고 바이너리를 붙여 호출점을 찾게 한다 →
  호출하는 곳이 없으면 그 함수를 특정 키 조합으로 부르는 치트를 만들게 한다.
- **개발용/제품용 분기가 보일 때**: 분기 값이 메모리 어디에 놓이는지 확인시킨다 → 개발용 쪽으로
  바꾸는 치트를 받는다 → 다시 덤프해 이전 메모리와 비교, 바뀐 플래그를 찾게 한다 → 그 플래그를 켜는
  치트를 받는다. 요점은 **한 번에 한 단계씩, 덤프 비교로 다음 단서를 얻는** 왕복이다.
- 원문 보관: `docs/reference/_inventory/prompts/hansicgu-32668.md` (로컬 전용, 커밋 안 함) ·
  원문 https://cafe.naver.com/f-e/cafes/16259867/articles/32668

- 실사례: PSP 초전자포 = 누락된 디버그 함수를 L+R+Select로 호출 + 삭제된 디버그 폰트를 빈 메모리에 치트로 생성. PS2 우에키 = 로컬랜/DISC 분기 플래그를 치트로 바꾸고 Select→L1+L2+R1+R2+Select로 디버그 메뉴 진입.
- 실전 주의: 기종별 메모리맵 주소를 알아야 AI의 역질문에 대응 가능. 중간중간 사람 개입 필수.

### 클로드 기준 AI 한글패치 하는 방법 (#33087)

- 참고 포인터: DC인사이드 원 소개글 https://m.dcinside.com/board/retrogame/183223 ("AI가 알잘딱으로 에뮬레이터를 개조해 디버깅하고 성공/실패 사례를 기록하며 한패 성공 확률을 높이는 MCP")

노베이스 유저가 emucap MCP로 완성작을 낸 경험담. emucap 지원 에뮬(베타): SS, PS1, MD, DC, SNES(SFC), PC98, PCE-CD, GG, NES(FC), GB(+A,C), NDS, PSP, 원더스완 13종(3DS는 안 됨). 재사용 팁:

- **필수 설치**: 소개글의 설치 지침(emucap 포함)을 안 하고 진행하면 토큰만 낭비. AI에게 README 링크를 주면 알아서 설치·디버깅.
- **작업 폴더**: 다운로드 폴더 아래 게임별 폴더를 만들고 ROM·폰트·(필요시)바이오스를 넣는다. **폴더명은 반드시 영문**(한글 폴더는 인식 오류로 AI가 영문 폴더를 새로 만듦).
- **시작 프롬프트의 꼴**: 폴더·파일·폰트 위치를 알려 주고 목표(배포까지)를 밝힌 뒤, 여러 롬 중 원본과 깨진 파일을 가리는 일과 작업 우선순위 결정을 에이전트에 맡긴다. (원문 보관: `docs/reference/_inventory/prompts/hansicgu-33087.md` — 로컬 전용, 커밋 안 함)
- **모델 선택**: Opus 4.8이나 Fable5 추천. 낮은 버전은 "저작권 때문에 안 된다, 원문 뽑아주면 번역만 해오겠다" 식으로 회피하기도 함.
- **컨텍스트 관리**: 우하단에서 컨텍스트 잔량 확인. 거의 차면 "다음 대화창에서 이어갈 수 있도록 준비해줘"로 인계 문서 생성. 보통 대화창 4개 정도면 한 게임 완성.
- **플랜 체감**: Pro는 하나 번역에도 토큰이 빨리 닳음, Max는 동시 3개 해도 5시간 제한 전에 다 못 쓰기도.
- **권한**: 매번 승인 팝업이 귀찮으면 "앞으로 모든 권한 부여할 테니 팝업 없이 계속해" → 권한 수정 후 재시작. 단 새 대화창마다 다시 물으므로 미리 말해둘 것.
- **emucap 동시 작업**: 같은 플랫폼 게임 2개 동시 작업은 불가(작성 시점). 다른 플랫폼(PS1/NDS/FC)은 "기종별로 나눠서 분석해줘"라고 하면 알아서 분리.
- **디버깅 지시 예**(스크린샷 기반 HITL): "지금 화면 그래픽이 깨졌어, 확인해봐" / "A 누르면 전투화면인데 왼쪽 아래 이상한 글자가 떠" / "승리화면 그래픽이 다 깨져, 원본이랑 비교해봐". 방향키가 안 먹으면 중지 후 "위 N번 아래 N번 A 누르면 시작돼 / 컨트롤러 매핑 다시 확인해".
- **폰트 라이선스**: 테스트는 무관하나 배포 시 라이선스 주의(한식구/눈누에서 조달).

### 초보자를 위한 chatgpt/codex 사용방법 가이드 (#33074)

- 원문: https://cafe.naver.com/f-e/cafes/16259867/articles/33074

CLI 에이전트(Codex) 기반 한글화 입문 가이드. 재사용 포인트:

- **왜 Codex(CLI)인가**: 웹/데스크톱 ChatGPT는 파일 직접 읽기·쓰기 불가, MCP/Skills 외 외부 프로그램 호출 불가, 느림. CLI 에이전트는 python/nodejs 패키지·nstool 등을 필요시 알아서 받아 쓰는 스무스한 환경.
