# SFC·GB 실전 작업일지

SFC(슈퍼패미콤)와 GB(게임보이) 게임을 처음부터 끝까지 한글화한 연재형 작업일지·후기를 재현 가능한 레퍼런스로 정리한 문서다. 롬 타입 판별, 폰트 고유번호 추적, 폰트 확장(대사공간 확장), VRAM 타일 직접 쓰기, RAM 상주 폰트 처리, 압축 그래픽 분석까지 실제 게임 4종(패트레이버, 세일러문 어나더스토리, 고 고 아크맨3, 잔쿠로무쌍검)의 디스어셈블·주소·오프셋·수치를 보존한다. 각 항목의 어셈블리는 원 저자가 게시한 그대로이며, 이미지로만 설명된 부분은 "원문 스크린샷 참조"로 표기했다.

> 출처: hansicgu 카페 작업/후기

## SFC — 기동경찰 패트레이버

무압축 폰트/대사 + 압축 그래픽으로 이루어진 1.5MB LoROM. 폰트 출력 루틴이 "일반 텍스트"와 "스토리 대사" 두 갈래로 나뉘어 있어, 확장 루틴도 각각 작성해야 하는 것이 이 게임의 핵심 난점이다. 저자가 사용한 범용 툴은 Mesen2(에뮬레이터·디버거), HxD(헥스), CrystalTile2(타일), Notepad++, SearchR X(폰트 고유번호 검색), Lunar Expand/Address/IPS, Advanced SNES ROM Utility(체크섬). 자작 툴로 Python 스크립트 추출 툴과 Excel 번역 통합적용 툴을 썼다.

### 1. 기초 분석 (#30363)
- 원문: https://cafe.naver.com/f-e/cafes/16259867/articles/30363

**롬 타입 판별.** 가장 먼저 롬 타입을 확인한다. LoROM/HiROM에 따라 이후 작업·디버깅 방식이 달라지기 때문. Mesen2 > Tools > Log Window에서 확인 가능. 패트레이버는 LoROM.
- LoROM: 뱅크 하나당 0x8000바이트, 뱅크는 주로 80부터 시작.
- HiROM: 뱅크 하나당 0x10000바이트, 뱅크는 주로 C0부터 시작.

**폰트 확인.** CrystalTile2로 롬을 열어 폰트 위치·수량을 확인한다. 그림자 효과가 없으면 타일을 [단색 1bpp]로, 있으면 [GB 2bpp]/[SNES 4bpp]로 놓으면 빨리 찾힌다. Mesen2 > Debug > Tilemap Viewer로 크기를 가늠 — 그림자 없는 고정폭 16x16이므로 [단색 1bpp] 8x8 또는 16x16으로 탐색. 폰트는 무압축으로 **30000 ~ 37DEF**에 한자 768개 + 가나/영수/기호 239개 = 총 1007개. 완성형 한글에는 턱없이 부족하니 폰트 확장 필요로 체크.

**대사/포인터 확인 및 추출 — SearchR 상대검색으로 고유번호 찾기.** 폰트 고유번호를 찾는 표준 절차(1바이트 폰트가 50음도 순으로 들어있는 경우):
1. 히라가나 평음으로만 되어 있고, 50음도상 가까이 모여 있고, 최대한 긴 대사를 고른다.
2. 기준 문자를 정해 a~z를 50음도 순으로 매칭, 매칭 안 되는 문자는 `*`(와일드카드). 예: `ここにあるかもしれません`에서 あ=a...は=z로 잡으면 `jjva*f*l**n*`. 별표가 적어지도록 기준 문자를 조정.
3. 롬을 열고 [상대 검색] > [새 검색]에 변환 문자열 입력. a에 해당하는 HEX값과 함께 결과가 나오며, 말도 안 되는 값(FF 등)은 거른다.
4. 확인은 첫 글자 값을 바꿔 게임 실행 — 의도대로 글자가 바뀌면 맞다.

실제로는 인트로 대사 `しかしそれは`를 SearchR X(16비트 검색 지원)로 검색. 매칭 알파벳 `lflo*z`로 검색하니 결과 하나, 오프셋 **17F3D7**, a=00 즉 **あ의 고유번호=00**. 대사도 무압축임을 확인. 모든 폰트·제어코드의 고유번호 테이블을 완성하고 대사 위치 전부 탐색. **대사 주변에 포인터가 있는 경우가 많으니 함께 찾는다.**

발견한 영역:
- 스토리 대사 포인터: 185B5 ~ 1B0B7
- 전투 대사 포인터: 1B0B8 ~ 1B107 / 전투 대사: 1B108 ~ 1B2BE
- 1~10화 스토리 대사: 1B2BF ~ 1F63D
- 11~21화 스토리 대사: 20072 ~ 24FB2
- 일반 텍스트(인트로/연결대사/사건파일명/스탭롤) 포인터: 17C21F ~ 17C4FC / 일반 텍스트: 17C4FD ~ 17F459

전투 대사·일반 텍스트 포인터는 예쁘게 2바이트 플립으로만 뭉쳐 있으나, **스토리 대사 포인터는 [2바이트 플립 포인터 + 각종 제어코드 + FE]** 형식이라 찾기 어렵다. 대사 시작 위치로 몇 개를 찾아 규칙성(패트레이버는 각 포인터 앞에 FE가 구분자)을 잡는다. 자작 Python 추출 툴로 원문 추출.

**그래픽.** 타이틀 외 컷씬·전투 기술 커맨드가 그래픽 타일인데 롬에서 안 보임 → 대부분 압축. 나중에 VRAM 직접 쓰기로 처리 계획. 메인 타이틀은 Mode 7. (메인 타이틀 Mode 7, 기술 커맨드 2bpp, 배경·기체 4bpp)

**결론:** 1.5MB LoROM, 가용 폰트 1007개(확장 필요), 대사·포인터 확인·고유번호 테이블·원문 추출 완료(대사 확장 필요), 그래픽 압축(VRAM 타일 쓰기 필요).

### 2. 폰트 확장을 위한 분석 (#30375)
- 원문: https://cafe.naver.com/f-e/cafes/16259867/articles/30375

**인트로(일반 텍스트) 폰트 출력 루틴 분석.** 인트로 대사 `ハイパーテクノロジーの...`의 첫 글자 ハ(고유번호 69)의 ROM 주소 17F38D(LoROM $AF:F38D)에 브레이크. 대사 로드 서브루틴:
```
;대사 1바이트를 읽는 루틴, $82:C43C 부터
82C43C  C2 20    REP #$20        ;A 16비트
82C43E  EE A7 1F INC $1FA7       ;대사 포인터 +1
82C441  AE A7 1F LDX $1FA7       ;X ← 대사 포인터
82C444  86 00    STX $00         ;→ $00
82C446  E2 20    SEP #$20        ;A 8비트
82C448  B2 00    LDA ($00)       ;대사 바이트 읽기 — 브레이크 지점
82C44A  60       RTS
```
`LDA ($00)`(B2)는 $00,$01이 가리키는 주소(F38D)의 값(=69, ハ의 고유번호)을 A에 로드. 이후 $C36C(제어코드 비교·분기)로 이동. `$82:C36C`는 로드한 고유번호를 FF/FA/F9(=한자 폰트 시작코드), FB(대사 종료), FE(전각 공백), F8(반각 공백), FC(개행), F7(폰트 색상)과 순차 비교해 분기. **패트레이버는 한자 폰트 제어코드로 FF/FA/F9 3개 사용**(각각 시작주소 8000/A000/C000). ハ는 1바이트라 모든 비교를 통과해 $C2D4로 이동.

1바이트 폰트일 때 Y=E000인데, 이는 대사 로드 직전 `$82:C2C7 LDY #$E000`에서 정해진다. 즉 처음엔 Y=E000, 한자면 8000/A000/C000으로 교체해 시작주소를 결정. 이후 **폰트 뱅크 로드 서브루틴 $82:C44B**:
```
82C44B  E2 20  SEP #$20
82C44D  8B     PHB            ;원래 DB($AF) 보존
82C44E  48     PHA            ;글자 번호 보존
82C44F  A9 86  LDA #$86       ;폰트 뱅크 $86 (= ROM $30000)
82C451  48     PHA
82C452  AB     PLB            ;DB ← $86
82C453  68     PLA            ;글자 번호 되돌림
82C454  A2 FF 15 LDX #$15FF
82C457  20 72 C4 JSR $C472
```
`PHA`+`PLB`로 데이터뱅크를 폰트 뱅크 $86으로 바꾼다. 폰트 상세주소를 찾아 출력하는 이후 루틴은 확장 단계에서 알 필요 없음.

**스토리 대사 폰트 출력 루틴은 별도 존재.** 1편 스토리 대사 `全員、そろっとるなー？`의 全(한자, 고유번호 FF1F) ROM 1B2BF(LoROM $83:B2BF)에 브레이크. 멈추는 곳은 $80:8D28로 배치가 완전히 다르다.
```
808D28  B9 00 00 LDA $0000,Y   ;상위 바이트(예: FF)
808D2B  A2 00 E0 LDX #$E000    ;X ← 1바이트 폰트 기점
808D2E  C9 F9    CMP #$F9
808D30  B0 03    BCS $808D35   ;≥F9 → 한자 경로
808D32  82 9E 00 BRL $808DD3   ;<F9 → 1바이트 경로
...FB(종료)/FD(화면넘김)/FC(개행)/FE(공백) 비교...
808DB8  C8       INY           ;포인터 +1
808DB9  C9 FA    CMP #$FA      ;FA → X=A000
808DC2  C9 F9    CMP #$F9      ;F9 → X=C000
808DCB  A2 00 80 LDX #$8000    ;나머지(FF) → X=8000
808DD0  B9 00 00 LDA $0000,Y   ;하위 바이트(예: 1F)
808DD3  C8       INY           ;여기부터 그리기
```
한자는 2바이트라 상위(FF) 먼저 로드 → 대역 비교 후 X에 시작주소 → 하위(1F) 로드 → 상세주소 계산. 이후 **폰트 뱅크 로드는 상/하단 두 군데**:
```
808E07  BF 00 00 86 LDA $860000,X  ;윗줄, 뱅크 $86
808E29  BF 00 00 86 LDA $860000,X  ;아랫줄, 뱅크 $86
```
폰트 상단(16x8) / 하단(16x8)을 각각 출력하며 둘 다 뱅크 $86. `$860000 + X` = 완벽한 폰트 위치. 정리: **일반 텍스트와 스토리 대사는 폰트 출력 루틴이 별개** → 확장 루틴도 각각 작성.

### 3. 폰트/대사 확장 (#30384)
- 원문: https://cafe.naver.com/f-e/cafes/16259867/articles/30384

**한글 폰트 배치.** 롬 확장 영역 180000~19470F에 한글 2361자를 넣고, 제어코드 F0~F6·F9·FA·FF 10개로 구분(F7·F8·FB~FE는 이미 제어코드라 사용 불가). 각 코드별 폰트 영역(2000바이트=8KB 단위):
- 1바이트 폰트(자주 쓰는 한글 중복 + 기호): 180000~181FFF ($B0:8000~9FFF)
- F0xx:182000~183FFF / F1xx:184000~185FFF / F2xx:186000~187FFF ($B0)
- F3xx:188000~189FFF / F4xx:18A000~18BFFF / F5xx:18C000~18DFFF / F6xx:18E000~18FFFF ($B1)
- F9xx:190000~191FFF / FAxx:192000~193FFF / FFxx:194000~195FFF ($B2)

**일반 텍스트 확장 루틴.** 제어코드 비교 시작점 $82:C36C(ROM 1436C)를 확장 서브루틴 196200($B2:E200)으로 점프시킨다:
```
82C36C  E2 20        SEP #$20
82C36E  85 FE        STA $FE           ;글자 번호를 빈 DP $FE 에 둔다
82C370  5C 00 E2 B2  JML $B2E200       ;→ 새 루틴
82C374~C394  EA...   NOP               ;옛 비교 루틴 비움
```
$00~FF는 거의 다 쓰이므로 미사용 주소 확인이 중요(불안하면 2바이트 주소 할당). 확장 서브루틴 $B2:E200은 F0~FF를 순차 비교해 Y에 시작주소(A000/C000/E000/8000 순환) 로드 후 대사 로드 루틴 $E268로:
```
B2E200 C9 F0 / D0 06 / A0 00 A0 (Y=A000) / 4C 68 E2 (→$E268)
... F1→C000, F2→E000, F3→8000, F4→A000, F5→C000, F6→E000,
    F9→8000, FA→A000, FF→C000 ...
B2E264 5C 95 C3 82  JML $82C395   ;1바이트 → 원래 제어코드 비교
;대사 읽기
B2E268 C2 20 / EE A7 1F / AE A7 1F / 86 00 / E2 20 / B2 00 / 18(CLC)
B2E277 5C D1 C3 82  JML $82C3D1   ;원래 경로로 돌아가 뱅크 로드
```
1바이트 폰트 시작주소는 8000이므로 $82:C2C7의 `LDY #$E000`을 `LDY #$8000`으로 수정. 폰트 뱅크 로드 $82:C44B에서 기존 `A9 86 48 AB`를 확장 서브루틴으로:
```
82C44F  5C 80 E2 B2  JML $B2E280
;폰트 뱅크 고르기
B2E280 A5 FE LDA $FE  ;글자 번호
       F0/F1/F2→뱅크 B0, F3/F4/F5/F6→B1, F9/FA/FF→B2, 1바이트→B0
B2E2DE 48(PHA) AB(PLB)  ;원래 명령
B2E2E0 5C 53 C4 82  JML $82C453
```

**스토리 대사 확장 루틴.** $80:8D28에서 1바이트 시작주소를 8000으로 바꾸고 $FF에 고유번호 저장 후 확장 서브루틴 $B2:E000으로:
```
808D28 B9 00 00 LDA $0000,Y
808D2B A2 00 80 LDX #$8000
808D2E 85 FF    STA $FF
808D30 5C 00 E0 B2 JML $B2E000
;1바이트인가
B2E000 C9 F7 → $808DD3(출력) / C9 F8 → $808DD3
B2E010 C9 F0 / B0 04 BCS $B2E018 / 5C D3 8D 80 (작으면 출력)
B2E018 5C 35 8D 80  JML $808D35  ;≥F0 → 원래 제어코드 비교
```
2바이트 시작주소는 $80:8DB9를 확장으로:
```
808DB9 5C 20 E0 B2 JML $B2E020
B2E020 F0~FF 순차 비교 → X에 시작주소 → 5C D0 8D 80 (JML $808DD0, 하위바이트 로드)
```
폰트 상/하단 뱅크 두 곳도 각각 확장:
```
808E07 5C 90 E0 B2 JML $B2E090   ;→ 윗줄 루틴
808E29 5C 20 E1 B2 JML $B2E120   ;→ 아랫줄 루틴
;두 루틴 모두 F0~FF 를 비교해 읽기 뱅크를 $B0/$B1/$B2 중에서 고른다
```

**대사 확장.** 폰트 확장보다 쉽다 — 대사 뱅크를 지정하는 곳을 찾아 확장 뱅크로 바꾸고 포인터를 조정하면 끝. 단, 뱅크가 다른 코드와 맞물리면 수정 어렵거나 불가.
- *일반 텍스트($AF 뱅크, ROM 178000)*: 인트로 대사 포인터 17C341($AF:C341)에 브레이크 → `82F9B7 LDA ($00),Y`에서 멈춤. DB=AF 확인. Step Back(Shift+F10, Mesen 고유 장점)으로 거슬러 올라가 `82F291 A9 AF LDA #$AF`(대사 뱅크 로드) 발견. 그러나 이 $AF를 확장 뱅크 $B8로 바꾸면 게임이 구동 안 됨(다른 코드에 영향) → **대사 확장 포기, 기존 영역 그대로 사용.** 대신 1바이트 폰트 영역에 자주 쓰는 글자를 중복 배치하니 기존 대사 영역에 충분히 들어감(댓글: 대사 확장을 안 할 때 유용한 절약 기법).
- *스토리 대사*: 대사 1B2BF($83:B2BF), 포인터 18674($83:8674). 브레이크 후 위로 올라가면 `80ED30 A9 83 LDA #$83`이 있으나 바꾸면 오류(포인터 뱅크와 대사 뱅크가 분리된 경우). 그래서 브레이크 지점부터 Step Into로 내려가면:
```
808D06 LDA $181F / LSR / BCS
808D0C A9 83 LDA #$83  ;1~10화 대사 뱅크
808D10 A9 84 LDA #$84  ;11~21화 대사 뱅크
808D12 48 AB PHA PLB
```
$83→확장 $B6(1B0000~1B7FFF), $84→$B7(1B8000~1BFFFF)로 바꾸고 포인터 조정 → 정상 적용. 대사 확장 완료.

### 4. VRAM 타일 쓰기 (#30391)
- 원문: https://cafe.naver.com/f-e/cafes/16259867/articles/30391

압축 그래픽은 직접 수정이 어렵다. **대안: VRAM(그래픽 저장 메모리)에 한글 타일을 직접 "덮어쓰기"** — 원본 타일이 VRAM에 쓰인 뒤 화면 출력되기 전에 새 타일로 덮으면 화면엔 새 타일이 보인다.

**기본 서브루틴(SFC VRAM 타일 쓰기 템플릿).** DMA 레지스터는 $43xx대, 활성화는 $420B. 확장 영역 1F8000($BF:8000)에:
```
BF8000 8B     PHB
BF8001 08     PHP
BF8002 8E 02 43 STX $4302   ;소스 주소
BF8005 8D 04 43 STA $4304   ;소스 뱅크
BF8008 8C 05 43 STY $4305   ;바이트 수
BF800B A9 01 00 / 8D 00 43 STA $4300
BF8011 A9 18 00 / 8D 01 43 STA $4301
BF8017 A9 01 00 / 8D 0B 42 STA $420B   ;DMA 시작
BF801D 28 PLP / AB PLB / 60 RTS
```
A(타일 뱅크), X(타일 주소), Y(타일 크기)를 지정하는 별도 루틴이 필요.

**대기 화면 메뉴 쓰기.** 2화부터 나오는 대기 화면 메뉴(대기실/격납고/전산실)는 진입 직전 **VRAM $9A00**에 로드. 주의: Tile Viewer가 표시하는 타일 주소는 이를 반으로 나눈 **$4D00**이며, 목적지 지정도 $4D00으로 해야 코드가 인식한다.

VRAM 쓰기 코드 찾기: Mesen2 > Debug > Memory Viewer > Video RAM에서 $9A00 근처의 유니크한 값(예: $9A03에 $7F)에 브레이크 → 진입 직전 멈춤. Step Out(Shift+F11) 몇 번 하면 VRAM에 타일이 쓰인다. **이 타이밍~게임 재실행 사이 어딘가에 신규 서브루틴을 삽입** — 위치는 Step Into로 찾으며 오로지 작업자 역량(팁: 재실행 직전에 가장 가까운 서브루틴 안이 오류율 최저). 저자는 3번 시도 끝에 성공(오류 원인=삽입 위치 오류 또는 비교 트리거 값 오류).

14AAE($82:CAAE)의 `A2 FB EB 22 3A 88 80`을 `5C 30 80 BF EA EA EA`로 바꿔 1F8030으로 점프:
```
BF8030 E2 20 SEP #$20
BF8032 AD 31 05 LDA $0531 / C9 00 CMP #$00 / D0 28 BNE  ;조건 1: $0531==00
BF8039 AD 32 05 LDA $0532 / C9 03 CMP #$03 / D0 21 BNE  ;조건 2: $0532==03
BF8040 C2 20 REP #$20
BF8042 A9 80 00 / 8D 15 21 STA $2115   ;VMAIN = #$80
BF8048 A2 00 00 / 8E 16 21 STX $2116   ;VRAM 주소 하위
BF804E A2 4D 00 / 8E 17 21 STX $2117   ;VRAM 주소 상위 → $4D00
BF8054 A9 B3 00 LDA #$00B3             ;소스 뱅크 $B3
BF8057 A2 00 80 LDX #$8000             ;소스 $8000 (ROM $198000)
BF805A A0 00 08 LDY #$0800             ;0x800 바이트
BF805D 18 CLC / 20 00 80 JSR $8000     ;공용 DMA 루틴
BF8061 A2 FB EB / 22 3A 88 80          ;덮어쓴 원래 명령
BF8068 5C B5 CA 82 JML $82CAB5
```
**핵심 두 가지:** (1) 알맞은 비교 트리거($0531=00, $0532=03이 메뉴 타일 쓰기 시점) (2) 타일 세부정보 정확히. 목적지를 $2116에 #$4D00 한꺼번에 넣어도 되지만 게임에 따라 오동작 → **$2116(하위)·$2117(상위)에 나눠 넣는 것이 가장 안전.**

**기체 선택 화면 메뉴 쓰기.** 방식 동일, 삽입 위치·타일만 다름. 157DE($82:D7DE)의 `A2 FB EB 22 3A 88 80`을 `5C 80 80 BF EA EA EA`로 → 1F8080. 타일 주소 8800(ROM 198800), 크기 0x2400.

**전투 화면 메뉴 쓰기 — 조건 분기.** 4화 "돼지의 도주"에서만 메뉴가 "연속기"→"포획"으로 바뀐다. 타일 세트 2종을 만들고 현재 화 판별. 현재 화는 메모리 $1F19에 저장(진입 시점 브레이크로 발견). 치트로 시작 화 조작(Mesen2 > Tools > Cheats, Pro Action Replay `7E18DCxx`/`7E1F19xx`, xx=00~14). 16BB($80:96BB)의 `A0 20 02 A9 3F 00`을 `5C D0 80 BF EA EA`로 → 1F80D0:
```
BF80D0 트리거($0531=00,$0532=03) 확인
BF80E0 AD 19 1F LDA $1F19 / C9 03 CMP #$03 / F0 24 BEQ $BF810B  ;4화인지 가른다
;4화 외: 소스 $8800, 0x1A00 바이트
BF810B ;4화: 소스 $B000, 0x1A00 바이트
BF812C A2 DB 8C LDX #$8CDB   ;⚠ 훅이 망가뜨린 X 를 원래 값으로
BF812F A0 20 02 / A9 3F 00 / 5C C1 96 80 JML $8096C1
```
**주의:** 타일 교체로 X에 계속 새 값(0000/8800/B000)이 들어가 원래 X값이 날아간다. 기존 루틴에서 Step Back으로 원래 X값 `#$8CDB`를 찾아 $BF:812C에서 복원해야 화면이 안 깨진다.

## SFC — 세일러문 어나더스토리

32Mbit **HiROM**($C0:0000~$EF:FFFF 사용). 패미콤처럼 1바이트 폰트만 있어 가용 폰트 약 240개 → 2바이트 폰트 확장 불가피. 영문/중문 패치도 없어 맨땅부터 시작. VRAM에 폰트를 전부 올리지 않고 **출력되는 대사 글자만 그때그때 찍는 방식.** 저자가 3일(중 이틀 반은 루틴 짜기)에 성공. 툴: Snes9X v1.51.ep10r2 Geiger's Debugger(특정 대사 주소만으로 디어셈블 시 보기 편함), Mesen-S v0.4.0, HxD, CrystalTile2, Lunar Expand v1.14. CrystalTile으로 열면 맨 위에 폰트가 있어 고유번호 따기 쉬움(00~EF).

### 1. 폰트 출력 방식 분석 — 어셈블리 읽는 법 (#27293)
- 원문: https://cafe.naver.com/f-e/cafes/16259867/articles/27293

롬 타입은 Snes9x가 실행 시 화면에 표시. 오프닝 대사 `カレは`의 カ 주소 **$C5:320C(오프셋 5320C)**에 Read 브레이크. Step Into로 디어셈블:
```
$80/B839 A7 C0    LDA [$C0]  [$C5:320C]  A:0000  ;대사 포인터로 글자 코드 읽기
$80/B83B 29 FF 00 AND #$00FF              A:7B57→0057  ;하위 바이트만
$80/B83E C9 F4 00 CMP #$00F4              A:0057  ;F4 이상이면 제어코드
$80/B841 10 14    BPL $B857               ;→ 제어코드 처리
$80/B843 20 7A B8 JSR $B87A               ;→ 글자 처리
```
- `LDA [$C0]`: CPU 메모리 $C0에 든 3바이트 주소($C5:320C)가 가리키는 값을 A에 로드. A=7B57(57=カ, 7B=レ).
- `AND #$00FF`: 하위 1바이트만 뽑음(7B57 & 00FF = 0057). (FF00이면 상위 1바이트.)
- `CMP #$00F4` + `BPL`: 0057-00F4 = 음수 → 분기 안 함, 다음 행 실행. (F4는 폰트/제어코드 경계.)
- 65816 명령어 참고: https://wiki.superfamicom.org/65816-reference

### 2. 폰트 주소 계산 과정 (#27299)
- 원문: https://cafe.naver.com/f-e/cafes/16259867/articles/27299

$B87A 서브루틴이 고유번호 0057로부터 폰트 주소를 계산:
```
$80/B87A 85 00    STA $00       ;코드 보존
$80/B87C 29 F8 00 AND #$00F8    A:0050
$80/B87F 4A       LSR A         A:0028   ;÷2
$80/B880 4A       LSR A         A:0014
$80/B881 AA       TAX           X:0014
$80/B882 BD BC B8 LDA $B8BC,x   A:1400   ;표 $B8BC+X → 1400
$80/B885 85 02    STA $02
$80/B887 A5 00    LDA $00       A:0057   ;코드 되읽기
$80/B889 29 07 00 AND #$0007    A:0007
$80/B88C~B890 0A ASL A ×5       A:0007→00E0  ;×32
$80/B891 18       CLC
$80/B892 65 02    ADC $02       A:14E0   ;행 기점 + 열 오프셋 = 14E0
$80/B894 18       CLC
$80/B895 69 00 00 ADC #$0000    A:14E0   ;+ 폰트 기점(0)
$80/B898 8D B0 0F STA $0FB0     ;폰트 주소
$80/B89B A9 C0 00 LDA #$00C0    ;폰트 뱅크 $C0
$80/B89E 8D B2 0F STA $0FB2
```
**결정적 발견:** 계산 결과 14E0은 CrystalTile에서 カ가 위치한 오프셋과 일치 — 이 계산들은 폰트 주소를 뽑아내는 것. `#$0000`=폰트 시작 기준주소, `#$00C0`=폰트 뱅크. **확장 시 이 두 값만 적절히 바꾸면 폰트 주소를 새로 지정할 수 있다.** B8A1 이후는 화면 출력 처리라 수정 불필요. (논리 시프트: LSR=÷2, ASL=×2. HEX 7을 5번 ASL = 7×2×2×2×2×2 = E0.)

### 3. 폰트 확장 계획·실행 (#27307, 끝)
- 원문: https://cafe.naver.com/f-e/cafes/16259867/articles/27307

**계획.** 완성형 2350자 위해 폰트 제어코드(앞 1바이트) **E5~EF 11개** 사용. 한 영역당 229자 사용 가능(각 영역 E5~FF 중 27개는 제어코드) → 최대 2519자. 폰트 1개=40바이트, 11영역 = 40×0x100×0xB = **0x2C000바이트** 필요. 빈 공간이 그만큼 없으니 롬 확장. HiROM은 0x400000까지 타입 변경 불필요하니 뒤에 10만 바이트 추가.

**작업 순서:** ①롬 확장 → ②확장 영역에 폰트 그림 → ③확장 영역으로 대사 이동 → ④확장 폰트 출력 코드 작성 → ⑤검증(오류 시 ④⑤ 반복).

- **①롬 확장:** Lunar Expand로 32Mbit(4MB) 선택. 오프셋 300000~3FFFFF가 00으로 생성.
- **②폰트:** 원본 폰트가 000000부터니 확장 폰트도 300000부터. 테스트로 원본 전체 복사. `57 7B 1A...`로 시작하던 오프닝 대사가 `E557 E57B E51A...` 2바이트로 바뀜. 300000=E5xx, 304000=E600~E6E4, 308000=E700..., 328000=EF00~EFE4까지.
- **③대사 이동:** 오프닝 대사(오프셋 5320C, 제어코드 포함 53208~53255)를 330000으로 옮기고 고유번호를 전부 2바이트로 수정(E500~EFE4 골고루). **대사 포인터는 대사 영역 바로 위** — SMAS는 50A00~53207에 **3바이트 포인터** 집결. 오프닝 포인터 50A00~50A02의 `0832C5`를 `0000F3`(오프셋 330000)으로 수정.
- **④출력 코드:** F30005/Read 브레이크. `$80/B843`의 `20 7A B8`(JSR $B87A)을 **`4C 00 F5`(JMP $F500)** — 빈 공간 오프셋 F500으로 점프. F500에 신규 서브루틴:
```
$80/F500 C9 E5 00 CMP #$00E5    ;선두 바이트 E5 인가
$80/F503 D0 4A    BNE $F54F     ;아니면 다음 비교(분기 거리는 다 짠 뒤 계산)
$80/F505 A7 C0    LDA [$C0]     A:57E5   ;코드 다시 읽기
$80/F507 EB       XBA           A:E557   ;바이트 교환
$80/F508 29 FF 00 AND #$00FF    A:0057   ;둘째 바이트
;(이후는 1바이트 경로와 같은 계산)
$80/F526 69 00 00 ADC #$0000    ;E5 폰트 기점 0000 (파일 오프셋 300000)
$80/F529 8D B0 0F STA $0FB0
$80/F52C A9 F0 00 LDA #$00F0    ;뱅크 $F0 (HiROM)
$80/F52F 8D B2 0F STA $0FB2
;F532~F549: 원래 루틴 사본 — 그쪽으로 점프하면 무한 루프가 나서 복제
$80/F54C 4C 46 B8 JMP $B846     ;원래 루틴 꼬리로
```
`XBA`로 57E5→E557 후 AND로 0057 확보. **중요 함정:** 처음엔 계산 후 원래 서브루틴으로 점프시켰더니 하위 57E5를 안 읽고 E557만 반복 읽는 무한루프(화면에 カ만 폭주) → F532~F549 원래 코드를 복사해 넣고 마지막에야 $B846으로 복귀. $B846은 `INC $C0`(대사 주소 증가)로 다음 바이트를 읽게 함:
```
$80/B846 C2 30 REP #$30 / ... / E6 C0 INC $C0 / 60 RTS
```
E5~EF까지 같은 패턴 반복(각 영역마다 폰트 시작주소·뱅크 수정 필수). BNE 분기값 4A는 서브루틴 완성 후 역산해 기입. 마지막 EF 비교 실패 시(=고유번호 뒤 1바이트로 E5 미만):
```
$80/F816 C9 EF 00 CMP #$00EF / D0 4A BNE $F865
$80/F865 18 CLC / 4C 54 B8 JMP $B854   ;캐리 정리 후 INC $C0 로
```
이렇게 하면 1바이트 폰트는 못 쓰고 무조건 2바이트 폰트만 사용(저자는 1바이트 불필요 판단). 전체 신규 서브루틴 HEX 덤프(E5~EF 11블록)는 원문에 수록.
- **⑤검증:** 다양한 2바이트 폰트를 대사에 적용해 문제없이 출력되면 성공. 이후 실제 번역 적용하며 오류만 체크.

*(댓글: 글쓰기 시 소스코드 첨부 기능을 쓰면 공백/탭이 유지됨. SFC는 FC(패미콤)의 6502 확장이라 어셈블리가 유사.)*

## SFC — 고 고 아크맨3

**LoROM.** 폰트코드가 2바이트만 사용. 대사공간 확장(뱅크 상수 교체)과 폰트 확장(폰트번호 기반)의 두 접근을 순서대로 보여준다. 툴은 Mesen(디버거), CrystalTile2, Lunar Address. 이 게임 포인터는 **뱅크값 없는 2바이트 주소값**이라 대사공간 확장에 어셈블리 수정이 필요.

### 2. 대사공간 확장 (#31306)
- 원문: https://cafe.naver.com/f-e/cafes/16259867/articles/31306

메인 대사는 **0x1B0000 ~ 0x1B6913**. 이후 0x1B6914부터는 다른 데이터라 침범 금지. 한 뱅크 0x8000 - 0x6913 ≈ 0x1700 여유. 번역이 원본 범위를 넘을 수 있으니 확장 확보가 유리.

**대사 읽기 로직 분석.** Mesen > Debug > Debugger. 두 번째 대사(0x1B002C 시작)의 두 번째 글자 위치를 잡기 위해 Breakpoint 추가: Memory Type=**PRG ROM**, Break on=Read, Address=`1b002c`. (PRG ROM 타입일 땐 CrystalTile의 일반 주소를 그대로 입력. 뱅크 주소 변환 802C가 아님.) Reset하면 두 번째 대사 직전 정지:
```
0x00C011 LDA [$00]  [$36802C]
```
서브루틴 시작 0x00C001부터 재분석(기존 조건 삭제, 0x00C001 좌클릭 = 토글 브레이크 = 조건 무관 무조건 정지). ESC로 재개하면 그 지점에서 멈춤(2바이트 코드라 0x1B002C+2=0x1B002E에서 정지한 상태):
```
LDA $01E8      ;$01E8 의 포인터 802E (리틀엔디안)
INC $01E8
INC $01E8      ;포인터 +2
STA $00        ;$00-01 ← 802E
LDA #$0036     ;뱅크 상수 36
STA $02        ;$00-02 = 36:802E
LDA [$00]      ;롱 간접 읽기 → 00C5
```
`0x00C013`/`0x00C024`의 CMP는 줄바꿈·문장종료 제어코드 판별이라 분석 불필요.

**정리:** ①$1E8·$1E9에 읽을 대사 주소 ②A에 로드 ③$00·$01에 저장 ④A에 뱅크값 36 상수 대입 ⑤$02·$03에 저장해 $00~$02에 [뱅크:주소] 3바이트 완성 ⑥그 주소로 롬에서 2바이트 로드.

**확장 방법 — 상수 뱅크 교체.** 롬을 2MB→3MB로 확장(마지막 0x2FFFFF). 대사를 0x1B0000→0x2F0000으로 이동, Lunar Address로 **0x2F0000의 뱅크값=0x5E** 확인. `0xC00C LDA #$0036` 우클릭 > Edit Selected Code > `#$0036`→`#$005E` > Apply. 이제 대사를 [주소:5E]에서 참조. File > Save Rom as로 3MB 롬에 저장 후 CrystalTile에서 대사를 0x2F0000에 복사 → 정상 이동 확인.

**주의:** 원래 뱅크 36일 땐 무해했지만, 대사 2바이트 읽은 직후 $00·$01에 0x1B6914 이후 값이 들어가 그 주소를 참조하면 뱅크가 5E로 바뀌었으니 에러 가능. (필요 시 대사 읽은 직후 우회처리로 $02를 5E→36 재수정.) 이번엔 문제없었지만 고려 필요.

### 5. 폰트 번호에 의한 폰트 확장 (#31323)
- 원문: https://cafe.naver.com/f-e/cafes/16259867/articles/31323

**한글 배치.** 0x200000부터 2350자. 한 뱅크당 510자 → 5뱅크로 커버:
- 0x200000(뱅크40)=코드 0x00A0~0xFFA1
- 0x208000(뱅크41)=0x00B0~0xFFB1
- 0x210000(뱅크42)=0x00C0~0xFFC1
- 0x218000(뱅크43)=0x00D0~0xFFD1
- 0x220000(뱅크44)=0x00E0~0xFFE1

**폰트코드가 이미 2바이트이므로, 뒤 1바이트의 앞자리에 A~E를 매겨 폰트세트(뱅크)를 구분.** 각 뱅크당 폰트코드 0x0000~0xFF01.

**로직.** 이전 대사공간 확장 코드(0x230000)를 지우고, 토글 브레이크 후 Step Into 한 번으로 리셋된 **46:8000**으로 점프. 기존 로직을 살려 뱅크 상수·대사 로드부터:
```
LDA #$005E / STA $02 / LDA [$00]   ;대사 2바이트 읽기(엔디안 뒤집힘 주의)
AND #$F000                          ;최상위 니블만
;뱅크 고르기
CMP #$A000 / BEQ $8040
CMP #$B000 / BEQ $8050
CMP #$C000 / BEQ $8060
CMP #$D000 / BEQ $8070
CMP #$E000 / BEQ $8080
;해당 없음 → 기존 폰트, 뱅크 35
LDA #$3500 / STA $FE
LDA [$00]                           ;코드 다시 읽기
AND #$0FFF                           ;최상위 니블 지움 — 빼면 오동작
JML $00C013                          ;복귀(AND 를 대신했으니 C013)
```
`AND #$F000`으로 앞자리(A~E)만 추출해 뱅크 판별. A~E 표식은 판별용이라 이후엔 `AND #$0FFF`로 제거해야 에러 안 남. 복귀는 AND가 추가됐으므로 00:C011이 아닌 **00:C013**. 각 뱅크 분기($8040 등)는:
```
LDA #$4000 / STA $FE / JMP $8028    ;A000 → 뱅크 40, 다시 읽어 니블 지우고 복귀
```
B000~E000도 각 뱅크값(41~44)으로 동일 작성. 폰트 데이터 취득 로직은 이전 시간에 $FE에서 뱅크값 참조하도록 이미 수정됐으니 그대로.

**Mesen 팁:** 한 번 실행된 로직만 Ctrl+G로 이동 가능 → 각 케이스 코딩 전 CrystalTile에서 첫 대사를 `11A1 11B1 11C1 11D1 11E1`(또는 `A111 B111...`)로 미리 넣어 해당 분기를 실행시켜 둔다. 5개 케이스만 반복. 결과: A/B/C/D/E 및 기존 0000~FF01 모두 정상 출력.

## GB — 잔쿠로무쌍검

게임보이. **폰트 데이터가 압축되어 롬이 아닌 WRAM에 풀려서 사용**되는 까다로운 타입. 대사는 무압축. 툴: BGB 1.6.6(에뮬레이터·디버거, WRAM 뷰어 없음), Mesen(WRAM 타일 확인용), HxD, CrystalTile2, GameboyRomAnalyzer. **뱅크 변환 공식**(GB 공통): 한 뱅크=0x4000. 뱅크=롬주소÷0x4000(몫), 주소=(롬주소 % 0x4000)+0x4000. 리틀엔디안이라 검색 시 플립.

### 1. 분석 (#31782)
- 원문: https://cafe.naver.com/f-e/cafes/16259867/articles/31782

BGB로 대사까지 진행 후 ESC로 디버거. Window > Vram viewer에서 **필요한 글자만 VRAM에 올리는 갱신형** 확인. `む`에 마우스 올리면 폰트 데이터가 **메모리 0x8C80**에 존재. 좌측 하단 우클릭 > Go to > 8C80 → む 데이터 `20 20 74 74 22 22` 확인. **그런데 이 데이터가 롬에 없다** → 폰트는 압축.

File > save memory dump(파일명 / 시작 0 / 끝 10000)로 덤프. 덤프 파일에서 `202074742222` 검색 → 3곳. 그중 **0xCB91**에 폰트세트 존재 → **폰트는 압축 데이터이고 WRAM 0xCB91에 풀린다.** GB 메모리맵 참고: https://blog.naver.com/sspp12/150116095422

**정리:** ①폰트는 압축 ②압축 폰트를 WRAM 0xCB91에 풂 ③쓰는 글자만 VRAM에 올려 출력.

**대사·포인터.** GB는 대개 1바이트 폰트코드, 높은 확률로 첫 글자 코드=0x00. tbl을 그렇게 만들어 CrystalTile 검색 — 안 나오면 (①첫 코드가 0x00이 아니거나 ②대사도 압축). 이 게임은 첫 코드 0x00 + 대사 무압축이라 다행. 대사 규칙성에서 `E3 FF`가 대사 시작지점으로 보임. 뱅크 변환 예:
```
0x20000 → 뱅크08:0x4000
0x20026 → 뱅크08:0x4026
0x2015A → 뱅크08:0x415A
```
모든 대사가 08번 뱅크(0x20000~0x23FFF)에 있으니 뱅크값은 로직 내 상수일 확률 높음 → 포인터는 2바이트일 확률 높음. `4000 4026 415A`를 플립한 `00 40 26 40 5A 41`로 검색 → 한 군데(포인터 테이블).

**RAM 상주 폰트에서 SearchR 쓰기.** 폰트세트가 ROM이 아닌 RAM이라 SearchR용 폰트를 못 넣는 문제. 해법: ①대사 나오는 곳까지 진행 ②덤프한 WRAM 파일의 **0xCB91 ~ 0xCF70**에 SearchR용 폰트를 넣어 저장 ③HxD로 그 범위 복사 ④BGB 디버거 좌측 하단 0xCB91로 이동해 에디트 창에 붙여넣기 ⑤게임 진행하며 적용 확인.

### 2. 개조 개요와 롬파일 확장 (#31790)
- 원문: https://cafe.naver.com/f-e/cafes/16259867/articles/31790

폰트가 램에 상주해 이런 타입을 처음 접하면 막힌다. **가장 간단한 접근: WRAM 0xCB91에 풀린 폰트세트를, 상황에 맞게 미리 롬에 준비한 한글 폰트세트로 로직 수정을 통해 교체.** (Z80 명령어·디버거·약간의 프로그래밍 지식 필요.)

**개조 개요:** ①대사 1바이트 읽어 폰트세트 제어코드(0xDD)인지 체크 ②0xDD 아니면 기존 로직 ③0xDD면 뒤 2바이트로 해당 한글 폰트세트를 WRAM 0xCB91에 덮어쓰기. (BGB는 WRAM 뷰어가 없어 Mesen으로 확인.)

**롬 확장(1MB→2MB):** ①롬파일과 1MBdummy.bin을 짧은 경로(한글 없이)에 복사 ②cmd에서 `copy /b "zankuro.gb" + "1MBdummy.bin" "zankuro2m.gb"`로 병합 ③GameboyRomAnalyzer로 열어 Rom Type `05h → 06h`(2MB). Cartridge Type은 이 게임은 수정 불필요 ④Edit > Write Rom 저장(Header Checksum 붉은 3D 경고 무시 가능, 최종 완성 후 체크섬 수정). BGB 실행 시 에러도 일단 무시.

*(댓글 — 2350자 확장 두 방법: ①VRAM에 올릴 때 읽어올 주소를 RAM→롬 확장폰트로 변경 ②WRAM을 갱신형처럼 1글자씩 고쳐 VRAM에 올리기. 저자가 든 ②의 상세 알고리즘: WRAM에 1바이트 "위치값" 공간을 두고, 제어코드 0xFF로 위치값을 리셋/설정, 한글 폰트값은 D0XX~D9XX 2바이트 코드. 각 글자마다 교체할 VRAM 위치 = 시작위치 + ((위치값-0x30)×0x20), 한글 폰트 데이터를 그 VRAM 주소에 올리고 A에 위치값을 출력 폰트코드로 넣은 뒤 위치값 +1. 즉 위치값은 "현재 출력 폰트코드"와 "VRAM 올릴 주소 계산"의 두 역할, 2바이트 값은 올릴 한글폰트 주소 역할만. GB는 나쁜 뱅크 때문에 1→2바이트 확장 시 대사 확장(뱅크 스위칭)도 얽혀 복잡. 이 게임은 대전겜이라 폰트세트 교체 방식으로 충분.)*

### 3. 로직 분석·우회처리·복귀 (#31791)
- 원문: https://cafe.naver.com/f-e/cafes/16259867/articles/31791

하오마루 대사(시작 0x20026) 대상. Debug > access breakpoints > `rom:20026`, on read, add. 대사 나올 때까지 진행 → **0x38FD**에서 멈춤:
```
0x38FD ldi a,(hl)    ;뱅크8:4026(=ROM 0x20026)의 E3 → a, hl++
                     ;af 4080→E380, hl 4026→4027
0x38FE push af
0x38FF ld a,l
0x3900 ld (C8C0),a   ;포인터 하위 → WRAM C8C0
0x3903 ld a,h
0x3904 ld (C8C1),a   ;포인터 상위 → WRAM C8C1
0x3907 pop af        ;a=E3 복원
0x3908 cp a,E0       ;제어코드 판정 시작
```
`hl`=값 자체, `(hl)`=hl이 가리키는 주소의 1바이트. 실제로는 4줄 위 **0x38F5**부터 봐야 함 — WRAM **0xC8C0·0xC8C1**이 "현재 어디까지 읽었는지" 대사 주소를 기록(세이브 파일 같은 역할). hl에 읽을 주소 설정 → 1바이트 로드 → hl+1 → 0xC8C0·0xC8C1 갱신 → 제어코드 판별.

**폰트세트 교체 제어코드 삽입 계획.** 대사에 [교체코드 1바이트 + 위치값 2바이트] = 3바이트를 넣는다. 예: `E3 FF DD XX YY 01 02 03`에서 `DD XX YY`가 교체 제어코드. 이 3바이트만큼 0xC8C0·0xC8C1을 갱신해줘야 다음에 XX YY가 대사로 잘못 출력되지 않음. **기존 0x3900부터 이미 0xC8C0·0xC8C1 갱신 로직이 있으니 이를 살려 우회.**

**우회처리.** 먼저 롬 0x0000~0x3FFF 빈 공간 확인 — **GB는 롬 0x0000~0x3FFF(뱅크0)가 램 0x0000~0x3FFF에 고정, 0x4000~0x7FFF는 뱅크 스위칭**되므로 로직은 가능한 뱅크0(0x0000~0x3FFF)에 짜야 안전. `jp`는 3바이트를 먹는데 0x38FD~0x38FF가 마침 3바이트고 0xC8C0·0xC8C1 갱신에 영향 없어 여기서 우회 시작. (jr은 2바이트지만 이동거리 제약.)

**희생될 코드** `ldi a,(hl) / push af / ld a,l`은 나중에 복원하려 메모. 0x38FD 에디트 창에 `jp 3d00` 입력 > OK. File > Save Rom as 저장. 0x38FD 더블클릭으로 토글 브레이크 > Reload Rom. 멈추면 F7로 0x3D00 점프 확인(복귀 주소는 다음 줄 0x3900). 0x3D00에 희생 코드 복원 + 복귀:
```
ldi a,(hl)
push af
ld a,l
jp 3900
```
저장·재시작 → 0x38FD에서 우회 시작 → 희생 로직 되살려 실행 → 0x3900 복귀. 문제없음 확인. **GB는 나쁜 뱅크·인터럽트 때문에 로직 수정을 적당히 끊어 저장·확인하며 진행하는 게 정신건강에 이롭다.** (실제 폰트세트 교체는 다음 회차.)

### 6. 압축 그래픽 데이터의 분석 (#31804)
- 원문: https://cafe.naver.com/f-e/cafes/16259867/articles/31804

타이틀 그래픽 수정. 폰트처럼 그래픽도 압축. VRAM 뷰어를 보면 타일이 조각나 있어 퍼즐 맞추기 필요. 압축을 VRAM에 올리려면 WRAM에 풀어야 하니 이 시점에 덤프. 그래픽 데이터 범위 **0xCB91 ~ 0xDB90**(풀린 상태로 WRAM에 남아 있음).

풀린 데이터 첫 부분 `80 80 83 83 FF FF FE FF`를 롬에서 검색 → 한 군데 **0xAA36E = 2A:636E**(FE FF 이후도 동일 → 타이틀 그래픽). 기억해 둠.

**압축 해제 시점 추적.** 끝부분 근처(0xDB81=0xF8이 쓰일 때)에 access breakpoint(db81, 값 f8, on write) > Reload Rom. 멈추면 F8(Step out, 현재 루틴 탈출) → **0x1E5F call 2C40**에서 멈춤(call 2C40이 압축 해제 로직으로 추정). db81 조건 삭제, 0x1E5F 더블클릭 토글 브레이크 후 재시작. 

**디버깅 3대 기능(식당 비유):** trace(F7)=요리 전 과정 세세히 추적 / step over(F3)=과정 생략하고 결과만 / step out(F8)=필요 부분만 보고 리턴까지 스킵.

0x1E5F에서 멈출 때마다 F3(Step over)로 0xCB91~0xDB90 변화 확인 → **hl=6368일 때** 타이틀 그래픽이 올라감. 5번의 2A:636E와 유사, 현재 뱅크 2A → `2A:6368`. 롬에서 `2A 68 63`(플립) 검색 → 한 군데. 그 값을 `2A 68 63 → 2A 6E 4F`(2A:4F6E)로 바꿔 저장·재시작 → 화면이 완전히 깨짐("대환장 파티") = 이 3바이트가 그래픽 포인터가 맞음.

**알게 된 점:** ①0x1E5F call 2C40 = 압축 해제 서브루틴 ②2A:6368(0xAA368) = 타이틀 그래픽 압축 데이터 시작 ③압축 그래픽은 [뱅크:주소] 3바이트 포인터 존재.

**압축 헤더.** 타이틀 압축 데이터는 **6바이트 헤더 + 압축 데이터**. 뱅크 0x2A의 다른 압축과 비교 시 헤더 첫 2바이트 `00 10`은 압축 플래그로 보이나 나머지 4바이트는 불명(파일 크기도 아님). 압축 해제 루틴이 비트 단위로 처리해 분석이 매우 복잡 → 정공법(압축 알고리즘 분석) 포기. **LZ 계열이었다면 8바이트마다 무압축 플래그라 쉬웠을 텐데** LZ가 아니라 안타까움. (To be continued.)

## 부록 — 게임 간 공통 기법 요약

- **롬 타입 판별이 최우선**: LoROM(뱅크 0x8000, 80~) vs HiROM(뱅크 0x10000, C0~). 이후 브레이크포인트 주소 환산·확장 한계가 달라진다.
- **폰트 고유번호 추적**: 무압축·50음도 순이면 SearchR 상대검색(패트레이버 SMAS). RAM 상주 폰트면 덤프 후 WRAM에 SearchR용 폰트를 주입(잔쿠로).
- **폰트 확장 두 축**: (a) 대사 주소·뱅크로 폰트를 찾는 게임은 출력 루틴에 제어코드(F0~/E5~/A~E 등) 비교 분기를 삽입해 확장 영역 시작주소·뱅크를 결정(패트레이버·SMAS·아크맨3). (b) 폰트 계산 루틴의 "시작주소·뱅크 상수" 두 값만 바꾸면 폰트 위치를 재지정할 수 있다(SMAS의 핵심 통찰).
- **대사공간 확장**: 3바이트 포인터([주소:뱅크])면 뱅크 상수 하나만 확장 뱅크로 교체(아크맨3). 2바이트 포인터만 있고 뱅크가 다른 코드와 얽히면 확장 포기가 나을 때도 있다(패트레이버 일반 텍스트).
- **압축 그래픽 우회 = VRAM 직접 쓰기**: 원본 타일이 VRAM에 쓰인 뒤 화면 출력 전에 한글 타일로 덮어쓴다. 비교 트리거 값과 삽입 위치 탐색이 관건(패트레이버, SFC DMA 템플릿). GB는 압축 포인터([뱅크:주소])를 찾아 다른 데이터로 바꿔보며 검증(잔쿠로).
- **디버거 활용**: Mesen의 Step Back(Shift+F10)은 역추적에 강력. 토글 브레이크(무조건 정지) vs 조건 브레이크(값 만족 시). Step Into(F11)/Step Over(F3)/Step Out(F8/Shift+F11)/Trace(F7)를 상황에 맞게.
- **GB 특유 주의**: 로직은 뱅크0(롬 0x0000~0x3FFF)에 짜야 뱅크 스위칭·인터럽트 사고를 피한다. 로직 수정은 잘게 끊어 저장·검증.
