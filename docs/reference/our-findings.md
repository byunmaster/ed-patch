# 우리 프로젝트 발견 (Our Findings)

이 프로젝트(eiyuu-densetsu-kr)에서 **직접 발견·검증한 재사용 기법**을 축적하는 살아있는 문서.
같은 폴더의 다른 문서들이 한식구 카페·외부 블로그 등 **커뮤니티 자료**라면, 이 문서는 **우리 실전 발견**이다.

## 축적 규칙

작업 중 새 해결책·기법을 확인하면:
1. **관련 플랫폼 문서에 이미 그 주제가 있으면** 거기(`ps1-saturn.md` 등)에 보강한다.
2. **없으면 여기**에 아래 템플릿으로 추가한다.
3. 확정(검증)된 것만. 추정은 "가설"로 명시.

```
### 제목 (플랫폼)
- 상황: 무슨 문제/맥락
- 해결: 실제로 통한 방법 (재현 가능하게 — 주소·수치·절차)
- 근거/위치: 커밋·파일:라인·태스크·메모리
- 일반화: 다른 게임/플랫폼에도 적용되는지
- 날짜:
```

## PS1 — 영웅전설 (ED1 / ED2)

> 아래는 프로젝트 메모리 기록 기반 시드 항목. 작업 재개 시 코드로 재확인하며 갱신할 것.

### 오프닝 자막 — PS1 BIOS 한자폰트 재사용 (PS1)
- 상황: ED1 오프닝은 롬 임베드 폰트가 아니라 **PS1 BIOS의 한자폰트(16×15, 30B/자)**를 사용해 출력.
- 해결(방향): 한글화 = 임베드 폰트 추가 + OPEN1 코드패치로 폰트 소스 전환.
- 근거/위치: 프로젝트 메모리 `ed1-opening-font`.
- 일반화: BIOS 폰트를 쓰는 PS1 타이틀 전반의 공통 이슈.
- 날짜: 2026-07(기록) — 재확인 권장.

### 시스템 텍스트 정렬 ASM — 정렬값 = 바이트수 × 3 (PS1)
- 상황: ED.EXE ↔ ED1MAIN.EXE UI 시스템 텍스트 이식 시 정렬 계산.
- 해결: 정렬 ASM의 값 X는 **문자 바이트수 × 3** (값 자체가 아니라 바이트 기반).
- 근거/위치: 프로젝트 메모리 `ed1-system-text`, task #12.
- 날짜: 2026-07(기록) — 재확인 권장.

### ED2 씬 매핑 — 윈도우 가설 오류 (PS1)
- 상황: ED2 KR 그룹0-8 vs JP SCN1-13 매핑.
- 해결: 초기 "윈도우 기반" 가설은 **오류**로 판명 → 재도출 필요.
- 근거/위치: 프로젝트 메모리 `ed2-scene-mapping`.
- 날짜: 2026-07(기록).

## 문안 파생 체계(textmap) — 저작권 있는 문장을 리포에 안 담는 구조

- 문제: 패치 도구에 번역 테이블을 임베드하면 팔콤 일문 원문·정발(만트라) 번역문이
  리포·git 히스토리에 남는다. 리포 공개 시 저작권·커뮤니티 리스크.
- 구조(3계층): `originals/`(소장 원본, gitignore) → `textmap/*.json`(커밋 — 정발 문안은
  **(파일·오프셋·길이) 포인터**로만, 우리가 쓴 번역만 원문 수록) → 빌드 시
  `tools/derive_text.py`가 원본에서 문장을 추출·검증(sha1 가드)해 테이블 재구성.
- JP 원문 키는 sha1 해시 — 소비 코드는 디스크에서 스캔한 JP를 해싱해 조회하므로
  일문이 리포 어디에도 없다. 단어 수준 명칭·라벨은 저작권 대상이 아니라 코드 유지.
- 임베드형 테이블을 이 구조로 옮길 땐 `tools/gen_textmap.py`: 테이블을 ast로 읽어 DOS
  코퍼스 역검색(원문 그대로/조판 역변형/미발견=우리 번역)으로 분류 → textmap 생성 →
  파생 라운드트립 == 원 테이블 assert → 소비부를 로더로 치환 → **빌드 바이트 동일** 확인.
- 위치: `games/ps1-eiyuu12/tools/derive_text.py`·`gen_textmap.py`·`textmap/`.
- 일반화: 정발판이 존재하는 모든 한글패치에 그대로 재사용(차기 게임 골격).
- 날짜: 2026-07-13.
