# 압축·인코딩 기법

레트로 게임 한글화에서 반복되는 압축(LZ/LZSS) 해제·판별, 문자 인코딩 변환(UTF-8↔SJIS, Shift-JIS↔JIS), 헥스/텍스트 정규표현 편집 기법을 정리한 레퍼런스.

> 출처: 한글화하는 사람들의 모임(hansicgu) 카페

## 한글화 강좌 - LZ 압축 풀어보기 (#31026)

- 원문: https://cafe.naver.com/f-e/cafes/16259867/articles/31026
- 도구: PS2 에뮬레이터 pcsx2-qt(내장 디버거), 헥스에디터, Python
- 대상 예시: PS2 "도키메키 메모리얼 걸즈 사이드"의 스크립트 파일 `A01_00_000.exs` (압축 크기 0x1A6C, 해제 크기 0x51A0)

LZ77 변종 압축을 어셈블리(MIPS32) 역추적으로 해석해 Python 해제 코드까지 만드는 실전 절차. 핵심 개념: LZ 매치 정보는 보통 (현재 바이트의 압축 유무 1비트) + (복사할 데이터의 위치=offset) + (복사할 길이=length)로 구성되며, 이 세 값을 몇 비트로/어디에 기록하느냐에 따라 변종이 갈린다.

### 헤더·비트필드 구조 (이 게임의 경우)
- 첫 4바이트(uint32, 리틀엔디안): **비트 개수**. 예시 파일은 `0x0EEE`(3822).
  - 어셈블리에서 `+7` 후 `>> 3`(=올림 나눗셈 ÷8) 하는 것을 보고 "이 값이 비트 개수이며 바이트 수로 환산 중"이라 역산. `(bits + 7) >> 3`이 비트필드의 바이트 길이.
- 이어서 그 바이트 길이만큼 **비트필드**가 온다. 각 비트 = 뒤따르는 payload 1항목의 압축 여부 플래그.
- 비트필드 뒤부터 실제 **payload**(압축된 본문).

### 플래그 해석 순서 (중요한 함정)
- 비트필드의 각 바이트는 **비트를 역순(LSB→MSB)으로** 읽는다. 어셈블리에서 동적 시프트로 1비트씩 역순 추출하는 것을 확인. Python에서는 `int('{:08b}'.format(byte)[::-1], 2)`로 바이트를 뒤집어 처리.
- **비트 == 0 → 압축(매치)**, **비트 == 1 → 리터럴(미압축)**. (분기 방향을 어셈블리에서 확인: 0일 때 복사 루틴으로 분기.)

### 매치 정보(비트=0일 때) 2바이트 해석
- payload에서 2바이트(리틀엔디안 word)를 읽는다.
- **하위 4비트 = length**, **상위 12비트 = offset**.
  - `length = (word & 0x000F) + 2` — 어셈블리에서 최소 1회 복사 + `+1` 보정이 걸려 실질 최소 길이 2.
  - `offset = (word >> 4) & 0x0FFF` — 12비트라 최대 0x0FFF이나 코드상 +1 보정으로 실질 최대 0x1000.
- offset은 4096(0x1000) 크기 **슬라이딩 윈도우 내 절대 위치**. length만큼 `window[(offset + j) & 0x0FFF]`를 읽어 결과와 윈도우 양쪽에 쓴다(윈도우 인덱스도 `& 0x0FFF`로 순환).
- 종료 조건: 매치의 12비트 값(offset)이 0이면 해제 종료(어셈블리에서 `jr ra`로 복귀). 즉 offset 0은 나올 수 없는 sentinel.

### 리터럴(비트=1일 때)
- payload에서 1바이트를 그대로 읽어 결과와 윈도우에 쓴다. (원문 주석: 게임에 따라 2바이트씩 읽는 변종도 있으니 주의.)

### 윈도우 참조 방식 — 절대 offset vs 상대 distance
- 이 게임은 **윈도우 내 절대 위치(offset)** 참조: `copy = window[(offset + j) & 0x0FFF]`.
- 다른 LZ 변종은 **현재 위치에서 뒤로 distance만큼** 참조: `copy = dist[dist_index - distance]`. 어느 방식인지 반드시 구분해야 결과가 맞는다.

### 역추적 워크플로 (재현용)
1. 첫 대사 스크립트처럼 로드 시점이 빠른 파일을 고른다(디버깅 편의).
2. 헥스로 열어 깨진 텍스트/헤더 패턴(첫 4바이트가 리틀엔디안 크기값 등)으로 압축 의심.
3. 에뮬 디버거의 메모리 검색으로 헤더 값(예 0x0EEE)을 찾아 로드 주소 확보(주소는 재실행마다 바뀔 수 있음).
4. 그 주소에 **읽기 브레이크포인트**(크기 4, 읽기만 체크)를 걸고 해당 장면까지 진행 → 게임이 데이터를 읽는 순간 정지.
5. 정지 지점부터 어셈블리를 따라가며 (a)4바이트를 리틀엔디안으로 합치는 부분, (b)`+7 >>3`로 크기 환산, (c)1비트 추출/분기, (d)2바이트에서 4비트·12비트 분해, (e)복사 루프를 각각 식별.
6. 파악한 규칙으로 Python 해제기 작성·검증.

원문에 완성된 Python `decompress(data, size)` 전체 코드와 각 어셈블리 블록(0x0010BA64 등) 주석이 실려 있다. 상세 스크린샷·전체 소스는 원문 참조.

## 변종 lzss를 속이는 방법 (#22335)

- 원문: https://cafe.naver.com/f-e/cafes/16259867/articles/22335
- 도구: Python(.py) + .bat 실행 래퍼
- 대상: 슈퍼로봇대전UX(전투 대사) 재삽입

재압축(부호화)이 어려울 때, **모든 데이터를 "무압축"으로 표시해 압축 파일 형태만 흉내내는** 우회 기법.

- 전제: 대상 기기에 "이 파일이 압축되었는가?"를 판정하는 루틴이 있고, LZSS류처럼 **키 바이트(플래그 바이트) 1바이트가 뒤따르는 8바이트 각각의 압축 여부를 비트로** 나타낸다고 가정.
- 핵심: 키 바이트를 `0x00`(이진 `0000 0000`)으로 두면 "뒤의 8바이트는 전부 무압축, 그대로 읽어라"는 뜻이 된다. 이 규칙으로 원본 데이터를 (키바이트 0x00 + 리터럴 8바이트) 블록의 반복으로 재구성하면, 실제 압축은 안 했지만 기기는 정상적인 압축 파일로 인식해 출력한다.
- 효과: 재압축 알고리즘 구현 없이 번역문 재삽입 가능. 형태를 안 맞추면 오류는 안 나도 해당 대사가 출력되지 않음.
- 부작용 주의(댓글): 이렇게 하면 데이터 오프셋이 밀리므로, 대사를 포인터로 불러오는 경우 밀린 만큼 포인터 값을 보정해야 한다.

주석 달린 Python 코드가 원문에 첨부. 사용법은 `.bat` 안에 `[.py] [압축할 파일]` 형태.

## 매우 간단하게 파일이 압축/암호화되었는지 확인하는 방법 (#26355)

- 원문: https://cafe.naver.com/f-e/cafes/16259867/articles/26355
- 도구: HxD 헥스 에디터

파일을 열지 않고 **바이트 분포(히스토그램)만으로** 압축/암호화 여부를 가늠하는 방법.

- 절차: HxD로 파일을 열고 메뉴 [분석] → [통계] 창을 연다.
- 판독:
  1. **압축된 파일**: 모든 바이트 값이 거의 고르게 분포(엔트로피 높음).
  2. **암호화된 파일**: 마찬가지로 모든 바이트가 고르게 분포(압축과 통계만으로는 구분 어려움).
  3. **평범한 이진 데이터**: 특정 바이트(특히 `0x00`)의 빈도만 유독 크게 튐(분포 편향).
- 결론: 분포가 평탄하면 압축 또는 암호화, 특정 바이트가 몰려 있으면 원시(raw) 데이터일 가능성.

분포 그래프 스크린샷은 원문 참조.

## shift-jis -> jis 변환소스 (#17635)

- 원문: https://cafe.naver.com/f-e/cafes/16259867/articles/17635
- 도구: C (표준 입력으로 SJIS 2바이트 16진수를 받아 JIS 2바이트를 출력)

Shift-JIS 2바이트 코드를 JIS(구점/면구) 코드로 변환하는 공식 구현. 입력 `82 A0` → 출력 `24 22`.

변환 로직(입력 바이트: c1 = 1번째, c2 = 2번째):
- 둘째 바이트 처리 (`c2 > 0x7F`일 때):
  - `temp0 = c2 - 1`
  - `temp0 < 0x9E`이면 `flag = 1`, `temp0 -= 0x1F`
  - 아니면 `flag = 0`, `temp0 -= 0x7D`
- 첫째 바이트 처리:
  - `c1 <= 0x9F`이면 `temp1 = c1 - 0x70`
  - 아니면 `temp1 = c1 - 0xB0`
  - `temp1 = temp1 * 2 - flag`
- 출력: 첫 바이트 = `temp1`, 둘째 바이트 = `temp0`.

(한글날팀 강좌 http://cafe.naver.com/hansicgu/1046 를 참조해 작성.)

## 정규표현이 배우고 싶어지는 8가지 예시 (#32042)

- 원문: https://cafe.naver.com/f-e/cafes/16259867/articles/32042
- 도구: 정규표현식 찾기/바꾸기 지원 텍스트 에디터(에디터명 미표기, 스크린샷 기반)

헥스 덤프/폰트 테이블/번역 텍스트를 다룰 때 자주 쓰는 찾기·바꾸기 정규표현 모음. `없음`은 바꿀 말을 비워 삭제한다는 뜻.

1. 개행 제거 후 2바이트(=4 hex 문자)마다 다시 개행
   - 개행 제거: 찾기 `\n` → 바꾸기 없음 (한 줄로 붙임)
   - 4문자마다 개행: 찾기 `(....)` → 바꾸기 `\1\n`
2. 바이트 플립(2바이트 단위 앞뒤 교환): 찾기 `(..)(..)` → 바꾸기 `\2\1`
3. `폰트코드=글자` 형태에서 한쪽만 추출
   - 코드(왼쪽)만: 찾기 `(.+)=(.+)` → 바꾸기 `\1`
   - 값(오른쪽)만: 찾기 `(.+)=(.+)` → 바꾸기 `\2`
4. `=` 좌우를 뒤바꾸기: 찾기 `(.+)=(.+)` → 바꾸기 `\2=\1`
5. 각 줄 맨 앞 1바이트(2 hex 문자)를 `0E`로 교체: 찾기 `^(..)` → 바꾸기 `0E`
6. 각 줄 끝 2바이트(4 hex 문자)를 `FFFE`로 교체: 찾기 `(....)$` → 바꾸기 `FFFE`
7. `{...}` 제어코드 제거: 찾기 `{[0-9A-Z]+}` → 바꾸기 없음
8. 일본어(한자·히라가나·가타카나·전각 영숫자)만 남기고 삭제: 찾기 `[^一-龠ぁ-んァ-ヴａ-ｚＡ-Ｚ０-９]` → 바꾸기 없음

각 단계의 전/후 스크린샷은 원문 참조.
