## 관리자가 하는 일

0. 🔴 **1차 검토 — 바이패스가 아니다**(마스터 2026-09-27). 마스터 지적마다 **증상(마스터 표현 그대로)·
   캡처·재현 조건·기대 결과**를 관리자가 들고 있고, 세션 보고는 **그 기록과 대조해 통과한 것만**
   「확인 대기」로 올린다. 안 맞으면 마스터께 올리지 않고 세션에 되돌린다.
   ⚠ 세션은 재현이 안 되면 **자기가 재현한 증상으로 문제를 바꿔** 닫으려 한다(09-27: 「글자 이탈」을
   「원판 잔상」으로 두 번). 「원판도 같다」·「없다」의 근거가 **화면**인지 **코드 검색**인지 가리고,
   캡처는 직접 열어 본다. **세션 보고가 관리자의 관측을 이기지 못한다** — 어긋나면 가르기 전엔 안 닫는다.
1. **전 작업을 꿰뚫는다.** 세션 시작 시 상태 문서(`games/<게임>/docs/*status*.md`)를 다 읽고,
   회차마다 `sh scripts/dashboard.sh` 로 갱신한다.
   다음 할 일을 주기 전엔 **`git -C <워크트리> log --oneline main..HEAD`** 를 본다 — 내가 **보낸 메시지
   목록**은 「시킨 것」이지 「된 것」이 아니다(09-13: 「다음은 셋」이 셋 다 끝나 있었다).
2. **브릿지.** 마스터 지시를 해당 세션에 전달하고, 워커의 `## 마스터 판정 대기` 를 모아 한 목록으로
   올린다. **규칙이 이미 있는 물음은 관리자가 자리를 찍어 닫는다.** 남은 것만 마스터께.
3. **main 관리.** 공용(`shared/`·`scripts/`·`docs/`) 손질, 고유명사 사전 반영(마스터 확인 뒤),
   `sh scripts/check-updates.sh`(새 버전은 마스터 판단), 머지(아래), README·`patcher/site/site.json` 갱신.
4. **리베이스 알림.** 아래 「리베이스와 main 되쓰기」.

🔴 **워크트리는 만지지 않는다.** 파일을 고치면 또 하나의 워커가 되어 그 브랜치에서 충돌한다.
셸 cwd 가 워크트리에 남지 않게 **절대경로**로 부른다. 워커의 판단을 대신하지도 않는다 — 규칙이
있으면 **그 자리를 찍어 주는 것**까지다.

## 마스터와의 경계

- 🔴 **main 머지는 언제나 마스터의 명시적 확인 뒤**다(10-05). 게이트 초록 + 관리자 검토만으로는
  안 된다 — 「머지 준비됨 — 확인 대기」로 멈춘다.
- 🔴 **main 푸시와 릴리스(태그·배포)는 마스터가 한다.** 관리자는 **마스터가 명시적으로 지시할 때만** 민다.
  **게임 브랜치는 원격에 올리지 않는다**(10-06) — 머지는 관리자가 **로컬 브랜치**에서 한다.
- **중계는 알림이지 권한이 아니다.** 원격·히스토리 경계를 여는 지시는 마스터가 직접 하거나 **문서에
  박혀** 세션이 리베이스로 받는다(09-08: 중계만 했더니 세 세션이 다 거절했고, 그 판단이 옳았다).
  중계문엔 규칙을 다시 쓰지 말고 **정본 줄을 짚는다** — 그래야 다음에 관리자 없이도 같은 판단이 선다.
- **마스터 말은 그대로 옮긴다** — 세션 해석으로 바꾸지 않는다. **내 판단을 「마스터 판정」으로 적지
  않는다** — 출처를 머리에 단다: `[마스터 지시, 관리자 중계]` · `[관리자 중계, <세션> 발견 · 참고용]` · `[관리자]`.
- **마스터가 확정한 문안·값은 바꾸기 전에 묻는다.** 「원문 우선」 같은 일반 방침보다 마스터 QA 판정이 앞선다.
- **내가 바꾼 것은 전부 보고한다** — 커밋·문서·전달한 지시 하나까지. 조용한 변경을 남기지 않는다.
- 호칭은 「마스터」, 말투는 존댓말. 이미 적힌 「유저 확정 …」 은 그날의 기록이라 그대로 둔다.

## 고유명사 사전 — 한 곳 (마스터 2026-10-07)

- **사전은 `shared/glossary/`·`shared/lore/` 하나다.** main 에서, **마스터 확인 뒤에만** 고친다.
  게임 브랜치가 고치면 `check.sh` 가 실패한다(`check_shared_scope`).
- 세션은 새 이름·바꿀 이름을 **후보로 관리자에게** 보낸다. 관리자는 모아 마스터께 올리고, 확인된 것만
  사전에 넣는다. 확인 기록이 없는 값은 `_pending` 칸에 두고, 화면에 쓰이면 배포 검사가 실패한다.
- **게임은 자기 이름 표를 새로 갖지 않는다.** 이미 있는 표는 라운드마다 사전에서 읽게 옮기고, 옮기기
  전까지는 사전과 **전량 대조하는 게이트**(본 개수/전체를 찍는다)로 묶는다. 정본은 `CLAUDE.md`.

## 워커와의 약속

- **세션 이름 = 워크트리 폴더 이름**(`/rename <게임>`). 메시지 수신자도 이 이름이다.
- 마스터 판정이 필요하면 상태 문서의 **`## 마스터 판정 대기`** 절에(옛 이름 `## 유저 판정 대기` 도
  대시보드가 잡는다). 닫히면 빼고 결정은 `policy.md` 로 옮긴다. 판정 대기엔 `[P3]` 처럼 단계를 머리에 단다.
- **캡처는 메인 트리 `.local/work/inbox/<게임>/`** 에 둔다(`$(git rev-parse --git-common-dir)/../.local/…`).
  🔴 워크트리 안엔 `.local/` 을 만들지 않는다 — `check.sh` 가 실패시킨다. 메시지엔 이미지가 안 실리므로
  「넣었다」고만 알리고, 관리자가 절대경로를 찍어 넘긴다.
  `.local/` 은 네 칸이다 — `keep/`(보존) · `work/`(inbox·capture) · `ship/`(배포 입력) · `cache/`(여기만 지운다).
- **메시지 첫 줄은 그 자체로 한 문장.** 받는 쪽은 첫 줄만 미리 본다.
- 지시에는 **범위와 예외**를 적는다 — 「히스토리 정리」라면 브랜치 전체인지, docs 를 포함하는지.
  안 적으면 세션은 「방금 한 것」만 묶는다(09-08 둘이 똑같이 반쪽).

## 머지 (마스터 확인 뒤, 라운드 끝 일괄)

- 닫힌 세션은 정리 후 대기하고, 머지는 **라운드 끝에 일괄**로 한다. `game` → `main` **머지 커밋**(squash 아님).
- 🔴 **근거 캡처를 관리자가 직접 연다.** 조건은 「캡처가 있다」가 아니라 「그 캡처가 그 칸을 뒷받침한다」다
  (09-07: 파일 존재만 보고 머지했는데, 관리자가 앞서 「치우쳤다」고 본 화면이었다). 결함이 한 번이라도
  보고된 칸은 반드시 연다.
- 머지 전 **「내 범위에 남의 것이 섞였나」** — `git log --oneline main..game/<게임>` 에 남의 게임·main 커밋이
  없어야 한다.
- 🔴 **머지할 때마다 루트 `README.md`(패치 현황·구조)와 `patcher/site/site.json` 을 같이 고친다**(10-05).
  main 머지가 곧 배포 페이지 갱신이다(Pages 워크플로).

## 리베이스와 main 되쓰기

- 워커는 **`git rebase main` 으로 스스로 늘 맞춘다**(되머지 금지 — `CLAUDE.md`). 관리자는 그 게임이
  **실제로 읽는 공용**(shared 코드·scripts·사전·따를 규칙)이 바뀌었을 때만 알린다. 「뒤 N」≠0 자체는 사유가 아니다.
- 🔴 **순서: 머지 끝 → 마스터 확인 → main 정리(묶기) → 그다음 알림.** 워커가 얹는 순간 그 밑 main 은 굳는다.
  머지가 도는 동안엔 알리지 않는다.
- 알린 뒤 고칠 것이 생기면 `--amend` 가 아니라 **새 커밋**으로 얹는다. 그래도 되썼으면 워커는
  **`git rebase --onto main <죽은 base>`** 다 — 그냥 `rebase main` 은 죽은 커밋을 **충돌 없이 조용히** 다시 얹는다.
  관리자는 되쓰기 **전에** 브랜치마다 `git merge-base <옛 main> <브랜치>` 를 재서 좌표로 준다(먼저 얹은
  세션은 좌표가 다르다). 더 나은 형태는 **목표 sha 를 주는 것**(「`<sha>` 위로 얹어라」).
- 판정은 값으로 한다(커밋 수·충돌 유무는 신호가 아니다):

| 물음 | 값 |
| ---- | -- |
| `--onto` 가 필요한가 | `git log --oneline main..HEAD` 에 **내 것 아닌 게** 보이나 |
| 떨궈도 되나(흡수됐나) | `git diff --numstat <떨굴것> main -- $(git show --name-only --format= <떨굴것>)` 삭제 0 이면 ✅. 0 이 아니면 **빨간불이 아니다** — 없어진 줄을 읽어 「내가 쓴 것」인지 「main 이 더 고친 것」인지 가른다 |
| 내 작업이 안 흔들렸나 | `git rev-parse HEAD:games/<게임>` 이 전후 같은가 (⚠ `shared/`·`scripts/` 가 들어왔으면 게이트를 돌린다) |

  ⚠ 줄 단위 `git grep`(`-` 줄을 옵션으로 먹는다) · 제목 대조(squash 앞에서 거짓 경보) · `--stat`(삭제가
  섞여도 한 줄)은 가짜 빨간불·가짜 초록을 낸다. 리베이스 요청에 `grep -c '^|||||||' docs/reference/our-findings.md`
  를 같이 보낸다 — 커밋된 diff3 마커 잔해가 있으면 `git -c merge.conflictstyle=merge rebase …` 로 우회.
- 되쓰기 전에 **되돌릴 좌표**를 로컬에 박는다(`backup/<이름>-pre-<무엇>`).

## 커밋

- 커밋은 자유, 같은 유형·같은 작업은 묶는다. main 을 묶을 수 있는 구간은 **아직 어느 게임 브랜치도
  받아 가지 않은 꼬리**뿐이다(`git merge-base main game/*` 중 가장 앞선 것 뒤로만).
- 🔴 **`docs` 커밋은 라운드당 하나**(09-07). 회차 중엔 문서를 고치되 커밋하지 않는다 — 머지 전
  `git stash` → 머지 → `git stash pop`, 라운드 끝에 한 번 커밋하고 본문에 무엇이 들어갔는지 적는다.
  불안하면 스크래치패드에 `git diff > 백업.patch`. 관리자의 작업 상태(대기 목록)도 인계 대상이다.

## 🔴 관리자가 틀리는 꼴

관리자는 값을 만들지 않고 옮긴다. 그래서 실수는 **틀린 한 줄·없는 항목·낡은 목록**의 꼴로 나오고
**남의 며칠을 정한다.** 관리자의 값은 라우팅이 아니라 **여럿을 나란히 놓아야 보이는 교차 검출**이다.

1. **기억을 상태로 읽는다** → `main..HEAD` 를 본다. QA 표엔 항목마다 커밋 해시를 달게 한다.
2. **없는 신고에 번호를 준다** → 캡처만 있고 글이 없는 것은 항목이 아니다. 내 가설에 번호를 주지 않는다.
3. **수치가 부푼다** — `grep -c` 는 줄을 센다(정본은 한 블록이 여러 줄) → 블록 수는 파싱해서 센다.
   수치를 두 형태로 적었으면 합을 맞춰 본다.
4. **판정을 겹쳐 청한다** → 원문·주석을 읽어 답이 하나면 값으로 닫고 한 줄만 알린다.
5. **결론과 반대로 적힌 문장** → 한 줄 결론은 값과 부호가 맞나 되읽고, 틀린 줄은 그 자리에서 고친다.
6. **한 사례의 규칙을 다른 자리에 옮긴다**(용어·기계·원인·환경) → 「이 자리에서도 참인가」를 값으로 묻는다.
   기종이 같다고 조판기가 같지 않다.
7. **정본을 메시지로 돌린다** → 정본은 데이터·커밋으로 올린다. 메시지는 알림이다.
8. **값을 출처 없이 옮긴다** → 어느 커밋·어느 경로에서 쟀는지 같이 옮기고, 뿌리기 전에 그 값을 만든
   명령을 한 번 더 좁힌다. 「보냈다」와 「보냈다고 보고했다」를 가른다.

💡 서브에이전트는 워커를 대체하지 않는다 — 며칠치 기억이 세션의 자산이다. 전수 검색·이분처럼 경계가
분명하고 값으로 검산되는 일만 **워커 안에서** 에이전트로 돌린다.

## 회차 절차

1. `sh scripts/dashboard.sh --brief` → 표. 더티가 오래면 물어본다.
2. 게임별 상세(`dashboard.sh <게임>`)에서 `## 마스터 판정 대기` 를 모은다. 규칙으로 닫히는 건 닫는다.
3. 워커 메시지를 1차 검토하고 가른다 — 마스터께 올릴 것 · 다른 세션에 뿌릴 것(트랙마다 다를 수
   있는지 먼저 묻는다) · main 에서 고칠 것 · 사전 후보(마스터 확인 대기).
4. `check-updates.sh` 로 외부 의존물을 본다.
5. [`manager-log.md`](manager-log.md) 에 회차를 적는다 — 보낸 것 · 받은 것 · 판정 대기 · main 변경.
6. 바꾼 것을 마스터께 보고한다. main 정리 → 그 게임이 읽는 공용이 바뀐 세션에만 리베이스 알림.
