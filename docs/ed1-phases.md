# ED1 이식판 공통 단계 (유저 확정 2026-09-06)

PS1 ED1 이 1회차 QA 를 마치고 main 에 머지됐다(ada1a54e). 나머지 ED1 이식판은 **PS1 이 밟은
순서를 같은 단계로 같이 간다** — 관리자가 한 줄로 비교하고, 유저가 단계마다 **다섯을 한 번에
판정·테스트**하기 위해서다. 문안 방침은 「PS1 저본, 원문 우선」(각 게임 `policy.md`).

| 단계 | 내용 | 닫는 기준 (PS1 이 실제로 쓴 것) |
| --- | --- | --- |
| **P0** 기반 | 원본 지문 · 대본 덤프 라운드트립 · 폰트 자리 · 재삽입 파이프라인 · 빌드 게이트 · 에뮬 부팅 | 첫 대사가 인게임에 한글로 뜬다. `check.sh` 가 선다 |
| **P1** 시스템·고유명사 | 메뉴 · 시스템 메시지 · HUD · 아이템/주문/지명/몬스터 표 | 정본은 `shared/glossary`. 표기 검사기가 게이트에 |
| **P2** 전투 + 조사 | 전투 문안 · 조사(종성) 처리 | 조사 일치 검사가 상주 게이트에. ⚠ 동적 훅은 **기종이 허락할 때**다 — PC-98 은 실행 파일 제자리 예산이 없어 **정적 대체**(병기 없이 정본 표기에 맞춘 조사 + 검사기)로 닫는다(유저 판정 대기) |
| **P3** 연출 | 오프닝 · 엔딩 · 타이틀 · 장 카드 | 인게임 확인(유저 스크린샷 또는 emucap) |
| **P4** 대사 정본 | 씬 단위 번역 정본 — PS1 저본, 원문과 갈리면 원문 | 씬마다 전량 이관 · 화면 바이트 게이트(탈락 0) |
| **P5** 정적 QA | 화면 일본어 0 · 조판 고아 0 · 블록 경계 0 · 되읽기 · 결정성 · **세이브 호환** | `check.sh` 한 번에 전부 초록 = **RC**. 세이브 호환(09-06, pce 실측)은 ① **세이브에 우리 글자가 복사되는 자리를 찾았나**(파티원 이름·세이브 제목·장 제목 — 스캔이 아니라 재삽입기 출처로) ② 그 자리의 코드 배정이 **빌드 간 고정**인가(완성형 통째면 구조적, 서브셋이면 순서 정본 + 게이트) ③ 원판 세이브·시험 빌드 세이브와는 비호환임을 안다(배포 안내). 1차 선별은 둘 — **이름 입력이 있나 · 세이브 목록에 글이 뜨나**(pce 둘 다 예 · sfc 둘 다 아니오 = 해당 없음) |
| **P6** 인게임 QA | 유저 1회차 완주 + 확정 락 | 판정 대기 0 |
| **P7** | main 머지(머지 커밋, squash 아님) | |

## 규칙

- **앞 단계가 안 닫힌 채 뒤 단계로 가지 않는다.** 예외는 **파이프라인 검증용 소량**뿐이다
  (재삽입이 서는지 보려고 대사 몇 블록을 넣는 것). 그건 상태 문서에 「검증용」이라고 적는다.
- **상태 문서 「한 줄 요약」 첫 줄에 `단계: P2/7` 을 적는다.** 대시보드가 그 줄을 표에 싣는다.
  단계가 바뀌면 그 줄만 고친다.
- **유저 판정 대기는 단계를 머리에 단다** — `[P3]` 처럼. 관리자가 단계별로 묶어 올린다.
- **P6 는 직렬이다.** 유저 시간이 드는 유일한 단계라 다섯이 P5 에 모이면 그때 순서를 정한다.

## 어느 게임이 이 표를 따르나

콘솔 넷 + PC-98: `ss-ed1+2` · `pce-ed1` · `md-ed1` · `sfc-ed1` · `pc98-ed1`.
⚠ `ss-ed1+2` 는 합본이라 ED2 를 같이 굴린다(PS1 과 같은 사정).

**레트로 PC**(pc88 · x68k · fmt · msx)는 **나중에 따로 묶어** 같은 표로 간다. 팔콤 자체 이식이라
대본 형식이 한 집안일 가능성이 커서, **pc98 이 그 묶음의 저본**(콘솔에게 PS1 이 그렇듯)이 된다.
그래서 pc98 은 이번 묶음에서 P5 까지 같이 가고, **P6 를 콘솔과 같이 돌지 레트로 PC 묶음까지
미룰지는 그때 정한다**(전투 프리즈·펌웨어 문제도 그때 갈린다).

## 점검표 — 「닫혔다」는 근거로 말한다 (유저 지시 2026-09-06)

자기 보고는 틀린다(09-06 하루: 관리자가 pc98 위치를 틀렸고, pce 의 「닫힌」 전투 문구에 일본어가
남아 있었고, ss-ed1+2 의 「고정」 배정이 반쪽이었다). 그래서 단계를 닫을 때와 관리자가 점검을
돌릴 때 **아래 항목마다 근거를 붙인다** — 명령 한 줄 + 출력 한 줄, 또는 스크린샷 경로.
「했다」·「됐다」는 근거가 아니다. **미확인은 미확인이라고 적는다** — 그게 틀린 ✅ 보다 낫다.

| 단계 | 항목 | 근거의 꼴 |
| --- | --- | --- |
| P0 | 원본 지문 검사가 도구 입구에 있다 | 지문 대조 코드 위치 + 다른 이미지를 주면 죽는 출력 |
| P0 | 대본 덤프 라운드트립 무손실 | 명령 + 「N/N 동일」 |
| P0 | 빌드 결정성 | 두 번 빌드한 산출물 sha1 둘(같아야 한다) |
| P0 | `check.sh` 가 빌드 + 검사기를 묶는다 | `check.sh` 가 부르는 검사기 목록 + 게이트가 **안 부르는** 검사기 수 |
| P0 | 무변경 구간 byte 대조 | 선언한 구간 수 + 대조 결과 |
| P0 | 첫 대사가 인게임에 한글로 | 스크린샷 경로 |
| P1 | 시스템 문자열 | 총수 / 넣은 수 / **화면으로 본 수** |
| P1 | 고유명사 정본 | `shared/glossary` 를 읽나, 자체 표면 정본과 갈린 수 |
| P1 | 표기 검사기가 게이트에 | 검사기 이름 + `check.sh` 에서 부르는 줄 |
| P1 | 메뉴·HUD 화면 | 스크린샷 경로(메뉴 하나 · HUD 하나) |
| P2 | 전투 문안 | 총수 / 넣은 수 / 화면으로 본 수 |
| P2 | 조사 처리 | 동적 훅 / 정적 대체 중 무엇 + 조사 일치 검사의 게이트 줄 |
| P2 | 전투 화면 | 스크린샷 경로(이름·데미지·등장 문구가 보이는 한 장) |
| P3 | 오프닝 · 엔딩 · 타이틀 · 장 카드 | 넷 각각 스크린샷 경로 또는 「미확인(이유)」 |
| P4 | 씬 이관 | 씬 총수 / 전량 이관 씬 수 / 블록 총수 / 넣은 블록 수 |
| P4 | 화면 바이트 게이트 | 탈락 검사 이름 + 지금 탈락 수 |
| P4 | 화면 일본어 잔류 | 검사 이름 + 지금 수 + **그 검사가 못 보는 범위** |
| P5 | 되읽기 · 조판 고아 · 블록 경계 · 결정성 · 세이브 호환 | 각각 검사 이름 + 수 |

관리자는 답을 받아 **읽기 전용으로 대조**한다 — 그 검사기가 그 트리의 `check.sh` 에 실제로
있나, 스크린샷 파일이 실제로 있나, 수치가 상태 문서와 맞나. 갈리면 그 항목은 열린 것이다.
