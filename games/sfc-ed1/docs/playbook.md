# sfc-ed1 플레이 매뉴얼 — 켜기 전에 읽는다

QA 회차의 준비물이다(규약 [`docs/ingame-qa.md`](../../../docs/ingame-qa.md)).
**지금 아는 것만** 적는다 — 모르는 자리는 「미탐색」이라고 쓰지, 그럴듯하게 채우지 않는다.
라운드⑥(전투③) 진행 중 — 시스템 메뉴·HUD·오프닝·엔딩은 라운드⑤까지 닫혔고(`status.md` 22항목),
엔딩까지 무개입으로 밟아 본 전적이 있다(`tools/savefile.py --ending`). 아래는 세션이 실제로
밟아 본 데까지다.

## 🔑 유저 세이브를 물리는 법 (2026-09-08)

유저 세이브는 `/root/save/sfc-ed1/*.srm`(2,048B). **파일을 Mesen 의 `Saves/` 에 넣는 건 안 먹는다** —
이름의 롬 md5 를 맞춰도 안 읽혔다. 대신 **SRAM 에 직접 쓴다**:

```
write_memory(memory_type="snesSaveRam", address=0,
             input_file={"path": "<srm>", "length": 2048})
reset()          # ⚠ power_cycle 은 SRAM 을 지운다
```

리셋 뒤 타이틀 → **모험을 계속한다** → 슬롯 둘. **1번 = 마을 안**(상점·설정·메뉴) ·
**2번 = 마을 밖**(전투·이동·HUD). 빌드를 갈아도 절차가 같다.

## 🔑 리셋 부팅으로 본다 — 세이브스테이트는 안 된다

글꼴은 **부팅 때 한 번만** VRAM 에 올라간다($00:9156). 옛 빌드의 스테이트를 새 롬에 얹으면
**타일맵은 새것 · 글리프는 옛것**이라 엉뚱한 글자가 뜬다. 회차는 늘 리셋에서 시작한다.

## 조작 (2026-09-07 실기 확인)

🔴 **커맨드 창이 안 열리면 「이동 입력이 남았나」를 먼저 의심한다.** 2026-09-07 첫 회차에서
세션이 <kbd>B</kbd> 로 못 열어 「여는 법을 모른다」로 보고했는데, **방향키를 누른 직후라
캐릭터가 걸었을 뿐**이었다. 몇 프레임 쉬고 누르면 열린다(`press_frames=3` 으로 확인).
유저는 09-06 에 같은 방법으로 열었다 — **여는 법은 처음부터 맞았고 조작 순서가 문제였다.**

커맨드 창 차례: `주문 · 사용 · 장비 · 버린다 · 상태 · 그외 · 리더`.
`그외` → 시스템 창(`로드 저장 시스템 설정`) → 설정·전투 설정.

## 시작 순서

1. 타이틀(로고) — **START**
2. `처음부터 모험한다` / `모험을 계속한다` / `데이터를 지운다` → 첫 줄에서 **A**(한글, E2 닫힘)
3. 메시지 속도 창(`サクサク` / `ドキドキ`) → **A**
4. 1장 시작 — 왼쪽 위 띠에 **`제1장 왕자의 여행`**
5. 침실에서 시녀·라이아스 대사 몇 개(**A** 로 넘긴다) → 자유 이동

## 원판(일본어)으로 같은 자리 밟기 — 대조용

우리 빌드와 **조작이 같다**(2026-09-07 확인). 저장 화면까지:
1. 타이틀 → **START** → 세 줄 메뉴(커서는 **↑↓ 로 움직인다** — 움직이는지 먼저 보면 입력이 닿는지 알 수 있다)
2. 첫 줄에서 **A** → 메시지 속도 창에서 **A** → 1장
3. 대사를 **A** 로 여덟 번쯤 넘기면 자유 이동
4. **START** → 저장 창 → **A**(1번 슬롯) → 「◯ばん にセーブしますか?」 → **A** → **오른쪽 위에 `はい/いいえ` 창**
⚠ 3에서 **`B` 를 누르지 마라** — 커맨드 창이 열려 그 뒤 조작이 어긋난다(회차 하나를 그렇게 버렸다).

## 🔑 헤드리스 실플레이 — 세이브로 「계속」 열기 (2026-11-05)

`tools/lua/real_play.lua` 로 타이틀 → 「모험을 계속한다」 → 슬롯 → 필드까지 간다. 12번 헛돈 두 원인:
1. **세이브를 파일로 두면 안 읽힌다**(위 🔑) — Lua 에서 `snesSaveRam` 에 직접 쓴다: `RP_SRM=<2048B .srm> RP_SRMF=5`. 검증 루틴(`$00:9F3B` 명령 0 → `$9F52`)은 SRAM 앞 20바이트 서명 `00 01 … 13` + 플래그 `$70:0014~16` 3중 다수결(bit0=슬롯1 · bit1=슬롯2)로 슬롯을 연다 — 마스터 세이브는 둘 다 정상이다.
2. **START 를 로고가 뜨기 전에 누르면 메뉴가 안 열린다** — 로고는 ~340 에 완전히 뜨고, `RP_SCRIPT` 에서 `450:start:10` 이후 메뉴 페이드(~840)가 끝나야 ↓ 가 먹는다(그 전의 A 는 「처음부터」로 가 챕터 로딩이 돈다).
흐름(프레임): `450:start:10;1000:down:6;1040:a:6`(계속) → `1140:down:6`(슬롯 2, 생략하면 1) → `1240:a:6`(슬롯) → `1340:a:6`(예) → `1600~1900:a:20` 반복(속도 창·로딩, 짧게 한 번은 씹힌다) → ~2000 에 필드. 슬롯 2 = 크루즈마을 L11 · 골드 1221 · 교회 앞(남쪽 담장). 도구점은 교회 남동쪽 — 필드에서 `2000:right:48;2100:right:48;2200:right:48;2320:left:44;2420:up:10;2480:up:8;2540:a:4`(말걸기) 후 `2800:a:4`(대사 넘김) → 메뉴가 뜬 다음에야 `down` 이 먹는다(`2950:down:4` → `3050:a:4` 팝니다).
이동은 프레임당 약 2px. 대사·창이 뜨는 동안은 방향키가 안 먹으니 A 를 사이에 둔다. `RP_PADLOG=a-b` · `RP_PCS=hex,…`(실행 PC) · `RP_TRACE=a-b`(그 프레임 구간 실행 PC 목록) · `RP_WRAMDUMP=프레임,…` 로 진단한다.
상자 위치는 정적으로 못 찾았다(상자 열기 사슬 「보물상자를 열었다/안에는 …들어 있었다/손에 넣었다」는 사전 `D5` 문장이고, 호출은 `$19` 뱅크 씬 스크립트 몫이라 맵 표가 없다). 대신 **세이브로 연 진짜 필드**의 루프 머리(`$00:8339`)에서 `JSL $02:DC8B` 를 흉내 내 부른다: `RP_ADDR="49=27C46A,4A=27C493,4C=27C51A"`(번호=`msg_addr.py` 로 구한 새 롬 주소) · `RP_POKE="0F42=05"`(`{D9}` 아이템 번호) · `RP_INJ="2100:0049,2500:004A"`(프레임:번호) + `RP_SCRIPT` 의 `a` 로 쪽 넘김. msg_viewer 와 달리 창·팔레트·HUD 가 실제 필드 그대로다.
