### 12.1 챕터 제목 — 그래픽 텍스트다 (2026-09-06 실측)

`第1章 王子の旅立ち` 는 글꼴이 아니라 **그래픽 타일**이다. 실기 VRAM 으로 자리를 확정했다:

| 무엇 | 값 |
| --- | --- |
| 층 | **BG2**(타일맵 워드 1024 = 바이트 2048 · 문자 베이스 워드 4096 = 바이트 8192, BG 모드 0 = 2bpp) |
| 자리 | 화면 **행 2~3 · 열 2~17** — 16타일 × 2줄 = **128 × 16 px** |
| VRAM 타일 | 위 `$1D0~$1DF` · 아래 `$1E0~$1EF` |
| 롬 원본 | 뱅크 `$18` 의 2bpp 글리프 표(`$18:F39C` 등) — ⚠ **자리가 흩어져 있다**(위 첫 넷이
  `F39C·F3CC·F3AC·F3BC`) ⇒ 통짜 그림이 아니라 **한자 글리프를 색인으로 조립**한다. 색인표 미특정 |
| 좌우 장식 | 열 1(`$1BF`/`$1CF`) · 열 18(`$195`/`$1A5`) — 내주면 **18타일 = 144px** 까지 넓어진다 |

🔴 **제목 글꼴은 비례폭 12px 이다**(2026-09-06 실측 정정). 처음엔 인게임과 같은 16px 고정폭으로 잡아
「128px = 8자, 장식을 내줘야 한다」고 적었는데 **틀렸다.** 실제로 재니:

| 잰 것 | 값 |
| --- | --- |
| 글자 세로 | **12px**(획만) · 13px(어두운 테두리까지). 15행은 글자가 아니라 **밑줄 막대** |
| 글자 가로 | **고정이 아니다** — 한자 10~14px · 숫자 7px (`第`0 `1`10 `章`17 `王`33 `子`45 `の`56 `旅`66 `立`80 `ち`92) |
| 제목 전체 | x 0~100 = **101px** — 128px 중 27px 이 남는다 |

⇒ 한글도 **12px 고정폭**으로 그리면 128÷12 = **10자**가 들어간다. PS1 정본 `제1장 왕자의 여행` 은
12px 기준 **103px** 로 지금 일본어(101px)와 거의 같다 — **장식을 안 내줘도 들어간다.**
12px 한글은 `Galmuri11`(11px)이 가장 가깝다. 제목은 대사와 경로가 아예 달라 글꼴이 달라도 규약이 안 깨진다.
⚠ 조립 색인표를 찾으면 **그 자리에 한글 글리프를 넣는 쪽**이 깔끔하다(글꼴 경로와 별개다).

### 13.1 🔴 창을 옆으로 옮기면 커서가 안 따라온다 (유저 제보 2026-09-06)

「그외」의 시스템 창을 열고 커서를 움직이면 **커맨드 창의 오른쪽 틀이 한 칸씩 지워졌다.**

| 조사 | 결과 |
| --- | --- |
| 어느 칸인가 | 타일맵 (선택 항목의 아랫줄, **열 9**) 한 칸이 틀 타일 `$402A` → 글꼴 타일로 바뀐다 |
| 열 9 는 무엇인가 | **커서 열 = 창의 `col` + 1**. 원본은 A06 이 col 8 이라 커서가 열 9 = 창 안이다(원본 실기 확인) |
| 우리는 왜 깨지나 | A06 을 col 8→10 으로 밀었는데 **커서는 열 9 에 그대로 남았다** — 넓힌 커맨드 창(열 1~9)의 오른쪽 틀 자리다 |
| 폭 때문인가 | **아니다.** 옮기기만 하고 폭은 그대로 둔 진단 롬에서도 같은 자리가 깨졌다 |
| 커서 열은 어디서 오나 | 창 배치 기록이 아니다. 롬에서 창별 좌표표(col·col+1·타일맵 워드)를 전수 검색 — **없다**. 코드가 계산한다(미특정) |

⇒ **제자리 확장만 한다**(2026-09-06). 시스템 창은 오른쪽이 비어 있어(상태판은 열 19부터) col 8 그대로 7→9 로
넓혔고, 커맨드 창은 오른쪽이 시스템 창이라 못 넓힌다 — 3음절 라벨은 커서 코드를 찾은 뒤로 미루고 `버린다`
하나만 **`버림`** 으로 줄였다(나머지 여섯은 원래 2음절). 실기 확인: 시스템 창이 `로드·저장·시스템·설정` 로
뜨고 커서가 창 안에 있으며 커맨드 창 틀이 온전하다(`work/emu/fix_submenu.png`).

⚠ **덤으로 잡힌 결함** — `menu_poc` 의 라벨 칸 예산이 `menus.json` 의 `budget_tiles`(원본 폭에서 잰 값)를
쓰고 있었다. 창을 넓힌 동안엔 남는 칸에 떨어져 안 보였지만, 넓히기를 걷으니 **오른쪽 틀과 다음 줄 첫 칸까지
덮어써** 창이 통째로 사라졌다. 이제 **지금 기록에서 잰다**(라벨 시작부터 첫 틀 타일까지).

### 13.3 🔴 글꼴을 줄여도 대사가 더 들어가지 않는다 (2026-09-06, 유저 물음)

대사창 안쪽은 **17칸 = 136px** 이다(원문 줄 길이 전수: **99%가 17칸 이하**, 창 기록 A0E `(10,1,19,12)`
= 열 1~19 중 틀 둘을 뺀 17).

| 규격 | 한 줄 |
| --- | --- |
| 일본어 반각 1칸 | **17자** |
| 한글 **16px 셀**(D1=A, 현행) | **8자** — 128px 쓰고 8px 남는다 |

🔴 **글꼴 크기는 이 숫자를 안 바꾼다.** 타일맵은 8px 눈금이고 한글 한 자가 **두 칸**을 먹는다 —
11px 글리프를 넣어도 여전히 두 칸이다. 셀 안 여백만 늘어난다(11px → 세로 5px 놀고, 14px → 2px).

⇒ 더 넣으려면 **셀 모델을 바꿔야 한다.** 두 갈래뿐이다:

| 갈래 | 한 줄 | 값 |
| --- | --- | --- |
| D1=B, 한 자 = **한 칸(8px)** | **17자** | 🟢 **된다 — `Galmuri11-Condensed`**(아래 13.4) |
| **줄 단위 렌더링** — 글리프가 아니라 **줄을 통째로 타일에 굽는다** | 12px 면 **11자** · 11px 면 12자 | 동적 적재를 어차피 만들 거라 가능하다. 한 창 = 17칸 × 4줄 × 2행 = **136타일**(지금 추정 128과 비슷) |

⚠ 줄 단위 렌더링의 값은 **타자 연출**이다 — 글자를 하나씩 드러내므로 한 자 늘 때마다 그 자리 칸
(최대 2칸 = 4타일)을 다시 올려야 한다. DMA 는 감당되지만 조판이 **픽셀 좌표**를 내야 한다.

### 13.4 🟢 **D1 = B 확정** — 한 자 = 한 칸(8×16) (유저 2026-09-06)

D1 을 정할 때 「8px 폭 한글은 읽기 어렵고 Galmuri 에 그 비율이 없다」며 B 안을 접었는데,
**틀렸다.** 글꼴 폭을 전수로 재니:

| 글꼴 | 가로 | 세로 | 8px 셀 |
| --- | --- | --- | --- |
| Galmuri7 | 6~7 | 7 | ○ (너무 작다) |
| Galmuri9 | 8~9 | 9 | ✗ |
| Galmuri11 | 10~11 | 11 | ✗ |
| **Galmuri11-Condensed** | **7 (전부)** | 11 | 🟢 **○** |
| Galmuri14 | 12~14 | 14 | ✗ |

**`Galmuri11-Condensed` 는 완성형 11,172자가 전부 폭 7px 다**(빈 글리프 0 · 8px 초과 0 ·
숫자·영문·부호도 전부 있다). 8×16 반각 셀에 **그대로** 들어간다 — 우겨넣는 게 아니라 설계가 그렇다.

| | 한 자 | 한 줄 | 화면(4줄) | 글리프 타일/자 | 글리프 뱅크 |
| --- | --- | --- | --- | --- | --- |
| 현행 Galmuri14 | 2칸 | 8자 | 32자 | 4 | 27.5KB |
| **Condensed** | **1칸** | **17자** | **68자** | **2** | **13.75KB** |

⇒ **일본어와 같은 밀도**가 된다(원문도 반각 17자/줄). 실측 예: 한 문장이 Galmuri14 로 **9줄**
(= 3페이지)인데 Condensed 로는 **4줄**(= 1페이지)이다. 타일 예산·롬 용량도 절반이다.
⚠ 값은 **글자 크기** — 세로 11px 로 원본 가나(13px)보다 2px 작다. 가로도 7px 로 가나(5~8px)와 같다.

🟢 **적용 완료**(2026-09-06, 실기 확인). `hangul_font.CELL_W` 가 8이면 한 칸으로 굽는다:

| 딸려 온 것 | |
| --- | --- |
| **D2(창 넓히기) 철회** | `WIDEN = {}`. 커맨드 창 4칸에 `버린다`(PS1 정본)가 들고, 시스템 창 4칸에 `시스템` 이 든다 ⇒ **창을 하나도 안 건드린다.** 13.1 의 커서 결함도 우회가 아니라 **안 건드려서** 사라졌다 |
| **전투 격자** | 13칸에 `공격·주문·방어`(끝칸 12) — 칸 시작 0·5·10 그대로라 커서도 그대로다 |
| 편차 대장 | 셋 중 둘이 지워졌다(`버림`·전투 격자). 남은 하나는 제약이 아니라 **원문이 다른** 자리다 |
| 타일 예산 | 한 자 4타일 → **2타일**. 「메뉴 상주 220 + 대사 128 = 348 > 324」 벽이 사라졌다 |
| 글리프 뱅크 | 27.5KB → **13.75KB** |
| 대사 조판 | 한 줄 8자 → **17자** · 화면 32자 → **68자** |

### 12.2 챕터 제목에 한글을 얹으면 (실측 목업 2026-09-06)

자리는 128px. `제1장 왕자의 여행` 을 자간 1px 로 재면:

| 글꼴 | 폭 | |
| --- | --- | --- |
| (원본 일본어 12px 비례) | 101px | |
| **Galmuri11** | **103px** | 원본과 거의 같다 |
| **Galmuri14** | **127px** | 🔴 한계 128px 에 **1px** 남는다 — 제목이 길어지면 바로 넘친다 |

🔴 **제목은 글자만이 아니다 — 밑줄과 테두리가 같은 타일 안에 있다**(유저 지적 2026-09-06):

| 요소 | 어디에 |
| --- | --- |
| **밑줄 2px** — 화면 행 14(색 1 어두움) · 행 15(색 3 밝음), 폭 전체 | **아래 타일 16장 전부가 같은 꼬리를 갖는다**(실측). 우리 타일로 갈아치우면 **그 구간만 밑줄이 끊긴다** ⇒ 반드시 같이 그린다 |
| **1px 테두리** — 흰 획 둘레를 어두운 색(1)으로 두른다 | 어두운 점 500개가 **100% 흰 획의 8방향 이웃**이다(그림자가 아니라 외곽선). 한글도 같이 둘러야 원본과 같은 톤이 된다 |
| 색 | 2 = 바탕 · 3 = 흰 획 · 1 = 테두리·밑줄 (2bpp 4색) |

**세로 자리**(유저 요청 「위로 좀 올려서 글자가 온전히 나오게」):

| dy | 흰 획 | 테두리 |

### 13.5 🟢 렌더러 훅 설계 — 그리기 루프는 **안 고쳐도 된다** (2026-09-06 실기 특정)

읽기 브레이크포인트로 글자→타일 표(`$03:F3EC`)를 읽는 자리를 잡고 둘레를 뜯었다.

**칸 배열과 변환 루프** — `$02:B07E`:

```
B07E  LDX $1713            ; 칸 색인(0~$43 = 68칸 = 17칸 × 4줄)
B081  LDA $0305,X          ; ← 칸마다 **글자 코드 1바이트**
B08F  ASL/ROL              ; ×2
B099  ADC #$EC / #$F3      ; $06/$07/$08 = $03:F3EC + code*2
B0A6  LDA $0305,X / CMP #$10   ; 공백이면 위·아래 같은 타일
B0AF  LDA [$06],Y          ; 타일 번호 하위 → $1734
B0B5  ADC #$10             ; 🔴 **아래 타일 = 위 타일 + $10** (하드코딩)
B0C7  LDA [$06],Y / ORA $0349,X ; 속성|상위 → $1735/$1737
B0DA  STA $038D,X / $038E,X    ; 위 워드
B0E6  STA $0415,X / $0416,X    ; 아래 워드
B0EF  INC $1713 / CMP #$44     ; 68칸까지
```

**글자를 칸에 넣는 자리** — `$02:DE73`(메시지 엔진):

```
DE4C  LDA $173A / CMP #$CF   ; $173A = 방금 읽은 글자 코드 · $CF = 개행
DE73  INC $173B              ; 칸 커서
DE7D  JSR $DE23              ; 줄이 차면 스크롤(0305·0349 를 한 줄 당긴다)
DE80  LDX $173B / LDA $173A
      STA $0305,X            ; ← **여기가 훅 자리**
      LDA $176C / STA $0349,X ; 칸 속성
DE94  STA $1713 / JSL $02B07B ; 그 칸만 변환
```

🟢 **그래서 변환 루프를 안 고쳐도 된다.** 한글 한 자가 **한 칸**(D1=B)이고 아래 타일이
**위+$10** 인데 우리 글리프 규약이 정확히 그것이다 ⇒ **코드 하나가 타일 하나를 가리키게만
해 주면 기존 경로가 그대로 그린다.**

**동적 슬롯 방식**(코드를 빌린다):

| | |
| --- | --- |
| 슬롯 | 표에서 **타일이 유일하고 업로드 범위($000~$17F) 안**인 코드 = **177개**(실측) |
| 필요분 | 한 창 68칸이 전부 다른 글자여도 68 · 메뉴 상주 ~55 ⇒ **여유가 2배 넘는다** |
| 훅 | `$02:DE80` 앞에서 코드가 `$C5~$CE`(한글 선두)면 **다음 바이트까지 읽어** 글리프 색인을 만들고, 캐시에 없으면 슬롯 하나를 잡아 **글리프를 그 슬롯의 타일 자리에 DMA** 한 뒤 그 **슬롯 코드**를 `$173A` 에 넣는다 |
| 그 뒤 | 기존 코드가 `$0305,X` 에 넣고 `JSL $02B07B` 로 변환한다 — **손 안 댐** |

⇒ 고칠 곳은 **글자 소비 지점 하나**다. 건너뛰기 표(`$02:E4E0`)에 `$C5~$CE` = 2바이트를 더하고,
슬롯 캐시(칸 배열이 스크롤될 때 함께 늙는다)와 DMA 큐만 얹으면 된다.
⚠ 아직 안 본 것: 스크롤(`$DE23`)이 슬롯 참조를 옮길 때 캐시 수명 · NMI DMA 예산 · 오프닝 경로
(`$1E`)가 같은 루프를 쓰는지.

### 14. 결정 D4 「글꼴」 — 인게임 = Galmuri14 · 오프닝/엔딩 = Neo둥근모 (유저 확정 2026-09-05)

🔴 **dy 는 눈이 아니라 기준선으로 맞춘다**(2026-09-06 수정). 예전 값(Galmuri14 −3 · Galmuri11 −1)은 Neo둥근모의
겉모습에 맞춘 것이라 각각 **한 줄씩 어긋나** 있었다. 원본 기준선(행 13)에 맞추면 셋 다 같은 줄에 앉는다 —
전수 확인: 잘리는 글자 0(BDF 는 셀 밖 잉크를 조용히 자르므로 넉넉한 창에 따로 떠서 셌다).

⚠ **「16px 글꼴」은 칸 이름이지 글자 크기가 아니다** — Neo둥근모 한글의 세로 잉크는 완성형 11,172자 전수로
재도 **13px**(행 1~13, 11,115자)이다. 대신 **가로는 x0~15 로 칸을 꽉 채운다**(Galmuri14 는 x1~14). 세로가
원본과 같은데도 빽빽해 보이는 건 이 가로 때문이다. 영문·숫자는 Neo둥근모 y2~14 · Galmuri14 y1~15 로
Galmuri 쪽이 칸 아래끝까지 닿는다(넘치지는 않는다).

🔴 **「Galmuri14 가 커 보인다」는 착시가 아니다** — 완성형 11,172자 중 11,115자가 **행 14** 에서 끝나
