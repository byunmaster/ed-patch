- 【코드 읽기】블록 9 의 「デバッグテスト」(오프셋 0x62C)는 **어디서도 참조되지 않는다**(BE16 워드 · pc-상대 `lea` 모두 없음; 문구 둘은 0x63B·0x652 를 `lea`). 앞 문구의 이름 자리일 뿐인 죽은 문자열이다.
- 【코드 읽기】`$FF01B2`==0x62: `0x188A6` 은 **C 단독 + 방향키**(`$FF1854` & 0xFFF0 == 0x20)일 때 `$FF00E2`=1, `0x1B3C2`(0x61/0x62)는 C 가 눌렸을 때 일반 행동 대상 계산(`(a2)+2/+3`)을 건너뛴다. 필드에서 C+방향을 눌러 봤으나 기준선과 같이 아무 일도 없었다(조작이 겉으로 안 드러나는 보조로 보임). 값별 기능 전수는 **미완** — 0x61 · `$FF00E2` 의 용도 · `0x2D09E` 의 창이 열리는 화면이 남았다.
- 【실측】**0x61·0x62 = 「C 를 누른 채 걷기」가 달라진다**: 같은 입력(왼쪽 20f → 왼쪽+C 30f)에서 기준선은 벽 앞에서 멈추는데(`06`) 0x61·0x62 는 벽 쪽으로 한 칸 더 들어간다(`07`·`08`, 두 값의 화면 해시가 같다; 더 눌러도 그 칸에서 멈춤 `09`). 코드(`0x1B3C2`: 0x61/0x62 + C 면 일반 대상 타일 계산·`$FF1A66` bit4 설정을 건너뜀)와 맞아 **충돌 판정 생략(벽 통과) 추정** — 한 칸만 확인했고 맵 밖까지는 안 봤다. 0x61 과 0x62 의 차이는 `0x188A6`(0x62 만: C 단독+방향 → `$FF00E2`=1) 하나이고 그 효과는 화면으로 못 가렸다.
- 【코드 읽기】`$FF00E2` 는 **보행 지연 카운터**다 — VBlank 에서 `0xD774` 가 1씩 깎고(0 이면 다음 걸음), 걷기 설정 루틴 `0x1884A` 가 2(기본)·4(`$FF185D` bit2 · `$FF1B04`≠0)·8 로 넣는다. 디버그 0x62 는 1 로 넣어 **고속 이동**. (기준선 걷기에서 값 1 이 읽힌 건 카운터가 줄어드는 도중 값이다.)
- 【코드 읽기】패드 소비 지점 전수(`$FF1854`/`$FF1856` 읽기 38곳 + `$FF004C` 호출 35곳) — 숨은 조합은 부팅 A+B+C 하나뿐이다. 나머지는 일반 입력: X(0x100)·A+아래(0x42) = 메뉴 열기 대용(효과음 0x1B, `0x18718`), Y(0x200)·A+왼쪽(0x44) = 비트 지우기(`0x1879A`; 3버튼 패드 보정), B 단독(0x10) = 메뉴, C 단독+방향 = 위 디버그, `0x34952` = 엔딩 끝 START 대기 → 리부트. Z80(사운드 드라이버)은 디버그와 무관해 보여 **안 봤다(미확인)**.
- 【미확인】`0x2D09E` 의 5줄 창(구조 `0x2F33C`)이 열리는 화면 — 필드 메뉴·기타 메뉴·`버린다` 목록·전투 취소창에서는 BP 가 안 걸렸다. 상점·여관·장비 등은 안 열어 봤다.
- 【실측·세이브 안전】**엔딩 직행(0x63 + 부팅 콤보)은 SRAM 을 건드리지 않는다** — 직행 전(타이틀)과 스태프롤 끝 그림까지 돈 뒤의 SRAM 16KB(`cpu` 0x200000~)를 덤프해 비교하니 **바이트 0개 차이**(슬롯 1~3 모두 동일). 즉 우연히 켜져도 세이브는 안 상한다.
- **진입로 후보(구현은 마스터가 고른 뒤)**: ㉮ `0x127BA` 의 `cmpi.b #$63,$FF01B2` 한 곳 패치(조건을 항상 참으로) — 바이트 몇 개, 타이틀 뒤 A+B+C 유지→B 떼기가 곧 진입. 위험: 우연 입력으로 오프닝 건너뛰고 엔딩이 돈다(드묾) · 엔딩 직행이 SRAM 을 건드리는지 **아직 안 봤다** · 끝나면 리부트. ㉯ 설정(기타) 메뉴에 「엔딩 보기」줄 추가 — 가장 눈에 띄는 길이지만 창 구조·문안·분기 코드가 필요하고 롬 꼬리 빈 공간이 2,270B 뿐이라 빠듯하다. ㉰ 타이틀에서 전용 패드 조합(코드 새로 필요, 타이틀 루프 `0x133A8` 안). ㉱ 기존 「ED2-END」 챕터 버퍼 후크는 세이브를 고쳐야 해서 일반 유저용이 아니다.

**「없다」의 근거** — 사운드 테스트 전용 화면 · 오마케(おまけ 는 대사 속 「おまけに」뿐) · 디버그 메뉴(문자열·`디버그` 전용 화면 코드)는 위 스캔에서 안 나왔다. 단 **스캔이 못 보는 것**: (a) 패드 소비 35곳 중 15곳은 읽지 않았다(`0x6C0A`·`0x9A8A` 등은 일반 입력 대기로 보임), (b) 런타임에 만들어지는 문자열, (c) 사운드 드라이버(Z80) 안의 시험 모드 — Z80 RAM·코드는 아직 안 훑었다.
