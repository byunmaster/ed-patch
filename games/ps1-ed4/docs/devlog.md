## 2026-10-24 — 사전 분석: ED3 의 도구가 안 닿는 곳은 그림 압축이었다

마스터 「미리 분석시작해둬도 될듯」. 범위는 정적 조사(상태는 `status.md`).

- **어떻게 풀었나**: 헤더 뒤 128B 가 `상위4비트=길이 · 하위12비트=오프셋` u16 64개이고 오프셋이 `앞 항목 오프셋+앞 항목 길이`로 이어진다(사전 표). 스트림 앞부분 `80 10 02 00 80 09 02 00`이 TIM 매직 `10 00 00 00 09 00 00 00` 이 되도록 RLE 규칙을 맞추고, 사전은 `C0~FF`로 추정. 이어서 TIM 이미지 블록 헤더(`w=0x80 h=0x80`)를 만들려면 `41 80 00` 이 `80 00 80 00` 이어야 해서 **40~7F = 두 바이트 쌍 반복**을 얻었다(이게 지시서의 「쌍 반복 토큰」). 검증은 알려진 평문(TIM 매직·블록 크기 합 66,080)이다.
- **한계와 해결**: 처음엔 8,867개 중 16개가 틀렸고(`C_855`·`P_420.MPZ` 등) 「마지막 토큰 규칙이 빠졌나」를 의심했다. 틀린 16개를 잡아 보니 전부 **사전 표가 비어 있는 파일**이었다 — 스트림 시작을 「사전 항목의 최대 끝」으로 계산해 0 이 나온 것(실제는 표 끝 134). 규칙이 아니라 시작 위치였다. 고치자 **전량 통과**(푼 크기에서 정확히 멈추고 입력이 남지 않음). 검사를 「TIM 매직 + 입력 소진」 둘 다로 한 덕에 잡혔다. 압축기는 없다.
- **본 것**: `CDEND.DAT` 41MB 는 전부 0(패딩). XA 는 ADPCM 채널 0~7(BGM). 디스크에 M01/M02/MOV 가 없다. 디버그 키워드 스캔 0건 의미 있는 히트 없음(화면 메뉴 문구 없음).
- **교훈**: 「같은 엔진」 판단은 헤더 바이트까지 대조하고 나서 쓴다 — 도구가 `--disc ed4` 를 받는다고 그 안쪽 단계가 다 통하는 건 아니다(체크리스트 구조 계약).

## 2026-10-24 (밤) — 「쪽 3줄 한도」: 틀리게 적었다가 시험으로 바로잡고, VM 을 읽어 쪽 늘리기까지

- **틀린 서술을 시험이 잡았다**: wrap.md 에 「한 조각이 3줄(72칸)을 넘으면 다음 쪽으로 이어진다」고 적었는데, 96·120칸을 넣고 끝까지 눌러 보니 4줄째가 안 떴다(앞 시험에선 「다음 창」이 다른 메시지인 줄 모르고 본 것). 반대로 **`01` 로 이은 조각 줄은** 3줄이 차면 자동 쪽 넘김이 된다. 「한 조각 안 접힘」과 「조각 사이 줄바꿈」이 다른 경로다.
- **`01`/`02` 를 VM 연산으로 읽으면 안 된다**: 디스패치 표(`0x8008860C`)의 2번이 JMP 라서 「흐름 바이트 `02` = 점프」로 착각했고, 점프 트램펄린 첫 시험이 **빈 창**을 냈다. emucap 으로 핸들러(`0x80045be8`)에 걸어 RAM 을 덤프하고 unicorn 으로 돌려 보니
  `0F` 는 **메시지 블록 시작 연산**이고 그 뒤가 별개의 「메시지 언어」(해석기 `0x8003c98c`, 점프표 `0x800103d0`)였다. 「조용히 맞아 보이는 가설」을 화면(빈 창)이 깨 줬다.
- **그래서 쪽 늘리기는 블록째 옮긴다**: 점프는 VM 층에서만 되므로 `0F … 00` 블록 전체를 스크립트 꼬리로 옮기고 원래 자리를 JMP 로 잇는다 — 앞 오프셋이 안 밀린다(`scriptedit.rewrite_message`). 가짜 한글 4쪽 확인.
- **원본은 성기다**: 쪽 채움 평균 24%, 줄마다 20칸 이상인 3줄 쪽 3개 — ED3 실측 한글 비로 3줄을 넘길 쪽은 반각 없이도 11쪽(0.07%). 쪽 한도 걱정은 번역 전체를 막을 크기가 아니었다.
- **창 높이 상수 하나**(`0x80045cdc`): 행 4 → 5 로 바꾸면 한 쪽 4줄. 한 창만 확인.
- 도구 메모: emucap 은 시작·BIOS 구간에서 같은 주소에 걸려 **게임 코드가 아닌 곳에서 멈춘다**(BP 가 BIOS 코드에도 걸렸다) — 게임이 올라온 뒤 BP 를 건다. unicorn MIPS 는 KSEG0 를 물리 주소로 번역하므로 RAM 을 **0 번지에 매핑**하고, 8MB 미러 스택(`0x807FFFE8`)은 2MB 안으로 접어야 한다.

## 2026-10-24 (밤 늦게) — 번역 시작: 타이틀 메뉴 한 줄이 가르쳐 준 것

「번역부터 들어간다」. 첫 묶음으로 타이틀 메뉴(`最初から始める`·`続きから始める`)를 실제 번역 빌드에 올렸다.
- **참조를 못 찾았다**: 문자열을 가리키는 `lui+addiu` 도, `u32` 포인터도, 오프셋 표도 정적으로 0건이었다. emucap **읽기 BP**(타이틀 화면에서)로 읽는 자리를 잡으니 `0x800173A0` — **`0x80017334` 문자열 출력 함수**(창 구조체 `t2` · 문자열 포인터 `a1`)였고 호출자가 60곳이다. 즉 UI 문자열은 호출자가 **런타임에 포인터를 만들어 넘긴다.** 그래서 **길이 고정 제자리 교체**(코드 수 ≤ 원문)가 유일하게 안전한 길이고, 늘리거나 옮기는 건 호출자 60곳을 알기 전엔 못 한다. 문안은 짧게 쓴다.
- **글리프 자리가 바닥났다**: 대본·실행파일 문자열이 안 쓰는 자리는 처음 58+반각 26 으로 거의 다 썼다. 한글이 필요하면 **쓰이는 가나·한자 자리를 덮어쓴다.** 아직 일본어로 남은 글이 그 자리를 쓰면 번역 도중 시험 빌드에서 그 글자만 한글로 **오독**된다 — 그래서 원본 출현이 가장 적은 글자부터 채운다(`slots.py`가 몇 곳이 오독되는지 센다: 이번 5자는 각 1곳). 최종 빌드에선 전부 번역되므로 문제없다. 정본(`hangul_map.json`)은 추가만 한다.
- **함정으로 남긴 것**: `uitext.put` 이 한글을 코드로 바꾸는 검사를 자리 배정보다 먼저 하면 새 글자에서 `KeyError` — 길이 검사는 글자 수로, 정확한 검사는 배정 뒤 `check` 로 미뤘다.

## 2026-10-24 (밤 늦게) — 「호출자 60곳은 주소를 어떻게 만드나」: 표 + 오프셋이었다(관리자 지시 ①)

관리자 지적(규칙 3-6 — 줄인 꼴부터 쓰지 않는다): 제자리 고정 길이를 기본으로 두지 말고 호출자부터 전수.
- **전수 결과**(`0x80017334` 호출자 60곳, 직전 명령 순방향 상수 추적): 직접 상수 주소 0 · 인자로 받은 것 3(호출자의 호출자가 만든다) · **계산 57**(`addu` 50 = 기준 + 오프셋, `addiu` 10 = 기준 + 상수 오프셋). 정적 포인터 검색이 0건이었던 까닭이다 — 주소가 **표 기준 + u16 오프셋**으로 만들어진다.

## 11-07 — 옮긴 표의 옛 기준 상수가 코드에 남았다(PCE 부류 점검)

- 관리자 알림(PCE II: 원판 문자열 칸 안쪽을 코드가 읽는 표 바이트가 겹쳐 있었다)에 따라 **비우거나 다시 쓴 칸을 읽는 코드**를 정적으로 찾았다. 방법: 원판↔구운 EXE 바뀐 구간 280곳(62,709B)을 뽑아, 구운 EXE 의 `lui+addiu/ori` 상수와 데이터 워드가 그 구간을 가리키는지 훑었다.

## 11-18 — QA 디버그 메뉴(마스터 「내 qa 용으로, 원본 디버그 살리며 편의성」)
- 원판에 디버그 메뉴·숨은 조합은 없다(정적 조사) → 살릴 게 없고 새로 만든다. 제품 롬은 불변이어야 해서 **빌드 스위치 `ED_DEBUG_QA=1`**(꼬리표 `qa-debug`)로만 얹는다 — 스위치 꺼진 제품 빌드 sha1 이 그대로임을 매번 대조.
- **코드 자리 찾기**: 정적으로 「함수 시작이 안 불리는 블록」을 찾으면 **거짓 양성이 쏟아진다** — 함수 머리의 로드 한두 줄이 `addiu sp` 앞에 올라가(지연 슬롯 채움) jal 이 블록 **앞 8B** 를 가리키기 때문(`0x80041460` 이 살아 있는 함수였다, 앞서 `0x800274F4` 와 같은 함정). 대신 **도달성 분석**(진입점·데이터의 주소 워드·`lui`+`addiu` 주소 상수에서 j/jal/분기/순차를 따라 닿는 명령 표시 → 안 닿는 런)을 쓰니 알려진 반각 동굴 둘(`0x8001842C` 1420B · `0x80060308` 1088B)을 정확히 되찾았다 — 방법 자체가 검증된 셈. 0x8007xxxx 의 큰 런은 데이터라 제외.
- **패드**: 원판 코드에 디버그 입력은 없고 패드 갱신 함수 한 곳(`0x80057E50`)이 읽기 호출 결과를 `0x801F0250` 에 둔다 — 그 호출을 훅으로 돌리면 입력을 가로채고(열려 있는 동안 0 을 돌려준다) 필요하면 통과시킨다. RAM 차분(버튼마다 6프레임 누름)으로 비트를 알아냈다.
- **창 엔진 사용법**: `0x80015B20(x, y, 열, 줄)` → 창 번호, 창 구조체 = `0x801EF9C8 + 42×번호`. `0x80017334(창, 문자열, 0, 0)` 은 창 칸 커서(+0x26 열·+0x28 행)에서 그리며 **열 수에서 자동 줄바꿈**이라 줄을 열 수만큼 채워 쓰면 한 창에 여러 줄이 선다. 글은 한 번 그리면 남고(타일 캐시) 창은 첫 u16 을 0 으로 쓰면 닫힌다 → 커서 이동은 닫고 다시 열어 그린다.
- 🔴 함정: 내가 쓴 임시 스크립트 이름 `dis.py` 가 표준 모듈 `dis` 를 가려 capstone 임포트가 순환 오류로 죽었다(스크래치 폴더가 `sys.path[0]`). 이름을 `mdis.py` 로.
- 🔴 함정: commit-tree 정리 때 docs 커밋의 트리를 **옛 HEAD 에서 읽지 않고** 새 코드 커밋 트리에서 만들면 docs 파일이 통째로 사라진다 — 최종 트리 = 옛 최종 트리 + 새 파일들로 만들고 `git diff --stat 백업 HEAD` 가 새 파일 4개뿐인지 본다.
