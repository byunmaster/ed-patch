# ED4 대사창 자동 개행 — 해독 (10-24, 정적 + 시험 빌드 실측)

산출 근거: 시험 빌드(`ED_BUILD_TAG=test-wrap`, 글리프 자리 정본 글자로 지은 무의미한 열)를 코어로 부팅해 프롤로그 첫 대사창에서 줄 길이·부호·공백을 바꿔 가며 캡처했다
(`.local/work/inbox/ps1-ed4/wrapA_sheet.png` · `wrapB_sheet.png`). 스크립트 통계는 `dump.py` 덤프(표 규격 356멤버)에서 냈다. 🔴 측정한 창은 **프롤로그의 화자 있는 대사창 하나**다.

## 규칙 (실측)

| 항목 | 값 |
| --- | --- |
| 칸(셀) | 코드 하나 = **12px 한 칸** — 공백 코드도 12px, 반각 코드는 **없다**(ED3 는 10-07 에 엔진 패치로 부호를 반 칸으로 만들었다 — ED4 엔진은 원판 그대로) |
| 한 줄 폭 | **24칸 = 288px**, 글자는 x=16~304 에 앉는다(창 틀 8~312) |
| 줄 간격 | **13px** (줄 머리 y=185 · 198 · 211) |
| 한 쪽 줄 수 | **3줄**(72칸) — 3줄이 차면 `▼` 가 뜨고 키를 기다린다. 🔴 **그보다 긴 글(4줄째부터)은 화면에 안 나온다** — 다음 쪽으로 이어지지 않는다(96·120칸·5줄 시험에서 4·5줄째가 끝내 안 떴다). 처음엔 「이어진다」고 적었다가 시험 빌드로 바로잡았다 |
| 쪽 수 | 스크립트가 정한다(`02`) — **조각 안 글자로 쪽을 늘릴 수 없다**. 빈 조각이 한 쪽을 차지하면 **빈 창이 한 번 뜬다**(빈 쪽도 ▼ 를 기다린다). 같은 쪽 안(`01` 로 이어진) 빈 꼬리 조각은 아무것도 안 그린다 |
| 접는 곳 | **정확히 24칸째** — 어절·낱말을 안 본다(`시`×14+공백+`스`×14 가 낱말 한복판에서 접힘) |
| 금칙 | **없다** — `。`·`、` 가 줄 머리에 온다(24칸째 뒤에 `。` 를 두니 둘째 줄 머리로 갔다) · 줄 끝 공백은 한 칸으로 센다 |
| 조각 안 `0x01`~`0x03` | 줄바꿈이 아니라 `、` `。` `・` 글자다(ED3 와 같음) — 줄바꿈은 **스크립트 쪽**에 있다(아래) |

## 스크립트 쪽 줄·쪽 제어 (표 규격 356멤버 통계)

대사는 `12 xx 0F <색인 u16>`·`13 xx 0F <색인 u16>`(화자 선택 + 문자열 출력) 뒤의 **한 바이트**가 흐름을 정한다:

| `0F` 색인 뒤 바이트 | 횟수 | 뜻(추정) |
| --- | --- | --- |
| `01` | 8,356 | **같은 쪽의 다음 줄** — 다음 `0F 색인` 이 이어서 붙는다 |
| `02` | 4,268 | **쪽 넘김**(키 대기 뒤 다음 쪽) |
| `00` | — | 메시지 끝 |

- 원본의 대사는 **쪽당 1~3줄**이다(`01` 로 이어진 묶음: 1줄 3,582 · 2줄 1,611 · 3줄 479 · 4줄 15 — 4줄은 오검출 의심).
- **원본 대사 줄은 24코드 이하**다(`12/13 xx 0F` 자리 전수 최대 24). 25~28코드 조각이 287개 있으나 대사 자리가 아니라 다른 연산·표 자리다 — 그러니 24칸은 우연이 아니라 **원작자가 맞춘 폭**이다.
- ⚠ 미측정: 상점·나레이션·전투 메시지 등 **다른 창 종류의 폭**. 통계상 같은 자리(`12/13`)는 전부 24 이하라 같은 폭일 공산이 크나 실측은 아니다.

## 조판(krwrap)을 어떻게 물리나 — 제안(결정 아님)

`krwrap.wrap`/`wrap_pages` 에 줄 폭 24 · `cell_width = 1`(전부 12px — 반각 없음) · 쪽당 3줄을 준다. 공백 정책: 엔진이 공백도 한 칸으로 세므로 「부호 뒤 공백 제거」(`strip_after`)는
줄이 24칸 안에서 짧아지는 쪽(안전)이다. ⚠ 이 절은 **반각 훅 이전**(10-24 오전) 기록이다 — 훅이 선 뒤의 규약은 아래 「반각 합성 훅」.

| | A. 엔진에 맡긴다 | B. 우리가 접고 엔진 접힘을 행 경계에 맞춘다(`pad_rows` 꼴) | C. 스크립트(`01`/`02` 바이트)를 다시 쓴다 |
| --- | --- | --- | --- |
| 방법 | 번역 조각을 길이 제한 없이 넣는다. 엔진이 24칸에서 자른다 | 행을 krwrap 으로 어절 단위로 나누고, **각 행을 공백 코드로 24칸까지 채워** 한 조각에 잇는다 — 엔진의 24칸 접힘이 우리 행 경계와 일치 | 조각을 줄 단위로 쪼개고 `0F 색인 01` 을 스크립트에 끼운다 |
| 장점 | 구현 0 · 멤버 크기 변화 최소 | 어절이 안 끊긴다 · **스크립트 불변**(표만 다시 계산 — 이미 검증된 길) · 쪽 경계(3줄)도 우리가 고른다 | 줄·쪽을 완전히 제어 |
| 단점 | **낱말 한복판에서 접힌다**(금칙 없음 — 한국어 가독성 나쁨) · `。` 가 줄 머리에 온다 · 쪽 경계를 우리가 못 고른다 | 패딩 공백이 멤버 크기를 늘린다(한 쪽 최대 72칸 = 144B/조각 — 아카이브 여유 안에서 재배치 가능한지는 전수 예산 계산 필요) · 행이 24칸을 **넘으면 어절 한복판에서 접힘**(krwrap 이 24 이하를 보장해야) | 스크립트 바이트 삽입 = 뒤의 **VM 절대 오프셋(점프·라벨)이 밀린다** — 이벤트 VM 해독 전엔 위험(ED3 도 같은 이유로 못 했다) |
| 비고 | 대사 한 줄이 원문 줄 수와 달라져도 쪽이 자동으로 나뉘나 쪽 경계에서 문장이 반반 걸린다 | ED3 `typeset.pad_rows` 와 같은 발상 — ED3 에서 이미 쓰는 길 | 지금은 닫아 둔다 |

⚠ 「엔진 자동 개행을 끄는」 안은 **끄는 스위치를 못 찾았다** — 24칸이 코드 상수인지 창 구조체 필드인지 아직 모른다(창 폭 필드가 있으면 키우는 엔진 패치가 B 의 패딩을 없앨 수 있다 — 정적 조사 과제).


## 조판 도입 (10-24) — `tools/typeset.py`

ED3 의 조판 규칙을 ED4 격자(24칸 · 쪽 3줄)로 옮겼다. 시험 빌드(가짜 한글)로 **우리 줄 경계와 엔진 접힘이 일치함**을 캡처로 확인했다(`wrapD_sheet.png`).

- `rows(text)` — krwrap(어절 단위·금칙·고아) 로 줄 폭 ≤ 24칸. 넘는 낱말은 운다.
- `pad_rows(rows)` — 줄마다 공백으로 24칸까지 채워 한 조각에 잇는다(마지막 줄 제외). 엔진이 24글자째에서 접으므로 우리 줄과 일치한다(ED3 `pad_rows` 와 같은 발상). 조각 안 `0x01` 은 줄바꿈이 아니라 `、` 다.
- `page_segments(texts, nseg)` — 스크립트의 한 쪽(`01` 로 이어진 조각 `nseg` 개)에 맞춘 조각 문자열들 — 문장을 이어 다시 나눠 **첫 조각에 몰고 나머지는 빈 조각**. 쪽 한도(3줄) 초과는 운다(넘치면 화면에서 사라지므로).
- `windows(mem)` — 표 규격 멤버의 메시지 → 쪽 → 조각 색인(`0F 색인` 뒤 바이트 `01`/`02`/그 밖).
- ED3 와 다른 점: ① 한 쪽 3줄(ED3 대사창은 4행) ② 조각이 **한 줄이 아니라 쪽 전체**를 담을 수 있다(패딩으로) ③ 쪽 수는 못 늘린다 ④ 반각은 훅이 선 뒤 `WIDTHS` 로 반영했다(아래).


## 반각 합성 훅 (10-24 밤) — `tools/halfwidth.py` · 시험 단계

엔진에 반각이 없어 공백·숫자·부호가 12px 한 칸을 먹었다. 업로더(`0x80016320`)의 두 곳에 훅을 걸어 **글자를 픽셀 위치에 합성**한다(모델 = `tools/tilecomp.py`):
- **H1** `0x80016528`(`sll v1,v1,1`) → `jal H1`. 글리프 18B 를 줄 위치(6px 단위)에 맞춰 이웃 타일과 합쳐 `s0` 로 돌려주고, VRAM 사각형을 **타일 칸**(글리프 칸이 아니라) 것으로 바꾼다.
- **H2** `0x800165d0`(`jal LoadImage`) → `jal H2`. 12px 글자가 칸 경계를 걸치면 오른쪽 조각을 한 번 더 올린다(링 버퍼 칸 하나 더 쓴다).
- 반각 글리프는 잉크가 왼쪽 6px 안에 들어야 한다 — `font.half_glyph` 가 **Galmuri11 Condensed**(잉크 ≤5px)로 굽는다(보통 Galmuri11 의 숫자는 7px 라 안 든다). 반각 목록은 `halfwidth_map.json`(자리) + 공백 610.
- 🔴 **칸 기점은 창 구조체 `+0x22`** 다(`+0x1e` 가 아니다 — `+0x1e` 는 틀·채움 명령이 쓴다). 처음 `+0x1e` 로 짜서 실게임에서 줄 중간부터 원래 칸으로 돌아갔다(시뮬레이터는 합성 창이라 둘 다 0 이라 못 잡았다). 실게임 대사창 실측: 열 24 · 행 4 · `+0x22`=63.
- 대사창(열 24)이 아니거나 칸이 범위 밖이면 원판 그대로다.

🔴 **줄 한도는 둘이고 둘 다 건다**(관리자 10-24): ① 글리프 24개 이하(엔진이 칸 수로 센다 — 훅도 못 바꾼다) ② 픽셀 폭 288 이하. 글리프가 12px 이하라 ①을 지키면 ②는 따라온다(`typeset.rows` 가 둘 다 단언). 훅은 **모양**만 준다 — 반각 때문에 생기는 줄 끝 여백은 그대로 두고 용량은 쪽 늘리기가 받는다. 줄바꿈 연산(`01`)까지 건드리는 용량 패치는 하지 않는다. `STRIP_AFTER` 는 비웠다(부호 뒤 공백 유지).

검증: ① `tests/test_halfwidth.py` — 업로더를 unicorn 으로 돌려 **모델과 같은 타일**이 올라가는지(반각 섞임·줄 둘·줄 중간 시작·반각 없음=원판) ② 시험 빌드(`probe.py --mode half`) 실게임 캡처 — 한 줄 `12.5`·`(45)`·`:`·`?` 와 두 줄(24글리프 접힘 뒤 둘째 줄) 정상.

### 동굴(훅 코드·데이터를 얹은 자리)
`0x8001842C~0x80018A5F`(1,588B) — **호출자 없는 죽은 함수**(정적: `jal`/`j`/데이터 포인터/`lui+addiu` 참조 0). 원판 sha1 `285a3e78…` 을 `patch_exe` 가 확인하고 덮는다. 코드 1,028B + 데이터 224B.
동적 확인(emucap — 원판 JP 이미지에 **실행·읽기·쓰기 BP** 를 구간 전체에 걸었다. 읽기·쓰기는 PC 0x80010000~0x801FFFFF 만 — BIOS 가 부팅 때 RAM 을 지우는 것은 제외): 타이틀 로고 → 오프닝(가사 화면 포함) → 타이틀 메뉴 → 새 게임 → 프롤로그 컷신(대사창 수십 개·맵 전환·연출 화면) 구간에서 **적중 0**.
⚠ **못 간 곳**: 필드 조작·전투·메뉴·상점·세이브/로드는 프롤로그 컷신이 길어(수백 프레임 단위 연타) 세이브 없이는 못 갔다. 그 구간은 정적 근거(호출자 없음)뿐이다 — 마스터 확인 때 같이 보거나 세이브가 생기면 같은 BP 로 다시 건다.

## 메시지 언어와 쪽 늘리기 (10-24 후반) — 정정과 새로 알아낸 것

**대사는 VM 연산 `0F` 가 시작하고, 그 뒤 바이트는 「메시지 언어」다**(unicorn 으로 `0x80045be8` 핸들러를 RAM 덤프 위에서 돌려 확인 — `0x8003c98c` 가 메시지 해석기, 점프표 `0x800103d0` 16개):

| 메시지 언어 | 뜻 |
| --- | --- |
| `0F [패딩] <u16 색인>` | 문자열 출력(색인 = 표 번호, u16 은 짝수 주소 — 앞 `0F` 뒤 커서가 홀수면 패딩 1바이트) |
| `01` | 줄바꿈 — 같은 쪽 다음 줄. **줄이 3줄 차면 `▼` 와 함께 자동으로 쪽을 넘긴다**(조각마다 1줄인 4줄 시험: 4줄째가 다음 쪽에 나왔다) |
| `02` | 키 대기 후 쪽 넘김 — **VM 점프가 아니다**(메시지 언어 안의 `02`) |
| `00` | 메시지 끝 — 다음 바이트부터 다시 VM 연산 |

⚠ 앞 절의 「`01`/`02`/그 밖」이 바로 이 메시지 언어 연산이다. VM 연산 층에는 **`02` = 무조건 점프**(`0x800431b0`: 커서를 짝수로 올리고 s16 을 읽어 **멤버 시작 + s16** 으로 점프 — 멤버 RAM 시작 `0x800C6E14` 확인)·`00` = 복귀·`0F` = 메시지 블록 시작·`12`/`13` = 화자 이름 문자열 선택 등이 있다(디스패치 `0x8008860C`, 160개).
정정 둘: ① **풀 규격 125멤버는 대본이 아니다** — 문자열 풀 조각이 0개(포인터 272개는 이벤트 자료)다. ED4 의 대사는 전부 표 규격 356멤버에 있다. ② **줄 한도**: 한 조각 안에서 24칸마다 접힌 줄이 3줄을 넘으면 그 줄은 사라지지만(시험: 4·5줄째가 안 떴다), `01` 로 이어진 조각 줄은 자동으로 쪽이 넘어간다 — `typeset.over_limit_pages` 가 이 규칙으로 판정한다.

### 쪽(줄)을 늘리는 길 — 서는 것을 확인했다

스크립트 한복판에 바이트를 끼우면 뒤 오프셋이 다 밀린다(VM 점프가 `멤버 시작 + s16` 절대 오프셋이라). 그래서 **끼우지 않고 블록째 옮긴다**(`tools/scriptedit.py`):
1. 새 문자열을 표 끝에 더한다(색인 N… — 스크립트는 색인으로 가리켜 안 건드린다).
2. 새 메시지 블록(원래 줄들 + 새 줄들, 흐름 `01`/`02`/끝 `00`)을 **스크립트 구간 꼬리**(`TEXT_BASE` 앞)에 덧붙이고 끝에 **원래 블록 다음으로 돌아가는 JMP** 를 둔다.
3. 원래 블록 자리 첫 바이트들을 `02 <s16>` JMP 로 바꾼다. 앞 스크립트의 오프셋은 하나도 안 변한다.
시험(`OP00000` 프롤로그 둘째 메시지에 쪽 둘 추가) — 가짜 한글이 **4쪽**(원래 2쪽 + 새 2쪽)으로 나오고 다음 메시지가 정상으로 이어졌다. 회귀(`tests/test_scriptedit.py`)는 작은 VM 해석기로 「점프를 따라가면 같은 메시지 + 새 쪽이 나오고 원래 다음 연산에 닿는다」를 본다.
⚠ 아직 **빌드(`edits["members"]`)로만 쓸 수 있고 번역 로더와는 안 이었다** — 쪽 수가 모자란 번역을 만났을 때 쓸 도구다. `rewrite_message(mem, seg, extra, flows)`.

### 창을 한 줄 키우는 엔진 패치 — 상수 하나 (시험으로 확인)

메시지 창은 VM 연산 `0F` 핸들러가 연다: `0x80045cd8 jal 0x80015b20(a0=4, a1=y, a2=0x18(24칸), a3=4(행))` — `a3` 는 지연 슬롯의 `move a3,a0`(`0x80045cdc`, 워드 `0x00803821`).
이 워드를 `addiu a3,zero,5`(`0x24070005`)로 바꾸니 **창이 5행(이름 1 + 글 4줄)** 이 되어 4줄짜리 한 쪽이 통째로 나온다(`rows5_sheet.png`, `▼` 정상). 쪽 한도가 3 → 4줄이 된다.
⚠ 한 창만 확인했다(프롤로그, 아래쪽 배치) — 위쪽 배치(`y=4`)·VRAM 글자 캐시 칸 수(24×5)·다른 창 종류는 미확인. ED3 가 열을 32 로 키웠다가 `▼` 가 사라진 전례(`policy.md`)가 있으니 열은 건드리지 말고 행만 시험했다.
