## 확정된 것

- **대사 「」『』 반각**(마스터 10-27, 롬 `4c7707a1`): 「」 = B판(닫는 쪽 이동 없음 — 1px 이동안은 기각) · 『』 = v2(가로 5칸). 반각 훅 새 글리프 4(코드 806·947·883·953, U+E020~E023), 대사 인코딩 때만 바꾼다(`reinsert.KAGI`) · 줄 폭 6px(`typeset.WIDTHS`) · UI 전각 부호는 원본 그대로. 도안 교체는 `font.KAGI_ROWS` 만.
- 「ＨＦ」 전각(규칙 1-4과 같은 꼴, 마스터 10-26). 반각 부호 모양은 11-13·14 판정으로 굽는다(「&」「%」는 전각 유지).
- **대사 숫자는 자리마다 원판 꼴**(마스터 11-16 「원판이 반각쓴곳은 반각, 전각쓴곳은 전각」 — 10-27 「전부 전각」 대체): 원판이 수 그리기(`0xEEEE`, HUD 와 같은 반각 꼴)로 낸 자리 293곳(양·값: 로제·나이·연수·횟수 등)은 ASCII 반각, 글자 코드로 박은 전각 212곳(제５용광로 등 이름·번호)은 전각. 원판에 숫자가 없는 3곳(한자 수사 一割·七不思議)은 전각 유지(관리자 목록). 라틴은 원판 대사에 반각이 없어 전부 전각(ＨＦ·ＯＫ·Ａ급). 판정은 `tools/check_digit_form.py`(게이트).
- **원판 사본 잔존 게이트**(전 게임 점검 11-17): `tools/check_stray_copies.py` — 제품 이미지 전체(섹터 전량)에서 번역한 원판 대본 조각(코드 5↑)·UI 문자열의 원판 바이트를 찾는다. 결과 **사본 0**(재배치로 비워진 옛 자리 출현은 디렉터리가 안 가리켜 제외). 예외: 아이템 구조체 옛 자리(실행파일 0xA38~, 사용처 패치로 안 읽힘 — 옛 주소를 가리키는 명령 0 을 같이 검산)·번역이 원판과 같은 조각·가나/한자 없는 숫자 조각(퍼즐 쪽지 표). `check.sh` 에 물림(약 5분).

### 그림 압축(.TIZ/.MAZ/.MPZ) — 해독 초안 (10-24)

`kind(1B: 1|2) 03 size(u32=푼 크기) | 사전 64×u16 | 스트림`
- 사전 항목 u16: 상위 4비트 = 길이 n, 하위 12비트 = 블록 안 시작 오프셋. 사전 바이트열은 표 바로 뒤(0x86~)에 있고 끝 = max(오프셋+길이).
- 스트림 op: `00~3F` 한 바이트 (op+1)번 반복 · `40~7F` **두 바이트 쌍**을 (op&3F)+1번 반복 · `80~BF` 리터럴 (op&3F)+1바이트 · `C0~FF` 사전 항목 (op&3F).
- 푼 크기에서 멈춘다. 결과가 TIM 매직(`10 00 00 00`)·블록 크기와 맞는다(B_010 = 8+524+65,548 = 66,080).
- 사전 표가 **비어 있으면(전부 0)** 스트림 시작은 표 끝(6+128=134)이다 — 처음엔 「사전 항목의 최대 끝」으로 잡아 16개가 틀렸다(10-24 정정).
- 전수 확인: TIZ 8,319 · MAZ 250 · MPZ 298 = **8,867개 전부** 풀린다(푼 크기에서 정확히 멈추고 입력이 남지 않음, TIZ 는 TIM 매직 일치). kind 1·2 는 같은 해독기다(차이는 미확인).
- 남은 것: `C_765.TIZ` 는 풀린 TIM 의 픽셀 블록이 `tim.parse` 에서 「잘렸다」로 나온다(해독 문제가 아니라 TIM 이 짧은 것으로 보임 — 미확인).
- 초안 코드: `.local/work/inbox/ps1-ed4/tiz_decode_draft.py`(커밋 안 함). 재삽입은 압축기가 필요 — **리터럴만으로 압축 없이 담아도 크기 맞추기 쉬운지**는 미조사(ED3 는 같은 크기 gmfz 로 맞췄다).

## 맵 이름 표 · 로더 (정적, 10-24 이어서)

- 실행파일 RAM `0x80087808`~(파일 0x78008): **8바이트 항목 372개** = 이름 7자(ASCII) + 1바이트(하위 7비트 = 영역 번호 0~16, 상위 비트 = 플래그 — 114개). 끝은 `Z`. 조회 함수 `0x80012068`·`0x800132a0`(이름 7자 비교 → 영역 번호 반환). ED3 의 10B 항목(이름6·팩번호·영역·값)과 다르다.
- 표 이름 372 중 디스크 `..\BIN\<이름>.BIN` 이 없는 것은 `DR08000` 하나. 반대로 디스크 멤버 중 표에 없는 것 109(`AT02000A~E` 같은 변형 접미)는 장면 변형 멤버다.
- 표 밖에 하드코딩된 맵 이름 리터럴: `GT07000`(코드 0x80046fa0·0x80048bc4) · `GT40000`(0x80056ce0·cf4) · `OP00000`(0x8005a338, 부팅 시퀀스 `0x8001252c(0,0,"OP00000")`).
- `0x8001252c(종류, 번호, 이름)` 이 **자원 로더**로 보인다: 종류 1 이면 번호가 그림 `C_<번호>.TIZ`(예 0x358=C_856 GMF 로고 · 0x35a=C_858 · 0x34d/0x34e/0x34f = C_845/846/847 → 오프닝·타이틀 그림이 번호로 로드됨). 종류 0 + 이름이면 맵. 호출처 32곳. → 그림 글자를 한글로 바꾸는 길은 ED3 처럼 같은 번호의 TIZ 를 교체하면 된다(압축기가 있으면).
- **새 게임 시작 맵 스위치**(ED3 `debugpatch` 식)는 아직 못 정했다: 새 게임 흐름이 `TITLE`(0x8005889c) 다음 어디서 맵을 정하는지 안 따라갔다. 가능성은 높다(맵 로더가 이름 문자열을 받는다). 이벤트 VM 은 안 읽었다.
