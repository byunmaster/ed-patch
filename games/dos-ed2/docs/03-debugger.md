# DOSBox-X 디버거로 크래시 순간 들여다보기

이슈 #1의 남은 질문은 하나다 — **모듈 해제 헬퍼(`seg4:0x0c64`)의 복귀 주소가
언제 깨지는가.** 정적 분석으로는 더 못 좁힌다. 메모리를 직접 봐야 한다.

## 준비

디버거 UI는 **실행한 터미널 창**에 뜬다. 그래서 `--app`(앱 번들)로는 못 쓰고
터미널에서 직접 띄워야 한다.

```bash
scripts/emu/dosbox.sh --debug      # -break-start 로 부팅 직후 디버거 진입
```

키보드가 불안정하면 `ed2.conf`의 `usescancodes=false` / `autolock=false`가
살아 있는지 확인한다(이미 들어가 있다).

**기동 시 간헐적 세그폴트가 있다.** 커서스 디버거 UI 초기화 단계에서 가끔 죽는데
재현성이 없다(가상 터미널 24x80 / 40x100 / 60x120으로 반복 시험 — 크기와 무관하게
대부분 정상, 드물게 죽음). 죽으면 **그냥 다시 실행하면 된다.** macOS 크래시 리포터
다이얼로그가 뜨면 닫아도 무방하다.

`--debug` 모드는 `-log-con`을 뺀다 — 커서스 UI와 같은 터미널을 두고 부딪힐 수 있다.
로그는 `ed2.conf`의 `logfile`로 계속 남는다.

터미널 창은 넉넉히 키워두는 게 좋다(레지스터·코드·데이터·출력 창이 세로로 쌓인다).

## 런타임 주소 (ED2MAIN entry table에서 산출)

데이터 심볼은 **DS 기준 오프셋**으로 export된다. 크래시 덤프 기준 `DS = 0277`,
`CS(seg4) = 0217`. `tools/ne_entries.py`로 뽑은 값:

| 심볼         | DS 오프셋 | 런타임                                       |
| ------------ | --------- | -------------------------------------------- |
| `SAVE_FLAG`  | 0x201F    | `0277:201F`                                  |
| `ROUTE_NO`   | 0x203F    | `0277:203F`                                  |
| `LOCAL_WORK` | 0x2074    | `0277:2074` (유람선 커서 = +2 → `0277:2076`) |
| `SIN_FLAG`   | 0x20A0    | `0277:20A0`                                  |
| `KEYBUF`     | 0x40A7    | `0277:40A7`                                  |

엔진이 SS:SP를 저장하는 슬롯: `0277:2F7C`(SP) / `0277:2F7E`(SS).
해제할 모듈 핸들: `0277:0BFA`.

## 절차

### 1. 승선 순간까지 건너뛰기

`ROUTE_NO`는 배를 탈 때만 쓰인다. 여기에 걸면 정확히 그 순간에만 멈춘다.
보호모드이므로 **`BPPM`**(pmode memory breakpoint)을 쓴다.

부팅 직후 디버거 프롬프트에서:

```
BP 0217:0C64          ← 셀렉터가 살아날 때까지 한 번 잡아두기 위한 임시 BP
F5                    ← 실행. 첫 시나리오 로드에서 걸린다
BPDEL *               ← 임시 BP 제거
BPPM 0277:203F        ← ROUTE_NO 변경 시 정지
F5
```

이제 게임 창에서 세이브 로드 → 스엘 → 유람선 NPC → 10000G 지불.
승선하며 `ROUTE_NO = 8`이 써지는 순간 디버거가 멈춘다.

### 2. 해제 헬퍼 진입/복귀 비교 (핵심)

```
BPDEL *
BP 0217:0C64          ← 해제 헬퍼 진입
BP 0217:0C9C          ← 폴트가 나는 retf
F5
```

**0x0C64에서 멈추면** (프롤로그 실행 전이라 SS:SP가 복귀주소를 가리킨다):

```
D 0277:2076           ← 유람선 커서 값 확인 (0x1a6 이어야 정상)
D 0277:0BFA           ← 해제할 모듈 핸들
```

그리고 데이터 뷰를 `SS:SP`로 옮겨 **복귀 CS:IP 4바이트**를 적어둔다.

**F5 → 0x0C9C에서 멈추면** 같은 자리를 다시 본다.

- 진입 시 복귀주소가 **이미** 쓰레기(`xxxx:501C`) → 손상은 이 함수 밖, 호출 이전
- 진입 시 정상 → 복귀 시 쓰레기 → **`FreeLibrary`(KERNEL.#96) 안에서 손상**
  (해제되는 DLL의 `WEP` 실행 경로 포함)

이 한 번의 비교로 범위가 절반으로 갈린다.

### 3. 손상 시점 특정

2번에서 "함수 안에서 손상"으로 갈리면, 진입 시 기록해둔 복귀주소 위치에
쓰기 감시를 건다:

```
BPPM 0277:<복귀주소 오프셋>
F5
```

멈춘 지점의 `CS:IP`가 범인이다.

## 자주 쓰는 명령

| 명령                      | 뜻                                         |
| ------------------------- | ------------------------------------------ |
| `BP seg:off`              | 코드 브레이크포인트                        |
| `BPPM sel:off`            | 보호모드 메모리 브레이크포인트(값 변경 시) |
| `BPLIST` / `BPDEL *`      | 목록 / 전체 삭제                           |
| `C seg:off` / `D seg:off` | 코드뷰 / 데이터뷰 위치 이동                |
| `SR reg value`            | 레지스터 값 설정                           |
| `MEMDUMP seg:off len`     | 메모리를 파일로 덤프                       |
| `HELP`                    | 명령 목록                                  |

키: **F5** 실행, **F10** step over, **F11** step into.

## 주의

- 게임은 그래픽 모드라 엔진의 `Where`/`What` 진단 메시지가 화면에 안 보인다.
  `scripts/emu/dosbox.sh`가 `-log-con`을 켜두므로 `work/dosbox/ed2.log`에서 확인한다.
- `MEMDUMP`으로 스택 주변을 떠두면 나중에 정적으로 대조하기 좋다.
