# sfc-ed2 devlog

## 2026-10-12 — 첫 조사: 엔진이 ED1 과 전혀 다르다

- 출발 가정(ED1 과 같은 가나 1바이트 엔진)은 **틀렸다**. 에뮬 첫 화면에서 한자 12px 글자가 떴고, 코드는 2바이트다.
- 글꼴을 롬에서 찾으려고 에뮬 VRAM 캔버스의 글리프를 그대로 검색했지만 **실패**했다 — 화면 글리프는 롬 원본에
  그림자(2번 색)를 합성한 것이라 비트가 다르다. 속은 점: 「안 나온다 = 압축됐다」로 읽을 뻔했다. 해법은 **그리는 코드를
  따라가는 것**(`$C0:9F56` 의 `mvn` 원본 주소) — 글꼴은 비압축이었다.
- 에뮬 중단점 함정 둘: ① `exec`·NMI 쓰기 중단점은 매 프레임 맞아 `poll_events` 한 번에 수만 자가 쏟아진다(`pause_on_hit` 없이
  큐에 쌓인 채 다음 호출에 터진다). ② `snesVideoRam` 이라고 준 write 중단점이 실제로는 CPU 주소 범위로 읽혀 스택 쓰기가 맞았다 —
  VRAM 쓰기는 `$2118` 의 `snesMemory` 중단점(이벤트에 `vram_addr` 가 붙는다)으로 본다.
- `read_memory` 는 인라인 hex 만 준다. 큰 덤프는 `debug dump_memory`(vram/wram/cgram/oam 파일) 로 뽑는다.

## 2026-10-12 (뒤) — 대사는 표가 아니라 스트림이었다

- 「포인터 표를 전수 해독」이라는 틀 자체가 어긋났다. 대사 출력기(`$C0:A691`)는 `[$A6]` 24비트 포인터를 따라 토큰을 읽는 **스크립트
  인터프리터**고, 메시지 시작은 네이티브 이벤트 코드의 즉치(`lda #lo / sta $A6`)로 들어간다. 정적으로 즉치를 긁어도 396곳(글자 9%)뿐이었다
  — 나머지는 트리거 표(`$C1:A2D1`, 6·8바이트 항목, `jml [$54]`)로 네이티브 코드를 거쳐 닿는다. 해법은 **시작 주소를 찾지 않고** 문법으로
  글자 덩이 앞뒤를 읽는 것(`script.py`) — 덤프에는 충분했고, 재삽입은 트램펄린 안이면 시작 주소가 필요 없다.
- 두 가지 출력기가 있다: `$C0:9395`(좌표 지정 UI 문자열 — `$C0`·`$C1` 의 글자 덩이)와 `$C0:A691`(대사). 문법이 달라서 `$C0`·`$C1` 덩이를
  대사 문법으로 읽으면 `$0C` 같은 UI 바이트가 인자로 오독된다. 덩이 범위를 `$C2` 이후로 가른 이유.
- 에뮬로 대사 출력기를 잡으려다 오프닝 중 `tap` 이 `native control retired` 로 죽었다(ED1 때와 같은 증상 — `debug.pulse_while_running`
  이 정식 조작). 결국 **정적 읽기가 더 빨랐다**: 글리프 복사 지점(`$C0:9F56`)의 호출자(`$C0:B2DD` 래퍼) → 그 호출자(`$C0:A9C2`)로 거슬러 올라가
  인터프리터에 닿았다.
- 글리프 순서는 JIS 가 아니라 음독 순이다(亜悪安暗案以位偉…). 처음 「JIS 에 가깝다」고 적은 가설을 시트로 뒤집었다 — 이름 검사용 원문 줄을
  내려면 색인→글자 표를 따로 세워야 한다.
- 원본 헤더는 2MB 를 선언하지만 실제는 1.5MB 다 — 체크섬이 뒤 0.5MB 를 반복해 합산한다. 2MB 로 실제 확장하면 합이 달라지므로
  `build.py` 가 체크섬을 재계산한다(보수 칸 규약: 합 계산 때 체크섬 4바이트를 `00 00 FF FF` 로 친다). 2MB 롬 부팅 확인은 아직이다.
- 글리프→글자 표: 갈무리 BDF 템플릿 매칭(IoU 최대)은 정확도 35% 로 버렸다 — 같은 12px 라도 글꼴 설계가 달라 획이 안 맞는다. 시트(16자 × 8줄)를
  육안으로 읽는 쪽이 정확했고(음독 순이라 순서가 오독 검증이 된다) 대사가 곧바로 일본어로 읽혔다. 사전 `E0` 표가 이름 74개(アートス国王·ゲイル3世…)라
  이름 검사의 첫 재료가 된다.
- 표 검증: 사전 `E0` 이름 74개 중 72개가 정본 사전(`canon.lookup`)에 원문 그대로 있다(남은 둘은 `ゲイル3世`·`ゴドウィン2世` — 숫자 표기 차). 한자까지 든 이름이라
  육안 표의 신뢰도 근거가 된다.
- `$88~$DF` 1바이트 글자는 히라가나였다(`$C0:90E8` 은 `$80` 미만만 처리하고 `$80+` 는 `$90A8` 로 새는데, 거기서 `$D6:E729+(코드−$8C)×16` 을 읽는다 —
  `$90A8` 부터는 디스어셈블이 한 바이트 어긋난 채 읽혀(`AND #$FF00` 이 `AND #$FF; BRK` 로 보인다) 처음엔 엉터리처럼 보였다). 한계: 일부 단위 머리에
  네이티브 코드 바이트가 토큰으로 오독되어 쓰레기 글자가 붙는다(`msg_start` 가 코드 영역 뒤쪽 `$00` 을 끝 토큰으로 오인) — 본문 글자는 영향 없음, 번역 삽입 전에 정리한다.
- 에뮬 대기 함정: `Monitor` 의 `sleep` 은 **기다려 주지 않는다**(즉시 돌아오고 알림만 나중에 온다) — 스크린샷을 너무 일찍 찍어 「로고에서 멈췄다」고 오진할 뻔했다.
  실제로 기다리려면 `timeout 90 tail -f /dev/null`(Bash 는 `sleep` 을 막는다). 오프닝 문장까지 약 100초.
- 에뮬 조작 요령(sfc-ed2): `tap` 은 죽으니 `debug pulse_while_running`(`status` 한 번 → `debug describe` 로 revision), 오프닝 대기는 `debug execution_speed unlimited`
  로 건너뛴다(100초 → 20초). 타이틀은 start → 아래 → a → 사운드 a → 첫 장면. 트램펄린 시험은 첫 장면 대사창(화자 アトラス)에서 확인했다.
- 트램펄린 덮는 자리를 「메시지 머리」가 아니라 **첫 전각 글자 토큰**으로 잡았다 — 머리에는 화자·색·플래그 검사(`$11~$14`+건너뛰기 3바이트)가 있어
  덮으면 분기 구조가 깨진다. 글자부터 덮으면 머리 구조는 그대로고, 뒤 꼬리는 도달 불가가 된다(번역문 끝 `$00` 이 메시지를 닫는다).
- 창 블록 이동 첫 시도는 **검은 화면으로 멈췄다** — 로더 `$C0:D6A7` 의 `mvn $7F,$C0` 이 소스 뱅크를 `$C0` 로 박아 놔서, 확장 뱅크 주소를 줬는데도 `$C0:xxxx`(코드)를 블록으로 복사했다.
  (`$AE` 에 뱅크를 저장하지만 `mvn` 은 즉치 뱅크만 본다.) 복사 루프를 `[$AC],y` 로 바꿔 해결. 두 번째 시험은 마지막 글자가 테두리에 잘렸다 — 원본 줄은 앞뒤에 공백을 둬 폭 계산에 들어 있었다.
- sfc-ed2 에뮬 `debug` 의 `known_capability_revision` 은 **실행(launch)마다 바뀐다** — 틀리면 오류 메시지가 새 값을 알려 주므로 `status`(8k 토큰)를 부를 필요가 없다.
- 🔴 **1바이트 글자 표를 두 번 틀렸다.** `$C0:90A8` 은 상위 바이트가 있을 때(`$1B19≠0`)와 없을 때가 **다른 표**를 읽는다(`AND #$FF00; BNE` — 디스어셈블이 한 바이트 어긋나 `AND #$FF; BRK` 로
  보여 못 봤다): 있으면 `$E729`(히라가나 — 실사용 없음), **없으면 `$E1C9`**(반각 가타카나, 일반 1바이트 글자). 처음엔 히라가나로 풀어 대사 속 「ポンコツ」가 「ぽんこつ」 꼴로 어긋났다.
  틀린 줄 안 건 **에뮬 사운드 창의 「ステレオ」(`bd c3 da b5`)** 가 JIS X0201 반각 가타카나(ス=$BD…)와 정확히 맞는 걸 본 뒤다 — 화면이 디코드의 정답지가 됐다.
- UI 문자열은 **다섯 갈래**다: ① 창 블록(`ui.json`) ② `mvn $7F,$C0` 으로 WRAM 줄 버퍼에 복사되는 값 상수(OFF·使わない·ステレオ·速い… 19곳, 소스 뱅크가 `$C0` 로 박혀 있다) ③ 코드 곁 인라인 문자열(`$C0:9395`/`$C0:A691`)
  ④ 이름 표(`$C1:762D` 주문 8B 레코드·`$C1:7733` 장비 16B 레코드·몬스터 `$CB:7769` 35B 레코드) ⑤ HUD(BG). 시작 메뉴·커맨드 창 같은 건 ①이고 필드 「使う」 창 제목은 ①에 없었다(③).
- 지역명(HUD 위치 표시)은 `$CB:30E9` **16비트 포인터 표**(`$A8=CB` 즉치로 뱅크 고정, 소비 4곳)다. 에뮬 읽기 중단점(`$CB:3175` 읽기, `pause_on_hit`)으로 `$C0:9395` 호출자(`$C0:C0D6`)를 잡았다 — 정적 검색은 표
  기준 주소를 직접 참조하는 코드가 없어 헛돌았다(표는 `$CB:30E9` 에서 색인으로 읽고 문자열은 12B 간격처럼 보이지만 실제론 가변). `get_state` 는 `groups:["cpu"]` 로 부르면 짧다(PC·레지스터만).

  필드 「使う」 창 제목이 일본어로 남아서 알았다(에뮬). 블록 뒤에 같은 stride 줄이 더 이어지는지 스캔했다(`$C0:DC35`도 1줄 더).
- 아이템 이름 표는 `$C1:772D` + id×14(7전각 칸, 오른쪽 정렬·왼쪽 전각 공백)이고 `$C1:3331~` 가 14바이트를 `$1201` 버퍼로 복사한다(읽기 중단점으로 확인) — 길이가 14B 고정이라 한국어 이름이 15B 인
  셋(성스러운 지팡이·마리스카의 친서·길모아의 무지개)은 아직 원문으로 남는다(`records` 게이트가 센다). 뒤에 `$1210~` 에 다른 필드가 붙은 버퍼라 폭을 늘리려면 코드 패치가 필요하다.

## 2026-10-12 — 대사 전량 번역과 걷이 구멍

- `script.units()` 가 약 500 메시지를 건너뛰고 있었다(`a < pos` 일 때 시작점). 검사(구간 수 고정)는 통과하고 화면에서만 일본어가 남는 부류 — 잔여 스캔(`resid`)으로 잡았다.
- 자동 걷이(`_clean`)는 짧은 조각·반각 섞임을 버린다 → 진짜 대사 28개가 빠졌다. `segs.EXTRA` 에 손으로 확인한 시작 주소를 더해 편입.
- 상점 프롬프트 등은 구간 앞에 6~8바이트 포인터 표가 붙은 가짜 구간이다 → `keep.json` + 진짜 시작에 span.
- 글리프가 748개 모자라 2패스 배정(안 쓰는 일본어 슬롯 재활용)으로 해결. `--strict` 는 떨어진 글리프에서 실패.
- 오프닝 가운데 정렬 폭은 256이 아니라 약 224px(텍스트 영역).
- 사운드·보관 창 문구는 포인터 없이 인라인(`1f 글자… 00`)이라 span 으로 제자리 치환했다. 도달 여부는 에뮬로 미확인.

- 에뮬 첫 장면에서 화자 이름표 「兵士」가 일본어로 남아 있었다: 같은 이름표가 번역 구간 **바깥** 7곳에 있었다(`<06>`/`<07>` 으로 나뉜 화자 목록 줄 6 + 개행 붙은 1). 구간 수 검사와 화면 게이트(번역 구간 수/전체)는 이를 못 본다 — `1e 글자… 04` 패턴을 구간 밖에서 직접 긁어 찾았다(`segs.EXTRA` 에 편입).
- 사운드 창 「ステレオ／モノラル」 12B 는 한 줄이 아니라 **옵션별 6B 둘**이다: 처음 「스테레오모노」(12B 한 줄)로 넣었더니 첫 6B 만 그려져 「스테레」로 잘렸다 → 옵션마다 전각 3자(입체음·모노음).
- 화면 HUD 의 「あと」는 `ui.json` 의 남다 블록(`$C0:F306`)과 무관하게 일본어로 남는다 — WRAM 검색에도 글자 코드가 없어 타일 그림이다.
- 저장 안내 5문장은 합쇼체로 바꿨다가 원문 말투(해요체, 번역 규칙 4-8)로 되돌렸다 — 해요체가 더 짧아 25B 칸에 들어 넓힐 필요가 없었다.

## 10-15 숨은 콘텐츠 조사 (마스터 지시, 조사만 — 결과는 status.md 「숨은 콘텐츠」)

- 디버그 메뉴는 「죽은 코드」(10-12 판단)가 아니라 **살아 있다**: 게이트가 `$137A` 비트7 이라 일반 입력으로는 못 켜질 뿐, 에뮬에서 RAM 에 써 넣으면 그대로 돈다. 그 판단을 뒤집은 근거는 `$137A` 를 입력 장치 복사 루프(`C0:11F1`)가 `$1377~`로 채워 주는 구조라는 것 — 「쓰는 코드가 없다」 검색은 **간접 인덱스 쓰기**(`sta $1397,x` 로 복사한 값)를 못 본다. 같은 실수를 피하려면 「stz 만 있다」는 주소의 **이웃 버퍼**(`$1377~$1380` 범위)가 어디서 채워지는지를 같이 본다.

- `$1B95`·`$0131` 이 자연 상태로 맞는 타이틀에서는 `$137A` 한 바이트(예 0x85)만 쓰면 사운드 모드가 열린다 — 진입로를 만든다면 타이틀이 가장 싸다.
- 몬스터 일람·사쿠사쿠 모드 메시지·「느닷없이 엔딩」 메시지는 **일본어 그대로** 화면에 나온다(번역 대상에서 뺀 죽은 코드로 취급했던 구간). 「워프로 전 지역에 갈 수 있다」는 이미 한글이다(`unreachable.json` 범위에 들어 있지만 따로 번역돼 있었다).
- 선택 6(오토매핑 해제) 본체는 `bra` 로 건너뛰어져 있어 진짜 죽은 코드다. 몬스터 일람은 0~0x76(119종)을 도는데 필드 몬스터 이름 풀과 같은 표인지는 안 봤다(화면에 일본어가 나오니 다른 표를 읽는다).
- 에뮬 요령: `debug` 의 인자는 `arguments` 안에 넣는다(`{"operation":"pulse_while_running","arguments":{"buttons":[…],"frames":N}}`). 필드에서 `b` 가 주메뉴, `a` 는 장 제목 배너다. `set_breakpoint` 는 `start`/`end` 문자열 · `pause_on_hit:true` 를 줘야 서고, 안 주면 NMI 마다 맞아 수십만 건이 쌓인다(`poll_events` 가 5만 자를 쏟았다 — 큐 비우기는 `clear_all_breakpoints`).
