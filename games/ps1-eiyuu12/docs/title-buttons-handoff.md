### 텍스트 제거 = rect-fill → **획 인페인트**로 전환 (2026-07-16, 유저 QA)

옛 방식(overwrite_text가 rect 전체를 밝은픽셀 평균으로 채움)은 ① **원본보다 밝은 흰 패치**
(선택 버튼이 원본 크림색보다 하얘짐), ② 행별 얼룩·모서리 맵색 오염을 남겨 유저 반려.
→ **일본어 어두운 획만 검출(적응 임계 = p75·p25 중간 + dilation)해서 inpaint_box로 최근접
버튼 내부색 메움**. 바탕·베벨·상태별 밝기가 원본 그대로 유지(선택=크림 그대로, 안 하얘짐).
검증(emucap): 선택 버튼 내부 ~[206,210,207] = 원본 크림 일치. Ⅱ는 중심 x 322로 살짝 좌측(유저 QA).

### ⭐⭐⭐ 최종 해법 — 버튼 원본 유지, 내부 텍스트만 교체 (2026-07-15, 유저 아이디어)

버튼을 **다시 그리는 접근을 모두 폐기**. 이전의 절차적 드로잉/인페인트/윈도우채움은
전부 위치·크기·테두리·배경 문제를 반복 유발. 근본 해결:

- **원본 버튼(프레임·베벨·선택/비선택 상태색·크기·위치)을 100% 그대로 둔다.** 렌더 함수는
  각 버튼 **내부(프레임 안쪽) rect만** 손댄다 → 지오메트리를 안 건드리므로 이동·크기변화·
  테두리 위화감이 원천적으로 불가능하고 "원본 느낌"이 그대로 유지됨.
- **내부 일본어 텍스트만** 행별 배경색으로 덮고(일본어 가림) 그 위에 한글을 얹는다.
  배경색 = 그 행의 밝은 픽셀(상위 ~32%) 평균 → **알약 금색 세로 그라디언트·박스 상태별
  밝기(선택 흰/비선택 맵투과)가 자동 보존**된다. (`overwrite_text()`)
- rect 좌표 = 원본 각 버튼 **일본어 텍스트 bbox 실측**(PILL_TEXT/COLL_TEXT). 좁으면 첫 글자
  좌측이 남으니(유저 QA) bbox+1px로. 알약은 세로를 텍스트 행 안에 둬 둥근 캡·아웃라인 보존.
- **컬렉션은 로마숫자 Ⅰ/Ⅱ(x403+)를 원본 유지**하고 英雄伝説(4자, x324-401)만 "영웅전설"로
  덮는다(유저: 내가 그린 Ⅱ가 어색 + 원본 Ⅰ/Ⅱ의 초록 엠보싱 살림). 패치 폭도 4자만이라 좁다.
- 글자 크기는 overwrite_text(wfrac,hfrac)로 조절 — 박스 hfrac 0.58, 알약 hfrac 0.48(더 작게,
  둥근 알약 안 여백 확보). 버튼 뚫지 않게(유저 QA).
- emucap 검증: 박스·알약 모두 프레임 불변(상태 간 diff는 내부만), 원본 베벨/맵투과/금색 유지.

### ⭐⭐⭐ emucap 캘리브레이션 확정 (2026-07-16) — 컬렉션 버튼 blit 규명

유저 QA: 커서 이동 시 폰트 위치·크기가 셀마다 달라 보임. 요구 = 버튼/폰트 크기·위치 고정,
**배경 밝기만** 선택=밝음/비선택=짙음. emucap로 직접 규명(캘리브레이션 = 각 셀에 고유색+
가로 눈금선 심어 디스크 write 후 화면 실측, `_calib_title.py` 임시):

- **엔진은 각 셀을 1:1(스케일 없음)로 화면 고정 슬롯에 blit한다** — TIM 눈금 10px가 화면
  10px로 나옴(scale=1.00). 즉 **화면 폰트 크기·위치 = TIM 폰트 크기·위치 그대로**.
- 4셀 매핑: Ⅰsel=cell0(빨강), Ⅰnorm=cell1(초록), Ⅱsel=cell2(파랑→CLUT 최근접 청록),
  Ⅱnorm=cell3(노랑). 좌버튼=Ⅰ의 sel/norm, 우버튼=Ⅱ의 sel/norm(둘 다 같은 화면 dest).
- 화면 셀 높이: Ⅰsel 27 / Ⅰnorm 28 / Ⅱsel 28 / Ⅱnorm 22 → 앞 3개 ~28 균일, cell3만
  내 경계 정의가 짧았던 것(원본 텍스트 중심 TIM-y ≈ 16.5/46/74.5/105, 약 29~30px 간격).
- **해법(확정): 4셀에 동일 크기 rect(W88×H22) + 동일 폰트를 원본 텍스트 중심에 배치.**
  scale=1:1·dest 고정이므로 TIM에서 동일 = 화면에서 동일 → 커서 이동에도 위치·크기 완전 고정.
  배경은 overwrite_text 행별 샘플이라 선택 흰/비선택 초록 밝기가 자동 유지. COLL_TEXT 참조.
- 검증: 좌/우 버튼 선택↔비선택 크롭 비교(out/title/FIN_cmp[LR].png) — 폰트 크기·위치 일치,
  배경 밝기만 차이. Ⅰ/Ⅱ 로마숫자도 폰트로 함께 렌더(원본 유지 시 한글과 괴리감 — 유저 QA).
- 미세조정(유저 QA): ① Ⅰ은 셀0/1 높이 균일(27/28)이라 고정 OK. ② **Ⅱsel 셀을 엔진이 화면상
  위로 올려 blit**(마스크 overlay 실측: Ⅱsel 폰트가 Ⅱnorm보다 y −2.6px, Ⅱnorm은 버튼 중앙에
  잘 맞음) → **Ⅱsel rect 중심을 +3 내려**(63-85 → 66-88) Ⅱnorm과 화면 y 일치(잔차 0.7px=Ⅰ 수준).
  ⚠ 첫 시도에 min/max 측정이 클램프로 방향을 뒤집어 오판(→ mask **centroid** overlay가 정본).
  ③ 폰트 2단계 축소(overwrite_text wfrac 1.0→0.72, hfrac 0.95→0.68). Ⅱ 버튼 패널 자체 크기변화는
  엔진 고유(원본 일본어도 동일) — 완전 고정은 ASM 훅 필요, 폰트 위치·크기는 위로 사실상 고정.
- ⚠ 알약(ED1/ED2 처음부터/이어하기)은 아직 미조정 — 같은 원리(1:1 추정)로 이후 작업.

### ⭐ emucap 실측 핵심 (2026-07-15) — 추측 종식

두 커서 상태 스크린샷을 **diff**하면 상태만 바뀐 박스 픽셀이 깨끗이 분리된다. 결과:

- **게임은 4개 컬렉션 셀을 화면상 고정 100×30 슬롯에 blit한다 — 선택/비선택 크기·위치
  완전 동일, 엔진은 확대/이동을 하지 않는다.** 즉 유저가 본 크기불일치·위치튐·"박스 위
  밝은 줄" 노이즈는 전부 **내 소스 셀 높이가 제각각**(Ⅱ선택 32px vs Ⅱ비선택 23px)이라
  게임이 고정 슬롯에 맞추며 다르게 늘린/읽은 탓. 밝은 줄 = 선택 박스(밝음) 바닥이 아래
  비선택 셀 read rect로 새어든 것.
- **해결(유저 방침과 일치): 네 셀 모두 동일 지오메트리로 그리고 틴트만 다르게.** 각 셀을
  중심y(원본 밝기 프로파일 실측: Ⅰsel16 Ⅰnorm45 Ⅱsel74 Ⅱnorm106)에 **동일 높이(COLL_BOX_H)**
  박스로 배치, 셀 사이 갭으로 밝은 줄 새어듦 차단. 알약도 동일(PILL_W×PILL_H 중심 배치).
- 재현: `python3 tools/build.py` → mednafen launch → 부팅 후 START → 컬렉션 화면. left/right로
  커서 이동, 두 상태 screenshot → `np.abs(a-b).sum(2)>40`로 박스 bbox 실측(out/title/EMU_*.png).

## 방식 전환 (이미지 → 절차적 드로잉)

유저 나노바나나 8버튼 에셋을 합성하는 이미지 방식은 크기 편차·구멍(배경 비침)·모서리
깨짐·선택↔비선택 반전을 반복해 유저가 반려. 최종적으로 **버튼 배경까지 코드로 그려
옛 그래픽을 통째로 덮는 방식**으로 확정(유저: "아예 덮어버리는거구나. 이게 깔끔할것 같은데").

유저 요구 스타일:
- 게임선택 박스: 약간의 radius(너무 딱딱하지 않게).
- 선택 박스: 순백이 아니라 **기본색에서 약간 밝아진 톤**.
- 텍스트: 선택/비선택 **둘 다 검정**(원본과 동일).
- 위치를 셀에 정확히 맞출 것.

## 구현 (`patch_gfx_title.py`)

절차적 드로잉 함수(전부 SS=4 슈퍼샘플 후 축소):

- `draw_pill(w,h,text,selected)` — 금색 라운드 알약. 선택=밝은 금색 그라디언트
  (255,232,120)→(210,160,40), 비선택=(238,205,70)→(180,132,30). 어두운 외곽선
  (44,26,8) + 상단 하이라이트. 검은 글자(18,16,12).
- `draw_box(w,h,text,selected)` — 라운드 프레임 박스(rad=3·SS). 선택 base=(196,200,190),
  비선택 base=(150,158,146). 밝은 외프레임(236,240,234) + 안쪽 어두운 선(40,46,40).
  검은 글자(16,16,16) **둘 다**.
- `_fit_font` / `_draw_text` — 셀 폭·높이에 맞춰 폰트 자동 축소 후 중앙 배치.
  폰트 = AppleSDGothicNeo.ttc index=6(Bold).
- `paste_over(canvas, old_mask, sprite, x0, y0)` — old_mask(옛 그래픽) 인페인트 후
  sprite를 (x0,y0)에 alpha_composite → RGB.

배치 상수(전부 TIM 픽셀 좌표):

```
PILL_CELLS  = (x0,x1,y0,y1, 문안, 선택)  # 하단2=비선택, 상단뱅크2=선택
  (47,113,192,218,"처음부터",False) (223,289,192,220,"이어하기",False)
  (322,387,2,29,"처음부터",True)    (323,387,32,60,"이어하기",True)
COLL_X = (320,420)  # 컬렉션 4셀 공통 x
COLL_CELLS = (y0,y1, 문안, 선택)
  (3,31,"영웅전설Ⅰ",True) (32,61,"영웅전설Ⅰ",False)
  (62,94,"영웅전설Ⅱ",True) (95,118,"영웅전설Ⅱ",False)  # y118서 끊음(PRESS START 보호)

```

**⚠ 알약 셀 좌표 = 원본 일본판 노란 알약 bbox 실측(scan). 게임이 읽는 실제 스프라이트
사각형과 반드시 일치**시켜야 한다 — 이보다 크게 그리면 게임이 중앙 밴드만 blit해 둥근
상/하가 잘린다(유저 QA "선택 알약 bottom 잘림"). 옛 셀 `(0,31)`·`(30,62)`는 서로 겹치고
실제 rect보다 커서 잘림 발생. 실측값: 뱅크 처음부터 x323-386 y3-28 / 이어하기 x324-386
y33-59(겹치지 않음, y28-33 갭) / 하단 x48-112 y193-217 · x224-288 y193-219.

- `render_buttons(tim)` — ED1/ED2 알약: 셀별 옛 노랑 인페인트(`_yellow_mask`) 후 draw_pill,
  셀+3px 여백 재양자화.
- `render_coll_buttons(tim, pix)` — 컬렉션: 옛 박스(밝음/녹색) 마스크 인페인트 후 draw_box.
  비선택은 셀 높이×COLL_NORMAL_HSCALE로 그려 게임 세로압축 선보정. 셀 중심 정렬.
- 로고 `render_logo`(inpaint+composite+quantize)는 그대로 검증된 레퍼런스.

## 게임 엔진 특성 (불가피, 원본 JP도 동일)

- **선택 버튼이 비선택보다 크게 렌더**(하이라이트 효과) — 원본 일본판 부팅해 확인됨.

## 타이틀 TIM 3장 (전부 START.DAT, 디스크 섹터 정렬)

| 스트림 오프셋 | 화면 | 크기 | 내용 |
| --- | --- | --- | --- |
| `0x50C800` | 컬렉션(부팅) | 480×240 8bpp | 대형 로고 + 英雄伝説Ⅰ/Ⅱ 4셀 |
| `0x52A000` | ED1 타이틀 | 390×240 8bpp | はじめから/つづきから(하단2+뱅크2) |
| `0x541000` | ED2 타이틀 | 390×240 8bpp | 위와 동일(같은 그래픽) |

- 스트림 오프셋 = 디스크 섹터×2048. `write_user_data(f, off//2048, blob)` + EDC.
