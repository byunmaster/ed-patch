## 다음 할 일 (집 세션용, 우선순위)

1. ✅ **캐릭터명 그래픽 — 완료(2026-07-14).** 상태창 이름판 TIM **0x566800**(220x215 8bpp,
   ED1PARTS.DAT) 발견 — 5명(セリオス/リュナン/ロー/ゲイル/ソニア)이 노란 카타카나 그래픽.
   `patch_hud_names.py`가 인페인트(idx39)+Galmuri9 조판(idx16/그림자46)으로 교체(build 체인 통합).
   ED1PARTS 타 UI TIM(160x160 색상타깃·128x128 이펙트시트·88x80 그리드)은 비-이름 확인 →
   **이름판은 0x566800 하나뿐, 5명 고정.** ⚠ 후속: ①번역명 잠정(류난·로우 — 정발 대조 검수)
   ②구판 로스터의 ミッシェル이 6번째 합류 캐릭터면 이 TIM(5슬롯)엔 없음 → 대사/스프라이트 쪽 확인.
2. ✅ **아이템·마법명 — 완료(2026-07-14, patch_items.py).** 수수께끼 해소: 소지품(たいまつ 등)의
   진짜 소스는 **ED.EXE 앞쪽 이름 블롭 0x828~0xE73**(장비·도구 100 + 마법 13, 널종단 가변길이,
   0xDC8~0xDD7에 데이터 섬 — 보존 필수). 0xF8DC4/0xF8E48의 8B 테이블(17+14)은 전투/이벤트용
   별도 세트. 참조는 이름당 lui/addiu 1쌍(공유 lui 0) — 초기화 루틴이 strcpy(jal 0x800CC6B0)로
   전 이름을 **런타임 테이블 0x8016xxxx(32B stride)** 에 복사하고 인덱싱은 사본 쪽에서만 하므로,
   **영역째 KR 재packing + addiu lo만 갱신**(146곳)으로 완결. 상위 16비트·lo 부호가 안 변해
   lui는 무수정(assert 강제). DOS 정발 매핑: 아이템 0x2695B~(stride 20, 이름 14B 우측정렬),
   마법 0x2727F~(stride 11, 이름 8B) — 순번이 PS1과 1:1(정발 여분 = PS1 8B 테이블과 일치).
   검증: 바이트 레벨 146/146 + 인게임 장비창(나이프/헝겊 옷) + RAM 런타임 사본(대형검·번개의
   지팡이). 편차는 대장 기록(치유의 로브·번개의 지팡이·무 등). 류난(0x80C)도 이식.
3. ✅ **몬스터명 — 완료(2026-07-14).** 208개(베이스 92) @0x9D58~0xA8CF, 아이템과 동일 구조
   (lui/addiu 참조, 뒤 0xA8DC~ 데이터 섬 보존). 정발 소스는 **MONDLL/M###.DLL**(이름 레코드
   0x280E + k×56, 인카운터별 DLL). 판정 4건 유저 확정(플라워리자드·송리그모·데스코브라·
   데쓰 가디안 계열 — 편차 대장 참조).
4. ✅ **전투·챕터·격투장 메시지 — 완료(2026-07-14).** 챕터 클리어 13(0xB9C0)·격투장 4(0xBD18,
   정발 T_204~207 어투)·전투 메시지 9(0xBDCC/0xBE60)·전투 조각 58(0xF8EEC)·이벤트 전투명
   21(0xF9074, 사령관·병사·가르고·바위인간·철거인 등 — 메인 테이블 밖 이름들의 행방).
   전부 lui/addiu 참조(u32 포인터 0)라 동일 재packing. 포인터 섬(0xBE48·0xBCDD) 보존.
   **조사 처리**: 병기(을(를)·은(는)) + 정발 고정형('으로는'). たち 사본 분리 — 0xF8ED4='일행'
   (승리 보상 문맥 추정), 0xF8F84/0xF9030='들'. 검증: 바이트 664/664 + 부팅 회귀 + RAM 패턴.
   4-b. ✅ **전투 코퍼스(0x4954~0x9938, 524 문자열) — 완료(2026-07-14).** 유저 전투 캡처로
   잔존 일본어 발견 → 미탐사 구간 전수 규명: 몬스터 행동 문장·조우 공지·상태이상·마법 효과·
   승리/패배·보스전 대사(아크담/헤르닐드/규리게스/실피/바질) + **전투 표시명 사본**(スライム
   @0x56D4 — 전투 HUD가 몬스터 테이블이 아니라 이 사본을 씀). 번역은 `battle_text.py`
   (MONDLL 문장 어투 준거). 데이터 조각이 섞여 통짜 재packing 불가 → **제자리 305 + 풀
   재배치 219**(이름 영역 잔여+비운 슬롯 병합, best-fit, lui까지 완전 갱신·공유 검사).
   부수 수정: patch_sys_ui 레벨업 부분치환이 긴 변형(強さが%c%d%cﾎﾟｲﾝﾄ…)의 꼬리를 자르던
   버그 — 12종을 코퍼스로 이관해 복원. 검증: 참조 604/604 + 부팅 + RAM 패턴.
5. **동적 조사 훅(개선 항목)** — 병기를 정확 조사로 바꾸려면: 우리 인코딩은 슬롯(한자영역)

## 빌드 & 테스트

```bash
cd games/ps1-eiyuu12
python3 tools/build.py                       # 대사+카드+UI+지명+메시지 → work/Eiyuu Densetsu (KR).bin
python3 tools/patch_opening_font.py          # 오프닝(제자리 갱신) — 아직 수동 2단계
```

- 테스트 이미지는 `work/Eiyuu Densetsu (KR).bin/.cue` **하나만** 유지(유저 방침).
- 에뮬: emucap MCP(mednafen) 또는 DuckStation. ⚠ **빌드 교체 후 reset 무효** — mednafen이
  디스크를 캐시하므로 프로세스 kill + launch. 정밀 캡처는 pause 후 step(≤240프레임).
- 오프닝까지: 부팅 ~2900f → start → 120f → circle(ED1). 오프닝 스킵: start.
  게임 시작: circle(はじめから) → 인트로 대사는 circle 홀드(100f)로 스킵.
- 인게임 조작: **cross=메뉴 열기**, circle=확인, cross=취소(서브메뉴). 시스템 설정 경로:
  cross → 기타(메뉴 6번째) → 시스템(서브 3번째) → EP 행(3번째)에서 circle로 값 순환.
  ⚠ 메뉴 이동 시 취소 직후 첫 방향키가 가끔 씹힘 — 사이에 run_frames 15~20 넣기.
- **검증 루프**: 유저가 DuckStation으로 직접 확인하는 쪽이 훨씬 빠름(에이전트 에뮬 내비는
  메뉴 커서 위치가 불안정) — 빌드 완료를 알리고 유저 스크린샷으로 확인받는 흐름 권장.

## 핵심 지식 (요약)

- **값 메뉴 정렬**: 값 X = 라벨 렌더폭 + 행별 갭(JP 라벨 폭 기준 하드코딩) → KR 라벨을
  JP 원본 렌더폭에 패딩(0x8140 전각공백+0x20). patch_sys_ui.py VALUE_PAD 주석 참조.
- **HUD 지명 소스**: ED.EXE 테이블이 아니라 SCN 오버레이 맵 세그먼트 헤더
  ([포인터테이블]+[지명 널종단]+[%c 대사]). 헤더 뒤 포인터 테이블은 위치 고정이라 확장 불가.
- **ED.EXE**: LBA 257, t_addr 0x80010000 (file 0x800 ↔ RAM 0x80010000). RAM 주소 =
  file - 0x800 + 0x80010000. mednafen 'ram' 오프셋은 & 0x1FFFFF.
- **오프닝**: HANDOFF 구판 상세는 devlog·patch_opening_font.py 주석. 줄당 21슬롯,
  0x0A 필드클리어, 영역 0x974~0xEEE(여유 6B).
- MIPS 손인코딩 함정: andi rs 필드, load-delay 슬롯 — 디스어셈블+시뮬로 검증.
