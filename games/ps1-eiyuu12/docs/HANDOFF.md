# ED1 작업 핸드오프

회사↔집 이어작업용 **살아있는 문서**. 세션 시작 시 이걸 먼저 읽고, 끝낼 때 "현재 상태"·"다음 할 일"을 갱신한다.
표기 편차는 [jeongbal-deviations.md](jeongbal-deviations.md)(변경 시 갱신 의무), 오프닝 여정은 [opening-font-devlog.md](opening-font-devlog.md).

마지막 갱신: 2026-07-23 — **인트로 탈출 이벤트 정지(유저 DuckStation) 조사 + %s 계약 가드**.
유저가 새 게임 → 밤 습격 갑옷 대사(ED1SCN1 **eid 28**, JP 노출 = window_deficit 제외 블록)의
▽에서 입력 무효·음악 지속 정지를 재현. differential로 **줄머리 공백 훅은 무혐의 확인**(훅 뺀
빌드도 동일) → 유저 방침(훅 대신 텍스트 검수)과 겹쳐 **훅 롤백**(patch_battle_wrap.py는 참고용
보존, build.py 주석). 데이터 전수 검사 결과: %c 계약은 전 씬 부족 0건이나 **JP의 %s/%d가
재조립본에서 사라진 블록 56건 발견**(인라인 화자 %c%s%c를 build_block이 못 보존) — 그중
eid 23이 정확히 1장 아침 체인. → **fmt_drop 가드 추가**(reflow_run: %s/%d 줄면 번역 제외),
재삽입 1000→**943블록**. **유저 재검증 통과(2026-07-23 "이제 잘돼") — 정지 원인 = %s 누락 확정.**
**교훈: 소프트락 계약은 %c 수만이 아니라 %s/%d 수까지다** — 서식 지정자 소비가 어긋나면
씬 이벤트가 정지한다. 진단 스위치 `PILOT_EXCLUDE_EIDS="ED1SCN1:26,27"` 신설(이분용, 이번엔 미사용).
**✅ %s 방출 구현 완료(2026-07-23, 인게임 검증 대기)** — fmt_drop **77 → 17**, 재삽입 943→**991블록**.
- **화자 헤더 %s(59블록)**: JP 헤더가 `%c%s%c`(런타임 이름 주입)인 블록을 `jp_header_is_fmt()`로
  판별해 **리터럴 이름 대신 %s를 그대로 방출**. 주인공 이름은 플레이어가 정하는 값이라
  리터럴("세리오스")로 박은 것이 애초에 틀렸다 — 이름 설정 반영 + 인자 소비 정합을 동시에 해결.
- **본문 이름 자리(11블록)**: 정발 인라인 `\x09` = 이름 주입 자리 → 센티널(`NAME_SENT`)로 조판을
  통과시킨 뒤 `encode_ext`가 **%s 바이트로 방출**. 폭은 `NAME_SLOTS=4.0`으로 근사(세리오스=4).
  → 오래 남아 있던 **"이름은 ." 이름 누락 버그 해소**.
- **인라인 화자 헤더 `%c%s%c`**: 창 구분 `%c` 뒤에 곧바로 `%c이름%c 0x0A`가 오면 그 창은 화자가
  바뀐 창이다(`jp_inline_fmt_windows`). 성문 병사 대사(SCN1 **eid 17**)가 이 형태 —
  병사 창 다음에 주인공이 답하는 창이 붙는다. 정발도 `세리오스 / 그래. 그러면 어쩔 수 없지.`로
  이름을 한 줄 띄워 표시(유저 확인). 우리가 이걸 빠뜨려 화자가 사라지고 `%s`가 줄어 제외됐던 것.
  - ⚠ **창 번호 off-by-one**: 구분 `%c`는 **앞 창을 닫고** 헤더는 **다음 창**의 것 → `win+1`.
  - ⚠ **창 수 식**: `W = mc - 2*블록헤더 - 2*(우리가 방출하는 %s 인라인)`. **리터럴 인라인 헤더는
    빼면 안 된다** — 방출하지 않으므로 창을 하나 더 만들어 %c를 맞추는 기존 동작을 유지해야 한다
    (빼면 window_deficit이 2→8로 튄다. 실측).
- **⚠ %s가 주입하는 이름의 소스 = SCN 오버레이의 단독 이름 문자열 사본** (2026-07-23 실증).
  `ED.EXE 0x800`은 '세리오스'로 정상 패치돼 HUD엔 한글로 뜨는데도 **대사창 이름만 일본어**로
  떴다 → 필드 대사 `%s`는 0x800이 아니라 **오버레이가 들고 있는 널종단 이름 사본**을 쓴다.
  전투 HUD가 몬스터 테이블이 아니라 별도 사본(`スライム @0x56D4`)을 쓰던 것과 같은 계열.
  실측: **ED1SCN1 @0x8C8 セリオス(슬롯12B, 참조O)**, **ED1SCN2 @0x3090 ソニア(슬롯8B, 참조O)** —
  이 둘뿐. 지명과 동일한 길이 보존 치환으로 `patch_sys_ui.CHAR_NAMES`에 추가(치환 167→170곳).
  ⚠ 주인공 이름은 **고정**이다(드퀘식 입력 아님, 유저 확인) — 그래서 `%s`도 결국 이 사본을 읽는다.
- **남은 fmt_drop 16건은 정상 동작**: 상점 대사류로, JP엔 아이템명·가격 `%s`/`%d`가 있는데
  **정발 원문에 그 자리가 아예 없다**(예 "됩니다. 괜찮으시겠습니까?"). 어디 넣을지 추론 불가라
  계속 제외가 맞다 — 넣으려면 정발 문안 자체를 손봐야 하고 이는 사전 보고 대상.

**✅ 정렬 채택 기준에 화자 일치 도입(2026-07-23)** — 재삽입 992→**1028블록** + 오매칭 대거 제거.
- **화자 일치가 LaBSE 유사도보다 강한 신호**다(실측). 유사도만 쓰면 ①점수는 높은데 화자가 틀린
  쌍이 채택돼 엉뚱한 대사가 나가고(**전 씬 113건** — 유저가 반복 보고한 "상관없는 대사")
  ②화자가 맞는데 점수 미달로 버려지는 쌍이 생긴다(**309건**).
  → `accept_pair()`: 화자 대응이 확인되면 **일치=채택(low_sim이어도) / 불일치=제외(무플래그여도)**,
  화자 정보가 없으면 기존 플래그 기준. 검증: 제거된 것 중 `jp110(라우엘↔병사)`은 HANDOFF에
  이미 "오매칭 확인"으로 기록돼 있던 건 — 사람이 찾던 걸 규칙이 자동으로 잡았다.
- 후보 1342→1480. SCN1은 수동 오버라이드 87건이 이미 오매칭을 잡아둬 변동이 적고(291→278,
  줄어든 13은 오매칭), SCN2~6에서 크게 늘었다.

**⚠ 1장 커버리지의 진짜 병목 = 공간 (2026-07-23 실측)**
- SCN1 대사블록 559 / 후보 391 / 재삽입 278 → **커버리지 49.7%**, 공간이 풀리면 **69.9%**.
- SCN1 제외 113건 중 **104건이 `size`** — 알고리즘이 아니라 물리적 공간 부족.
- 한국어가 일본어보다 **약 5.5% 길다**. 전 후보 번역 시 부족분: SCN1 **+5,187B**,
  전 씬 합계 **+21,884B**. 텍스트 영역 사용률 SCN1 98.7%.
- **오버레이엔 여유 0**(text_end 이후 256B+ 0런 전 씬 0곳). ED.EXE는 512B+ 0런 합 16.1KB이나
  파편화(최대 4,203B @RAM 0x80105959) + 일부는 런타임 버퍼 위험.
- 단편화 요인 점검: 미참조 블록 핀(Rule A) 비용은 **2블록뿐** → 유지가 맞다(공간 문제와 무관).
- ⇒ 커버리지를 더 올리려면 **도너 공간 확보가 선행**(오버레이 확장 또는 ED.EXE 여유 활용).
  문안 축약은 사전 보고 대상이라 별개 트랙.

**다음 할 일(우선순위)**:

1. **%s 구현 인게임 검증** — ①주인공 이름이 대사에 제대로 뜨는지(특히 "제 이름은 %s") ②이름
   설정한 값이 반영되는지 ③습격 이벤트 등 정지 재발 없는지.
2. **정렬 커버리지 확대** — 대사 커버리지 47%(미번역 1506블록)가 체감 품질의 최대 병목.
3. 1장 QA 잔여: 화자 다른 대사 병합(splice), 오매칭, 퍼거슨 헤더 깨짐, 빈 창 25건, 색 코드 위치.
4. 창 수 초과 166건(꼬리 잘림) — 문안 축약은 사전 보고 대상.

**줄머리 공백 훅 — 미채택 확정(2026-07-23 유저 결정. "보류"가 아니라 종결)**
`patch_battle_wrap.py` 구현·검증은 완료했다(훅 지점 = 루프 헤드가 아닌 **`0x800AD604`**
그리기 직전 수렴점 — wrap ① 빈틈까지 커버, stub 30명령 @0x80105D00, 셀프테스트+capstone+
인게임 실측). 그럼에도 채택하지 않는다:
① differential로 **인트로 정지와 무관함이 확인**돼 실익이 없었고(진범은 `%s` 누락),
② 매 문자 분기를 거는 런타임 비용·리스크보다 **화면을 보고 그때그때 텍스트를 고치는 편이 낫다**
   는 판단(개발에서 for문 printf보다 개행 넣은 printf 한 번이 낫듯이).
→ 전투 띄어쓰기 wrap 문제는 앞으로도 **데이터 우회**(공백→개행, battle[9·27·345] 방식)로 대응.
훅 코드는 렌더러 규명 자산이라 참고용 보존 — **되살릴 계획 없음**. 되살릴 일이 생기면 위 주소·
설계는 QA 메모의 "전투 텍스트 렌더러 규명" 절에 그대로 남아 있다.

직전 갱신(2026-07-22 낮): **1장 탈출→월드맵 먹통(소프트락) 해결**. 원인 = 창 수 계약 위반의
"과잉읽기": 엔진은 블록당 %c 세그먼트를 **원본 개수만큼** 읽는데 KR 재조립본이 창을 **적게**
만들면 종단을 못 만나 뒤 데이터를 읽어 깨진 글자 + 무한 대기 → 씬 상태머신(0x800B50C0,
state var 0x80108A68)이 state 5에서 stall. 수정: **창 수 부족 블록은 번역 제외**(window_deficit,
전 씬 32개). 부수 수정: **미참조·비번역 블록 이동 금지**(핀 고정 — 앵커가 못 잡는 값 테이블
@0x757E 보호). 유저 검증: 탈출→곶의 동굴까지 정상 진행. 이어서 **창 수 계약 packing 구현 완료**
(줄 하드리밋 6 실측, 헤더 유무별 구조 일치, 목표 N창 균형 분배): 일치 60.8%→87.5%,
꼬리 잘림 500→166, 재삽입 912→**1000블록**.

## 핵심 지식 (요약)

- **값 메뉴 정렬**: 값 X = 라벨 렌더폭 + 행별 갭(JP 라벨 폭 기준 하드코딩) → KR 라벨을

  0x0A 필드클리어, 영역 0x974~0xEEE(여유 6B).
