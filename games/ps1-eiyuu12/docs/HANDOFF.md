**✅ ED.EXE 도너 공간 구현(07-26 밤) — size 퇴출 해소의 1차 답**

- **도너 = ED.EXE 데이터 세그먼트의 미사용 0런 16개(~8.3KB)**, `DONOR_RUNS`(reinsert).

  이동, 코드 훅·런타임 비용 0.
- **안전성 3중 검증(방법론 — 풀 확장 시 반복할 것)**: ①원본·현빌드 파일에서 0
  ②ED.EXE+전 SCN 디스어셈블에서 포인터/절대 접근 참조 0건(주변은 개별 주소 CPU 데이터
  세그먼트 374건 = 통짜 DMA 아님) ③emucap 필드·전투 스테이트 RAM 덤프에서 0 유지(런타임
  버퍼 아님).
- **2단계 배치 설계**: 오버레이 재배치·공유 lui 수렴이 끝난 뒤, size 퇴출 블록 중
  참조(delta 0) 있는 것만 큰 순서로 도너 할당 → 참조만 ED.EXE 주소로 패치. 원본 JP는
  오버레이 제자리에 남는다(레이아웃 불변 = 기존 검증 무손상). 공유 lui가 타 블록과 얽히면

**✅✅ 오버레이 확장 = 공간 문제의 근본 해결(07-26 밤 3, 부팅 스모크 통과)**

  양 엔디언) 패치. 이미지 크기 불변. 원본 섹터는 그대로(무참조 stale).

  2.3KB 사용 섬 + 0x801B0000부터 본격 사용 영역. SCN2가 상한에 정확히 닿음(+3.2KB만).
  추가 여유가 필요하면 0x801A0000 섬(2.3KB)과 0x801A1000~0x801B0000(60KB)의 정체 규명이
  다음 관문.
- **하류 배선**: 재배치 결과를 `out/scn_layout.json` 매니페스트로 기록 — patch_sys_ui

  반드시 매니페스트를 읽을 것(하드코딩 LBA는 재배치 전 위치).

**⚠ %c의 정체 = 제어 인자 escape (2026-07-23, 코드로 확증)**
`%c`는 창 구분자가 아니라 **제어 인자를 소비하는 escape**다. 전투 데미지 조립부 디스어셈블에서
`sprintf(buf, "%c%s%c…", 2, 이름, 1)` — **%c에 색상 코드(2=ON, 1=OFF)가 인자로 들어가는 것**을
확인했다. 원본 용도: 블록 화자 헤더 / 인라인 화자(%s·리터럴) / 연속 %c 페이지·색 전환 / 창 경계.
우리가 이를 전부 "창"으로 세어 텍스트를 N조각으로 재분할하면서 **대사가 엉뚱하게 쪼개지고
색이 문장 중간에서 바뀌었다**(eid 23 퍼거슨·eid 27 라이아스 실측). 현재는 재현 못 하는 구조를
`ctrl_seq`로 제외해 깨짐만 차단한 상태.

**■ ✅ 템플릿 채우기 구현 완료(2026-07-23) — 구조 충실도 77.4% → 82.0%**
`parse_template`/`template_windows`/`build_from_template`. 제어 토큰(%c/%s/%d)을 **바이트 그대로**
방출하고 본문 창에만 정발 문장을 채운다. 용량 초과 시 기존 `build_block`으로 폴백(커버리지 유지).

- ⚠ **버그 교훈**: SJIS 2바이트 선두는 `0x81~0x9F`/`0xE0~0xEF` **뿐**이다. `0xA1~0xDF`는 반각
  가타카나 1바이트라, `0x81~0xEF`로 뭉뚱그리면 `･`(0xA5)에서 파싱이 밀려 뒤의 %c를 삼킨다
  (초기 구현에서 %c 불일치 13건·재삽입 1014→961 하락으로 발현).
- ⚠ **정정: 바이트 절감은 없다.** 초기 A/B에서 "-32KB"로 나온 건 **템플릿 실패분을 일본어 원본
  바이트로 계산한 착시**였다(실패 244 × ~130B). 실측 증가분은 현행 +7687B vs 템플릿 +7755B로
  사실상 동일 — 바이트는 한국어 텍스트가 지배하지 제어코드가 아니다.
  ⇒ **`size` 제외 417개(공간 문제)는 템플릿으로 해결되지 않는다.** 도너 공간이 여전히 선행 과제.

_구조 실측(전 씬 번역대상 1480블록, `%c` 경계로 창 분할):_

- **다화자(이름창 ≥2)는 단 7블록** — 이미 ctrl_seq로 제외 중이라 사실상 무시 가능.

  eid 27 같은 복잡 블록은 극소수 예외였다.

_구현 메모(프로토타입 검증됨):_

- `parse_template(raw)` → 토큰열 `('c'|'s'|'d'|'nl'|('t',bytes))`. 꼬리 0패딩은 버린다.
- `windows(tpl)` → `'c'`를 경계로 창 분할. **이름 창 판정** = 창 안에 텍스트(또는 %s) 하나뿐이고
  `nl`이 없으며 **다음 창이 nl로 시작**. (이 판정을 안 하면 여러 줄을 각각 span으로 세어
  `body2!=page1`류 오탐이 쏟아진다 — 1차 프로토타입의 실패 원인.)
- 조립: 제어 토큰은 **바이트 그대로 방출**, 이름 창은 정발 화자명(원본이 `%s`면 %s 토큰이라

      **`0x800AD3A8` = 폭 제한 문자열 드로어(범용, 폭이 인자)**. 레지스터: `s0`=열(1-based)
      `s1`=줄 `s3`=문자인덱스 `s4`=폭 `s6`=x기준 `s7`=y기준, `[sp+0x20]`=문자열 `[sp+0x30]`=strlen.
      제어코드 1~14는 점프테이블 `0x8001BEF8`, 일반 문자는 `0x800AD570`.
      **줄바꿈 지점 = `0x800AD5FC`**: 열>폭이면 남은 칸을 글리프 `0x91`로 채운 뒤
      `s1++`(줄) `s0=1`(열). 그 **직후 같은 문자 `str[s3]`를 새 줄 1열에 그리므로 그게 공백이면
      줄머리 공백**이 된다.

      현재 문자를 새 줄에 그려 못 잡는 빈틈이 있었다(공백이 정확히 29열이면 재현). `0x800AD604`는

- **값 메뉴 정렬**: 값 X = 라벨 렌더폭 + 행별 갭(JP 라벨 폭 기준 하드코딩) → KR 라벨을
  JP 원본 렌더폭에 패딩(0x8140 전각공백+0x20). patch_sys_ui.py VALUE_PAD 주석 참조.
- **HUD 지명 소스**: ED.EXE 테이블이 아니라 SCN 오버레이 맵 세그먼트 헤더
  ([포인터테이블]+[지명 널종단]+[%c 대사]). 헤더 뒤 포인터 테이블은 위치 고정이라 확장 불가.
- **ED.EXE**: LBA 257, t_addr 0x80010000 (file 0x800 ↔ RAM 0x80010000). RAM 주소 =
  file - 0x800 + 0x80010000. mednafen 'ram' 오프셋은 & 0x1FFFFF.
- **오프닝**: HANDOFF 구판 상세는 devlog·patch_opening_font.py 주석. 줄당 21슬롯,
  0x0A 필드클리어, 영역 0x974~0xEEE(여유 6B).
- MIPS 손인코딩 함정: andi rs 필드, load-delay 슬롯 — 디스어셈블+시뮬로 검증.
