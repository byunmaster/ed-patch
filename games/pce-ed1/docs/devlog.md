## 2026-09-05 — 첫 세션: 대본·코덱·폰트 소재

- **정적 분류로는 대본이 안 보였다.** 섹터별 엔트로피·SJIS 밀도로 트랙을 훑으니 SJIS 는 시스템
  문구 9섹터뿐이고 나머지가 「MID」로 뭉개졌다. 1bpp 비트맵 탐지는 0xFF 채움 섹터에 속았다(같은
  바이트끼리 XOR 이 0 이라 「상관 높음」으로 읽혔다). ADPCM 은 니블 크기 분포로만 갈라졌다.
  ⇒ 결국 **에뮬로 첫 대사까지 가서 RAM 을 뒤진** 게 빨랐다(SJIS 평문이 뱅크 0x76 에 있었다).
- **BP 는 두 번 헛돌았다.** 뱅크 0x76 의 대사 자리에 쓰기 BP 를 걸었더니 (1) BIOS 의 CD 전송
  루프가 그 자리에 **다른 데이터**(그래픽 스테이징, $C400 에 0x1C00B)를 쓰는 걸 먼저 잡았고,
  (2) 그걸 읽는 디코더($4837)를 대본 디코더로 오해할 뻔했다 — 뱅크 0x68 은 RAM 이라 **오버레이가
  갈리면 같은 논리 주소에 다른 코드**가 온다. 실제 대본 쓰기는 $6E55 였고 값(0x82 = お 의
  상위 바이트)으로 가렸다.
- **스테이트 로드 직후 `tap` 이 씹혔다.** 타이틀 스테이트를 올리고 run 을 눌렀는데 오프닝을
  한 바퀴 돌고 타이틀로 돌아왔다. 두 번째 탭은 먹었다.
- **LZ 는 첫 바이트 하나가 함정이었다.** 디렉터리 src 가 가리키는 첫 바이트는 헤더(모드 변형,
  0)였고 스트림은 그 다음부터다. 링 초기 커서 0xEF 는 초기화 루틴($45A9)에서 읽었다 — 그걸
  0 이나 0xF0 으로 두면 31바이트째부터 갈린다.
- **컨테이너 스캔의 가짜 양성 둘**(rel 1,249 · 1,475) — 디렉터리 모양은 맞는데 블록 헤더가
  쓰레기였다. 헤더 검사를 넣으니 걸러졌다. 「디렉터리로 읽힌다」는 계약이 아니다(체크리스트 10).
- **cue 의 대문자 파일명**: redump cue 가 `.ISO` 로 적어 리눅스 emucap 이 못 열었다. 심볼릭
  링크는 emucap 이 「too many levels of symbolic links」로 거부해 **하드링크**로 뒀다 — 원본과
  같은 inode 라 거기 쓰면 원본이 망가진다.
- **syscard3.pce 가 393,728B** — 표준 256KB 가 아니라 384KB+512 헤더 덤프인데 부팅은 됐다.
  BIOS 안 12×12 글꼴 시트가 파일 0x10000~0x28000 부근에 있다(24B 로 그려 보면 가나·1수준 한자가
  보인다 — 실제 저장은 18B 패킹이라 시트 정렬이 어긋난 채로도 눈엔 들어왔다).
