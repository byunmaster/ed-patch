## 한 줄 요약

**대본이 손에 들어왔다.** 씬 블록 214개(12.8만 자)를 LZ 에서 풀어 덤프했고 코덱은 왕복이
된다. 글꼴은 BIOS(시스템 카드) 것이라 **후킹 자리도 잡혔다**(`EX_GETFNT` 호출 한 곳).
남은 본진은 **재삽입 설계**(씬 블록 재압축 → 컨테이너 재조립 → 섹터 패치)와
**한글 글리프를 RAM 어디에 두느냐**다.

## 확정된 것

### 1. 원본 — 22트랙, ISO9660 아님, 게임 좌표는 「트랙 상대 섹터」

`originals/jp/pce-ed1/*.iso`(2352B raw · 279,919섹터). 지문·상수는 [`tools/common.py`](../tools/common.py).

| 트랙 | 파일 섹터           | 무엇                                                                 |
| ---- | ------------------- | -------------------------------------------------------------------- |
| 1    | 0~3,364             | 오디오(경고 트랙)                                                    |
| 2    | 3,365~13,436 (10,072) | **데이터**(MODE1). 유저 데이터 20.6MB — 끝 286섹터는 0               |
| 3~21 | …                   | CD-DA(BGM)                                                           |
| 22   | 278,186~ (1,733)    | 데이터 — **트랙 2 머리 1,733섹터의 복제**(1,730 동일). 부팅 보호 관행 |

- `CD001` 없음 — ISO9660 이 아니다. 로더는 **트랙 2 시작 = rel 0** 으로 세는 섹터 번호로 읽는다.
  ⚠ redump cue 의 INDEX 01 이 3,365 인데 IPL 블록은 **rel 1**(3,366)에 있다(rel 0 은 Hudson

- IPL: rel 2 부터 20섹터를 $4000 에 올리고 $4000 실행. 타이틀 「DRAGON SLAYER VI」(Hudson 내부명).
- 트랙 2 유저 데이터의 얼개(rel): 0~1 헤더 · 2~ 프로그램(오버레이 뱅크들, 4섹터=1뱅크) ·
  57/85/222/459~462/909/1617 에 시스템 문구·아이템표·몬스터 도감 **SJIS 평문** ·
  **1,252~1,683 시나리오 컨테이너**(아래 3절) · **~1,749~9,785 ADPCM**(음성, ~14MB) · 9,786~ 0.
  ⚠ 그래픽·맵·프로그램 오버레이의 정확한 경계는 아직 안 잡았다(「남은 일」).

### 2. 폰트 — 🔴 디스크에 없다. 시스템 카드 BIOS 의 12×12

인게임 대사·이름·메뉴가 전부 **12×12** 글꼴이다(스크린샷 실측). 글리프는 게임이 글자마다
BIOS `EX_GETFNT`($E060 → $F124)를 불러 받는다 — 실측 호출부(뱅크 0x6D 오버레이, 논리 $9301~):

```
$9301  LDA #$98 / STA $FA / LDA #$3A / STA $FB   ; _bx = $3A98  (출력 버퍼, RAM)
$939F  LDA #$01 / STA $FF                         ; _dh = 1     (12×12)
$93A3  JMP $E060                                  ; EX_GETFNT(_ax = SJIS 코드)
```

- 입력 `_ax`(=$20F8/$20F9) = SJIS 코드(문자열에서 상위 바이트를 먼저 읽어 $F9 에), 출력 = **32B
  버퍼(16행 × 2B, MSB 가 왼쪽)**에 12×12 를 얹어 준다. BIOS 안에서는 12×12 가 **18B 로 패킹**돼
  있고(`$F2CC` 가 32B 로 편다), 16×16(32B)도 따로 있다(`_dh` 비트0 = 0).
- ⇒ **후킹 자리는 `$93A3` 한 곳**(같은 패턴이 다른 오버레이에도 있는지는 「남은 일」).
  우리 루틴이 SJIS 코드(→ 한글 코드) 를 받아 RAM 의 한글 글리프를 같은 32B 형식으로 돌려주면
  나머지 타일 변환은 게임이 그대로 한다.
- 🔴 **자리가 문제다.** 한글 2,350자 × 24B(12×12) = 56KB = 뱅크 7개. SCD RAM 은 뱅크 0x68~0x7F
  (192KB) + 기본 0x80~0x87(64KB)인데 대사 장면에서 0x68~0x7F 전부에 뭔가 실려 있었고
  0x80~ 은 컨테이너 자리다(3절). 어느 뱅크가 **그 장면에서** 비는지 메모리 지도가 필요하다
  (「남은 일」). 후보: 사용률 낮은 뱅크(0x74·0x7C 는 절반 이상 0) · ADPCM RAM 64KB(음성과 충돌) ·
  BIOS 에 얹기(이스 IV 방식 — 실기 배포 조건이 는다).

### 3. 대본 — SJIS 평문 + 제어코드, LZ 컨테이너 23개에 씬 블록 214개

게임은 씬(맵)마다 **이벤트 코드 + 대본** 블록을 뱅크 0x76($8000~)에 풀어 놓는다. 그 블록은
디스크의 **컨테이너**(디렉터리 + LZ 블록들)에 있다 — 정본은 [`tools/containers.py`](../tools/containers.py).

```
컨테이너 = [디렉터리: 5B 항목 × n + FF][LZ 블록 …]      rel 1,252 부터 16섹터 간격, 23개
디렉터리 항목 = id(1B) src(2B, 컨테이너 시작 기준) len(2B, 풀린 길이)
LZ 블록 = 헤더 00 + 스트림 — tools/lz.py (플래그 1비트: 1=리터럴, 0=링 절대인덱스 1B + 길이 4비트+2
         링 256B 0 초기화, 쓰기 커서 0xEF 시작)
```

- 로더(오버레이 $479C, 모드 6 — 모드는 헤더<<3 | 6 로 고르고 다른 모드는 그래픽용)를 emucap 으로
  되짚어 옮겼고, 실측 블록(rel 1,252 id 2, 3,702B)과 **바이트 단위로 일치**한다. 인코더는
  `decode(encode(x)) == x` 로 묶여 있다(`tools/tests/test_lz.py`).
- 게임 쪽 색인: 그룹 번호($2061, 장?) → `$378D[]` 표 → 컨테이너가 실린 뱅크(0x68+0x10+표값,
  예 0x80). 씬 id 는 `$C009`(맵 헤더)로 디렉터리를 찾는다. **컨테이너를 어느 섹터에서 읽는지**는
  아직 안 잡았다(로더의 섹터 표 — 「남은 일」).
- 덤프 실측: 컨테이너 23 · 블록 318 · **고유 214**(같은 블록이 여러 컨테이너에 중복) ·
  SJIS **127,725자** · 화자 125종(兵士 190 · 男 123 · 道具屋 83 · 神父 80 · 老人 80 …).
  ⚠ rel 1,249 · 1,475 에도 디렉터리 모양이 있지만 블록 헤더가 쓰레기라 **옛 사본**으로 본다
  (id 목록이 1,284 · 1,556 과 같다). 게임이 정말 안 읽는지는 인게임으로 확인해야 한다.
- 씬 id 0 블록마다 **지명표**(47개 × 7칸 · `07` 구분)가 들어 있다.

제어코드(실측 빈도순): `00` 문장 끝 · `01` 개행 · `05` 페이지(대기) · `07` 구분/대기 ·
`04` 화자 끝 · `1F` 화자 시작(`1F 화자 04`) · `09 00` 주인공 화자? · `12` · `10 1E xx` 씬 안
분기/조건 머리? · `1E`. `07`·`09`·`10`·`12`·`1E` 의 뜻은 **아직 추정**이다 — 재삽입 전에
렌더러($92A0~ 근처)를 읽어 못 박는다.

### 4. 창 규격(스크린샷 실측)

대사창 3줄, 한 줄 12×12 글자 **12칸**(「おはようございます。」= 10자 + 여백), 화자 줄 따로.
줄바꿈은 대본의 `01` 이 정한다(자동 줄바꿈 여부 미확인). 이름칸은 12B 고정(`81 40` 패딩 +
`06` 종료 — 지명 「エルアスタ」 실측).

### 5. 에뮬 — emucap(mednafen pce), 디버거 전부 됨

```
launch_plan → launch  content_path = games/pce-ed1/work/emu/ed1.cue  system=pce
    (원본 cue 는 ISO 파일명이 대문자라 못 연다 — work/emu/ 에 하드링크 + cue 사본. syscard3.pce 는
     ~/.local/share/emucap/firmware/ 에 있어야 한다)
시스템 카드 화면 → run 탭 → 약 1,200프레임 뒤 오프닝 → run 한 번 더 → 타이틀(Beginning/Continue)
타이틀에서 run → 약 6,000~8,000프레임 뒤 첫 대사(「侍女 / おはようございます。」)
```

- 세이브스테이트: `work/emu/title.mcs`(타이틀) · `work/emu/dialog1.mcs`(첫 대사, 뱅크 0x76 에
  대본이 풀려 있는 상태). ⚠ 스테이트를 로드한 직후의 첫 `tap` 은 씹힐 수 있다 — 한 번 더.
- 브레이크포인트는 `physical`(뱅크×0x2000+오프셋) 로 건다. 쓰기 BP 는 BIOS 의 CD 전송
  루프($EA9C, `STA ($FA),Y`)에도 걸리므로 PC 로 거른다. 블록 전송(TII) 쓰기는 안 잡힐 수 있다.
- 메모리 타입: `physical`(2MB) · `ram`(8KB, ZP 는 $2000~) · `vram0` · `adpcm` · `bram`.

## 남은 일 (순서대로)

1. **컨테이너 로더의 섹터 표** — 게임이 그룹→섹터를 어떻게 얻나(오버레이 안의 표). 이게 있어야
   재조립한 컨테이너를 **같은 자리**에 되쓰거나 자리를 옮길 수 있다. 빈 섹터 지도(9,786~10,071 은
   0, 트랙 22 복제는 안 건드린다)도 같이.
2. **제어코드 의미 확정** — 렌더러를 읽어 `07 09 10 12 1E` 를 못 박는다. 자동 줄바꿈 유무 ·
   한 줄 최대 칸 · 한 페이지 줄 수.
3. **메모리 지도** — 대사 장면에서 비는 뱅크. 한글 글리프 56KB 의 자리.
4. **폰트 후킹 PoC** — `$93A3` 을 우리 루틴으로 돌려 한글 한 글자를 띄운다(PoC 는 「완성을
   막는 것」부터 — patcher-checklist 10-C). 오버레이가 여럿이면 호출부가 더 있는지 스캔.
5. **재삽입 파이프라인** — 씬 블록 재압축 → 컨테이너 재조립(디렉터리 갱신) → 섹터 쓰기 +
   EDC/ECC 재계산(MODE1 이라 필요) → 무변경 대조 → 되읽기 게이트.
6. 프로그램 오버레이·그래픽 영역 경계, 시스템 문구 6곳(rel 57 …)의 재삽입 규격.
7. 음성만 나가는 장면이 있는지(ADPCM 14MB) — kr 범위를 정한다.
