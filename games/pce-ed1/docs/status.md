### 2. 폰트 — 🔴 디스크에 없다. 시스템 카드 BIOS 의 12×12

인게임 대사·이름·메뉴가 전부 **12×12** 글꼴이다(스크린샷 실측). 글리프는 게임이 글자마다
BIOS `EX_GETFNT`($E060 → $F124)를 불러 받는다 — 실측 호출부(뱅크 0x6D 오버레이, 논리 $9301~):

```
$9301  LDA #$98 / STA $FA / LDA #$3A / STA $FB   ; _bx = $3A98  (출력 버퍼, RAM)
$939F  LDA #$01 / STA $FF                         ; _dh = 1     (12×12)
$93A3  JMP $E060                                  ; EX_GETFNT(_ax = SJIS 코드)
```

- 입력 `_ax`(=$20F8/$20F9) = SJIS 코드(문자열에서 상위 바이트를 먼저 읽어 $F9 에), 출력 = **32B
  버퍼(16행 × 2B, MSB 가 왼쪽)**에 12×12 를 얹어 준다. BIOS 안에서는 12×12 가 **18B 로 패킹**돼
  있고(`$F2CC` 가 32B 로 편다), 16×16(32B)도 따로 있다(`_dh` 비트0 = 0).
- **호출부는 디스크 전체에 18곳**(`4C/20 60 E0` 스캔): 본 프로그램 4(대사 `$7044`=뱅크 0x6C ·
  `$93A3`=0x6D 이름칸 · 0x6C+0xF5A · rel 99=0x78 초기 적재분) + IPL·타이틀·오프닝·모듈 450·898
  + 컨테이너 영역 3(압축 데이터 우연 일치일 가능성). 우리 루틴이 코드를 받아 RAM 의 한글 글리프를
  같은 32B 형식(**행 0~11, 2B/행, 비트 15~4 = 12픽셀**)으로 돌려주면 나머지 타일 변환은 게임이
  그대로 한다 — 대사 경로는 `$7047~` 가 그 32B 를 4비트씩 밀어 12px 셀 2개 = 타일 3개로 짠다.
- ✅ **가시성 PoC 통과(2026-09-05, `docs/img/poc1-hangul-dialog.png`).** 대사 그리기 호출부
  `$7044`(물리 0xD9044) 의 `JMP $E060` 을 RAM `$3F00` 의 루틴으로 돌리고(리드 바이트 `F0` 이면
  `$3F40` 의 32B 를 `($FA)` 에 복사, 아니면 BIOS 로), 병사 대사 첫 글자 `お`(0xEC6F6) 를 `F0 40`
  으로 바꿨더니 「한待ちください！！」 — Galmuri11 「한」이 제자리·제 모양으로 나왔고 이웃 글자·
  화자 줄이 멀쩡하다. **증명한 것**: 대사 경로에서 (코드 → 우리 글리프 → 게임 타일 변환 → 화면)이
  잇긴다, 리드 바이트 `F0` 이 인터프리터·렌더러를 통과한다. **증명 안 한 것**: 다른 17개 호출부 ·
  글리프 자리(`$3F00` 은 LZ 링 버퍼라 제품용이 아니다) · 인코딩 충돌 없음 · 폰트 완성도.
- 🔴 **자리가 문제다.** 한글 2,350자 × 24B(12×12) = 56KB = 뱅크 7개. SCD RAM 은 뱅크 0x68~0x7F
  (192KB) + 기본 0x80~0x87(64KB)인데 대사 장면에서 0x68~0x7F 전부에 뭔가 실려 있었고
  0x80~ 은 컨테이너 자리다(3절). 어느 뱅크가 **그 장면에서** 비는지 메모리 지도가 필요하다
  (「남은 일」). 후보: 사용률 낮은 뱅크(0x74·0x7C 는 절반 이상 0) · ADPCM RAM 64KB(음성과 충돌) ·
  BIOS 에 얹기(이스 IV 방식 — 실기 배포 조건이 는다).

### 3. 대본 — SJIS 평문 + 제어코드, LZ 컨테이너 23개에 씬 블록 214개

게임은 씬(맵)마다 **이벤트 코드 + 대본** 블록을 뱅크 0x76($8000~)에 풀어 놓는다. 그 블록은
디스크의 **컨테이너**(디렉터리 + LZ 블록들)에 있다 — 정본은 [`tools/containers.py`](../tools/containers.py).

```
컨테이너 = [디렉터리: 5B 항목 × n + FF][LZ 블록 …]      rel 1,252 부터 16섹터 간격, 23개
디렉터리 항목 = id(1B) src(2B, 컨테이너 시작 기준) len(2B, 풀린 길이)
LZ 블록 = 헤더 00 + 스트림 — tools/lz.py (플래그 1비트: 1=리터럴, 0=링 절대인덱스 1B + 길이 4비트+2
         링 256B 0 초기화, 쓰기 커서 0xEF 시작)
```

- 로더(오버레이 $479C, 모드 6 — 모드는 헤더<<3 | 6 로 고르고 다른 모드는 그래픽용)를 emucap 으로
  되짚어 옮겼고, 실측 블록(rel 1,252 id 2, 3,702B)과 **바이트 단위로 일치**한다. 인코더는
  `decode(encode(x)) == x` 로 묶여 있다(`tools/tests/test_lz.py`).
- **분모(참조표)** — 본 프로그램 뱅크 0x6A(=rel 42) `$6BF4` 의 3B 항목 `rec_lo rec_hi 섹터수`
  44개(장 `$C1B6` 별 시작 포인터 `$6BE8` + 장 안 지역 `$C010`), **rec = rel − 34**. 고유 24개가
  스캔 결과와 정확히 같다(`containers.py --check` 가 양쪽을 맞댄다). rel 1,249 · 1,475 의 디렉터리
  모양은 **표에 없고** 블록 헤더가 쓰레기다 — 옛 사본, 게임이 안 읽는다.
- 로더(`$56D8`, 본 프로그램): A = 섹터 수, X:Y = rec → `_dl:_dh` 에 +0x22 해서 CD_READ(모드 6,
  `_bl` = 목적 뱅크). **16뱅크 리소스 캐시**(0x78~0x87 = 0x68+0x10+슬롯)를 `$374C`(주인)·
  `$375C`(크기|0x80 머리)·`$376C/$377C`(rec) 표로 관리하고, 같은 rec 가 이미 있으면 **안 읽는다**
  (캐시 적중). 그룹(`$378D[0..9]`, 씬 텍스트는 그룹 `$61`)이 슬롯을 가리킨다. 7절.
- 덤프 실측: 컨테이너 24 · 블록 332 · **고유 220**(같은 블록이 여러 컨테이너에 중복) ·

  ⚠ 부피 라벨: **하한**이다 — 씬 컨테이너 밖의 문안(시스템 문구 6섹터 · 상점 대사처럼 프로그램
  코드 안에 박힌 SJIS(rel 222) · 전투·메뉴 문구 · 그래픽 글자)은 아직 셈에 없다.
- 씬 id 0 블록마다 **지명표**(47개 × 7칸 · `07` 구분)가 들어 있다.

**제어코드 — 인터프리터 실측(2026-09-05, 본 프로그램 뱅크 0x6C `$6712`, 점프표 `$67A4` 36개).**

  대본이 풀려 있는 상태) · `work/emu/overworld1.mcs`(필드). ⚠ 스테이트를 로드한 직후의 첫 `tap` 은
  씹힐 수 있다 — 한 번 더. ⚠ `field1.mcs` 는 ADPCM 재생 중이라 로드하면 멎는다(지웠다).
- 브레이크포인트는 `physical`(뱅크×0x2000+오프셋) 로 건다. 쓰기 BP 는 BIOS 의 CD 전송
  루프($EA9C, `STA ($FA),Y`)에도 걸리므로 PC 로 거른다. 블록 전송(TII) 쓰기는 안 잡힐 수 있다.
- 메모리 타입: `physical`(2MB) · `ram`(8KB, ZP 는 $2000~) · `vram0` · `adpcm` · `bram`.
- 버튼: `i` 대사 넘김·확정 · **`ii` 메뉴 열고 닫기** · `run` 시작 · 방향키는 `press_frames` 60~250.
  첫 전투는 성 → 마을 왼쪽 농부(ファーガソン) 이벤트 → 필드 첫 걸음에 난다.
- 🔴 **새 게임은 타이틀에서 `Beginning` 으로 연다.** 「Continue → 게임의 최초부터 시작」으로 열면
  첫 대사까지는 가는데 **그 뒤 캐릭터가 안 움직인다**(방향키·`i`·`ii` 전부 무반응, CPU 는 뱅크
  0x6B `$8F62` 부근을 돈다). **원본 디스크도 똑같다** — 차분으로 확인했으니 우리 탓이 아니라
  그 경로가 초기화를 건너뛰는 것이다. 오프닝을 건너뛰려다 한 회차를 통째로 날린다.
- 🔴 **스테이트로 우리 문안을 확인하지 말 것.** 시스템 문구·이름표는 CD RAM(뱅크 0x74·0x78)에
  부팅 때 올라오므로 **스테이트가 곧 옛 빌드**다 — 새 이미지로 껐다 켜도 스테이트를 로드하면 옛
  바이트가 그대로 복원된다(2026-09-06 실측: HUD 지명·메뉴 라벨이 통째로 일본어였다).
  빠르게 보려면 스테이트를 로드한 뒤 그 자리를 `write_memory` 로 덮는다 — 다만 **다시 그릴 때만**
  반영되므로(HUD 이름칸은 맵이 바뀔 때 그린다) 결론은 **깨끗한 부팅**으로 낸다.

### 7. 메모리 — 리소스 캐시가 꽉 차 있다 (한 장면 실측, 하한)

  BSS 로 본다 — 「0 이면 빈 자리」는 계약이 아니다).
- **피크 측정(2026-09-05, 타이틀→1장 첫 전투까지 CD_READ 마다 + 상태마다 표를 읽었다):**

| 상태 | 주인 있는 뱅크 | 비고 |
| --- | --- | --- |
| 오프닝 컷신 로드 중 | 3 → 10 → 11 | 초상화 1뱅크씩 슬롯 12~15 를 돌려 쓴다 |
| 첫 대사 · 성 안 · 마을 | **12** | 씬 컨테이너 4뱅크(슬롯 8~11) 포함 |

  ⇒ 관측 피크 **12**. 미측정: 던전(岬の洞窟) · 상점 · 장(章) 전환 · 엔딩 · 2장 이후 대형 맵.

  16→13 으로 줄인 뒤 실패를 소리 나게**(눈에 띄는 오류 화면·정지) 만든다. 넘치는 장면이 있으면

### 11-b-2. 전투 문구 — 뜯는 길은 섰고 **자리가 모자란다** (2026-09-06)

몬스터 이름과 같은 블록의 뒤쪽에 씬 문법 문구가 있다(「…が現れた。」·보스 대사). `battle.msg_units`
가 뜯고 `battle.patch_msgs` 가 되쓴다. 덤프는 `work/derived/battle/messages.json`(원문이라 커밋 금지).

**경계 잡는 법** — 둘을 겹쳐 쓴다:

- **범위**는 탐욕 스캔 — 글자와 사이에 낀 제어코드를 먹다가 종단을 만나면 끝.
  🔴 「≥0x24 면 글자」라는 **인터프리터 규칙을 스캔에 쓰면 안 된다**. 포인터 표(`40 C5 46 C5 …`)가
  글자로 읽혀 코드가 문구에 딸려 온다 — 실측 792단위 중 **391이 그런 쓰레기**였다.
  스캔은 **유효한(디코드되는) 전각 코드**만 글자로 센다 ⇒ 441단위 · 깨진 것 0.
  🔴 낀 제어코드는 **피연산자 없는 것만**이다 — `0F/10~15` 는 주소 2B 를 달고 다녀서, 글자로 먹으면
  되쓸 때 **점프 주소를 덮는다**(실측 「の左{0F}鞍」).
- **자르는 자리**는 코드의 분할 즉치(`LDA #lo/STA/LDA #hi/STA`)가 준다. 덩이 중간을 가리키면
  공유 조각이라 거기서 끊는다(sysmsg 와 같은 사정).
  ⚠ 표·계산 참조는 못 본다 ⇒ 되쓰기는 **자리를 안 옮기고 꼬리를 원본 바이트로 남긴다.**
  못 본 참조가 조각 중간을 가리켜도 최악이 「그 자리만 일본어」이지 우리 바이트 한복판이 아니다.
- 열쇠는 **제어코드를 포함한** 원문 해시다(sysmsg 는 빼고 만든다). 빼면 337 → 320 으로 뭉치는데,
  그 뭉침이 `{02}`(행위자 이름) 자리가 다른 단위를 같은 문안으로 묶어 **이름을 잃게** 한다.

**자리 — `0F` 이어쓰기로 풀렸다**(2026-09-06, 유저 지적에서 출발).

처음엔 「제자리에 들어가야 한다」로 보고 막혔다고 적었다. 338문구에 총 **9,814B**, 중앙값 25B(12자)인데
한국어가 여기선 일본어보다 길어서(「現れた」 3자 → 「나타났다」 4자) 「が現れた。」의 방 10B 에
자연스러운 「{조사} 나타났다.」(14B)가 안 들어간다.

⇒ 유저가 「길면 개행되지 않나」라고 물었고, 답은 **개행이 아니라 `0F`** 였다. 자동 줄바꿈(13칸)·
자동 페이지(4행)는 **표시** 문제라 애초에 막힌 적이 없고, 막힌 건 **저장 자리**였다. 그런데
sysmsg 가 이미 쓰는 `0F` 이어쓰기를 여기서도 쓸 수 있다 — **원본 전투 대본이 그렇게 쓰고 있다**
(실측: rel 194 blk12 두 자리에서 `0F` 가 대본 중간에서 다른 대본 자리로 뛴다).

**되쓰기 규칙** — 자리에 들어가면 제자리에, 넘치면 원래 자리엔 `0F <주소>` 셋만 남기고 **문안 전체를
블록 끝에 덧붙인다.** 블록의 풀린 길이는 디렉터리가 들고 있어 우리가 늘린다.
⇒ 제약이 「방 ≥ 문안 길이」에서 **「방 ≥ 3B」**로 바뀌었다 — 338 중 337이 통과한다(3B 미만이 하나).

**실측(1차 초벌 70문구 기준)**: 제자리 70 · `0F` 이어쓰기 102 · 자란 블록 58개 ·
가장 큰 블록 1,232B(상한 가설 2,826B). 한 블록이 최대 +133B 자랐다 — 여유가 넉넉하다.
⚠ 상한 2,826B 는 **가설**이다(원본에서 +0x400 위로 처음 0 이 아닌 자료가 +0xF0A). 「0 이니 빈 자리」는
계약이 아니다 — 전투 화면에서 뱅크 0x74 를 떠서 확정한다.

### 11-f. ADPCM 음성 추출 — 코덱·정렬·디스크 위치 **전부 확정** (2026-09-16/17 밤)

**넷 다 확정됐다**(마스터가 실제로 들어서 "오하요 세리오스" 를 알아들었다):

1. **니블 순서 = 하위(lo) 먼저.** 바이트 하나가 니블 2개(샘플 2개) — 하위 4비트가
   먼저 디코드된다.
2. **샘플레이트 = 레지스터 실측 `SampleFreq=14`** → `rate = 32087.5/(16-14) =
   16,043.75Hz`. ⚠ **재생 중(그 순간)의 레지스터를 읽어야 한다** — 재생 전후엔 0으로
   보인다(추측이 아니라 실측이어야 하는 이유).
3. **추출 위치 = 스트림 재생 초입의 `CD.RdAddr`~`CD.Length` 구간, 디코더 상태를
   그 자리에서 새로 시작.** ⚠ **ADPCM RAM(64KB)을 통째로 풀면 안 된다** — 링 버퍼라
   과거 재생분(찌꺼기)이 섞인다. 또 **에뮬을 진짜로 멈춰야 한다**(`pause()`) — 브레이크
   포인트 하나 지난 뒤 `resume()` 상태로 남아 있으면 연속 `get_state` 사이에도 값이
   계속 바뀐다("멈춘 줄 알았는데 돌고 있었다").
4. **디코더 = mednafen `src/sound/okiadpcm.{h,cpp}` 포팅(OKI MSM5205 호환) 그대로
   맞다** — 코덱 자체를 의심할 필요 없다.

**디스크 직접 추출 경로도 검산했다** — SCSI 저수준 명령 버퍼는 RAM `$224C`(디스어셈블로
확인, `LDA $224C,X`→`STA $1801` 루프로 CDB 를 한 바이트씩 내보낸다). 이번 클립의 CDB
첫 바이트는 `08 00 14 e8 20`(SCSI READ(6) 꼴: 옵코드 `08` · LBA `0x14E8`=5,352 ·
길이 `0x20`=32섹터). **그 LBA 를 그대로 우리 `rel` 좌표로 쓰면 안 된다** — 이건
**디스크 전체 기준 절대 LBA**(레드북 관습, LBA0=트랙1 시작)다. `rel = LBA − 3,590`
(트랙2 데이터 시작의 절대 LBA, `tools/common.py` 의 `T2_SECTOR` 값 3365 는 **파일
섹터**이고 이 3,590 은 **레드북 절대 LBA** — 서로 다른 축이니 섞지 않는다).

- **검산 방법**: ADPCM RAM 버퍼(성공한 그 클립)의 중간 조각(256B)을 데이터 트랙
  전체(rel 0~10,071)에서 바이트 패턴 검색 → **rel 1,762 에서 정확히 발견**(섹터
  경계에 딱 맞음). `common.track_data(1762, 32)` 로 32섹터(65,536B)를 뜨니 **ADPCM
  RAM 버퍼와 완전히 바이트 단위로 일치**(`match ratio 1.0`).
  ⇒ `rel = 5,352 − 3,590 = 1,762` — **공식이 정확히 들어맞는다.**
- ⇒ **앞으로 ADPCM 음성은 에뮬 없이 디스크에서 바로 뽑을 수 있다** — SCSI 명령(또는
  같은 지점의 `RdAddr`~`Length` 로 역산한 rel)만 알면 `common.track_data(rel, 32)`
  로 결정적으로 추출된다. **에뮬 타이밍에 안 흔들린다** — 레포 「빌드는 결정적이어야
  한다」 원칙과 맞는다.

**이 클립 자체(라이아스→세리오스 대사 목소리)** — `rel 1,762`, 32섹터, freq=14,
`.local/inbox/pce-ed1/D1-laias-nearstart-lonib-freq14-16044Hz-7.80s.wav`(정답).
청취 받아쓰기(STT)는 **아직 안 한다** — 소리를 다 모은 뒤 한 번에 한다(ss-ed3 파이프라인
재사용 예정).

**오늘 뒤집힌 전제 넷 — 다음에 같은 순서로 안 헤매려고 적는다:**

1. 「CD-DA 19트랙은 BGM 전용」— **실측이 아니라 가정**이었다(09-06 devlog 원문 추적,
   실제로 들어 본 적 없었다). ⇒ 옛 기록도 **"우리가 실측이라고 적었다"와 "진짜 실측"을
   구분해서 읽는다.
2. 「긴 시네마틱은 `CD.Playing` 전 구간 0 이라 무성」— **그 플래그는 ADPCM 전용**이라
   CD-DA 로 나는 음성은 원래 못 본다. "없다"가 아니라 "그 검사기가 그걸 못 본다"였다.
3. 「에뮬이 멈춰 있다(frozen)」— `resume()` 뒤 `pause()` 를 명시적으로 안 부르면
   **연속된 `get_state` 사이에도 실시간으로 계속 돈다.** "멈췄다고 표시된다"와 "진짜
   멈췄다"가 달랐다.
4. 「ADPCM RAM 을 통째로 뜨면 그 순간의 전체 클립이다」— **링 버퍼라 과거분이 섞인다.**
   `RdAddr`~`Length` 만 유효 구간이다.

⚠ **다음 수 — 오프닝(별하늘 시네마틱) 음성 위치를 찾는다.** 마스터가 그 장면에서도
음성을 들었는데 `CD.Playing` 이 그 구간 내내 0 이었다(09-16 (22) 재확인). 위 뒤집힌
전제 ②에 따라 **CD-DA 일 가능성이 크다** — 오프닝을 돌리며 `CD.Playing`(ADPCM)·SCSI
명령 버퍼(`$224C`, 옵코드로 ADPCM 데이터 읽기(`08`)와 CD-DA 재생 계열을 가른다)를
**촘촘히**(반드시 `pause()` 로 멈추고) 본다. **진행 중** — SCSI 명령 `D9`(CD-DA 계열로
추정)를 잡았고, 파라미터를 BCD MSF 로 풀면 **트랙19 시작 LBA 와 정확히 일치**했으나
마스터 청취로 트랙19·(D8=시작 가설의) 트랙18 둘 다 기각(각각 음악·길이초과) —
후보 트랙9·16 미확인 상태로 남음(devlog (35)(36) 참조).

🔴 **09-17 — 마스터 질문("디스크에 대본 데이터가 있나")에 답함**: 데이터 트랙

### 12. 동적 조사 훅 (2026-09-05, 유저 결정 「넣는다」)

이름·아이템이 런타임에 끼워지는 자리(`{02}`·`{0E}`)라 조사를 빌드가 못 고른다. **폰트 후킹 루틴 안에서**
푼다 — 코드 흐름은 그대로고 글리프 공급만 바뀐다(PS1 은 메시지 조립 앞에 훅을 걸어야 했다).

- **조사 코드** = 리드 `F9` + `0x24+종류`(은/는 · 이/가 · 을/를 · 과/와 · 으로/로 · 아/야 · 이랑/랑).
  리드 F9 는 글리프 배정에서 뺀다. 두 글자 조사는 첫 글자만 코드고 둘째는 보통 글자(`으로` → `F9 28` + `로`).
- **판정** = 루틴이 매 글자 끝에 코드를 `LAST`($3DA0)에 남기고, 조사 코드를 만나면 그 글자의 받침 비트맵을
  본다. 우리 글자가 아니면(숫자·일본어) **받침 있음**으로 폴백. `으로/로` 는 ㄹ 비트맵을 한 번 더 본다.
- **표**(빌드가 만들어 루틴 뒤에 싣는다): 조사 오프셋 28B($3C80) · 받침 비트맵 128B($3CA0) ·
  ㄹ 비트맵 128B($3D20). 글리프 인덱스당 1비트다.
- 문안 표기는 `은/는` 그대로 — `script/` 어디서나 쓴다(`font.encode` 가 토큰으로 본다).
- ✅ 검증: `tools/tests/test_hook.py` 가 **HuC6280 미니 인터프리터로 조립 결과를 돌린다**(받침·무받침·ㄹ·
  폴백·BIOS 폴백 5케이스). 인게임은 `docs/img/josa1-battle.png`(전투 문구 · `1Gold을` = 폴백 경로).
- ⚠ 아직 갈리는 걸 화면으로 본 건 폴백뿐이다 — 이름 뒤 은/는이 실제로 갈리는 장면(상태이상·아이템 획득)은
  QA 회차에서 본다.

   ### 09-15 (3) — ① 디스크 원좌표: VRAM 쓰기 BP 부정 결과, 여기서 멈춘다

   패턴 주소 공식을 정정했다 — `$380` 의 실제 VRAM 바이트는 `0xE000` 이 아니라 **`0xE020`**
