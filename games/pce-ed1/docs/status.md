### 2. 폰트 — 🔴 디스크에 없다. 시스템 카드 BIOS 의 12×12

인게임 대사·이름·메뉴가 전부 **12×12** 글꼴이다(스크린샷 실측). 글리프는 게임이 글자마다
BIOS `EX_GETFNT`($E060 → $F124)를 불러 받는다 — 실측 호출부(뱅크 0x6D 오버레이, 논리 $9301~):

```
$9301  LDA #$98 / STA $FA / LDA #$3A / STA $FB   ; _bx = $3A98  (출력 버퍼, RAM)
$939F  LDA #$01 / STA $FF                         ; _dh = 1     (12×12)
$93A3  JMP $E060                                  ; EX_GETFNT(_ax = SJIS 코드)
```

- 입력 `_ax`(=$20F8/$20F9) = SJIS 코드(문자열에서 상위 바이트를 먼저 읽어 $F9 에), 출력 = **32B
  버퍼(16행 × 2B, MSB 가 왼쪽)**에 12×12 를 얹어 준다. BIOS 안에서는 12×12 가 **18B 로 패킹**돼
  있고(`$F2CC` 가 32B 로 편다), 16×16(32B)도 따로 있다(`_dh` 비트0 = 0).
- **호출부는 디스크 전체에 18곳**(`4C/20 60 E0` 스캔): 본 프로그램 4(대사 `$7044`=뱅크 0x6C ·
  `$93A3`=0x6D 이름칸 · 0x6C+0xF5A · rel 99=0x78 초기 적재분) + IPL·타이틀·오프닝·모듈 450·898
  + 컨테이너 영역 3(압축 데이터 우연 일치일 가능성). 우리 루틴이 코드를 받아 RAM 의 한글 글리프를
  같은 32B 형식(**행 0~11, 2B/행, 비트 15~4 = 12픽셀**)으로 돌려주면 나머지 타일 변환은 게임이
  그대로 한다 — 대사 경로는 `$7047~` 가 그 32B 를 4비트씩 밀어 12px 셀 2개 = 타일 3개로 짠다.
- ✅ **가시성 PoC 통과(2026-09-05, `docs/img/poc1-hangul-dialog.png`).** 대사 그리기 호출부
  `$7044`(물리 0xD9044) 의 `JMP $E060` 을 RAM `$3F00` 의 루틴으로 돌리고(리드 바이트 `F0` 이면
  `$3F40` 의 32B 를 `($FA)` 에 복사, 아니면 BIOS 로), 병사 대사 첫 글자 `お`(0xEC6F6) 를 `F0 40`
  으로 바꿨더니 「한待ちください！！」 — Galmuri11 「한」이 제자리·제 모양으로 나왔고 이웃 글자·
  화자 줄이 멀쩡하다. **증명한 것**: 대사 경로에서 (코드 → 우리 글리프 → 게임 타일 변환 → 화면)이
  잇긴다, 리드 바이트 `F0` 이 인터프리터·렌더러를 통과한다. **증명 안 한 것**: 다른 17개 호출부 ·
  글리프 자리(`$3F00` 은 LZ 링 버퍼라 제품용이 아니다) · 인코딩 충돌 없음 · 폰트 완성도.
- 🔴 **자리가 문제다.** 한글 2,350자 × 24B(12×12) = 56KB = 뱅크 7개. SCD RAM 은 뱅크 0x68~0x7F
  (192KB) + 기본 0x80~0x87(64KB)인데 대사 장면에서 0x68~0x7F 전부에 뭔가 실려 있었고
  0x80~ 은 컨테이너 자리다(3절). 어느 뱅크가 **그 장면에서** 비는지 메모리 지도가 필요하다
  (「남은 일」). 후보: 사용률 낮은 뱅크(0x74·0x7C 는 절반 이상 0) · ADPCM RAM 64KB(음성과 충돌) ·
  BIOS 에 얹기(이스 IV 방식 — 실기 배포 조건이 는다).

### 3. 대본 — SJIS 평문 + 제어코드, LZ 컨테이너 23개에 씬 블록 214개

게임은 씬(맵)마다 **이벤트 코드 + 대본** 블록을 뱅크 0x76($8000~)에 풀어 놓는다. 그 블록은
디스크의 **컨테이너**(디렉터리 + LZ 블록들)에 있다 — 정본은 [`tools/containers.py`](../tools/containers.py).

```
컨테이너 = [디렉터리: 5B 항목 × n + FF][LZ 블록 …]      rel 1,252 부터 16섹터 간격, 23개
디렉터리 항목 = id(1B) src(2B, 컨테이너 시작 기준) len(2B, 풀린 길이)
LZ 블록 = 헤더 00 + 스트림 — tools/lz.py (플래그 1비트: 1=리터럴, 0=링 절대인덱스 1B + 길이 4비트+2
         링 256B 0 초기화, 쓰기 커서 0xEF 시작)
```

- 로더(오버레이 $479C, 모드 6 — 모드는 헤더<<3 | 6 로 고르고 다른 모드는 그래픽용)를 emucap 으로
  되짚어 옮겼고, 실측 블록(rel 1,252 id 2, 3,702B)과 **바이트 단위로 일치**한다. 인코더는
  `decode(encode(x)) == x` 로 묶여 있다(`tools/tests/test_lz.py`).
- **분모(참조표)** — 본 프로그램 뱅크 0x6A(=rel 42) `$6BF4` 의 3B 항목 `rec_lo rec_hi 섹터수`
  44개(장 `$C1B6` 별 시작 포인터 `$6BE8` + 장 안 지역 `$C010`), **rec = rel − 34**. 고유 24개가
  스캔 결과와 정확히 같다(`containers.py --check` 가 양쪽을 맞댄다). rel 1,249 · 1,475 의 디렉터리
  모양은 **표에 없고** 블록 헤더가 쓰레기다 — 옛 사본, 게임이 안 읽는다.
- 로더(`$56D8`, 본 프로그램): A = 섹터 수, X:Y = rec → `_dl:_dh` 에 +0x22 해서 CD_READ(모드 6,
  `_bl` = 목적 뱅크). **16뱅크 리소스 캐시**(0x78~0x87 = 0x68+0x10+슬롯)를 `$374C`(주인)·
  `$375C`(크기|0x80 머리)·`$376C/$377C`(rec) 표로 관리하고, 같은 rec 가 이미 있으면 **안 읽는다**
  (캐시 적중). 그룹(`$378D[0..9]`, 씬 텍스트는 그룹 `$61`)이 슬롯을 가리킨다. 7절.
- 덤프 실측: 컨테이너 24 · 블록 332 · **고유 220**(같은 블록이 여러 컨테이너에 중복) ·
  SJIS **132,834자** · 화자 125종(兵士 190 · 男 123 · 道具屋 83 · 神父 80 · 老人 80 …).
  ⚠ 부피 라벨: **하한**이다 — 씬 컨테이너 밖의 문안(시스템 문구 6섹터 · 상점 대사처럼 프로그램
  코드 안에 박힌 SJIS(rel 222) · 전투·메뉴 문구 · 그래픽 글자)은 아직 셈에 없다.
- 씬 id 0 블록마다 **지명표**(47개 × 7칸 · `07` 구분)가 들어 있다.

**제어코드 — 인터프리터 실측(2026-09-05, 본 프로그램 뱅크 0x6C `$6712`, 점프표 `$67A4` 36개).**
바이트 < 0x24 는 옵코드, ≥ 0x24 는 **2바이트 글자**(첫 바이트 → `$F9`, 둘째 → `$F8` → 그리기).
반각 가나·ASCII 는 없다 — 전각뿐. 스크립트 포인터는 ZP `$14/$15`(엔티티별 표 `$2F95/$2FE7`).

| 코드 | 뜻 | 근거 |
| --- | --- | --- |
| `00` | 문장 끝(키 대기 후 닫기) | `$6C08` |
| `01` | 줄바꿈(다음 글자 전에 적용) | `$6AB5` = `INC $CF15` |
| `03` | 페이지 대기(창 유지, 줄 끝이면 줄바꿈 먼저) | `$6B92` |
| `04` | 표시 모드 복원(= 화자 끝) | `$6D5F` ← `$8C` |
| `05` | 페이지 대기 + 지우기 | `$6BCD` |
| `06` `07` | 문장 끝 변형(07 은 줄 끝 처리 후) — 지명표의 구분자 | `$6D51` `$6D49` |
| `09 nn` | **공용 문구 nn 호출**(`$C330 + nn×64`, 되돌아온다) — `09 00` = 화자 「セリオス」 | `$6863` |
| `0F lo hi` | 점프 | `$6A34` |
| `10 lo hi` | 이벤트 서브루틴 호출(되돌아옴 `$91/$92`) — 텍스트 토큰 아님 | `$6A44` |
| `11/12 lo hi` | 플래그 조건 — 다음 3바이트(점프) 건너뜀 | `$6A13/$6A1A` |
| `13/14 lo hi` | 플래그 클리어/세트 | `$69F9/$6A09` |
| `15 lo hi` | 기계어 호출 | `$6A72` |
| `19`~`20` | 표시 모드 1~7 (`1F` = 6 = **화자 이름**, `1E` = 5) | `$6D63`~`$6D7B` |

- **자동 줄바꿈이 있다** — 열 `$38BB` ≥ `$99`(=**13**)이면 다음 글자 전에 줄을 바꾼다(단어 무시).
  **자동 페이지** — 행 `$38BC` ≥ `$9A`(=**4**)이면 키 대기 후 지운다. 화자 줄이 행 0 을 쓴다.
  ⇒ 창 = **4행 × 13칸**(화자 있으면 본문 3행). 우리 조판(krwrap)이 `01` 을 넣어 줄을 정하고,
  자동 줄바꿈에 걸리지 않게 13칸 이내로 맞춘다.
- 덤프에서 `[10][1E]ｨ…` 로 보이던 건 `10 1E A8`(서브루틴 호출)이다 — 토큰이 아니다.

### 4. 창 규격

대사창 **4행 × 13칸**(인터프리터 상수 `$99`=13 · `$9A`=4, 3절), 화자 줄이 행 0. 글자는 12×12.
지명·이름칸은 12B 고정(`81 40` 패딩 + `06` 종료 — 지명 「エルアスタ」 실측).
- 🔴 **화자 줄 밀림(실측 2026-09-05)**: 첫 줄이 10칸을 넘으면 화자 이름이 **(첫 줄 칸수 − 10) 칸**
  오른쪽으로 밀린다(10칸 → x=42 · 12칸 → 66 · 13칸 → 78, 코드 패치 유무와 무관 — 문안만 바꾼 빌드로
  확인). 기전은 아직 안 읽었다(측정 패스가 남긴 커서로 본다). ⇒ **조판 규칙: 화자가 있으면 첫 줄 ≤ 10칸**,
  2·3줄은 13칸. 기전을 읽어 풀 수 있으면 규칙을 넓힌다.
- 본문이 4줄이면 화자 줄이 위로 밀려 나간다 — 본문은 3줄까지.

  부팅 때 올라오므로 **스테이트가 곧 옛 빌드**다 — 새 이미지로 껐다 켜도 스테이트를 로드하면 옛
  바이트가 그대로 복원된다(2026-09-06 실측: HUD 지명·메뉴 라벨이 통째로 일본어였다).
  빠르게 보려면 스테이트를 로드한 뒤 그 자리를 `write_memory` 로 덮는다 — 다만 **다시 그릴 때만**

### 6. 프로그램 모듈과 CD 읽기(실측, `CD_READ` $E009 BP)

### 11-b. 전투 데이터 컨테이너 (2026-09-06) — 몬스터 이름

씬 컨테이너와 **형식이 다르다**. `tools/battle.py` 가 정본이고 게이트가 분모를 지킨다.

| | 씬 | 전투 |
| --- | --- | --- |
| 자리 | rel 1,252~1,620 (16섹터 간격) | **rel 162 · 170 · 178 · 186 · 194 · 202** (8섹터 간격) |
| 디렉터리 | 5B `id, src(2), 풀린길이(2)` + `FF` 끝 | 4B `src(2), 풀린길이(2)`, **끝 표시 없음** — 길이는 첫 src 가 준다 |
| 분모 | 24 · 332블록 · 고유 220 | **6 · 100블록 · 레코드 259 · 이름 224** |

- 블록을 풀면 **64B 몬스터 레코드**가 이어지고 `FF FF FF FF` 로 끝난다. 뒤에는 전투 코드와 씬 문법
  문구(「…が現れた。」)가 붙는다 — 그 문구는 아직 안 건드렸다(다음 할 일).
- 레코드 뒷칸 **16B 가 이름**이고 `이름 06` + 00 패딩이다 — 화자 레코드·HUD 지명과 같은 꼴.
- 🔴 **긴 이름은 간접이다** — 칸에 안 들어가면 `23 주소(2)` 로 블록 안 다른 자리를 가리키고 꼬리(`Ａ`)가
  뒤에 붙는다(「<긴 이름>Ａ」). 주소 기준은 블록이 올라가는 **$C400**(실측: 블록 +0x255 ↔ $C655).
  되쓸 때는 **대상 문자열만** 갈아 끼운다 — 칸을 인라인으로 바꾸면 「자이언트에이프Ａ」가 17B 라 안 들어간다.
- ⚠ **긴 이름 보관 칸을 레코드로 오독하기 쉽다**(실측 rel 186 blk9): 이름칸이 `42 0a ダークリッチ 06` 처럼
  보이는데 그건 앞 레코드 셋이 가리키는 **저장소**다. 파서는 둘째 바이트가 `<0x20` 이면 표가 끝났다고 본다.
- 표기 정본은 `shared/glossary`(monster · person) — 224 전부 붙었다. ⚠ 대조는 **정규화해서** 한다:
  PCE 는 장음을 `－`(전각 하이픈)로 적고 사전엔 PS1 시절 **반각 가나**(`ｷｬﾘｵﾝ ｸﾛｰﾗｰ`)가 섞여 있다.
  `battle._norm` 이 NFKC + 공백·`・` 제거 + 하이픈→`ー` 로 맞춘다.
- 🔴 **PS1 과 원문이 갈린 자리 셋** — PCE 는 `サンダーバウンド`·`バーストバウンド` 인데 PS1 표는 `…ﾊｳﾝﾄﾞ`(hound)다.
  각 판의 원문을 그대로 옮겼다(선더바운드 · 버스트바운드) — **유저 확인 대기**. `ジャーデインゾンビ` 는 새 이름.
- 되쓰기는 **풀린 길이를 안 바꾼다**(레코드가 고정폭). 압축 크기만 바뀌므로 컨테이너를 다시 깐다 —
  칸은 **원본이 쓰던 섹터 수**다(로더가 그만큼만 읽는다). 실측 재압축은 원본보다 작거나 같다.
- 되읽기 게이트는 **바이트 대조**다(`battle.verify`) — 우리 코드(리드 F0~F8)는 SJIS 가 아니라 이름 파서가
  못 읽는다. 블록 전체를 바이트로 대조하면 파서 없이 「푼 결과가 뜻대로인가」가 닫힌다.

### 11-d. 음성과 음악 (조사 2026-09-06, 유저 요청)

**디스크 구성**(원본 cue 실측) — 우리 도구가 여태 훑던 `rel 0~1,760` 은 데이터 트랙의 **일부**였다.

| 트랙 | 종류 | 크기 | 무엇 |
| --- | --- | --- | --- |
| 1 | AUDIO | 44초 | 리드인(PCE CD 관례) |
| **2** | **MODE1/2352** | **10,297섹터 ≈ 20MB(유저 데이터)** | 프로그램·대본·그래픽 + **ADPCM 음성** |
| 3~21 | AUDIO (CD-DA) | 19트랙 ≈ 58분 | 🔴 **BGM 이다 — 우리가 건드릴 것이 없다** |
| 22 | MODE1/2352 | 1,733섹터 | 트랙 2 머리 복제 |

- 트랙 2 안에서 프로그램·대본·그래픽은 대략 **rel 0~1,748**, 그 뒤 **약 8,550섹터(≈17MB)가 ADPCM**이다.
  ⚠ 음성은 뒤쪽에만 있는 게 아니다 — 프롤로그 음성은 **rel 674**(32섹터)로 앞쪽에 끼어 있다(6절).
- **적재 경로(실측)** — BIOS `CD_READ`($E009) 호출 시 제로페이지가 인자다:
  `_al`($F8) = **섹터 수** · `_dh`($FF) = **0xFF 면 ADPCM 행**. 살아 있는 화면에서 확인했다 —
  오프닝 모듈 적재가 `_al`=0x77(119, rel 514 와 일치) · 프롤로그 음성이 `_al`=0x20(32) + `_dh`=0xFF.
  ⇒ **QA 재현법**: `$E009` 에 exec BP → 걸릴 때마다 `ram` 의 `$F8`·`$FF` 를 읽는다.
- 🔴 **오프닝은 자막이 없다** — 「Beginning」 뒤 애니메이션 프롤로그를 끝까지 돌렸는데 **글자 창이
  한 번도 안 뜬다**(용·바다·인물 컷이 이어지고 바로 첫 대사로 넘어간다). 음성만 나가므로
  **kr 범위 밖**이다 — 자막을 넣는 건 번역이 아니라 **mod** 다(루트 ROADMAP). 라이아스 컷신과 같다.
- ⚠ **실패한 접근을 적어 둔다** — 「4B 로드 레코드(rec 3B + 섹터수)」 꼴로 트랙을 훑어 음성 색인표를
  찾으려 했더니 후보가 **162개** 나왔고 대부분 같은 값이 반복되는 **압축 데이터 우연**이었다.
  정적 패턴으로는 못 가른다 — 위 **런타임 탐침**이 정본이다.

### 11-c. 씬 밖 문안의 분모 (전수 스캔 2026-09-06)

데이터 트랙 rel 0~1,760 을 SJIS 로 훑어 **화면에 나갈 수 있는 글**을 자리별로 셌다. 남은 일의 근거다.

| 자리 | 무엇 | 상태 |
| --- | --- | --- |
| rel 0 | 허드슨 저작권 고지(부팅 첫 화면) | **안 건드린다** — 법적 고지 |
| rel 34~129 | 본 프로그램(11절 여덟 가족) | ✅ 완료 |
| rel 162~209 | 전투 컨테이너 — 몬스터 이름 224 | ✅ 완료 · 전투 문구는 남았다 |
| rel 210~256 | 씬 문법 **평문**(상점·마을 대사) — 압축 컨테이너와 **같은 문안**이 여기 또 있다 | ❓ **살았나 죽었나 미확정** |
| rel 455~465 | 도감·사운드 테스트 — 몬스터 설명 ~280건(HP 수치 포함) | 미착수 |
| rel 517 | 오프닝 **성우 크레딧** 14줄(`声優出演` + 이름 13) | 미착수 — 아래 |
| rel 1,252~1,620 | 씬 컨테이너 220 | 1건 완역 |
| rel 909 | **엔딩 스태프롤** — 성우 14 + 제작진 약 60, 2,241B(`0x1A` 종단) | 미착수 — 아래 |
| rel 1,629 | 엔딩 **타이틀 카드** 「終章 / そして / 英雄たち / の伝説 / 完」 | 씬 컨테이너 rel 1,620 **안**이다 — 씬 번역에 딸려 온다 |

- ❓ **rel 210~256 의 평문 사본** — 참조표(rec = rel − 34)는 rel 1,252~1,620 만 가리키고, 첫 대사 씬은
  압축본에서 나오는 걸 인게임으로 확인했다. 그런데 같은 문안이 여기 평문으로 또 있다. 죽은 자료(옛 빌드
  잔재)일 가능성이 크지만 **증명이 아니다.** 판정법: 한 회차 내내 `CD_READ`($E009)를 잡아 이 구간 섹터가
  한 번이라도 읽히는지 본다. 읽히면 번역 분모가 그만큼 는다.
- **오프닝 크레딧**은 모듈 rel 514 안이고 그 모듈에 **자기 `EX_GETFNT` 호출부**가 있다(rel 514 +0x1CE1).
  한글로 내려면 오프닝 모듈에도 글리프·후킹을 심어야 한다 — 오프닝이 본 프로그램(rel 34)보다 **먼저**
  돌아 우리 스텁이 아직 안 깔렸기 때문이다. 값(일본 성우 이름)에 비해 판이 커서 **뒤로 미룬다.**
- **타이틀 화면**(rel 322)의 Beginning/Continue 는 **그림**이고 **원래 영문**이라 할 일이 아니다.
- **엔딩 스태프롤**(rel 909, 모듈 rel 898 안 오프셋 0x5A25~0x62E5) — 탭(`09`)·CRLF(`0D 0A`)·
  강조 여닫이(`1B`/`1D`)가 섞인 **평문**이고 `0x1A` 로 끝난다. 바로 뒤가 그래픽이라 **여유가 없다**
  (2,241B 안에 들어가야 한다). 렌더러는 엔딩 모듈의 `EX_GETFNT` 호출 두 곳(+0x56B3 · +0x57CC).
  ⚠ 오프닝과 **같은 물음**이 걸린다 — 그 모듈이 돌 때 우리 글리프 뱅크(0x85~0x87)와 루틴($3B00)이
  살아 있나. 엔딩은 본 프로그램 **뒤에** 도므로 오프닝보다 유리하지만 증명이 필요하다.
  ⚠ 사람 이름(성우·제작진)을 한글로 옮길지는 **유저 판단**이 필요하다 — 실존 인물 표기라
  옮겨 적으면 틀릴 위험이 있고, 그대로 두면 크레딧만 일본어로 남는다.


### 12. 동적 조사 훅 (2026-09-05, 유저 결정 「넣는다」)

이름·아이템이 런타임에 끼워지는 자리(`{02}`·`{0E}`)라 조사를 빌드가 못 고른다. **폰트 후킹 루틴 안에서**
푼다 — 코드 흐름은 그대로고 글리프 공급만 바뀐다(PS1 은 메시지 조립 앞에 훅을 걸어야 했다).

- **조사 코드** = 리드 `F9` + `0x24+종류`(은/는 · 이/가 · 을/를 · 과/와 · 으로/로 · 아/야 · 이랑/랑).
  리드 F9 는 글리프 배정에서 뺀다. 두 글자 조사는 첫 글자만 코드고 둘째는 보통 글자(`으로` → `F9 28` + `로`).
- **판정** = 루틴이 매 글자 끝에 코드를 `LAST`($3DA0)에 남기고, 조사 코드를 만나면 그 글자의 받침 비트맵을
  본다. 우리 글자가 아니면(숫자·일본어) **받침 있음**으로 폴백. `으로/로` 는 ㄹ 비트맵을 한 번 더 본다.
- **표**(빌드가 만들어 루틴 뒤에 싣는다): 조사 오프셋 28B($3C80) · 받침 비트맵 128B($3CA0) ·
  ㄹ 비트맵 128B($3D20). 글리프 인덱스당 1비트다.
- 문안 표기는 `은/는` 그대로 — `script/` 어디서나 쓴다(`font.encode` 가 토큰으로 본다).
- ✅ 검증: `tools/tests/test_hook.py` 가 **HuC6280 미니 인터프리터로 조립 결과를 돌린다**(받침·무받침·ㄹ·
  폴백·BIOS 폴백 5케이스). 인게임은 `docs/img/josa1-battle.png`(전투 문구 · `1Gold을` = 폴백 경로).
- ⚠ 아직 갈리는 걸 화면으로 본 건 폴백뿐이다 — 이름 뒤 은/는이 실제로 갈리는 장면(상태이상·아이템 획득)은
  QA 회차에서 본다.

   읽히는지 본다. 읽히면 번역 분모가 는다. **씬 번역을 크게 벌이기 전에 답이 나와야 한다.**

   눈에 띄게 만들어야 판단이 선다.
