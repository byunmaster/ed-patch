## 나레이션 ON 대사창 넘김 커서(▽) 숨기기 (마스터 10-16 「나래이션 일때 대사창 커서도 안나오게」) — 시험 롬 확인, 제품 반영, 마스터 확인 대기

- **코드 읽기** — 커서는 엔진(뱅크 0x6C) 엔티티다: `$6C8D` 가 만들고(`$3559,X` 비트7 켬 · `$3509,X`=`$62`), 대기 루프가 매 프레임 `JSR $6CC3` 으로 `$3559,X` 비트6 을 16프레임마다 뒤집어 깜빡인다(비트6=1 이 꺼진 쪽, 실측으로 확인: 보일 때 `$83`). 처음 시도한 `STA $3509,X`(애니메이션 번호) 무력화는 ▽ 를 못 껐다(실측 — RAM 패치 후에도 보임).

X 는 원래 루틴이 남긴 커서 번호, A·Y 는 호출부가 쓰므로 원래 결과와 같은 꼴. 다섯째 `JSR $6CC3`(`$736C`)은 자막 모드 경로가 아니라 안 건드렸다. 단위 테스트 `test_blink_hides_cursor_in_subtitle_mode`(플래그 0/1) · CPU 모의에 `ORA #imm` 추가.

## 디버그 — 마스터용 사용법 (마스터 10-17 「다 쓸 수 있었으면 해. 인게임 QA 할 때 도움될 듯」)

원판 게임이 원래 가진 **부팅 단축 입력**입니다(우리가 만든 게 아니고, 한글 패치 ROM 에서도 똑같이 됩니다). 새 기능·새 코드 없이 바로 씁니다.

**쓰는 법** — ① 게임을 켜서 시스템 카드 화면(「PUSH RUN BUTTON」)이 뜨면 **RUN 을 눌렀다 뗍니다**(RUN 을 쥔 채로 두면 안 됩니다). ② 곧바로 아래 표의 **버튼 조합을 2~3초 쥔 채** 기다립니다(로딩이 끝나 화면이 뜰 때까지 쥐고 있어도 됩니다). 에뮬이면 키 설정에서 I·II·RUN·SELECT·방향키가 어느 키인지 먼저 확인하세요.

| 하고 싶은 것 | 누르는 조합 | 나오는 화면 | 실기 패드로 가능? |
| --- | --- | --- | --- |
| 타이틀·오프닝 건너뛰고 이어하기 | I | 저장 파일 선택 화면(슬롯을 고르면 필드) | 가능 |
| 음악 듣기·몬스터 도감 | ↑ + SELECT + I + II | 오마케 메뉴 | 가능 |
| 오프닝만 보기 | ← + → + I | 오프닝 | **불가**(← → 동시 입력 — 에뮬 전용) |
| 엔딩만 보기 | ← + → + II | 엔딩(보스·파티 컷부터) | **불가**(에뮬 전용) |
| 극장(오마케 극장) | ← + → + I + II | 극장 | **불가**(에뮬 전용) |

- **인게임 QA 에 쓸모 있는 것**: 「I 단독」(타이틀·오프닝 없이 곧바로 세이브 로드 — 매번 오프닝을 안 봐도 됩니다)과 「오프닝/엔딩 직행」(자막 확인용). 엔딩은 끝까지 가는 데 오래 걸립니다.
- 주의: RUN 과 SELECT 를 같이 누르면 카드 화면으로 **리셋**됩니다. 위 조합에는 RUN 이 없습니다.
- 주의: 세이브스테이트로 문안을 확인하면 옛 빌드가 복원됩니다(문안은 새로 부팅해서 확인). 단축은 새 부팅에서 씁니다.
- 디버그 메뉴·치트 메뉴는 이 게임에 **없습니다**(전수 조사 결과 — 아래 분석 절). 실기에서 ← → 직행이 필요하면 별도 진입로(안 A~D)를 마스터가 고르셔야 합니다.
- 에이전트용 절차(emucap 프레임 수)는 바로 아래 「디버그 빌드/테스트 단축」 절.

## 디버그·숨은 기능 분석 (10-16, 마스터 「디버그모드 먼저 분석」) — ROM 무변경, 진입로 안은 마스터 선택 대기

실측(원판 에뮬)과 코드 읽기를 갈라 적는다. 캡처: `.local/work/inbox/pce-ed1/debug/`.

- **디버그 메뉴·개발자 문구 없음**(코드 읽기) — 트랙·컨테이너 24개 ASCII·SJIS·반각 카나 키워드 약 30종 0건, 개발 RAM 뱅크($F0~F7) 게이트 없음.
- **IPL 부팅 패드 표**(IPL rel 2, 표 `$408E`, 5바이트 항목 `[패드, $FC, $FD, $FE, $F8 섹터수]` → 로더 스텁 `$2648`, 패드 = `$2228`; I=01 II=02 SELECT=04 RUN=08 ↑10 →20 ↓40 ←80). 실측: RUN 을 먼저 눌러 카드를 넘기고 떼고 → 조합을 약 200프레임 쥔다(SELECT+RUN 은 카드 리셋).

  | 조합 | 목적지 | 실측 |
  | --- | --- | --- |
  | 없음 | rel 322 ×100 타이틀 | 정상 |
  | I | rel 34 ×96 메인 직행 | **저장 파일 선택 화면으로 직행**(타이틀·오프닝 생략) — 슬롯 1 로드까지 정상(10-16 재실측, 옛 「카드로 튕김」 기록은 정정) |
  | ↑+SELECT+I+II | rel 450 ×16 오마케 | 원판·현재 KR ROM 모두 열림(실기 패드로 가능) |
  | ←+→+I | rel 514 ×119 오프닝 직행 | 타이틀 건너뜀 |
  | ←+→+II | rel 898 ×128 엔딩 직행 | 보스·파티 컷부터 |
  | ←+→+I+II | rel 706 ×64 극장 | 오마케 극장 |

  🔴 **←+→ 동시 입력은 실기 패드로 불가능** — 오프닝·엔딩·극장 직행은 에뮬 전용이다.
- **오마케 화면 목록** — 최상위 「음악을 들려줘」「몬스터 도감」, 음악 14곡+전부+돌아가기(재생 중엔 L/R dB 레벨미터 패널이 뜬다 — 정상 기능, 숨은 게 아님), 도감 = 장 선택(제1~5장·종장·돌아가기)→페이지(이름·HP→설명문, 다음/이전 페이지·돌아가기). 도감은 조우와 무관하게 전 몬스터를 보여 준다.
- **「か？か？」 정정** — 트랙 전체에 SJIS 로 없고, 오마케 모듈의 「？」 문자열은 장 선택 문구뿐이다. 10-14 오마케 보고의 「못 만난 몬스터는 か？か？」 는 RAM 장면에서 본 것을 덧붙인 미확인 추정이었다. 정상 플레이에서 그런 표시는 없다(표본 안 본 페이지에 잔여 가능성은 작다).
- **0x1A 잔재**(코드 읽기+BP 실측) — 오마케 모듈 offset 0x447A(실행 `$847A`)에 `LDA $222D; CMP #$1A` → `LDX #$20; LDY #$C8; SEC; JSR $4F1B` — ↑+RUN+II 동시 입력. 최상위 메뉴·장 선택·음악 화면·도감 페이지에서 BP(`$8454`·`$8477`·`$8481`)가 한 번도 안 걸렸고 음악 화면 RAM 엔 이 코드가 올라와 있지 않다. 정적 호출·포인터 참조도 없다 → **도달 불가 잔재로 보이나 확정 아님**.
- **진입로 안(마스터 선택 대기, 구현 안 함)** — A 문서 안내만(↑+SELECT+I+II 오마케, 위험 0) · B 타이틀 모듈(rel 322, `$222D`)에 실기 패드로 눌리는 숨은 입력 추가해 오마케·직행 모듈로 분기(위험: 타이틀 코드 패치 · 직행 시 초기 상태가 안 맞으면 카드로 튕김 — I 직행과 같은 부류) · C IPL 표 ←+→ 항목을 ↑/↓+SELECT 계열로 교체(단순하나 IPL 오타 시 부팅 불능·RUN 먼저 절차) · D 클리어 후 해금(UI·플래그 설계 큼). 추천 A 즉시 + 필요하면 B.
- **I 단독 직행 정정(실측)**: 메인 프로그램이 곧바로 파일 선택 화면을 띄우고 슬롯 1 을 고르면 필드가 정상으로 열린다 — 직행 시 초기 상태 문제는 이 경로에선 없었다(B 안 위험 하나 감소). 이전 「카드로 튕김」은 재현 안 됨(그때 입력·세이브 상태가 달랐던 것으로 추정, 미확인). `$4090` 은 BIOS 소프트 리셋 벡터(SELECT+RUN) 루틴으로 메인 루프가 `$00` bit5 를 보고 `JMP $E000` 한다 — 이 경로의 BP 는 안 걸렸다.
- 🔴 **개발용 프로파일러·MPR 덤프 코드가 남아 있다**(코드 읽기, 실행 확인 안 함) — 메인 프로그램 rel 99 구역(뱅크 0x78 → 실행 `$8000+`, 파일 오프셋 0x20800~)의 `0123456789ABCDEF` 표 곁에 문자열 「MPR=## ## ## ## ## ## ## ##」 와 `TMA #$01…#$80` 로 MPR 8개를 읽어 16진 출력하는 루틴(`$8DBE`)이 있다. 이를 부르는 `$8CE0` 루틴은 메인 루프(`$402E`)와 **같은 서브루틴 순서**(`$4BAD`·`$8D87`·`$4F87`·`$434C`·`$409D`·`$416B`·`$4093`)를 돌면서 사이사이에 `$8D78`/`$8D87`(VCE 색 레지스터 `$0402~$0405` 쓰기 — 구간별 CPU 시간을 색 막대로 재는 래스터 프로파일러로 보인다)과 MPR 덤프를 끼우고, 이어 vsync 대기(`$E063`) 후 I 버튼(`$222D` bit0)로 한 스텝씩 넘기며 `$9026`·`$9077`·`$911F`·`$90CF`·`$8F3A`·`$8F54`·`$8E4F`(표시 루틴)를 부르는 루프다. **이 루틴(`$8CE0`)을 부르는 코드·포인터는 어디에도 없다**(정적, main 전체 검색) → 사다리가 끊긴 개발 도구 잔재. 일반 유저 진입로로 쓰려면 호출부를 만들어야 하고 화면 문구는 영어 ASCII(「MPR=」 한 줄)뿐이라 번역 대상이 아니다. 같은 `0123456789ABCDEF` 표가 rel 709+0x316(극장 모듈)에도 있다 — 같은 서브루틴 사본(미확인).
- ✅ **`$8CE0` 프로파일러 강제 실행(실측, 원판)** — I 직행으로 파일 선택 화면까지 간 뒤 RAM 스텁(`$5FC0`, 빈 구역 — `$416E` 의 `LDA $24; CMP $01` 4바이트를 `JMP $5FC0` 으로 갈아 한 번만 `JSR $8CE0`)으로 호출했다. **돈다**: 화면이 검은 바탕에 붉은 줄무늬(VCE 색·VRAM 덮어씀)로 바뀌고, **I 를 한 번 누를 때마다 왼쪽 아래에 「)」 한 개씩 늘어난다**(1→2→3, 한 스텝 = 한 프레임 처리). 「MPR=」 줄은 이 시도에선 안 보였다 — 파일 선택 화면의 타일·팔레트 위에 억지로 얹은 호출이라 도구가 기대한 화면 설정이 없다(미확인: 깨끗한 환경에선 보일 수 있음). 캡처 `.local/work/inbox/pce-ed1/debug/profiler-{1..6}*.png`. 일반 유저에게 줄 가치는 없다(영어·깨진 화면, 번역 대상 아님).
- **극장 모듈 사본 아님(정적)** — rel 706 에는 `0123456789ABCDEF` 표만 있고 「MPR=」 은 메인에만 한 번(rel 99 구역). 극장 쪽 표 뒤는 10진 변환(`CMP #$64` 등) 숫자 출력 루틴이라 프로파일러가 아니라 숫자 표시 보조다. 타이틀(322)·오마케(450)·오프닝(514)·엔딩(898)에는 표 자체가 없다.
- **남은 확인**: ② 0x1A 루틴이 올라오는 화면(도달 불가 잔재 추정 유지).

## 디버그 빌드/테스트 단축 — emucap 에서 쓰는 순서 (마스터 10-16 「테스트용 디버그 빌드는 지금, 사용자용 진입로·번역은 나중」)

이 게임엔 디버그 메뉴가 없고 새로 만들 것도 없다. 원판이 가진 **IPL 부팅 패드 표**가 곧 테스트 단축이다(제품 KR ROM 에서도 같다 — 오마케는 실측).

```
launch(원판 work/emu/ed1.cue 또는 KR 빌드) → pause
step 240                       # 시스템 카드 「PUSH RUN BUTTON」 화면(프레임 ≈ 590)
tap run  press_frames 5 after_frames 2     # 카드 통과, RUN 을 반드시 뗀다
tap <조합> press_frames 200 after_frames 0 # IPL 이 패드를 읽는 동안 쥐고 있는다
step 300                       # 로딩이 끝나 화면이 뜬다
```

| 쓰고 싶은 것 | 조합(`tap buttons`) | 도착 화면 |
| --- | --- | --- |
| 타이틀 없이 이어하기 | `["i"]` | 저장 파일 선택 → 슬롯 선택(I)으로 필드. 세이브가 있어야 한다 |
| 오마케(음악·도감) | `["up","select","i","ii"]` | 오마케 최상위 메뉴 |
| 오프닝 직행 | `["left","right","i"]` | 오프닝(용 장면부터) |
| 엔딩 직행 | `["left","right","ii"]` | 엔딩(보스·파티 컷부터) |
| 극장 | `["left","right","i","ii"]` | 오마케 극장 |

- ⚠ **RUN 을 쥔 채 SELECT 를 누르면 카드 리셋**이다 — 위 순서처럼 RUN 은 먼저 눌러 떼고 조합을 쥔다. RUN+SELECT 동시는 쓰지 않는다.
- ⚠ **←+→ 는 실기 패드로 못 누른다** — 오프닝·엔딩·극장은 에뮬 전용 단축이다(일반 유저 진입로는 나중, 마스터 판정).
- ⚠ 세이브스테이트로 문안을 확인하지 않는다(루트 규칙). 단축은 **새 부팅**에서 쓴다. 엔딩을 보려면 그 뒤 화면이 끝까지 가는 데 오래 걸린다 — `step` 은 5000 이하로 끊는다.
- 임의 코드 호출(개발용 프로파일러 `$8CE0` 시험): 위 순서로 I 직행 파일 선택까지 간 뒤 `write_memory`(논리 주소, cpu)로 `$5FC0` 스텁(`LDA $5FE0; BNE; INC $5FE0; LDA #$78; TAM #$10; JSR $8CE0; LDA $24; CMP $01; JMP $4172`)과 `$5FE0=00`, `$416E` 를 `4C C0 5F EA` 로 쓴다. 재현 바이트는 devlog 10-16.

### 2. 폰트 — 🔴 디스크에 없다. 시스템 카드 BIOS 의 12×12

인게임 대사·이름·메뉴가 전부 **12×12** 글꼴이다(스크린샷 실측). 글리프는 게임이 글자마다
BIOS `EX_GETFNT`($E060 → $F124)를 불러 받는다 — 실측 호출부(뱅크 0x6D 오버레이, 논리 $9301~):

```
$9301  LDA #$98 / STA $FA / LDA #$3A / STA $FB   ; _bx = $3A98  (출력 버퍼, RAM)
$939F  LDA #$01 / STA $FF                         ; _dh = 1     (12×12)
$93A3  JMP $E060                                  ; EX_GETFNT(_ax = SJIS 코드)
```

- 입력 `_ax`(=$20F8/$20F9) = SJIS 코드(문자열에서 상위 바이트를 먼저 읽어 $F9 에), 출력 = **32B
  버퍼(16행 × 2B, MSB 가 왼쪽)**에 12×12 를 얹어 준다. BIOS 안에서는 12×12 가 **18B 로 패킹**돼
  있고(`$F2CC` 가 32B 로 편다), 16×16(32B)도 따로 있다(`_dh` 비트0 = 0).
- **호출부는 디스크 전체에 18곳**(`4C/20 60 E0` 스캔): 본 프로그램 4(대사 `$7044`=뱅크 0x6C ·
  `$93A3`=0x6D 이름칸 · 0x6C+0xF5A · rel 99=0x78 초기 적재분) + IPL·타이틀·오프닝·모듈 450·898
  + 컨테이너 영역 3(압축 데이터 우연 일치일 가능성). 우리 루틴이 코드를 받아 RAM 의 한글 글리프를
  같은 32B 형식(**행 0~11, 2B/행, 비트 15~4 = 12픽셀**)으로 돌려주면 나머지 타일 변환은 게임이
  그대로 한다 — 대사 경로는 `$7047~` 가 그 32B 를 4비트씩 밀어 12px 셀 2개 = 타일 3개로 짠다.

  `$7044`(물리 0xD9044) 의 `JMP $E060` 을 RAM `$3F00` 의 루틴으로 돌리고(리드 바이트 `F0` 이면

### 3-b. 씬 블록 재삽입 구조 (10-11 — 마스터 「구조문제 해결해」)

번역을 전량 넣자 세 구조가 한꺼번에 터졌다. 전부 `tools/build.py`·`messages.py`·`glyphdyn.py` 가 푼다(회귀 테스트 `test_assemble` · `test_pinned_split` · `test_glyphdyn`).

### 5. 에뮬 — emucap(mednafen pce), 디버거 전부 됨

- 세이브스테이트: `work/emu/title.mcs`(타이틀) · `work/emu/dialog1.mcs`(첫 대사, 뱅크 0x76 에
  대본이 풀려 있는 상태) · `work/emu/overworld1.mcs`(필드). ⚠ 스테이트를 로드한 직후의 첫 `tap` 은

  첫 대사까지는 가는데 **그 뒤 캐릭터가 안 움직인다**(방향키·`i`·`ii` 전부 무반응, CPU 는 뱅크
  0x6B `$8F62` 부근을 돈다). **원본 디스크도 똑같다** — 차분으로 확인했으니 우리 탓이 아니라
  그 경로가 초기화를 건너뛰는 것이다. 오프닝을 건너뛰려다 한 회차를 통째로 날린다.
- 🔴 **스테이트로 우리 문안을 확인하지 말 것.** 시스템 문구·이름표는 CD RAM(뱅크 0x74·0x78)에
  부팅 때 올라오므로 **스테이트가 곧 옛 빌드**다 — 새 이미지로 껐다 켜도 스테이트를 로드하면 옛
  바이트가 그대로 복원된다(2026-09-06 실측: HUD 지명·메뉴 라벨이 통째로 일본어였다).
  빠르게 보려면 스테이트를 로드한 뒤 그 자리를 `write_memory` 로 덮는다 — 다만 **다시 그릴 때만**
  반영되므로(HUD 이름칸은 맵이 바뀔 때 그린다) 결론은 **깨끗한 부팅**으로 낸다.

### 7. 메모리 — 리소스 캐시가 꽉 차 있다 (한 장면 실측, 하한)

첫 대사 장면(`work/emu/dialog1.mcs`)에서 캐시 표를 읽었다:

```
슬롯(뱅크)  0(78) 1 2 | 3(7B) | 4(7C) 5 6 7 | 8(80) 9 10 11 | 12(84) | 13(85) 14(86) 15(87)
주인        80  ─  ─  |  없음  | 85 81 82 83 | 84 ─  ─  ─    |  86    | 없음   없음   없음
크기        3뱅크     | 1      | 1  1  1  1  | 4(컨테이너)   |  1     | 1      1      1
```

- **주인이 있는 뱅크 12 / 16.** 주인 없는(비울 수 있는) 4뱅크 = 슬롯 3·13·14·15.
- 본 프로그램 영역 0x68~0x77 은 코드·표·씬 버퍼(0x76)라 빈 뱅크가 없다(0x74·0x7C 의 0 은
  BSS 로 본다 — 「0 이면 빈 자리」는 계약이 아니다).
- **피크 측정(2026-09-05, 타이틀→1장 첫 전투까지 CD_READ 마다 + 상태마다 표를 읽었다):**

| 상태 | 주인 있는 뱅크 | 비고 |
| --- | --- | --- |
| 오프닝 컷신 로드 중 | 3 → 10 → 11 | 초상화 1뱅크씩 슬롯 12~15 를 돌려 쓴다 |
| 첫 대사 · 성 안 · 마을 | **12** | 씬 컨테이너 4뱅크(슬롯 8~11) 포함 |
| 메뉴(呪文…その他) · 強さ 화면 | 12 | 메뉴는 디스크를 안 읽는다 |
| 필드(오버월드) | 12 | 표가 바이트 단위로 같다 — 필드 자원은 캐시 밖에 상주 |
| 전투(슬라임) | 12 | 전투 코드는 본 프로그램 영역 0x72~0x75, **CD 읽기 0회** |

  16→13 으로 줄인 뒤 실패를 소리 나게**(눈에 띄는 오류 화면·정지) 만든다. 넘치는 장면이 있으면
  QA 회차에서 그 자리에서 드러나고, 그때 C(장별 동적)로 내려간다(8절 재검토 트리거).

### 11-b-2. 전투 문구 — 자리는 `0F` 이어쓰기로 풀렸다 (2026-09-06, 10-07 전량 347)

몬스터 이름과 같은 블록의 뒤쪽에 씬 문법 문구가 있다(「…が現れた。」·보스 대사). `battle.msg_units`

**경계 잡는 법** — 둘을 겹쳐 쓴다:

- **범위**는 탐욕 스캔 — 글자와 사이에 낀 제어코드를 먹다가 종단을 만나면 끝.
  🔴 「≥0x24 면 글자」라는 **인터프리터 규칙을 스캔에 쓰면 안 된다**. 포인터 표(`40 C5 46 C5 …`)가
  글자로 읽혀 코드가 문구에 딸려 온다 — 실측 792단위 중 **391이 그런 쓰레기**였다.
  스캔은 **유효한(디코드되는) 전각 코드**만 글자로 센다 ⇒ 441단위 · 깨진 것 0.
  🔴 낀 제어코드는 **피연산자 없는 것만**이다 — `0F/10~15` 는 주소 2B 를 달고 다녀서, 글자로 먹으면
  되쓸 때 **점프 주소를 덮는다**(실측 「の左{0F}鞍」).
- **자르는 자리**는 코드의 분할 즉치(`LDA #lo/STA/LDA #hi/STA`)가 준다. 덩이 중간을 가리키면
  공유 조각이라 거기서 끊는다(sysmsg 와 같은 사정).
  ⚠ 표·계산 참조는 못 본다 ⇒ 되쓰기는 **자리를 안 옮긴다.** `0F` 로 옮긴 문구의 남은 원래 자리는 **10-07 부터 0 으로
  지운다**(죽은 원문이 컨테이너 칸을 넘겼다 — 처음엔 「못 본 참조가 가리켜도 그 자리만 일본어」라며 원문을 남겼다).
- 열쇠는 **제어코드를 포함한** 원문 해시다(sysmsg 는 빼고 만든다). 빼면 337 → 320 으로 뭉치는데,
  그 뭉침이 `{02}`(행위자 이름) 자리가 다른 단위를 같은 문안으로 묶어 **이름을 잃게** 한다.

**자리 — `0F` 이어쓰기로 풀렸다**(2026-09-06, 유저 지적에서 출발).

처음엔 「제자리에 들어가야 한다」로 보고 막혔다고 적었다. 338문구에 총 **9,814B**, 중앙값 25B(12자)인데
한국어가 여기선 일본어보다 길어서(「現れた」 3자 → 「나타났다」 4자) 「が現れた。」의 방 10B 에
자연스러운 「{조사} 나타났다.」(14B)가 안 들어간다.

⇒ 유저가 「길면 개행되지 않나」라고 물었고, 답은 **개행이 아니라 `0F`** 였다. 자동 줄바꿈(13칸)·
자동 페이지(4행)는 **표시** 문제라 애초에 막힌 적이 없고, 막힌 건 **저장 자리**였다. 그런데
sysmsg 가 이미 쓰는 `0F` 이어쓰기를 여기서도 쓸 수 있다 — **원본 전투 대본이 그렇게 쓰고 있다**
(실측: rel 194 blk12 두 자리에서 `0F` 가 대본 중간에서 다른 대본 자리로 뛴다).

**되쓰기 규칙** — 자리에 들어가면 제자리에, 넘치면 원래 자리엔 `0F <주소>` 셋만 남기고 **문안 전체를
블록 끝에 덧붙인다.** 블록의 풀린 길이는 디렉터리가 들고 있어 우리가 늘린다.
⇒ 제약이 「방 ≥ 문안 길이」에서 **「방 ≥ 3B」**로 바뀌었다 — 338 중 337이 통과한다(3B 미만이 하나).

**실측(1차 초벌 70문구 기준)**: 제자리 70 · `0F` 이어쓰기 102 · 자란 블록 58개 ·
가장 큰 블록 1,232B(상한 가설 2,826B). 한 블록이 최대 +133B 자랐다 — 여유가 넉넉하다.
⚠ 블록 성장 상한은 **실측 1,792B**(`battle.SAFE_UNPACKED`, 슬라임전 뱅크 0x74 덤프 — 가설 2,826B 보다 1,000B 좁았다).
한 전투에서 잰 값이라 큰 전투에서 다시 잰다. 10-07 전량(347)도 이 안에 든다(빌드 검사).

### 11-f. ADPCM 음성 추출 — 코덱·정렬·디스크 위치 **전부 확정** (2026-09-16/17 밤)

**넷 다 확정됐다**(마스터가 실제로 들어서 "오하요 세리오스" 를 알아들었다):

1. **니블 순서 = 하위(lo) 먼저.** 바이트 하나가 니블 2개(샘플 2개) — 하위 4비트가
   먼저 디코드된다.
2. **샘플레이트 = 레지스터 실측 `SampleFreq=14`** → `rate = 32087.5/(16-14) =
   16,043.75Hz`. ⚠ **재생 중(그 순간)의 레지스터를 읽어야 한다** — 재생 전후엔 0으로
   보인다(추측이 아니라 실측이어야 하는 이유).
3. **추출 위치 = 스트림 재생 초입의 `CD.RdAddr`~`CD.Length` 구간, 디코더 상태를
   그 자리에서 새로 시작.** ⚠ **ADPCM RAM(64KB)을 통째로 풀면 안 된다** — 링 버퍼라
   과거 재생분(찌꺼기)이 섞인다. 또 **에뮬을 진짜로 멈춰야 한다**(`pause()`) — 브레이크
   포인트 하나 지난 뒤 `resume()` 상태로 남아 있으면 연속 `get_state` 사이에도 값이
   계속 바뀐다("멈춘 줄 알았는데 돌고 있었다").
4. **디코더 = mednafen `src/sound/okiadpcm.{h,cpp}` 포팅(OKI MSM5205 호환) 그대로
   맞다** — 코덱 자체를 의심할 필요 없다.

**디스크 직접 추출 경로도 검산했다** — SCSI 저수준 명령 버퍼는 RAM `$224C`(디스어셈블로
확인, `LDA $224C,X`→`STA $1801` 루프로 CDB 를 한 바이트씩 내보낸다). 이번 클립의 CDB
첫 바이트는 `08 00 14 e8 20`(SCSI READ(6) 꼴: 옵코드 `08` · LBA `0x14E8`=5,352 ·
길이 `0x20`=32섹터). **그 LBA 를 그대로 우리 `rel` 좌표로 쓰면 안 된다** — 이건
**디스크 전체 기준 절대 LBA**(레드북 관습, LBA0=트랙1 시작)다. `rel = LBA − 3,590`
(트랙2 데이터 시작의 절대 LBA, `tools/common.py` 의 `T2_SECTOR` 값 3365 는 **파일
섹터**이고 이 3,590 은 **레드북 절대 LBA** — 서로 다른 축이니 섞지 않는다).

- **검산 방법**: ADPCM RAM 버퍼(성공한 그 클립)의 중간 조각(256B)을 데이터 트랙
  전체(rel 0~10,071)에서 바이트 패턴 검색 → **rel 1,762 에서 정확히 발견**(섹터
  경계에 딱 맞음). `common.track_data(1762, 32)` 로 32섹터(65,536B)를 뜨니 **ADPCM
  RAM 버퍼와 완전히 바이트 단위로 일치**(`match ratio 1.0`).
  ⇒ `rel = 5,352 − 3,590 = 1,762` — **공식이 정확히 들어맞는다.**
- ⇒ **앞으로 ADPCM 음성은 에뮬 없이 디스크에서 바로 뽑을 수 있다** — SCSI 명령(또는
  같은 지점의 `RdAddr`~`Length` 로 역산한 rel)만 알면 `common.track_data(rel, 32)`
  로 결정적으로 추출된다. **에뮬 타이밍에 안 흔들린다** — 레포 「빌드는 결정적이어야
  한다」 원칙과 맞는다.

**이 클립 자체(라이아스→세리오스 대사 목소리)** — `rel 1,762`, 32섹터, freq=14,
`.local/work/inbox/pce-ed1/D1-laias-nearstart-lonib-freq14-16044Hz-7.80s.wav`(정답).
청취 받아쓰기(STT)는 **아직 안 한다** — 소리를 다 모은 뒤 한 번에 한다(ss-ed3 파이프라인
재사용 예정).

**오늘 뒤집힌 전제 넷 — 다음에 같은 순서로 안 헤매려고 적는다:**

1. 「CD-DA 19트랙은 BGM 전용」— **실측이 아니라 가정**이었다(09-06 devlog 원문 추적,
   실제로 들어 본 적 없었다). ⇒ 옛 기록도 **"우리가 실측이라고 적었다"와 "진짜 실측"을
   구분해서 읽는다.
2. 「긴 시네마틱은 `CD.Playing` 전 구간 0 이라 무성」— **그 플래그는 ADPCM 전용**이라
   CD-DA 로 나는 음성은 원래 못 본다. "없다"가 아니라 "그 검사기가 그걸 못 본다"였다.
3. 「에뮬이 멈춰 있다(frozen)」— `resume()` 뒤 `pause()` 를 명시적으로 안 부르면
   **연속된 `get_state` 사이에도 실시간으로 계속 돈다.** "멈췄다고 표시된다"와 "진짜
   멈췄다"가 달랐다.
4. 「ADPCM RAM 을 통째로 뜨면 그 순간의 전체 클립이다」— **링 버퍼라 과거분이 섞인다.**

⚠ **다음 수 — 오프닝(별하늘 시네마틱) 음성 위치를 찾는다.** 마스터가 그 장면에서도

### 12. 동적 조사 훅 (2026-09-05, 유저 결정 「넣는다」)

이름·아이템이 런타임에 끼워지는 자리(`{02}`·`{0E}`)라 조사를 빌드가 못 고른다. **폰트 후킹 루틴 안에서**

  본다. 우리 글자가 아니면(숫자·일본어) **받침 있음**으로 폴백. `으로/로` 는 ㄹ 비트맵을 한 번 더 본다.
- **표**(빌드가 만들어 루틴 뒤에 싣는다): 조사 오프셋 28B($3C80) · 받침 비트맵 128B($3CA0) ·
  ㄹ 비트맵 128B($3D20). 글리프 인덱스당 1비트다.
- 문안 표기는 `은/는` 그대로 — `script/` 어디서나 쓴다(`font.encode` 가 토큰으로 본다).
