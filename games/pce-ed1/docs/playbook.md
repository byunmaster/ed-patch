### emucap 으로 굴릴 때

- 🔴 **`tap` 은 안 먹는다.** `input_control` → `pulse_while_running` 을 쓴다.
  ⚠ **정확히는 「필드 이동」만 안 먹는다** — 메뉴 커서·대사 넘김은 `tap` 으로 된다(2026-10-05 재확인).
  이걸 섞어 「입력이 안 먹으니 게임이 굳었다」로 읽으면 **오진**이다 — 라이아스 컷신 뒤 「9분 멈춤」이
  실은 플레이어 이동 대기였다(policy.md 나레이션 절). 굳었다고 적기 전에 펄스로 한 걸음 걸어 본다.
  - 버튼 한 번 = **10~12프레임** · 이동 한 칸 = **40~70프레임**(짧으면 안 움직인다)
- **어트랙트(로고·별밤)는 `step` 으로 넘긴다** — 그 구간엔 입력이 튕긴다.
- 전투 한 판 ≈ **1,300~1,400프레임**. 승리창까지 그 정도 `step` 하면 된다.
- 전투 메시지는 **글자 훅 `$261C`(`hook.MARK_ADDR`)에 실행 BP** 를 걸고 걸으면 첫 글자에서 멈춘다 — BP 를 풀고
  `tap` 빈 입력으로 40~60프레임씩 넘기며 찍으면 등장·공격·회심·승리가 다 잡힌다(10-07).
- ⚠ **정본 세이브는 자동 전투다** — 커맨드 창(공격·주문·…·도망)이 안 뜬다. 커맨드 창·도망은 자동을 끈 세이브가 필요하다.
- ⚠ **캡처로 글자를 판정하지 않는다** — 341×232 라 `ㅏ`/`ㅣ` 가 안 갈린다. 확대하거나 바이트를 댄다.
- ⚠ 빌드를 갈면 **프로세스를 죽이고 다시 띄운다**(mednafen 디스크 캐시).
- ⚠ 실행 중 `write_memory` 는 **첫 바이트를 놓치는 경합**이 있다 — 쓴 직후 되읽어 확인한다.

## 마스터 mednafen 상태(`/root/save/pce-ed1/state/*.mednafen`)를 emucap 에 올리기 (11-18)

🔴 마스터 상태는 **gzip 압축본**이다 — emucap `load_state` 는 비압축 native 상태만 받아 「invalid snapshot history record」로 거절한다(롬 탓이 아니다, 11-17 에 두 번 막힌 원인). `gunzip -c <상태>.mednafen > <스크래치>/mcN.mc` 로 풀어 `load_state` 하면 어떤 시험 롬에서도 통과한다(롬이 달라도 됨).
⚠ 상태는 **마스터 빌드의 RAM(상주 코드·글리프·캐시)을 그대로 되살린다** — 결함 재현은 상태 그대로, 고침 확인은 맵 전환·씬 재입장으로 새 롬에서 다시 읽힌 뒤에만 판정한다.
⚠ 로드 직후 `screenshot` 은 `no_frame` — `step` 2~3프레임 뒤에 찍는다. 필드 이동은 `tap` 의 `press_frames` 40~90 으로도 움직인다(타일 한 칸 ≈ 30~40프레임). VRAM·BAT 는 상태 파일(`VRAM` 변수 열)을 직접 파싱해도 읽힌다(헤더 `MDFNSVST`, 이름 붙은 변수 열).

### 🔑 마스터 상태를 **새 롬에서** 다시 여는 길 — `tools/state2save.py` (11-18)
상태를 불러 새 코드를 시험할 수 없는 문제(옛 빌드 RAM)는 **상태 → 세이브**로 푼다: gunzip 한 `.mc` 의 `SysCardRAM` 구역(뱅크 0x68~)에서 뱅크 0x74 머리(게임 변수 `$C000~$C3FF`: 씬·좌표·깃발·파티·소지품)를 읽어 BRAM 세이브 슬롯으로 구워, **새(또는 원판) 롬을 콜드부트 → 이어하기**로 그 씬에 선다(맵·씬 블록·상주 코드는 롬이 새로 올린다).
```
python3 games/pce-ed1/tools/state2save.py <mcN.mc> --sav /root/save/pce-ed1/ed1.sav --out <스크래치>/sN.sav --slot 3
# emucap: launch(새 롬 또는 원판 `.local/cache/orig-pce/ed1.cue`) → pause → reset → write_memory(bram, 0, input_file={path:sN.sav,length:2048})
#         → step 2500 → tap run +1900 → tap run +1000 → right +30 → i +450 → down ×2(슬롯 3) → i +1400
```
- 씬 입장은 걷기 없이 된다 — `--fake`(savefile goto)가 필요 없고, 원판 롬으로도 같은 자리를 만들어 **원판/우리 대조**를 한다(11-18 mc7·mc8·mc9 확인).
- 이어하기 직후 입장 스크립트가 다시 돈다(씬 57 가르고 음성 자막은 약 1,400프레임 뒤에 뜬다). 필드 말 걸기는 `ii`·`ii`·`i`.
- **씬 57(유렐의동굴 — 어둠 원 · 창 겹침 시험, 11-21 실측)**: 세이브 `mc8` 의 슬롯 2 = 자유 이동 필드(파일 선택에서 `down` 1번), 슬롯 3 = 가르고 이벤트(`down` 2번). 🔴 파일 선택 커서 첫 자리는 상태마다 다르다 — 누르기 전에 화면을 한 번 찍는다.
  - 대사 창 겹침 구도(자유 필드, 프레임 수는 누름/뒤): 아래 = `up` 16/40 · 왼 = `left` 16/30 `up` 16/30 `right` 8/40 · 오른 = `right` 16/30 `up` 16/30 `left` 8/40 · 왼2 = `left` 8/30 `up` 16/40. 그 뒤 `ii`·`ii`·`i`. 긴 이동은 랜덤 조우가 난다 — 구도를 잡으면 상태를 저장한다.
  - **원 크기 = 횃불 타이머**(물리 0xE804A 2바이트): `40 03` 작은 원 · `80 05` 가운데 · `00 08` 큰 원 — 적고 **한 걸음** 걸어야 BG(어둠 타일)까지 따라온다. 개체 종류 바이트를 직접 덮어쓰면 BG 가 안 따라와 가짜 화면이 된다.
  - 가르고 이벤트(슬롯 3 로드 `i` 뒤 300프레임 기준): +700 음성 자막 · +1160 대사 창 · +1850 전투 화면 · +2100 전투 뒤 문구.
  - 버린다 확정 `i` 는 누름 3프레임(1프레임은 안 먹는다).
  - **버린다 확인 프레임 재기(11-21)**: 2장 필드 세이브(슬롯 3) → RAM `0x17A7`=1(조우 끔) → `ii`(10/60) → `down`×3 → `i`(4/90) = 버린다 목록. 커서를 품목에 두고 상태 저장 → `set_input [i]` 를 건 채 `step 2` = 확인 직전(목록 그대로), 그다음 `step 1` 마다 f0·f1·f2. 🔴 프레임 이름은 **목록 화면과 픽셀 차분 0 인 마지막 장 = 확인 직전**으로 맞춘다(전/후 묶음이 한 장 밀려 있었다). 한 숫자 계측: `$9D8B`(논리, exec BP) 에 멈춰 `VDC.Line` — 70 근처면 그 프레임에 옛 글자·틀 조각이 찍힌다(고친 뒤 54~56). 소지품 칸은 물리 `0xE8060 + n`(쓰기 전에 화면 목록과 덤프를 맞춰 본다), 아이템 표 꼬리[1] = 값의 10 지수(`sysstrings.read_fixed("items")`). 🔴 스테이트는 상주 뱅크 0x6F 의 옛 코드를 되살린다 — 새 롬 확인은 콜드 부팅 + BRAM.
  - 창 겹침 판정은 **창을 띄우기 직전 프레임과 띄운 프레임을 창 사각형 밖에서 픽셀 차분**(0px 이어야 한다). 스크린샷 ↔ SAT: y + 46 · x + 14.
- **장별 시작 세이브 + 디버그 W 재현(11-21)**: `python3 tools/savefile.py goto /root/save/pce-ed1/ed1.sav 0 --pick <N> --slot 3 --out <sav>` — pick 0 = 1장 · 16 = 2장 · 33 = 3장 · 53 = 4장 · 75 = 5장 · 84 = 종장. 부팅(`BRAM` 에 세이브 → `run`·`run`·`right`·`i` → **파일 선택 `down`×2 → `i`**, 로드 1400프레임) 뒤 필드에서 디버그는 **SELECT 단독 1초(누름 75프레임)**. 조우를 끄려면 RAM `0x17A7`=1(디버그 M ON 과 같다). 날개 목록의 모든 번호를 보려면 방문 깃발 물리 `0xE8178` ×8 을 FF 로. 목록은 연속 리스트라 `down`/`up` 이 쪽을 넘고 `left`/`right` 는 쪽 단위(끝에서 순환). 도착 판정은 **1500프레임 기다린 뒤 HUD 지명**(300프레임은 던전 적재에 모자라다).
- 폭이 안 맞는 값($C013·$C014·$C019·$C039 — 실행 중에만 쓰는 값)은 틀 슬롯 값을 둔다(도구가 알린다).
- 🔴 emucap `launch` 는 `launch_plan` 의 `indirect_media_approval` 을 그대로 받아야 한다. 롬을 바꿔 띄울 땐 `stop(launch_id)` 뒤 새로 `launch`.
- 🔴 틱(VBlank) 코드에서 SAT(VRAM `$7F00`)를 매 프레임 고치지 마라 — 게임 메인 스레드가 SAT 를 매 프레임 다시 쓰고(`$6555~$6589` 루프, 뱅크 0x69), 틱의 VDC 접근이 그 시퀀스와 엇갈리면 화면이 깨진다(11-18 시험 롬 `test-ring`).

## 세이브 — 어디에서 시작하나

- 유저 세이브: `/root/save/pce-ed1/ed1.<이미지해시>.sav` → emucap 홈의 `sav/` 로 복사한다
  (`scripts/emu.sh` 가 이미지 해시에 맞춰 이름을 대신 맞춘다).
  🔴 **`mcp__emucap-control__launch` 를 직접 부르면 이 동기화를 건너뛴다**(09-15 실측) —
  직접 launch 했을 땐 파일 선택 화면이 **셋 다 비어 보인다**(`ファイルがありません`) —
  세이브가 없는 게 아니라 안 실린 것이다. `scripts/emu.sh` 경로로 띄우거나, 안 되면 아래
  이름으로 emucap sav 폴더에 손수 복사한다.
  ⚠ **파일명 정정(09-15, 처음 적었던 `ed1-kr.<해시>` 는 틀렸다)** — mednafen 로그의
  `CD Layout: 0x<해시>`(모듈 로드 직후 한 줄)가 **정본 해시**이고, 접두어도 `ed1-kr` 이
  아니라 **드롭박스에 온 그대로 `ed1.<해시>`** 다. 즉 `/root/save/`에서 받은 파일을
  **이름을 안 바꾸고** `emucap_home/sav/`(포트별, 예:
  `~/.local/share/emucap/mednafen/<port>/sav/`)로 그대로 복사하면 된다. 헷갈리면 한 번
  launch 해서 `mednafen.log` 에서 `CD Layout:` 줄을 직접 확인한다 — **빌드를 안 바꾸면
  이 해시는 그대로**다(트랙 구조 기반이라 문안 패치로는 안 갈린다, 실측 재확인됨).
- **위치: 엘아스타 바로 남쪽 필드.** 1장, LV1, HP 30.
- 🔴 **2026-09-06(커밋 `ee4aa469`) 이전에 뜬 세이브는 파티 이름이 깨진다** — 글리프 배정을
  그때 정본으로 못 박았다. 그 전 세이브는 「서린온을」처럼 나온다. **새 세이브로 본다.**
- ⚠ **문안 검증에 세이브스테이트를 쓰지 않는다**(루트 CLAUDE.md) — 텍스트가 RAM 오버레이라
  스테이트가 곧 옛 빌드다. 리셋 + BRAM 정식 로드.

## 진행 순서 (1장, 실측 구간까지)

1. **새 게임** — 침실에서 시녀가 깨운다. 아래로 내려가며 이벤트가 이어진다.
2. 성 밖으로 나가려 하면 **병사가 막는다**(「라이아스 님께서 왕자님을 밖에 내보내지 말라고…」).
   계속 아래로 가면 대화가 이어지고 **퍼거슨**이 개구멍을 알려 준다.
3. 개구멍으로 마을 밖 → 필드. **여기가 유저 세이브 지점**이다.
4. 필드에서 **위로** 돌아가면 엘아스타 재입장 — **「라이아스」 씬**이 뜬다.
   🔴 예전 빌드는 여기서 굳었다(후킹 페이로드 자리 문제, 2026-09-07 수정). **지금은 정상이다** —
   굳으면 그건 새 결함이니 보고한다.
5. 그 뒤(2장 진입 · 상점 · 도감)는 **아직 안 가 봤다 — 미확인.**

## 막히는 자리 (알려진 것)

- **성문 병사** — 대화를 끝까지 봐야 개구멍이 열린다(2번).
- **필드 조우율** — 위 표. 메뉴를 열려면 마을로.
- **도망** — 전투 커맨드에서 `down`·`down`·`right`·`i` 로 「도망」인데, 실측에서 커서가
  공격으로 되돌아가 실패했다. **한 번 더 확인 필요(미확인).**
- 2장 이후 요구 레벨·열쇠 따위는 **미탐색**.

## 캡처 규율

확인한 칸은 **캡처를 남기고 경로를 보고에 적는다.** 둘 곳은 `.local/work/inbox/pce-ed1/`,

**캡처 없는 초록은 안 센다.** 화면을 못 잡는 칸은 스트림 동일성 같은 다른 근거를 댄다.

- **레지스탕스 장면(장1 씬3 필드 — 한 줄 스프라이트 넘침 · 이름판 숨김 시험, 11-21 실측)**: 세이브 = 마스터 상태 mc1 005539 를 `state2save` 로 슬롯 3 에 옮긴 것. 콜드 부팅 → BRAM 쓰기 → step 2500 → `run`(4/1900) → `run`(4/1000) → `right`(4/30) → `i`(4/400) → `down`(4/20) ×2 → `i`(4/1314) = 필드 정지(이름판 숨김 상태: `sat0` 첫 칸 y = 0).
  - 줄당 칸 수는 `sat0` 512B 를 읽어 센다(32폭 = 2칸, 속성 비트 8). 숨김 셈 = 물리 `0xE1BFE`(뱅크 0x70 +0x1BFE: 0xFF = 안 숨김, 0 = 숨김).
  - 메뉴 여는 프레임 재기: BP `$623E`(cpu, 논리) → `ii` 탭 → 멈춘 자리에서 `vram0` 바이트 0xFE00(SAT 첫 칸)과 `sat0` 을 같이 읽는다. `vram0` 이 켠 값(y = 0x60)이면 그 프레임의 BG 판 다시 쓰기는 스프라이트가 덮는다.
  - ⚠ 헤드리스 코어(pcehl)는 메뉴 여는 프레임의 타이밍이 mednafen 과 다르다(빈 판 한 프레임이 보일 수 있다) — 이 부류 판정은 mednafen 으로.
- **게임 안 LOAD 길(11-22)**: Ⅱ(4/60) → 메뉴 `down`×5(press 6/after 20)로 기타 → `i` → SAVE·LOAD… `down`(6/20) → `i`(4/90) → 슬롯 `down`×(슬롯−1) → `i` → 예 `i`(4/900). ⚠ **메뉴·부메뉴·슬롯 커서를 기억한다** — 두 번째부터는 `down` 이 모자라거나 넘쳐 리더로 간다. 매번 스크린샷으로 커서를 보고 누른다. `up` 은 press 6 이상.

### 패배(전멸) 강제 — 확인 문구·선택 창 보기 (11-22)
조우를 `write` BP 로 물리 `0xE805F`(조우 번호)에서 잡아 전투에 들어간 뒤, **파티 레코드(물리 `0xE8300 + 0x40×n`)의 HP 현재(+4)와 MP 현재(+8) 둘 다 0** 을 쓴다(HP 만 쓰면 소니아의 회복 주문이 되살린다). 한 판에 안 끝나면 다음 조우에서 남은 사람의 HP 를 한 번 더 쓴다. 패배 문구 → `i` 두 번 → 「마지막 들른 마을로 / 전투 직전으로」 → `i` → 「(지명)의 입구로 돌아갑니다.」 확인.
