## 디버그·개발 기능 분석 (마스터 10-16, 1차 — 롬 불변, 시험 롬 읽기만)

산출·캡처: `.local/work/inbox/ps1-ed3/debug/`(`maplist_443.tsv` 맵 표 · `printf_inventory.txt` · 실화면 캡처). **실측** = 에뮬 화면·BP 로 확인, **코드 읽기** = 정적 디스어셈블.

- **① printf 로그 — 화면으로 보는 길이 없다**(코드 읽기): `printf`=`fprintf(1,…)` 래퍼(SLPS_012.01 `0x8001E944`·ED3.EXE `0x80087B74`, 호출 107/80곳)는 stdout=콘솔 TTY 로 가고 그리는 길이 없다. **실측**: 새 게임까지 exec BP 로 a0 를 읽으니 ED3.EXE 가 `game system initialize` … `start status select:%d` … `game_program start`(열둘)·`CD Play`(BGM 마다)·`\XA\ED3B_0%dP.XA READ!!` 를 **조건 없이 찍는다**(mednafen 로그엔 안 남음). 나머지는 SDK 라이브러리 로그(ResetGraph·CD_init·xa_ini·SPU:T/O …). 인벤토리 `printf_inventory.txt`.
- **① 부팅 프로그램(SLPS_012.01)의 개발 로그는 플래그로 막혀 있다**(코드 읽기): `debug:E%d,M%x,R%d`·`ev(num,val)`·`t1/t2/t3`·`Chain #`·`Run #`·`MCLoad` 등은 전역 `0x80050594`(초기 0·코드로 쓰는 곳 0) 가 켜져야 찍힌다 — 켜는 길은 이진 패치(RAM 한 워드)뿐이며 켜도 TTY 다. `debug:E…` 덤프 함수 `0x8001834C` 는 직접 호출 0, 점프 표 `0x80037244`(9칸 중 8번째)에 있어 부팅 프로그램 안 작은 스크립트 VM 의 opcode 로 보인다(구동 데이터는 못 찾음, 미조사).
- **① 로더의 ABE·GAME2~4**(코드 읽기): 부팅 프로그램이 `gp+0x296`(0~4)로 다음 실행파일을 고른다 — ED3.EXE · `ABE\ABE.EXE` · `GAME2·3·4\MAIN.EXE`. 이 값을 쓰는 코드는 없고(초기 0 = ED3.EXE) **디스크에 해당 폴더도 없다**. 도달 불가.

- 코드 `0x0010~0x003E` 기호·숫자 대역이 아직 반쯤 비었다.

- 안 B 로 못 본 것: 약초(아이템 사용) 화면 · 부호 줄의 실기(해석기 테스트로만) — 세이브가 열리면 회귀로 본다.
