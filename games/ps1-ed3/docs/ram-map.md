# ED3 워크램 지도 (조사 중 — 10-08 밤 1차)

목적: 진행 세이브 없이 RAM 주입으로 도구·마법·상점·여관·전투 화면을 열어 UI 훑기·변수 조사 확인을 하는 것.
**상태: 소지품·골드·마법·맵 번호는 아직 못 찾았다**(아래 막힌 곳). 확정한 것과 레시피를 남긴다.

## 확정 (정적 + 실측)

| 무엇 | 주소 | 근거 |
|---|---|---|
| 메시지 VM 의 「현재 변수 번호」 바이트 | `0x800C1600` | `0x04`(아이템 이름)·`0x05`(숫자) 핸들러가 읽는다(`0x80038D74`·`0x80039174` 디스어셈블) |
| 아이템 이름 포인터 표 | `0x800A6734`(u16 `[번호]`) → 문자열 `0x800A682C + off` | `0x04` 핸들러 |
| 아이템 데이터 표(12B × 번호) | `0x800A6E84` | `0x05` 핸들러가 `lh [0x800A6E84 + 번호×12]` 를 숫자 표시기로 넘긴다 — **값 = 가격**(상점 문장 「…ピア」). 즉 `0x05` 숫자는 소지품이 아니라 **정적 표**에서 온다 |
| 숫자 그리기 | `0x8001BA38`(a0 = 창 핸들, a1 = 값, a2 = 색) — 10진 분해 후 창에 직접 그린다 | 디스어셈블. ⚠ **상태 패널의 숫자(LV·HP·골드)는 이 함수를 안 거친다**(exec BP 0회) |
| 글리프 업로드 | `LoadImage(0x8008A8DC)` rect `fp+0x40`, 데이터 링 `fp+0x58 + idx×84` | `root-cause.md` 8절 |
| 조작(필드) | **×(cross) = 말 걸기/조사 · ○(circle) = 필드 메뉴**, 방향키 이동 | 실측: 아버지에게 ×로 대사, ○로 필드 메뉴(상태 패널 + 5항목) |
| 필드 메뉴 | 전투설정 · 장비 · 도구 · 마법 · 시스템. 상태 패널(이름 LV HP MAX VP · **Goa/Pia 두 통화**) 상시 표시 | 캡처 `ui-sweep/`(원판도 같은 배치) |
| 장비 화면 | 능력치 열: 공격력·방어력·행운·민첩·지혜·마력·마법방어·경험치·남음·MP | 캡처(메뉴 → 장비) |

## 후보 (미확정 — 쓰기로 검증 실패)
- `0x800C05F8`: u16 `[HP=20][MAX=20]` 뒤에 `01 05 03 06 03 02 06`(레벨·능력치 일곱) — 장비 화면 값(5 3 6 3 2 · 6)과 **순서가 맞는다**. 상태 패널의 LV 1 / HP 20/20 / VP 100 과 일치하는 유일한 u16 쌍. `0x800C0630` 에 `0x64`(VP 100?).
  ⚠ **HP 를 10 으로 써도 패널이 안 바뀌었다** — 패널이 복사본·다른 구조체를 읽거나(저장 시점 캐시), 갱신 타이밍이 다르다. 쓴 뒤 메뉴를 닫고 다시 여는 것으로는 부족.
- `0x800B57A8`: u32 `[20][20]` — EXE 데이터 영역. 이 주소에 쓰자 **필드 메뉴(○)가 열리지 않게 됐다**(상태 되돌림 필요) → 입력/타이머 표일 수 있다. 건드리지 않는다.

## 막힌 곳 · 다음 수
1. **골드(Goa·Pia)·소지품·마법·맵 번호는 값이 0/미관찰이라 값 변화 탐색이 안 선다.** 값이 바뀌는 사건이 필요하다 — 상점 구매·획득 이벤트·이동. 프롤로그엔 없다.
2. **저장 데이터에서 거꾸로**: 세이브 블록(8KB, 데이터 `0x200` 부터)에 능력치 직렬화가 있다(`dc 22 00 00 14 00 01 04 02 06 03 02 06 …` — HP 20·레벨·능력치가 **바이트로 압축**). 저장 루틴(BIOS 카드 쓰기 직전의 버퍼 채우는 함수)에 exec BP → 그 함수가 읽는 RAM 주소가 곧 워크램 구조체다(소지품·골드·플래그 포함). **가장 유망한 길** — 세이브 화면까지 가는 것(시스템 → 세이브/로드 → 세이브)은 이미 된다(`ui-sweep/010`).
3. 필드 메뉴의 도구 항목 핸들러(`0x8003…`/`0x8002…` 근처 — 소지품 창 라벨 `0x9D0F6`)에서 소지품 배열을 읽는 `lw`/`lbu` 를 따라간다.
4. 상태 패널 그리기 함수를 exec BP 로 잡아(`LV`·`HP` 가 어디서 로드되는지) 구조체 주소를 확정 — `0x8001BA38` 은 아니었다. 후보: 대사 어셈블러 `0x800386AC` 계열이 숫자를 글자로 바꿔 쓴다(패널 숫자는 글리프 경로 — 숫자 글리프 코드 확인에도 쓸 수 있다).

## 레시피 (재현)
```
상태 파일: 새 빌드로 프롤로그를 넘겨(○ 연타 ~55) 전투설정 팝업까지 가서 ×로 닫는다 → save_state(field-free-house.state)
필드 메뉴: ○ · 말 걸기: 방향키로 마주 본 뒤 ×
RAM 덤프: save_state → .state 파일에서 `MainRAM.data8` 헤더 뒤 4바이트(크기) 다음 2MB 가 램(0x80000000 기준)
값 탐색: 파이썬으로 u16/u32 패턴(예: HP 20·20)을 램에서 찾고 → write_memory 로 값을 바꿔 화면 갱신을 본다
```
⚠ `write_memory` 주소는 **10진 정수**로 줘야 헷갈리지 않는다(16진 문자열도 되지만 손계산으로 `0x800C05F8` = 2148272632). 한 번 스택을 잘못 써서 상태를 다시 불러왔다.
