# 커서 줄(종류 4)에 반각 합성을 넣는 조사 — 2026-10-10 (구현 전, 다음 라운드 후보)

마스터 질문: 목록 창에서 커서가 놓인 줄만 반 칸 공백이 전각으로 남는다(square 창 실측). 그 경로에 안 B 훅을 걸어 **일반 반각**으로 통일할 수 있나.

## 1. 왜 커서 줄만 다른가 (확정 — 코드 주소·실측)

| | 일반 줄 | 커서가 놓인 줄 |
| --- | --- | --- |
| 그리는 함수 | `0x8001A40C` (문자열 → 글자 명령 **종류 1**) | `0x8001A7E8` (문자열 → 글자 명령 **종류 4**) |
| 실행기 | `0x80018758` 의 종류 1 핸들러 `0x800189CC`, **훅 자리 `0x80018ACC`** | 종류 4 핸들러 `0x800191C8` — 타일 N장을 슬롯에 `LoadImage`(`0x8008A8DC`)로 올릴 뿐(84B씩) |
| 글리프 → 타일 | 훅이 1bpp 18B 를 6px 단위로 합성해 타일을 고친다 | 글리프마다 `0x80019FE8`(→ `0x80018574`: 글리프 18B `FONT+코드×18` 를 확장표 `0x800A620C` 로 4bpp 72B 로) 뒤 `0x8001A080(버퍼, 종류 7·5·0xD, 색 0xC)` 로 **커서 테두리 타일 조각**(왼쪽 캡·가운데·오른쪽 캡)을 입힘 |
| 반각 | 훅이 먹는다 | **안 먹는다**(공백 = 12px) — 그래서 커서 줄이 6px 밀린다 |

실측: 7×4 창 앞 반 칸 공백 4개 → 커서 없는 줄 24px(정확), 커서가 놓인 줄 +6px. 커서를 옮겨 찍어야 보인다(캡처 한 장으론 안 보인다).

## 2. 이 경로를 쓰는 창

`0x8001A7E8` 직접 호출자 41곳, 그 중 **목록 항목 그리기 `0x8002F04C`**(커서 번호와 같은 항목만 종류 4, 나머지는 `0x8001A40C`)를 부르는 함수 11개:
`0x8002F328 · 0x8002F4DC · 0x80030EE0 · 0x80032918 · 0x80032BB4(2택 팝업) · 0x80032E14 · 0x80033C94(필드 메뉴) · 0x80034090 · 0x8005C02C(전투 square) · 0x80064F48 · 0x8006557C`.
즉 **선택 가능한 목록 창은 전부**(필드 메뉴 「시스템」·도구·마법·상점류·전투 square·예/아니오 팝업…).

## 3. 설계안과 크기 가늠

핵심: 커서 줄도 **같은 조판**(반 칸 압축)을 그려야 일반 줄과 위치가 같다.

1. `0x8001A7E8` 가 글자 코드 배열(`fp+0x28`, 열 수만큼)을 모은 직후(`0x8001A9C8`)에 훅: 창(`a0`)의 열×행이 반각 허용 목록(`tile_hook.MSG_WINDOWS` 와 같은 표)이고 줄에 반 칸 글자(`OFF_HALF` 목록)가 있을 때만 동작.
2. 줄의 **합성 타일 T₀…Tₙ₋₁**(1bpp 18B, 6px 단위 시프트 — `tile_hook` 의 24비트 시프트 루프와 같은 계산)을 임시 버퍼(자료 자리 빈 곳, 칸 수×18B)에 만든다.
3. 코드 배열을 **가상 코드**(예: `0xF000+칸`)로 바꿔 쓴다.
4. `0x80018574` 의 글리프 주소 계산(`0x80018594~0x800185AC`: `FONT + 코드×18`)을 `jal` 스텁으로 바꿔 **가상 코드면 임시 버퍼**에서 읽게 한다 — 그 뒤 4bpp 확장·테두리 입히기(`0x8001A080`)는 원판 그대로라 테두리·색이 안 깨진다.
- 크기: asm 약 100~130 워드(합성 루프 + 가상 코드 스텁 + 분기), 임시 버퍼·상태는 자료 자리(0x8008CD94+0x418) 안. `tile_hook.msg_stub` 처럼 창 목록 표를 공유.
- 위험: ① 목록 창 11곳이 전부 영향(반 칸 글자가 없는 줄은 그대로 통과하게 해야 한다) ② `0x80019FE8` 은 풀 포인터(`0x800C3EE0`)를 전진시키므로 호출 수·순서를 안 바꿔야 한다 ③ 일반 줄(종류 1)은 훅 목록(열×행)으로 거르는데 목록 창은 현재 대부분 **훅 밖**(전각 공백) — 반각을 켜려면 일반 줄도 같은 창을 목록에 넣어야 두 경로가 같아진다.
- 검증 방법: 모델(`tilecomp`)과 해석기(`test_tile_hook` 의 Sim) 확장 + **커서를 줄마다 옮겨 찍는 화면 확인**(이번 square 실측처럼).

## 4. 되면 얻는 것 (마스터 질문 ③)

- 필드 메뉴 「시스템」처럼 잘라 만든 합성 글리프와 이번에 전각 칸으로 맞춘 메뉴(square·예/아니오 등)를 **일반 반각**으로 대체 가능(커서 줄 포함 정확한 가운데·반 칸 공백).
- 못 하는 것: 반 칸 미만 단위. 줄이 열 수를 넘는 글자 수(글자 수 = 칸 수라는 구조)는 그대로.

## 6. 연구 진행 (10-10 밤) — 원리 확정 · 고칠 자리 · 막힌 곳

**종류 4 의 정확한 흐름(`0x8001A7E8`, 디스어셈블 확정)**: ① 창 `a0`·문자열 `a1`·커서 줄 `fp+0x14`(= `window[0x14]`), 열 `fp+0x1e`(= `window[6]`), 시작 칸 `fp+0x24`(= 줄×열) ② `fp+0x18` 에 **열 수만큼** u16 글자 코드 배열(**`fp+0x28`** — 원본이 `fp+0x10` 에 0x18 을 더해 읽는다. 처음엔 `fp+0x18` 로 오독해 지역 변수를 덮어 줄이 사라졌다)을 0 으로 비운 뒤 문자열에서 제어값(≥0x8000)까지 채운다(남는 칸 = 코드 0 = 전각 빈 글자) ③ **칸마다** `0x80019FE8(코드)`(→ `0x80018574(코드, 풀)`: 글리프 18B = `0x8009E170 + 코드×18` 를 확장표 `0x800A620C` 로 4bpp 타일로 풀어 풀 `0x800C3EE0` 에 씀) 뒤 `0x8001A080(타일, 7|5|0xD, 색)` 로 **왼쪽 캡·가운데·오른쪽 캡 테두리** 조각을 입힌다 ④ 명령 두 개를 쓴다: 종류 4(타일 N장 업로드: 슬롯 = `window[0xE]+시작 칸`, 장수 = 열, 풀 포인터) 와 종류 3(위치).
→ **커서 줄은 항상 열 수만큼의 타일을 전각 칸 격자에 놓는다** — 칸 폭 12px 는 여기가 아니라 「코드 1개 = 타일 1장」 구조에서 나온다. 반 칸을 쓰려면 **글리프 코드 배열이 아니라 타일 내용**을 합성해야 한다.

**고칠 자리(설계 확정)**
1. 코드 배열이 다 찬 직후 `0x8001A9C8`(`lui v0,0x801F`)·`0x8001A9CC`(`lhu v0,0x76B8(v0)`) 두 워드를 `jal 훅 · nop` 으로 바꾸고 훅 끝에서 원래 두 명령을 실행해 돌아온다(원본 두 워드는 훅이 대신).
2. 훅: 창(`lw t0,0x78(fp)`) 열×행이 반각 허용이고 배열에 반 칸 글자(`OFF_HALF`)가 있을 때만, 줄의 **합성 타일 T₀…T_{열−1}**(1bpp 18B, 6px 시프트 — `tile_hook` 과 같은 24비트 `srl 6 & 0x03F03F` · `sll 6 & 0xFC0FC0` 계산)를 임시 버퍼에 만들고 배열을 **가상 코드**로 덮는다.
3. 가상 코드: `0x80018574` 의 글리프 주소 계산이 **부호 있는 16비트**(`lh`)이므로 **음수 코드**로 임시 버퍼(= `FONT − 18·m`, 자료 자리 안)를 가리킬 수 있다 — 글리프 주소 계산 자리를 안 고쳐도 된다(`0x80018574` 무수정).
4. 대사 줄(종류 1)과 같은 창 허용 목록을 쓴다(두 경로가 일치해야 커서가 움직여도 글자가 안 움직인다).

**막힌 곳(크기)**: 합성 루프까지 넣으면 asm ≈ 100~120 워드(≈ 450B) + 임시 버퍼(열 ≤ 12 → 216B) ≈ **670B**인데 자료 자리(`0x8008CD94`+0x418)의 남는 곳은 **약 424B**(상태·표 0x100 · 패널 스텁 180B · 메시지 갈래 176B 뒤). 방법 둘: ① **더 큰 죽은 코드 자리를 검증해 얻는다**(`0x8008D1AC~0x8008DAD0` 2.3KB 중 호출자 없는 함수 `0x8008D3A4`·`0x8008D634`·`0x8008D77C`·`0x8008D90C` 는 같은 SDK 군으로 보이나 `0x8008D884`·`0x8008D9B4`·`0x8008DA54` 는 호출자가 있다 → 구간 전체를 실행 BP 로 부팅~전투~메뉴 전 구간 0회인지 먼저 잰다) ② 타입 1 훅의 합성 핵을 서브루틴으로 빼 두 경로가 공유(−60워드). ①이 싸다.
다음: ① 검증(실행 BP 범위 0회) → 통과하면 시험 빌드(`ED_CURSOR_HW=1`, 정본 이미지 불변)로 구현.

### 6-1. 죽은 코드 자리 정적 검증 (관리자 요청 — 「BP 0회」만으론 약하다)

- 방법: ED3.EXE 전체 + 오버레이 후보 85개 파일(`work/derived/ed3/iso/*`)에서 ① `jal`/`j` 대상 ② 포인터 워드 ③ `lui`+`addiu`/`ori` 쌍 ④ 다른 파일에서 EXE 범위로 가는 `jal` 이 **하나도 없는** 함수(`addiu sp` 시작·`jr ra` 끝)만 찾았다.
- 🔴 **`0x8008D1AC~0x8008DAD0`(2.3KB)은 대부분 살아 있다** — `0x8008D1D4`·`0x8008D204`·`0x8008D214`(0x8008A32C·0x80086024 등 살아 있는 코드에서 `jal`)·`0x8008D62C`·`0x8008D904`·`0x8008D9B4`·`0x8008DA54`·`0x8008DFF0` 이 호출된다. 죽은 건 앞의 SDK 오류 함수 넷(`0x8008CD94~0x8008D1AC`, 이미 자료 자리)과 작은 조각뿐이라 **쓰지 않는다**(관리자 짐작이 맞았다).
- 대신 EXE 전체에서 참조 0 인 함수를 이어 붙여 본 연속 구간: **`0x8008A108~0x8008A2B4` 428B**(함수 둘) · **`0x8008A428~0x8008A598` 368B**(함수 셋) — 나머지는 60~216B 파편. 둘 다 `LoadImage(0x8008A8DC)` 바로 앞쪽 libgpu 군으로 보인다.
- 남은 검증: 이 두 구간을 **실행 BP(범위, `pause_on_hit` 없이)로 부팅~序章~전투~메뉴~세이브/로드 0회**인지 확인(동적). 정적은 통과했으나 런타임에 계산되는 함수 포인터(BIOS 콜백 등록)는 정적으로 못 잡는다 — 그래서 동적 검증이 필요하다(앞의 자료 자리·죽은 함수와 같은 방식, sha1 사전조건 포함).
- 크기: 루틴 ≤ 428B(107워드) 면 첫 구간에 들고, 임시 버퍼(216B)는 자료 자리 남는 곳(424B)에 둔다. 넘으면 둘째 구간(368B)에 나눠 `jal`.
- **동적 검증 결과(10-10)**: 실행 BP(범위, 멈춤 없음, `start_frozen` 로 첫 명령 전부터)로 두 구간 **`0x8008A108~0x8008A2B3` · `0x8008A428~0x8008A597` 모두 0회** — 부팅·타이틀·첫 대사·집·필드 메뉴·시스템 메뉴(세이브/로드 화면, 「세이브합니다. 괜찮습니까?」 예/아니오까지)·멧돼지 조우·승리·레벨업·패배. (⚠ 처음 십진 주소를 잘못 넣어 `0x80089D08~` 을 걸었더니 대사 경로에서 폭주 — 그 구간은 **살아 있는 코드**다. 검증은 16진 정본 범위로 다시 했다.) 아직 안 가 본 곳: 뒤 장·이벤트·엔딩·상점 — 구현 전에 **베이스 라인으로 더 걸어 본다**(범위 BP 를 계속 켜 둔 채 일반 플레이).

## 7. 시험 빌드 결과 (10-10 밤) — **된다**

- 다음 단계(정본 채택 시): ① 목록 창 전반(필드 메뉴·도구·마법 등 11개 함수)의 허용 열×행 표 확정과 각 창 화면 확인 ② 「시스템」처럼 잘라 만든 합성 글리프·전각 칸 메뉴를 일반 반각으로 대체(원문 정렬이 바뀌는 곳은 마스터 판정) ③ 위 죽은 코드 구간 동적 검증을 뒤 장·이벤트·엔딩까지 확대 ④ `ED_CURSOR_HW` 를 정본 빌드에 켜기(되돌리기 쉽게 사이트 원본 워드 기록).

## 8. 시험 빌드 2차 (10-10 밤) — 마스터 정정 반영: square 6열 유지·필드 메뉴 「시 스 템」

마스터: 「6칸 유지하고 띄어쓰기 다 빼고 … 키설정변경만 양옆 0.5, 상태보기·퇴각하기는 양옆 1」 · 「필드메뉴도 시스템 잘라서 그리지 말고 반각으로 시 스 템」. 시험 빌드 `ps1-ed3-cursor`(`ED_CURSOR_HW=1`, 정본 이미지 불변), 캡처 `.local/work/inbox/ps1-ed3/cursor-hw/v4-sq-1~4`·`v4-fm-1~3`.

- **square(전투) — 된다.** 창 열 6 유지(창 테이블 6/4), 줄 = 상태보기·퇴각하기(앞 전각 빈 칸 1 + 4글자, 뒤 1칸은 열 안 빈 칸) · 자동전투선택(6글자) · 키설정변경(**띄어쓰기 없음**, 앞 반 칸 공백 + 5글자). 네 줄 글자 소실·줄바꿈 없음, 커서 상자 네 변 정상.
  제약: **줄당 글리프 수 ≤ 열 수**(앞 반 칸 공백도 글리프 하나) — 그래서 「키설정변경」의 뒤 반 칸은 공백 글리프가 아니라 줄 끝 빈 칸이다(0.5 + 5 + 0.5 를 글리프로 쓰면 7 > 6).
- **필드 ○ 메뉴 「시 스 템」 — 결론: 반 칸씩 구운 합성 글리프(정본 방식) 유지**(마스터 10-10 「ed3은 그냥 시스템 반씩굽기」). 시험한 길 셋을 접었다:
  1. 일반 글자 + 반각 공백 5코드 + 창 5열 + 목록을 R2 빈 꼬리로 이전(`field_menu`, 표 0번 항목이 연속 5줄 25워드라 못 옮기고 포인터 읽는 자리 넷을 `lui;ori` 로 고침) — 화면에선 **된다**(`v4-fm-*`)지만 창이 5열이 돼 오른쪽에 빈 칸·커서 상자가 김 → 마스터가 4칸을 원해 접음.
  2. 같은 5코드를 **4열**에 — **안 된다**: 엔진이 코드 하나에 칸 하나를 잡아(반각 공백 코드도) 넘친 「템」이 창 밖으로 사라진다(`v5-fm-*`). 합성 뒤 타일 수로 셀 수 없다(코드→칸 배정은 엔진 몫). 표지 비트로 코드 수를 줄이는 길은 대사 줄 훅 자리(1092B 중 1088B 사용)가 없어 큰 공사라 안 감.
  3. **채택**: 정본 UI 문안의 4코드 합성(시 | ½+스 | 스+½ | 템, `font.SPLIT`)을 그대로 — 4열 창, 코드 4개(`v6-fm-*`: 「시 스 템」 간격이 균등, 커서 상자 4열 폭 네 변 정상, 다른 항목 정렬 원래대로).
- 확인 경로(교훈): **「이어서 하기」는 헤드리스에서 카드를 안 가린다**(devlog 09-27) — 카드 복사본을 포트 홈 해시 없는 이름 자리에 두고 **게임 안 ○ 메뉴 → 시스템 → 세이브/로드 → 로드**로 불러와야 한다(「기록이 없습니다」는 이름 탓이 아니었다).
- 정본 채택 전 남은 일: 목록 창 11곳의 허용 열×행 표와 창마다 화면 확인 · 마스터 판정.

## 9. 기본 빌드로 승격 (10-10 밤, 마스터 「당연히 빌드에도 포함」)

- 시험 손잡이(`ED_CURSOR_HW`·`cursor_hook.enabled`·`tile_hook`/`build` 의 환경 분기)를 걷고 **기본 경로**로 넣었다. 허용 창 목록 `tile_hook.MSG_WINDOWS` 에 `(6, 4, 0)`(전투 square — 창 열을 6 으로 줄인 뒤)이 들어가고 `cursor_hook.PROTO_WINDOWS` 가 같은 값을 쓴다(두 경로가 일치해야 커서가 움직여도 글자가 안 움직인다). `SQUARE_LINES` 는 「상태보기」(앞 1) · 「자동전투선택」 · 「키설정변경」(띄어쓰기 없음, 앞 반 칸) · 「퇴각하기」(앞 1). 필드 ○ 메뉴 「시스템」은 정본 4코드 합성 글리프 그대로(§8).
- **목록 창 허용표(실측: 정적)** — 커서 줄 훅은 `0x8002F04C`(목록 줄 그리기)를 부르는 함수 아홉(호출 20곳, 위 「11개」는 호출 함수 수를 잘못 센 것)의 창에서 돈다. 각 함수의 창 생성(`0x800174A0` 인자 상수)으로 허용 규칙(개별 목록 + 일반 규칙: 행 1~3 · 열 5~18 · 창 y −48~−12)을 대 봤다:

| 함수 | 창(열×행, 표 y) | 허용 |
| --- | --- | --- |
| `0x80030EE0` | 4×2(−84) · 8×4(−108) · 11×8(−30) | ✗ |
| `0x80032918` | 3×3(−30) | ✗ |
| `0x80032BB4` | 4×2(−24) · 4×2(0) | ✗ |
| `0x80032E14` | 3×2(−36) · 6×8(−56) · 14×4(−56) | ✗ |
| `0x80033C94` | 7×4(−69) | ✗ |
| `0x80034090`(필드 ○ 메뉴) | 4×5(−108) 외 가변 열 둘(y ≥ −16) | ✗ |
| `0x8005C02C`(전투 square) | **6×4**(−36, 열 7→6 패치 후) · 8×4(−12) | **6×4 만 ✓** |
| `0x80064F48` | 3×2(−27) | ✗ |
| `0x8006557C`(필드 메뉴 변형) | 4×6(−108) 외 가변 열 둘 | ✗ |

  ⇒ **허용되는 목록 창은 square 6×4 하나**(나머지는 열·행·y 가 밖이라 원판 그대로). 일반 규칙에 걸리는 창(전체 창 생성 75곳 중 열 5~18·행 1~3·y 범위: `0x80040DA8`·`0x80059FD8`·`0x8005AAB8`·`0x8005C820`·`0x80070B88`·`0x80070E58`·`0x8007113C`·`0x80071740`)은 전부 **목록 함수가 아닌** 메시지 창이다 — 커서 줄 경로를 안 탄다. 6×4 인 다른 창은 창 생성 상수로 없다(가변 열 창 제외 — 화면 회귀로 확인).
- 화면 회귀: `.local/work/inbox/ps1-ed3/reg-1010/`(필드 메뉴·목록·시스템 설정·세이브/로드·전투 square·퇴각·승리·대사창).
