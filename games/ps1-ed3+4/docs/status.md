## 대본이 어디에 얼마나 있나 (전수 조사 2026-09-03, `tools/find_text.py`)

계통이 **둘**이고, 둘은 폰트도 인코딩도 다르다 — 한쪽 파이프라인으로 안 덮인다.

### 계통 A — 자체 16비트 코드 + 내장 12×12 폰트 (우리가 다루는 그것)

| 어디                  | 무엇                          | 심볼   |
| --------------------- | ----------------------------- | ------ |
| `SC*.DAT!..\DATA\*.BIN` | **맵 대사** (ED3)             | 381,824 |
| `SC*.DAT!..\BIN\*.BIN`  | **맵 대사** (ED4)             | 304,393 |
| `ED3.EXE` 0x0010B4    | 시스템 메뉴 (はい/いいえ·매매) | —      |
| `ED3.EXE` 0x096E52    | **인물** 이름 → 이어서 **무기** | 1,147  |
| `ED3.EXE` 0x097AE0    | **마법**                       | 481    |
| `ED3.EXE` 0x0995FE    | **몬스터**                     | 712    |
| `ED3.EXE` 0x09B5E0    | **지명**                       | 609    |
| `ED3.EXE` 0x09C52E~   | **읽을거리**(교본·책)          | 7,761  |

🔴 **맵 대사 밖에서 코드표로 읽히는 자리는 실행파일 하나뿐이다.** 전수 조사에서 뜬 나머지
후보(`*.TIM`·`*.ANM`·`*.VB`·`ENDDATA*.BIN`)는 **전부 그림·소리 오탐**이었다 — 카나 밀도만
보면 걸리지만 디코드하면 뜻이 없다. 밀도는 후보 좁히기지 판정이 아니다(체크리스트 5).

### 계통 B — 생 SJIS + PS1 BIOS 한자 폰트 (아직 미착수)

| 어디                            | 무엇                                             |
| ------------------------------- | ------------------------------------------------ |
| `/PSX2.EXE`·`/SLPS_012.01` 0x000864 | 이 계통이 쓰는 **문자표**(JIS 1·4·5구 통째)   |
| 〃 0x000E24~0x001610            | **월드맵 지명 ~170** (6전각 고정칸)              |
| 〃 그 뒤                        | **메모리카드 UI**(「差されていません」「ロ－ド完了」) |

⇒ 여긴 **글리프를 우리가 못 굽는다**(BIOS 폰트다). ED1 오프닝과 같은 문제이고 해법도 같다 —
폰트를 심고 읽는 코드를 고친다. **별도 트랙**으로 잡는다.

## P2 준비 — 조사(종성)를 어떻게 처리하나 (설계, 2026-09-07)

**결론: 동적 훅으로 간다(ED3 먼저).** 근거는 셋이다.

1. **자리가 있다.** 글리프를 올리는 순간에 이미 훅이 있고(`0x80018ACC`, `engine_patch`),
   그 훅은 **폰트 베이스 `a1` 를 돌려주는 자리**다 — 호출부가 `a0 = 코드×18` 을 이미 만들어
   두었으므로 `a1 = 베이스 + (고를 코드 − 마커 코드)×18` 로 **글리프를 바꿔치기**할 수 있다.
   즉 문안에 「을」 자리에 **조사 마커 코드**를 넣어 두면 화면에 나갈 때 을/를이 정해진다.
2. **앞 글자를 안다.** 우리 훅은 이미 칸 번호(`0x10(fp)`)와 폭 표(`SLOTW`)를 든다 —
   같은 방식으로 **직전 칸의 코드**를 한 칸짜리 표에 적어 두면 그 코드의 종성만 보면 된다.
   종성은 코드마다 고정이니 **비트맵 1장**(1,829비트 = 229B)이면 끝난다. 죽은 함수에 남은
   자리로 충분하다(지금 90워드 + 512B 를 쓰고 1,092B 중 약 220B 가 남는다 — 모자라면
   `0x8009544C`(1,076B) 등 죽은 함수가 더 있다).
3. **정적 병기로는 아까운 자리가 많다.** 변수 주입 자리 실측 — 문두가 `を`·`が`(문장을
   시작할 수 없는 조사)인 조각이 **ED3 125 · ED4 525**, 앞 조각이 조사로 끝나고 이어지는
   짝이 ED3 98 · ED4 235. 아이템·인물 이름이 들어가는 정형 문장이라 **가장 자주 보이는 줄**이다.

⚠ **초벌은 병기로 쓴다**(`을(를)`). 훅이 서기 전에도 화면이 맞고, 훅이 서면 마커로 바꾸는
것은 정본 일괄 치환이라 싸다. ED4 는 렌더러가 따로(`0x800164F0`)라 훅을 다시 찾아야 하므로
그때까지 병기가 정답이다.
🔴 **런타임 배치는 워크램 함정을 조심한다** — ps1-ed1+2 에서 「배치=런타임 워크램」으로 물렸다
([[ed1-josa-hook]]). 여기 훅은 **글리프 주소만** 바꾸므로 그 함정을 안 밟는다.

## 열려 있는 물음

- **공백 코드가 무엇인지 모른다.** PoC 에서는 빈 글리프를 한 자리 배정해 때웠다(화면상
  12px 공백이라 그대로 보인다). 원본 일본어엔 띄어쓰기가 없어 표에 안 들어 있는 듯하다 —
  본 빌드에서 정본으로 자리를 정한다.
- ED4 미지 코드 643 · ED3 350 — 대개 상대 디스크에 없는 저빈도 한자다. 번역엔 안 걸리지만
  **「일본어 안 남았나」 검사에는 걸린다.**
- `0xEEEE` 가 267번 나온다 — 블록 구분(`0xFFFF`)과 다른 무엇인가.
- 코드 `0x0010~0x003E` 기호·숫자 대역이 아직 반쯤 비었다.
- 로마자는 **쓰는 글자만** 있다(Ｇ·Ｌ·Ｑ·Ｔ·Ｕ·Ｗ·Ｘ·Ｚ 없음) — 필요하면 글리프를 새로 굽는다.
