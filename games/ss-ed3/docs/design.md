### 2. 텍스트 — `/MAP/MAP*.BIN` 88 파일, 44.2만 자

맵마다 파일이 넷이다(`.BIN` `.ED3` `.7UP` `.FON`, 88씩 352개). **텍스트는 `.BIN` 에만** 있다
(나머지 셋은 일본어 마커 0~29, 그래픽·타일로 본다).

```
0x00  매직 `ED3WW MAPDATbin\x1a`   ← 88/88 동일
0x10  포인터표 37칸 고정 · BE32 **절대주소**(LWRAM 0x00200000 기준)
0xA4  맵 이름(SJIS, NUL 종료)      ← `アンデラ城` `鷹の爪号` …
```

블록 문법: **SJIS + 제어(`0D` 개행 · `0F` 페이지)로 이어지는 최대 구간**. 여는 옵코드는
`FF 00` · `09 xx` · `02 <서브>` 등 여럿이라 **텍스트 자체를 저본으로 삼는다**(옵코드로
찾다가 84% 에서 멈췄다). 오탐은 종료 바이트(`10 0E 00 09 FF FE`)와 **가나 유무**로 거른다.

- **블록 17,604 · 글자 441,877 · 마커 포착 99.0%**(8,685/8,770)
- **전 파일 라운드트립 통과** — 되끼우면 바이트 동일. 두 디스크 결과가 같다.
- 덤프: `tools/dump_map.py` → `work/derived/map_jp/*.json` (⚠ 원문, 커밋 금지)

### 3. 본체·시스템 문자열 — 41 파일, 1,725 개

`MAP` 밖의 텍스트다. 표 꼴이라 스크립트와 문법이 달라 정본을 따로 뒀다(`tools/strtab.py`).
덤프: `tools/dump_sys.py` → `work/derived/sys_jp/*.json`. **전 파일 라운드트립 통과.**

| 소재                    | 무엇이 들었나                                       |
| ----------------------- | --------------------------------------------------- |
| `/0.BIN` (본체 520KB)   | 인명 · **챕터 제목** · 메뉴 · 스탯 이름 · 저장 안내 |
| `/SYSTEM/PARAM.BIN`     | 몬스터명(레코드 stride 0x4C, 이름이 머리)           |
| `/SYSTEM/BOOK00~39.BIN` | 도감·읽을거리                                       |

- **본체 `/0.BIN` 의 로드 주소는 `0x06004000`** — IP.BIN 0xF0 실측(`06 00 40 00`).
  파일 안 BE32 가 그 절대주소로 문자열을 가리킨다 → **132 개가 포인터로 확인**됐다.
  재삽입에서 고쳐야 할 자리가 바로 이것이다.
- 자리는 **NUL 로 가른다** — SJIS 런을 앞에서부터 훑으면 정렬이 밀려 `天球儀２−２` 가
  `球儀２−２` 로 잘린다(실측). 잘린 걸 되끼우면 옆 바이트를 먹는다.
- 오탐은 **두 겹**으로 건다 — 조각은 「2글자 이상 + JIS 제1수준」, 파일은 **가나 비율 ≥0.3**.
  실측으로 완전히 갈렸다: `/SYSTEM` 중앙 0.97 vs `/EVT` 최대 0.20 · `/BTL` 최대 0.00.
- 마커 포착 **95.4%**(166/174). 놓친 8건은 스탯 이름처럼 **길이 바이트가 앞에 붙은 표**다
  — 「몇 바이트 넘기고 다시 본다」를 재 봤더니 마커 0.6% 얻고 쓰레기 2,633 개를 얻어 버렸다.

⚠ IP.BIN 메타: `T-143`(허드슨) · `T-14322G` · `V1.001` · `19980115` · `CD-1/2` · `SHIROKI MAJO`.

### 4. 조판 계약 — 원본이 스스로 답을 냈다

정본은 [`tools/typeset.py`](../tools/typeset.py)(수치를 그 자리에서 다시 잰다).

| 무엇         | 값          | 어떻게 알았나                                       |
| ------------ | ----------- | --------------------------------------------------- |
| 대화창 폭    | **17 전각** | 정적 절벽 + **실기 확정**(2026-08-25 눈금자)        |
| 대화창 줄 수 | **3 줄**    | 실기 확정 — 17·17·17 이 다 나왔다                   |
| 화면 폭      | **24 전각** | 나레이션 최대 관측 24 · 320px ÷ 12px = 26.7 과 정합 |
| 반각(원문)   | **안 쓴다** | 본편 대사 419,066자 **전부 전각**(반각 0자)         |
| 반각(우리)   | **쓴다**    | 어절 공백 = 반각 — **0.5 칸 · 1 바이트**(실기 확정) |

🔬 **상한을 실기로 닫았다**(2026-08-25). 대사 블록에 전각 숫자 눈금을 심고 **New Game 첫
장면**으로 확인했다(세이브가 필요 없어 3 분이면 돈다). 저자가 `0D` 로 접은 3 줄도, 접지 않은
51 자 한 줄도 똑같이 **17·17·17** 로 나왔다 — 폭도 줄 수도, 「엔진이 접는다」까지 한 화면에서.

🔴 **`0F` 는 「페이지」가 아니라 「대기점」이다**(같은 실측). 창을 비우지 않고 **한 줄씩 위로
스크롤**하며 뒤가 맨 아랫줄에 이어 붙는다. 그래서 **`0F` 자리를 옮기면 읽는 순서가 바뀐다** —
원문의 `0D`·`0F` 배치를 따르는 것이 기본이다. 원문에도 3 줄을 넘는 구간이 있는데(저자가
그렇게 썼다) 그건 스크롤로 흘러가므로 **원문만큼은 게이트가 봐준다**(`reinsert.fit`).
⚠ 빈 줄로 끝나는 구간 뒤는 잘린다 — 원문에 없는 빈 줄을 만들지 않으면 안 만난다.

🔑 **어절 공백은 반각으로 쓴다.** 한국어는 띄어쓰기가 필요한데 일본어 원문엔 없어서, 전각
공백을 쓰면 예산이 곧바로 터진다(서장 71 블록 중 29 건이 초과였다). 실기에서 재 보니
반각 공백은 **깨지지 않고 정확히 0.5 칸**이다 — 한 줄에 전각 9 자 vs 반각 섞어 11 자.
바이트도 절반이라 예산·폭이 동시에 풀린다. ⚠ 설명창은 반대다(반각이 개행 파싱을 깬다).

⚠ **엔진이 접는다.** `0D` 는 강제 개행이고, 저자가 안 접은 줄은 엔진이 접는다 — 대화
39,825줄 중 **566줄이 24자 이상**(최대 48). 「원문 개행 자리를 지키면 된다」가 아니라
**우리 문안도 17자에서 접히는 걸 전제**해야 한다.

⚠ **나레이션은 다른 물건이다** — 전각 공백으로 가운데 정렬한 전체화면 연출이라 줄이
17~24자에 몰리고 페이지가 **8~11줄**까지 간다(블록 54개). 대화창 자로 재면 전부 오탐이라
`is_narration()` 이 가른다.

### 5. 재삽입 — **길이 보존**으로 간다 (정찰 2026-08-24)

🔴 **텍스트가 포인터로 참조되지 않는다.** 블록 시작을 직접 가리키는 파일 내 BE32 가 있는
블록은 **17,604 중 302(1.7%)** 뿐이다. 즉 대사는 **스크립트 스트림에 인라인**이고,
새턴 ED1+2(포인터 커버리지 100%)와 정반대다 — 그쪽 재삽입 설계가 여기 안 붙는다.

인라인이라는 건 **블록 길이를 바꾸면 그 뒤 전부가 밀린다**는 뜻이다. 밀리면 헤더 37칸 표 ·
`FD 03 <주소>` 레코드 · 스크립트 안 절대주소를 전부 재계산해야 하는데, 파일 안을 가리키는
BE32 를 세면 75,600 개가 잡힌다(대부분 오탐이다 — 데이터 바이트가 `0020xxxx` 로 읽힌다).
**진짜 포인터만 골라내려면 스크립트 옵코드 문법을 다 풀어야 한다.**

→ **그래서 길이를 안 바꾼다.** 성립하는 근거가 실측으로 있다:

- **한국어가 일본어보다 짧다.** ps1-ed1+2 의 실제 번역 **11,994 쌍**에서 KR/JP 바이트 비
  **중앙 0.730**(글자 비 0.692), **95.0% 가 1.0 이하** · 97.6% 가 1.1 이하.
  즉 원문 바이트 예산 안에 대체로 들어간다.
- **남는 바이트는 줄 끝 전각 공백으로 채운다.** 창 폭이 17 인데 줄 길이 중앙이 10.6 이라
  **줄마다 평균 6.4자(12.8B) 의 여백 예산**이 있고, 블록당 줄이 2~3개다.
  ⚠ 줄당 17자를 넘기면 접혀서 **빈 줄이 생긴다** — 조판기가 줄 단위로 채워야 한다.

🔬 **실기로 확인했다**(2026-08-24, 눈금자 수법 · `work/review/state-map001-first-dialog.mcs`):

- **전각 공백은 접힘에 그대로 세어진다** — `１２３４５６７８９` + 공백 8칸(=17) 뒤의
  `あいうえお` 가 정확히 다음 줄로 갔다. 즉 줄당 17칸 규칙이 공백에도 적용된다.
- **줄 끝·줄 전체 공백은 화면에 흔적이 없다.** 공백만 남은 줄도 빈 줄로 안 보인다.
- 🔴 **`▼` 대기 표시는 텍스트 맨 끝에 붙는다** — 마지막 줄을 채우면 ▼ 가 한 줄 밀려
  혼자 뜬다(무해하지만 보기 나쁘다). 그래서 **마지막 줄은 되도록 안 채운다.**
- **반각 공백(`0x20`)은 정확히 0.5칸**(6px)이고 역시 접힘에 세어진다. 본편이 반각을 한 자도
  안 쓰지만 렌더는 멀쩡하다 — 값은 **1바이트 눈금**이다(전각만 쓰면 2B 단위라 예산이
  홀수일 때 못 맞춘다). ⚠ 폭 예산은 안 는다: 17칸 = 전각 17 = 반각 34 = **둘 다 34B**.
- 소프트락·깨짐 없음. 스크롤도 정상.

✅ **낼 결과물 그대로 실기 확인**(2026-08-24) — `pad_to_budget` 이 만든 블록을 그대로
RAM 에 심었다. 패딩이 화면에 전혀 안 보이고 `▼` 도 마지막 줄 텍스트 바로 뒤에 붙었다.
2페이지 3줄까지 정상.

🔴 **줄을 17칸까지 꽉 채우면 안 된다** — 엔진이 **자동으로** 줄을 넘기고, 뒤따르는 `0D` 가
**빈 줄을 하나 더** 만든다. 그러면 페이지가 3줄을 넘어 **화자 줄이 스크롤로 사라진다.**
실기에서 정확히 그 사고를 냈다(첫 줄을 17칸으로 채웠더니 「クリスの母」가 없어졌고,
상한을 **16.5칸**으로 낮추자 살아났다). `pad_to_budget` 이 한 반칸을 남긴다.

**얼마나 되나 — 90.9%** (`typeset.pad_to_budget`, 전 블록 시뮬레이션):

| 결과                    | 블록   | 비율  |
| ----------------------- | ------ | ----- |
| ok (마지막 줄 보존)     | 10,229 | 58.3% |
| ok (마지막 줄까지 채움) | 5,716  | 32.6% |
| 문안이 길다             | 1,145  | 6.5%  |
| 패딩 자리 부족          | 324    | 1.8%  |
| 배치 실패               | 136    | 0.8%  |

⚠ **시뮬레이션이다** — (당시) 한국어 문안이 없어서, ps1 실측 비율 분위(0.536~1.024)에서
뽑은 **길이만 같은 가짜 문안**을 원문과 **같은 페이지·줄 수**로 배치해 쟀다. 줄 배치를
원문대로 유지하는 게 중요하다 — 줄 수를 최소화하면 패딩 자리가 사라져 **14.3%** 로 떨어진다.

**남은 실패의 성격**:

- **문안이 길다 6.5%** — 번역·조판으로 푼다(번역자가 예산을 보고 쓰면 대부분 사라진다).
- 패딩 자리 부족 1.0% · 배치 실패 0.8% — 그 블록만 줄 배치를 다시 잡는다.
- ⚠ **반칸 단위로 세야 한다.** 칸을 정수로 반올림하면 자리를 한 칸 더 있다고 착각하고,
  그만큼 밀려 **다음 줄 첫 글자가 0.5칸 들여쓰기** 된다(실기에서 그 현상을 봤다).

### 6. 한글 파이프라인 — **화면에 나왔다** (2026-08-24)

전 체인이 붙었다: 배정 → 폰트 굽기 → 인코딩 → 길이 보존 재삽입 → EDC/ECC → 이미지 → 실기.

```bash
python3 games/ss-ed3/tools/hangul_map.py --freeze   # 배정 정본 (한 번만)
python3 games/ss-ed3/tools/build_font.py            # KANJI12.FON 에 한글 굽기
python3 games/ss-ed3/tools/reinsert.py --check      # 길이 보존이 되나
python3 games/ss-ed3/tools/build.py                 # 이미지 (1.9초)
```

- **배정**(`hangul_map.json`) — 완성형 2,350자를 안 쓰는 한자 슬롯에 가나다순 배정.
  `가` = 구16 점1 = SJIS `889f`(PS1 과 같은 자리에 떨어졌다). 빈 슬롯 4,818 중 2,350 사용.
  🔴 **파생물이 아니라 정본이다** — 소재를 더 열면 빈 슬롯이 밀려 이미 넣은 문안이 전부
  다른 글자가 된다. `--freeze` 로만 갱신하고, 그때 문안을 다시 굽는다.
- **폰트** — Galmuri11 을 `dy=-3` 으로 12×12 에 얹는다. 원본 잉크가 **0~10행**이라
  (실측: 1,638/1,833 이 0행 시작, 1,589 가 10행 끝) 베이스라인이 그대로 맞는다.
  파일 크기 불변(140,544B).
- **빌드** — 원본 사본 → 폰트 교체 → 문안 재삽입 → 섹터 자기검증 → **무변경 구간 대조**
  (선언한 파일 밖은 원본과 바이트 동일). 실패하면 산출물을 `*.failed` 로 무효화한다.

### 8. 시스템 문자열 재삽입 — 장 제목이 들어갔다 (2026-08-24)

`reinsert_sys.py`. 대사(`reinsert.py`)와 규칙이 다르다 — 표라서 **문자열마다 종료 NUL 과
패딩**이 있어 **조금 길어져도 된다**:

    예산 = 원문 바이트 + (뒤따르는 NUL 개수 − 1)     ← 종료자 1개는 반드시 남긴다

🔴 **포인터는 안 고친다** — 문자열 **시작 위치를 안 옮기기** 때문이다. 옮기면 `/0.BIN` 안
BE32 132 곳을 다시 계산해야 한다(3절). 늘리는 건 패딩 안에서만이고, 넘치면 다음 문자열의
첫 바이트를 먹는데 **포인터는 그대로라 화면에만 엉뚱한 글자가 나온다.**

**장 제목은 자체 번역**이다(`script/system.json`). ED1+2 도 정발 제목을 안 따르고 원문으로
옮겼다. 정발과 갈린 자리 셋:

| 장     | 원문           | 정발                    | 우리              |
| ------ | -------------- | ----------------------- | ----------------- |
| 제５장 | `わかたれた湖` | 와카타레타 호(**음차**) | **갈라진 호수**   |
| 제６장 | `動き出す予言` | 시작된 예언             | **움직이는 예언** |
| 제７장 | `巡礼者の軌跡` | 순례자의 흔적           | **순례자의 궤적** |

나머지 다섯은 달리 옮길 길이 없어 결과가 같다(`테그라의 보석`·`볼트 대결전`·`삼도교의 환영`·
`성수가 사는 숲`·`상냥한 마녀`). ⚠ 그 안의 **고유명사는 정본 표기**를 쓴다(`테그라`·`볼트`·`삼도교`).

**9개** 전부 예산(27~28B) 안에 들어갔고 RAM 에서 되읽어 확인했다. ⚠ 처음에 `第` 로만
찾아 **서장을 놓쳤다** — `序　章　　〜小さな巡礼者〜`(0x1D00)이라 패턴이 달랐다.

🔴 **장 표시는 `/0.BIN` 에만 있는 게 아니다.** `MAP*.BIN` 대사 블록에도 **장 시작·완료
화면**이 들어 있다(나레이션 꼴, 전각 공백 들여쓰기):

```
MAP001 0x1CF7E  　　　　　　　序章　小さな巡礼者
MAP011 0x11464  　　　　　　序章　小さな巡礼者　完
MAP011 0x1514E  　　　　　　　第１章　テグラの宝石
MAP019 0x12D82  　　　　　　第１章　テグラの宝石　完
…  MAP047 0x169F2  　　　　　　　最終章　やさしき魔女
```

⚠ **`/0.BIN` 과 표기가 갈리는 자리가 있다** — 6장이 본체는 `動き出す予言`(한자 出)인데
MAP039·MAP042 는 `動きだす予言`(히라가나 だ)다. 둘 다 잡아야 한 벌로 보인다.
⚠ `章間イベントへ`(MAP042·MAP047) 같은 진행 표시도 있다.
✅ **21 블록 중 20 을 자동으로 박았다**(`gen_chapter_lines.py --write`). 남은 하나(MAP070)는
나레이션이 섞여 있어 대사 번역과 함께 간다.

🔴 **이 화면은 가운데 정렬이다** — 들여쓰기 = `(화면 24칸 − 제목칸) ÷ 2`. 21 블록 중 19 가
그 규칙에 정확히 맞았다. 그래서 번역 길이가 달라져도 **들여쓰기를 다시 계산**하면 제자리에
놓이고, **예산을 넘으면 들여쓰기를 한 칸씩 줄여 흡수**한다.

⚠ 처음엔 자동이 4/21 이었다. 원인 둘 다 **오판**이었다:
· 원문이 `…巡礼者\n` 처럼 개행으로 끝나 **빈 줄**이 생기는데 그걸 「나레이션 섞임」으로
읽었다(10건).
· **반각 공백 한 자(1B)** 로 예산이 넘쳤다(7건) — 가운데 정렬이 0.5칸 단위라 바이트가
홀수로 떨어진다. 들여쓰기 조정으로 흡수한다.

⚠ **`完` 은 「끝」**이다(유저 확정 2026-08-24).

⚠ **숫자는 전각(`１`)으로 쓴다** — 원문이 그렇다. 반각(`1`)은 `ASCII.FON`(8×12)에서 그려져
본문 `KANJI12.FON`(12×12)과 **높이·폭이 갈린다.** 처음에 반각으로 넣었다가 RAM 을
되읽고 잡았다. 전각이 1B 더 들어 빠듯해진 장은 전각 공백을 하나로 줄였다.

⚠ **선행 서식을 벗기고 맞춘다** — 최종장이 `<09>最終章…` 꼴이라 표의 키와 안 맞아
**한 자리를 조용히 놓쳤다**(7/8). 서식은 그대로 두고 몸통만 갈아 끼운다.

⚠ **인명·지명 표는 안 고친다** — 그 이름들은 **대사 안에서** 쓰이므로, 표만 고치면
대사와 갈린다. 대사 쪽이 정본이다.

(음성 자막이 든 맵)을 옮겼을 때 **엔진이 늘어난 크기만큼 그대로 읽는 걸 실기(에뮬)로
확인했다**(`relocate.py` 머리말). 트랙을 넘는 자리가 다르지만 **읽는 경로는 같은 ISO9660
디렉터리 레코드**이므로, 레코드 기반 읽기라는 결론이 트랙2 파일에도 이어질 가능성이 높다.
✅ **트랙 전환도 실기에서 확인됐다** — 09-26 이자벨 직전 세이브로 엔딩 그림·크레딧 음성까지 화면으로 봤고 마스터가 10-07 에 최종 확인했다.

⚠ 「원본이 어땠는가」는 originals 에서, 「우리 결과가 어떻게 보이나」는 **빌드본**에서
읽는다 — 관리자가 짚은 함정이고, 위 대조에서도 그대로 지켰다(원본 대조는 `C.disc_tracks()`
가 주는 `originals/` 경로, 결과 확인은 `work/build/`).

✅ **`BJDATA.PAK`(블랙잭)은 정적으로 풀렸고, 고칠 게 없다**(2026-08-28). 항목 8 =
**4bpp 320×96**(팔레트 항목 9) 테이블 · 항목 10~14 = **8bpp 선형 폭 40px**(항목 16)
캐릭터 스프라이트 · 항목 5 = 액션 라벨. 🔑 **글자가 원판부터 영문**이다
(`BET AREA`·`Stand`) — 일본어가 아니라 한글화 대상이 아니다. 항목 0(15,168B)만 미해결.
🔑 **푸는 법** — ① 줄 폭은 **자기상관**으로(이웃 줄이 닮는다. ⚠ 폭 8B 가 1등이면 8×8
타일이다) ② 색깊이는 **`.PAK` 안의 32B·64B·96B 짜리 작은 팔레트**로(16색이 짝이면 4bpp)
③ 렌더해서 눈으로(세로 줄무늬 = 색깊이 틀림).

### 폰트 기준선 — 원판 자리

**기본 글리프가 원판 한자와 같은 자리(잉크 0~10 행)**다. 0 행을 자르는 창에 나가는 문안만
**한 행 내린 판**(`lowered_map.json` 560 자)으로 인코딩한다.
종전엔 반대였다 — 전역으로 한 행 내려(`DY=-2`) 스탯 창 하나를 피하고, 안 자르는 창
**전부**에서 1 px 씩 손해를 봤다(메뉴 챕터 바에서 글자가 아래 테두리에 붙어 드러났다).

```
기본        DY -3 · ASCII_DY 1 · DIGIT_DY 1     대사 · 책 · 챕터 바
내린 판     lowered_map.json 560 자 (잉크 1~11)  시스템 표 · 이름 · 설명문
```

🔴 **원판도 똑같이 잘린다 — 처리가 아니라 글자 모양이 다르다.** 실측: 원본이 쓰는 글리프
1,841 중 89% 가 0 행에 잉크가 있지만 **평균 3.0 화소**(攻 1 · 力 1 · 知 1)다. 한자는 세로획이
위에서 시작해 점 한둘인데, 한글은 초성 윗변이 **가로획**이라 공 9 · 구 9 · 마 8 이 통째로
날아간다.

인게임 확인(메모리카드 세이브로 부팅, 2026-09-03):

| 화면            | 0 행을 자르나 | 결과                                    |
| --------------- | ------------- | --------------------------------------- |
| 대사창          | ✗             | 첫 행 27 화소 살아 있음 (잘리면 8)     |
| 책              | ✗             | 줄마다 잉크 11 행 온전 · 줄 간격 24    |
| 챕터 바         | ✗             | 잉크 y19..29 → **y18..28** (원판 자리) |
| 스탯·장비 창    | ✅            | 「공격력」 행별 프로파일이 전과 동일    |
| 세이브 목록     | —             | 지명만 뜬다(내린 판이라 안전)          |

⚠ **대가 하나** — 대사에 아이템 이름이 `%s` 로 주입되는 **38 블록(0.2%)** 에서 그 낱말만
주변보다 1 px 내려앉는다(이름은 스탯 창에도 나가서 내린 판을 써야 한다).
ⓘ 되돌리려면 상수 셋(`DY`·`ASCII_DY`·`DIGIT_DY`)과 `lowered_map.json` 이면 된다.

### 숫자와 반각 글리프 (2026-10-07)

대사·해설·장 제목의 숫자는 반각으로 써도 **전각 `０`~`９`** 로 그려진다(렌더러가 ASCII 숫자를 전각 칸으로 옮겨 그린다, 2026-09-01 실측) — 이 전각 숫자는 한글과 같은 **갈무리11**(0~10 행)에서 뽑는다(`build_font`, `DIGIT_DX=3`).
`ASCII.FON`(HUD 소지금 「40 Pia / 0 Goa」 등 게임이 직접 그리는 반각)은 **원판 그대로**다 — 숫자를 마스터 도안으로 키워 `ASCII_DY` 를 내려 봤더니 창마다 기준선이 갈려 원복했다(devlog 10-07).
반각 계열(숫자·알파벳·부호)은 한 세트로 키울 때만 맞는다 — 갈무리11 알파벳은 94자 중 50자가 폭 7 이라 6px 칸에 안 들어가 도안을 일일이 찍어야 한다.

## 무비 · 음성 자막

### 이벤트 무비 자막 — 하드섭으로 빌드에 들어갔다

소프트섭(엔진이 그린다)을 접었다 — 엔진의 글자 그리기가 **VDP1 스프라이트 VRAM 을 덮는다**
(아래 음성 자막 절). 대신 **자막을 영상에 태운다**: 「Cinepak 인코더가 없다」는 옛 단정이 틀렸고,
ffmpeg 7.1 의 `film_cpk` 먹서 + `cinepak` 인코더로 **왕복이 된다.** `tools/movie_hardsub.py`.

- 자막은 **게임에 넣는 것과 같은 Galmuri11** 을 직접 찍어 PNG 로 얹는다(시스템 폰트 안 씀 —
  머신마다 바이트가 갈리면 제1 원칙이 깨진다).
- **크기가 오히려 준다**(M05: 3,497,432 → 3,115,138B). 남는 자리는 0 으로 채워 원본 크기에
  맞추므로 ISO 를 제자리에서 갈아 끼운다.
- 굽는 게 비싸서(M01 10 분) `work/derived/cpk/` 에 캐시한다. `build.py` 는 **구워 둔 것만**
  넣고 안 구운 편은 세어서 알린다.

✅ **열두 편(M00·M01·M04·M05·M08 · M11·M13~M18) 전부 문안·싱크가 닫혔다**(유저와 한 편씩,
2026-09-02 — 191 줄) 그리고 새 인코더 옵션으로 **전부 다시 구워 빌드에 들어 있다**(2026-09-05).
✅ **인게임에서 돈다**(M01, 2026-09-04) — 단 엔진이 받는 건 **표준 Cinepak 이 아니라 원본의
부분집합**이라 ffmpeg 산물을 두 군데 손봐야 했다(둘 다 `finish()` 가 게이트로 센다):

- **4 바이트 정렬** — 파서가 스트립 머리를 워드로 읽어 **홀수 청크 길이면 CPU 가 멈춘다**
  (`0x0600094E`, 재생 1 초). `align_samples` 가 청크마다 0 을 채운다(원본은 고정점).
- **스트립은 언제나 2 × 112** — 3 스트립 경로가 코드북 버퍼를 공유해 **가운데 띠가 깨진다**
  (`ENC_OPTS = -min_strips 2 -max_strips 2`, `check_strips`). 옛 산물은 255 표본이 걸렸다.

⚠ **`M00`(게임 시작 전 오프닝)은 뒤늦게 붙었다**(2026-09-07) — **말소리가 없어** 자막이
0 줄이었고 그래서 `--list` 에 아예 안 떴다. 넣은 건 타이틀 카드의 제목 한 줄(7.2~12.0초)뿐이다.
로고 자체를 갈아 끼우는 길은 접었다(무비 로고 312px vs 우리 로고 243px — devlog 09-07).

⚠ 캐시 열쇠에 인코더 옵션이 들어가 옵션을 바꾸면 **옛 `enc.CPK` 는 전부 다시 굽는다**(편당
2~10 분). 인게임 전편 재생 확인은 M01 만 했다 — 나머지는 QA 회차에서 본다.

### 인게임 음성 자막 — V01~V19 · 엔딩 V20 크레딧 (빌드에 전부 들어 있다)

무비 말고 **인게임에도 음성만 나오는 장면**이 있다(`/SAP/V01~V21` = 20 장면·41 분, 옵코드 **`FF 42 <BE16>`** 이 튼다
— 재생 함수 `0x060426dc`, 번호가 맵과 1:1). 엔진 텍스트로는 못 한다 — 글자 그리기가 **VDP1 VRAM `0x25c78000`** 을 직접 채우는데
컷신엔 배우 패턴이 거기 있고, 엔진 창은 컷신을 깨뜨린다(배우 복제 · 게임 정지). ⇒ **우리가 그린다.** 전부 `build.py` 안이다:

| 조각 | 어디 | 무엇 |
| --- | --- | --- |
| 렌더러 스텁 + 훅 | `tools/subtitle_stub.py` → `/0.BIN` | 매 프레임 창·글자 명령을 얹는다(훅 `0x060101BA`, 스텁 `0x06018C00` — 디버그 메뉴 코드 구역) |
| 칸 + 글자 표 | `tools/voice_sub.py` → `MAP*.BIN` 꼬리 | 트램펄린 칸(32B)과 글자, ISO 디렉터리 크기 갱신 |
| 정본 | `script/voice.json` · `script/voice_credits.json` | 장면마다 칸(`off`·`delay`·`lines`·`dur`·`speaker`) 또는 시계 표 · V20 은 자막 94 |

두 방식이 같이 있다.
- **스크립트 후킹(V01 · V17~V19)** — 칸을 스크립트의 `FF 35` 대기 자리에 걸어 `delay`(디스패치 뒤 프레임)로 갈라 쓴다. 장면마다 에뮬로 프레임을 재야 해서 비싸다.
- **시계(V02~V16)** — 음성 시작(`FF 42`) **바로 뒤 옵코드 하나**만 후킹해 그때부터 전역 프레임 시계(`GCLK`)로 센다. 시각은 받아쓰기의 음성 기준 초를 그대로 쓰므로 스크립트 흐름에 안 흔들린다(`tools/voice_clock.py`, `clock.origin` 한 값으로 민다).
  ⚠ 얼굴은 **음성 앞** 미리 싣기 자리가 있어야 뜬다(음성 중엔 CD 가 음성 것이라 로드가 안 끝난다) — 정한 장면만 얼굴을 쓴다.

공통 규칙: 같은 화자가 이어 말하면 **창·얼굴은 두고 글만 바꾼다**(앞 칸을 다음 칸까지 붙잡는다, 화제가 바뀌면 `new`). 말 사이가 **`HOLD_GAP`(1.0초) 넘게** 비면 닫고 새로 띄운다 —
**칸 자리(`off`)가 달라도** `_t`(음성 0초 기준)로 잰다(10-07 고침: 종전엔 자리가 다르면 이어 붙여 1.95초·4.0초 공백에도 창이 안 닫혔다). 자막은 음성 끝 + 1.0초에 끈다.
글자는 3 줄 · 첫 줄이 이름(색 14)·본문 두 줄, 숫자는 **전각으로 적는다**(스텁이 직접 그려 반각이 ASCII 폭으로 나온다). 말줄임표는 바닥 높이 `...`.

**V20 크레딧(엔딩)** — 창·얼굴 없이 **글자만** 그린다. 시각은 프레임 시계(크레딧 시작 = 0), 자막 94(대사 19 · 듀르젤 편지 70). 쪽은 **게임 중에 정한다**: 글자 스프라이트의
`XA` 최소값으로 그림이 왼쪽/오른쪽인지 알고(`CV_SIDE`), 자막은 반대쪽 검은 칸에 뜬다 — `force`(`L`/`R`)로 못박을 수 있다(#23 왼쪽 · #39 오른쪽).
줄은 216px 버퍼 안에서 **앞 공백(반각 4px)으로 가운데 맞춘다**: 줄 끝 부호 폭 0, 가장 긴 줄 기준 상대 반올림(줄 사이 ≤2px). 마스터가 편집기로 맞춘 값은 자막의 `pads` 가 자동값을 이긴다.
글리프는 크레딧 전용(Galmuri9 · `credits_map.json` 308자 — 새 글자가 들어가면 `hangul_map.py --freeze-cred`, 없으면 빌드가 멈춘다).

  뒤로 밀고 그 자리에 맵을 두며 디렉터리 레코드의 LBA·크기만 갈아 끼운다. 옛 자리는 죽은
  데이터로 남는다. 엔진은 부팅 때 레코드로 GFS 표를 짜므로 **새 부팅**에서만 반영된다.

  워크램 L 의 맵 꼬리가 옮긴 파일과 바이트 동일(옛 자리엔 다음 파일이 있다) · 자막 표시.

  엔진이 같은 자리(0x200000)에 싣는 `MAP026` 이 130,708B 다 — 그 크기까지는 엔진이 이미 감당한다.
- **실행 경로 해독** — 읽기 추적으로 실제 지나간 자리만 해독하고 `FF 35` 대기로 시각을
  준다(`tools/script_ops.py --path`). ⚠ 파일 전체 훑기용이 아니다.
- **받아쓰기는 20 장면 전부 끝났다** — `work/review/movie/V**.json`, 463 마디.

### 런타임 조사 훅 (인게임 확인 2026-08-31)

`%s` 이 들어가는 시스템 문구는 이름이 **런타임에 꽂히니** 빌드 때 받침을 모른다
(박아 두면 절반이 틀린다 — 인물 20 중 듀르젤·방방·모리슨·알프레드 왕이 받침을 가진다).
⇒ 문안엔 **병기**를 넣고(`%s을(를)`), 표시 직전에 하나로 줄인다.

**인게임 확인** — 도구점에서 둘 다 봤다:

    약초 → 「약초**를** 팔았다.」    (받침 없음)
    구슬 → 「구슬**을** 샀다.」      (받침 ㄹ)

정본은 `tools/patch_josa_hook.py`(설계·좌표·함정이 그 안 docstring 에 있다).
`build.py` 가 `/0.BIN` 재삽입 뒤에 부른다. ⓘ 훅이 안 돌면 `을(를)` 이 그대로 보인다 —
**틀리지는 않는다**(ps1-ed1+2 와 같은 규약).

🔴 **훅 지점은 점프 테이블이 아니라 코드 변위다.** 선조판기의 점프 테이블(`0x06065608`)
83 칸을 우리 자리로 돌리는 방식은 **스텁이 아예 안 돌았다** — 케이브를 바꿔도,
스텝으로 `jmp @r0` 가 우리 주소를 무는 걸 봐도 그 다음이 예외 핸들러였다.
**캐시 통과 미러도 못 쓴다**(표 칸이 부호 16비트라 미러 주소가 사거리 밖).
⇒ **`%s` 처리기 안의 명령 여섯**(`0x06065E5C`, 12B)을 밀어냈다. 실행 중인 코드
한복판이라 도달 경로에 의문이 없고, 밀어낸 코드가 **`r12`(인자 문자열)를 만들어 준다.**

💡 **자기검증이 딸려 온다** — 스텁이 안 돌면 `r12` 가 안 채워져 아이템 이름이 화면에서
사라진다. 「돌긴 도나?」를 따로 물을 필요가 없다.

**남은 것** — `%s` 이 든 문안을 늘릴 때 병기(`을(를)`·`은(는)`·`이(가)`)로 쓰면 된다.
지금 쓰는 자리 다섯: 구매·판매·전수·전투 획득·기술 습득.

## 선택지 글이 칸보다 길 때 — 맵 꼬리 재배치 (2026-10-07)

선택창 항목은 `FF 81 <번호 2B> <글> 00` 이라 글이 스크립트 안에 인라인이고, 칸(원문 바이트)이 모자라면 **뒤 바이트가 밀린다.**
`FF 81` 핸들러(`0x060155CC`)는 글을 해석하지 않고 **포인터만 메뉴 표에 등록**하므로 글이 꼬리에 있어도 된다. 인라인 아이템 코드(`01 xx`)는 선택창이
안 그린다(시험: 칸이 빈다) — 글자로 써야 한다.

- 정본 `script/MAPnnn.json` 의 `"_wide": {"블록": "대역"}` — 값은 **진짜 문안**, `_wide` 는 칸 안에 둘 **대역**(예: 「진홍불꽃」 8B).
  `reinsert.load_script` 는 대역을 돌려주고(재삽입·되풀이 검사가 「칸 안에 뭐가 있나」를 묻는다), 이름 검사·조판 지문은 JSON 그대로(진짜 문안)를 읽는다.
- `choice_tail.patch` 가 `FF 80`(S)부터 **6바이트**(`FF 80 FF 81 00 NN`)를 `FD 00 <꼬리>` 로 덮고, 꼬리에 S 부터 긴 글 앞까지를 복사한 뒤
  진짜 글 + `00 09` + `FD 00 <긴 글 뒤 다음 옵코드>` 를 둔다. 맵 파일은 음성 자막 맵처럼 트랙 1 끝으로 옮겨진다(`build.py`).
- 🔴 **옵코드는 짝수 주소 단위다.** ① 덮는 자리 S 와 꼬리 시작의 홀짝이 같아야 한다 — 처음엔 `FF 80` 앞 `09`(홀수 주소)부터 덮어 저장 목록 UI 가
  떴다. ② 꼬리의 글은 **짝수 바이트**라야 한다 — 11B 「진홍의 불꽃」이 끝의 `00 09` 를 홀수에 앉혀 화면이 멈췄다(PC 가 0 으로 떨어짐). 끝에 반각 공백 하나를 붙여 맞춘다.
- 덮는 6바이트의 마지막 바이트는 원래 값을 지킨다(`mapfile` 이 블록 머리를 알아보게). 꼬리 주소의 낮은 바이트를 그 값에 맞춘다.
