# 이벤트 애니메이션 자막 — 계획

> **상태(10-07)**: 이 문서는 **착수 당시 계획·경위 기록**이다. 결론 — 하드섭으로 열두 편이 빌드에 들어 있다(현재형은 [`design.md`](design.md) 「이벤트 무비 자막」). 아래 「소프트섭」은 폐기됐다.

유저 확정 2026-08-25 미뤄 뒀다가, **2026-08-29 착수**(대사가 닫혀서).

## 무엇이 있나 (실측)

`/CPK/*.CPK` — **Sega FILM** 컨테이너 · Cinepak `320×224` · 음성 2ch **8bit** 22,050Hz **내장**.

| | |
| --- | --- |
| 디스크1 | `M00`~`M08` 9 개 · **5.4 분** |
| 디스크2 | `M09`~`M18` 10 개 · **11.4 분** |
| 합계 | **19 개 · 19.8 분** |

- `M00`(46.9 초)은 **오프닝** — 음악만이고 **대사가 없다**(끝까지 재생해 확인).
- 나머지는 **일본어 음성 대사가 들린다**(유저 청취 확인).
- 별도 `/SAP/*.SAP` — **28 개**(d1 12 · d2 16, `V50~V53` 넷은 양쪽 공통). 아직 정체 미확인.
  ⚠ **표본율을 잘못 적어 뒀었다**(2026-08-29 정정) — 머리가
  `[BE32 프레임수][BE32 2ch][BE32 16bit][AIFF 80비트 확장 부동소수 표본율]` 인데,
  그 지수부가 `0x400D` 라 **22,050Hz** 다(`0x400E` 라야 44,100). 그래서 길이가 두 배다:

  ```
  V01 74.0초 · V04 195초 · V12 284초 …  합계 약 41 분   (무비 19.8 분의 두 배)
  ```

  ⇒ **무비 음성이 아니다**(길이가 어느 편과도 안 맞는다). `V01` 앞 45 초는 **음악**이었다.
  `/SND/MUS*.DAT` 가 따로 있으므로 성격이 더 헷갈린다 — **자막 작업의 걸림돌은 아니라 미뤄 둔다.**
  ⓘ PCM 은 머리 뒤 **`0x080A`** 부터 시작한다(그 앞은 0 으로 채워져 있다).

도구: `tools/cpk.py`(목록·길이 · `--wav` 로 음성 추출).
⚠ 음성은 **planar + signed** 다 — `docs/reference/our-findings.md` 의 해당 항목.

## 🔴 방식이 바뀌었다 — **하드섭**으로 간다 (2026-08-31)

아래 「소프트섭」 절은 **폐기된 계획**이다. 남겨 두는 이유는 왜 접었는지가 판단 근거이기
때문이다. 접은 이유 둘:

1. **엔진의 글자 그리기를 못 쓴다.** 인게임 음성 자막을 파다가 잡았다 — 띠 그리기 함수
   (`0x0600ff70`)가 **VDP1 VRAM `0x25c78000`(0x980B)** 을 직접 채우는데 그 자리에
   **배우 스프라이트 패턴**이 올라와 있다. 자막을 띄운 동안 인물이 뭉갠다
   (`devlog.md` 「자막이 인물을 먹는다」). 「VDP2 남는 레이어를 쓰면 된다」는 아래 낙관은
   **자리를 안 찾아 본 상태의 추정**이었다.
2. **재인코딩을 막던 전제가 틀렸다.** 아래 「왜 재인코딩이 아닌가」의 근거가 무너졌다 —
   ffmpeg 7.1 에 `film_cpk` **먹서**와 `cinepak` **인코더**가 다 있고, 실측하니
   **크기가 오히려 준다**(M05: 3,497,432 → 3,115,138B). ISO 재배치가 없다.
   화질도 원본이 1996년 인코더라 눈에 띄게 나빠지지 않았다(오히려 원본의 블록 깨짐이 줄었다).

⇒ 지금 도구는 **`tools/movie_hardsub.py`** 다. 자막은 게임에 넣는 것과 같은 **Galmuri11** 을
  직접 찍어 PNG 로 얹는다(시스템 폰트를 쓰면 머신마다 바이트가 갈려 제1 원칙이 깨진다).
  `build.py` 가 **구워 둔 것만** 이미지에 넣는다.

## ~~방식 — **소프트섭**(엔진이 그린다)으로 간다~~ (폐기, 2026-08-31)

영상을 다시 인코딩하지 않는다. 커뮤니티 선례 둘이 같은 결론을 가리킨다
(`docs/reference/worklog-consoles.md`):

- **PS2 「령 제로3」**(#31273) — 일어판은 컷신에 자막이 없어 **자막 시스템을 직접 구현**했다.
  이유가 우리와 같다: **영상·음성을 손대지 않아 패치가 1GB 급에서 수 KB 로** 줄었다.
  구현은 ① 프레임 버퍼 스왑 직후 후킹 ② 파일 로드 루틴 후킹으로 재생 중인 컷신 식별
  ③ 자막 데이터 파싱 ④ GPU 전송·합성.
- **PC엔진 「악마성 피의윤회」**(#31144) — 배경 레이어가 하나뿐이라 스프라이트로 자막을 띄우고,
  **1 바이트 명령 자막 스크립트 인터프리터**를 만들었다(`F1` 표시 · `F2` 대기 · `F4` 좌표…).

### 왜 재인코딩이 아닌가

- **화질** — 이미 Cinepak 인 것을 다시 Cinepak 으로 누르면 세대 손실이다. 320×224 라 원본도
  거칠어 눈에 띈다.
- **업스케일은 불가** — VDP 가 `320×224` 를 전제로 재생한다. 해상도를 올리면 VRAM·대역폭·CD
  읽기 속도가 안 맞는다.
- **크기·배치** — 원본 이하로 맞추지 못하면 ISO 재배치가 따라온다.

### 새턴이 유리한 점

- **VDP2 배경 레이어가 여럿**(NBG0~3 · RBG0) — PC엔진처럼 하나가 아니라 **남는 레이어**를 쓸 수 있다.
- **폰트가 이미 있다** — `KANJI12.FON` 에 한글을 구워 뒀다. 령 제로3 가 「원본 폰트 재사용」으로
  푼 자리를 우리는 이미 지났다.

## 남은 선결 과제

🔴 **대본이 게임 안에 없다.** 무비에 자막이 없으므로 **음성을 받아써야** 한다(STT + 사람 검수).
번역 이전 단계이고 사람 손이 든다. `tools/cpk.py --wav` 로 음성을 뽑아 두면 바로 걸 수 있다.

## 순서

**대사 44.2 만 자 → 무비 자막.** 무비는 20 분이라 체감 비중이 작고, SH-2 훅은 지금까지 한
문자열 치환과 성격이 다른 역공학이다. 대사 파이프라인을 굴리며 새턴 코드에 익숙해진 뒤에 붙는다.

### ② 엔진 — **세가 공식 CPK 라이브러리**다 (큰 수확)

`/0.BIN` 을 뒤져 재생 경로를 특정했다. 자체 구현이 아니라 **세가 SDK 의 CPK 플레이어**다:

| 자리            | 무엇                                                    |
| --------------- | ------------------------------------------------------- |
| `0x0605D804`    | `"CPK Version 1.25 1997-06-11"` — 라이브러리 버전 배너   |
| `0x0605E5E8`    | `"FILMraw "` — FILM 컨테이너 파서                        |
| `0x06040050`    | `"M%02d.CPK"` — **파일명 서식**. 재생 중인 편 번호를 코드가 안다 |
| `0x060402F4`    | 그 문자열을 가리키는 리터럴 (유일한 참조)                |
| `0x0601AC6C`    | 디렉터리 표 `SYSTEM MAP BTL EVT SAP CPK SND`             |

**재생 루틴은 `0x0604016C`~`0x06040450` 근처**다. 안에 자리가 둘 보인다:

```
0x060401BE~0x060401E6   프레임 루프 (@(36,r14) 를 되풀이 호출하고 0x60403A0 으로 돌린다)
0x0604023A~0x06040294   같은 꼴의 블록 둘 — 더블버퍼(필드 둘)로 프레임마다 돈다
```

⇒ **자막을 그릴 훅 자리가 있다.** 「령 제로3」가 한 ①프레임 후킹 ②재생 중 컷신 식별을
우리는 **둘 다 이미 손에 쥐었다**(`M%02d.CPK` 가 곧 식별자다).

### ③ 검수 영상 굽기 — GPU(VA-API)로 인코딩 (2026-08-29)

`tools/movie_preview.py`. `ffmpeg` 이 **Sega FILM 컨테이너(`film_cpk`)와 Cinepak 을 기본
지원**해서 CPK 를 그대로 읽는다. 우리가 실측한 `pcm_s8_planar` 오디오 판정도 ffmpeg 과 일치했다.

🔴 **GPU 로 넘어가는 건 인코딩뿐이다.** 나머지 둘은 원리상 CPU 다:

```
디코드  Cinepak      CPU  — 1991년 코덱이라 VA-API 프로파일에 아예 없다
필터    scale+자막   CPU  — libass 는 시스템 메모리 필터다
인코드  H.264        GPU  — h264_vaapi
```

⇒ 체인이 이렇게 된다. `format=nv12,hwupload` 로 **필터가 끝난 뒤** GPU 에 올린다
(VA-API 인코더는 NV12 서피스만 받는다):

```
-init_hw_device vaapi=va:/dev/dri/renderD128 -filter_hw_device va
-vf "scale=640:448:flags=neighbor,subtitles=X.srt:force_style='…',format=nv12,hwupload"
-c:v h264_vaapi -rc_mode CQP -qp 28 -profile:v high
```

**실측**(`M01`, 3분9초 · Ryzen 7 5825U iGPU · Mesa radeonsi renoir):

| | 크기 | 시간 |
| --- | --- | --- |
| GPU qp24 | 33.8 MiB | |
| GPU qp28 | 22.9 MiB | **2초** |
| GPU qp32 | 14.5 MiB | **2초** |
| CPU crf20 | 31.4 MiB | |
| CPU crf26 | 16.3 MiB | 5초 |
| CPU crf26 `slow` | 16.4 MiB | 13초 |

🔑 **GPU 가 더 빠르면서 더 작다** — 같은 프레임을 겹쳐 봐도 구분이 안 간다. VA-API 는 보통
압축률이 나쁜데, 원본이 320×224 저디테일이라 둘이 수렴한 것으로 보인다.
⚠ 화질 단계의 **첫 값은 「가장 긴 편이 한 번에 30MiB 한도 안에 들어오는」 자리**로 잡는다
(전엔 낮게 잡아 매번 두 번 구웠다). `--no-hw` 로 CPU 강제.

🔴 **받아쓰기(Whisper)는 GPU 로 못 옮긴다.** VA-API 는 **영상 코덱 전용 고정기능 하드웨어**지
범용 연산 장치가 아니다. iGPU 로 돌리려면 ROCm 인데 Renoir(gfx90c)는 스톡 PyTorch 지원이
사실상 없다(여기 깔린 것도 `torch+cpu`). ⇒ **STT 의 OOM 은 RAM 으로 푼다** — 16GB+스왑 4GB 로
올리고서야 어절 타임스탬프가 완주했다.
