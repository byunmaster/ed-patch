# scene_shots — 대사 보기(ED1·ED2, 실게임 흐름)

씬 대사나 임의 문안을 **실제 게임이 그리는 창**으로 찍는다. 문안을 고친 뒤 화면에서 줄바꿈·이름창·조사·글리프를 보는 용도다.

    cd games/ps1-ed1+2/tools
    sh ../../../scripts/capture.sh <venv>/bin/python -m scene_shots.shots \
        --core <pcsx_rearmed_libretro.so> --system-dir <BIOS 폴더> --save-dir <저장 폴더> --out <출력 폴더> \
        natural  ED1SCN2:26  "text:이름|본문\n둘째 줄"  ED1SCN4:153 --variant "무받침=발견의 피리" --variant "받침=강철검"

- 에뮬 실행은 **`scripts/capture.sh` 칸**으로만(칸 하나 = 프로세스 하나). 코어 `.so` 는 레포에 없다 — `PS1_LIBRETRO_CORE` 로도 준다.
- 이미지는 기본 현재 `BUILD_DIR`(`--bin`/`--cue` 로 덮는다). 문안은 **그 이미지 안 씬 바이트**에서 읽는다(`catalog` — 이미지 안 오프셋과 씬 오버레이 sprintf 인자까지).
- 산출: `<out>/<대상>_p<쪽>.png`(창이 든 200x96 영역, 테두리 바깥까지) + `index.tsv`(타자끝·커서 열 — 둘 다 1 이어야 완성 프레임).

## 원리와 옛 방식을 버린 까닭

새 게임 → 1장 오프닝 → 엘아스타 성에서 NPC 에게 말을 걸기 직전 상태까지 정식 진행해(`realflow.ROUTE`, 첫 실행 때만 · 상태는 이미지별로 `.local/cache/scene_shots/` 에 캐시)
그 NPC 의 대사 문자열(RAM)을 목표 바이트로 바꾸고 **실제로 말을 건다**. 창 행 수·타자 애니메이션·대기 커서(▽)가 전부 게임 코드가 그린 것이다.

옛 방식(필드 VSync 훅에서 엔진 메시지 표시 함수를 직접 호출)은 실제 흐름과 달라 ① 창이 5행으로 그려져 「이름 + 본문 5줄」에서 이름이 밀려 났고
② 쪽 끝 글자 뒤에 점무늬가 찍혔다(실게임엔 없다 — 실게임은 창 아래 가운데 ▽). 실게임 캡처와 픽셀 차이가 0 임을 확인했다
(「이름+5줄」「이름+4줄」 쪽 각 0px · 자연 대사 대 같은 문안 주입은 ▽ 깜박임 21px 만 다름).

## 한계

- 게임마다 진행 경로·말걸기 대상이 다르다(`realflow.PROFILES`). ED1 은 엘아스타 성 NPC 에게 말걸기, ED2 는 서장 교육계 라우엘 쪽으로 걸어가면 대사가 자동 시작되는 직전(talk=위로 한 걸음)에서 문자열 교체. `--game ED1|ED2`(기본은 첫 씬 대상의 접두). ED2 는 자연 5줄 대사로 대조할 경로가 없어 자연 대사 대 같은 문안 주입(차이 0)으로 증명했다.
- 창 위치는 이 NPC 에서 고정(화면 아래 왼쪽). 필드 위치에 따라 위로 뜨는 창은 안 찍는다.
- `%s`(이름 주입)·`%d` 는 `pages.evaluate` 가 흉내 낸다 — 이름은 `--variant` 로 준다(받침 있는/없는 이름 하나씩).
- 쪽 종단 코드(6/8/11/12)는 문자열에서 떼고 찍는다(실제 흐름에선 창을 닫거나 곧장 이어져 못 찍는다) — 쪽 내용은 같다.
- 말걸기 앞 대사 쪽 수가 바뀌면 `--presses` 를 맞춘다(기본 10). 상태 캐시는 이미지마다 새로 만든다.
