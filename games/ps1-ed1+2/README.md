# PS1 영웅전설 1+2 패처

PS1 『영웅전설 1+2』(The Legend of Heroes I & II - Eiyuu Densetsu, SLPS-01323) 한글패치 제작 도구.

완성된 패치는 이 리포의 Releases에서 `ps1-ed1+2-v*` 태그로 배포 예정 (원본 이미지 미포함).

## 대상

- `Legend of Heroes I & II, The - Eiyuu Densetsu (Japan).bin/.cue`
- 단일 트랙 MODE2/2352 raw 이미지, 107,355섹터 (252,498,960 bytes)

## 지금까지 파악된 구조

- 시나리오 텍스트: **평문 SJIS, 무압축**
  - ED1: `/BIN/ED1SCN1.BIN` ~ `ED1SCN6.BIN`
  - ED2: `/BIN/ED2SCN1.BIN` ~ `ED2SCN13.BIN`
- 전투·시스템 메시지, 지명: `/ED.EXE`, `/ED2.EXE`
- ED2 몬스터명: `/BIN/ED2MON0~5.BIN`
- 엔딩 스크립트: `/END1.EXE`, `/END2.EXE`
- raw 섹터 구조: 유저 데이터는 섹터당 오프셋 +24, 2048바이트 (Mode2 Form1)

### 런타임 (no$psx로 검증, 2026-07-08)

- 같은 바이트 수의 SJIS 교체는 그대로 화면에 반영됨 → 무압축·무결성체크 없음 확정
  (`tools/patch_test.py`로 시작 마을 대사 5곳 교체 테스트 완료)
- 시나리오 텍스트는 RAM 약 0x8016A000 부근에 파일 데이터 그대로 로드됨
  (예: ED1SCN1.BIN 내 오프셋 0x1C7의 문자열 → RAM 0x8016A1C8)
- no$psx 메모리 뷰는 미러 주소(0x0036xxxx 등)로 표시될 수 있음: 물리 = 주소 & 0x1FFFFF
- 대사 사이에 제어 코드 존재: `25 63`("%c"), `0A` 등

### 스크립트 포맷 (ED1SCN1.BIN 선두 분석, `tools/dump_scn.py`)

```
파일 선두: 지명 (예: エルアスタ) + 00 패딩
대사 블록: %c 화자명 %c 0A 본문 %c 00패딩(4바이트 정렬 추정) → 다음 블록
본문 내: 0A=개행, 20=어절 간격, A5=반각 ・
```

- 텍스트가 파일 오프셋 0부터 시작 — 선두 포인터 테이블 없음

### SCN 파일 정체: 코드+텍스트 오버레이 (해결, 2026-07-08)

길이 변경 실험(`patch_lentest.py`, 2바이트 시프트)이 로딩 멈춤 유발 → 원인 분석 결과:

- SCN 파일은 **RAM 0x8016A000에 로드되는 오버레이**. 텍스트 영역(0x0~0x13207) 뒤
  0x13208부터는 **MIPS 기계어 코드**(이벤트 핸들러). 시프트가 코드를 깨뜨린 것.
- 텍스트 참조 방식: 코드 내 **`lui`+`addiu/ori` 절대 주소 쌍**. ED1SCN1 기준 566건이
  562개 블록 전부를 커버 (`tools/hunt_pointers.py`). 별도 u32 테이블 없음.
- **재삽입 전략 확정**: ① 텍스트 영역을 번역문으로 재구성(총량 0x13208 이내)
  ② 각 블록의 새 주소로 lui/addiu 이뮤디에이트 패치(lo≥0x8000이면 hi+1 보정)
  ③ 섹터 재패킹 + EDC 재계산. 전형적인 PS1 오버레이 번역 파이프라인.

### 폰트 (해결, 2026-07-08)

- **1bpp, 행당 2바이트(MSB 우선), 글리프당 22바이트(= 11행 × 2B, 16px 폭 저장). 무압축.**
- 디스크 위치: `ED.EXE`(ED1) / `ED2.EXE`(ED2) 내장 — 엔진별 사본
- 런타임: EXE와 함께 RAM ~0x800F1xxx대에 상주. VRAM에 폰트 텍스처 없음 —
  글리프를 RAM에서 읽어 프레임버퍼에 직접 그리는 방식
- 구성: 구두점→영숫자→가나→그리스/키릴→괘선→한자 (JIS 계열 전체 세트)
- 발견 방법(재사용 가능): no$psx 비압축 스냅샷(`sna_extract.py`) → 프레임버퍼에서
  실제 글자 픽셀 추출 → RAM 다중 패킹 역검색(`hunt_font_in_ram.py`) → ISO 파일 검색

### SJIS→글리프 주소 변환 루틴 (역분석 완료, 2026-07-09)

ED.EXE의 변환 함수(RAM 0x800AE6C8~) 디스어셈블(`find_glyph_routine.py`)로 확정:

- SJIS 2바이트를 합쳐 **범위 판정 → 블록 베이스 선택**:
  - `0x8140~0x84BE` (기호·영숫자·가나) → RAM **0x800F1BA0**
  - `0x889F~0x9872` (한자 1급, 亜~) → RAM **0x800F48A8**
- **글리프 주소 = 베이스 + 로컬인덱스 × 22**
- 한자 블록은 표준 JIS X 0208 순차 → 공식으로 직접 계산 가능:
  `주소 = 0x800F48A8 + ((구−1)×94 + (점−1) − 1410) × 22` (亜 = JIS 16-1 = 1410)
- 프레임버퍼 매칭 검증: 王(0x800F593C), 子(0x800FA5B8)와 공식 결과 일치(±2).
  한자 블록 스트라이드 22 렌더 시 亜唖娃阿哀愛… 깨끗이 재현.
- 로컬 인덱스 계산은 `font_map.py`에 구현(한자). 가나 블록의 로컬 인덱스는
  0x800AE768의 커스텀 계산이라 필요 시 추가 역분석.
- **한글 패치 핵심**: 한자 슬롯(SJIS 0x889F~)을 한글 글리프로 덮어쓰고, 번역문을 해당
  한자 SJIS 코드로 인코딩하면 됨. 인덱스 루틴을 우회 — 게임 자체 매핑을 그대로 활용.

### DOS 정발판(만트라) 대사 추출 + 일문 정렬 (2026-07-09)

번역 저본인 DOS 정발판의 씬별 대사 파일 구조 (ED1 `SINDLL\*.DLL` 225파일, 실측):

- **MZ 헤더 + 공용 인터프리터 스텁**(전 파일 공통 prefix — ED1은 0xF64, 런타임 계산)
  뒤 씬별 x86 스크립트 코드에 **CP949 평문 대사가 인라인**으로 박힘. 포인터 테이블 없음.
- 제어코드: `1E <화자명> 04` 화자 지정, `01` 개행, `05` 페이지 전환, `00` 메시지 종료
- `extract_dos_kr.py`: 한글 런 클러스터링(방법 B) → 블록 2,825개, 전 파일 라운드트립
  무손실. 코드 오탐 필터로 버린 고립 런은 `out/dos_kr/<게임>/_dropped.json`에 전수 기록.
- **씬 대응 규칙 (정렬의 핵심)**: DLL 파일명 둘째 자리 숫자 N ↔ `EDxSCN(N+1)`.
  접두사 = 역할 (T=마을 대화, C=이벤트, D=던전, H=집, A/E/F=보조).
  (검증: T1 폴스↔SCN2 フォルス, T4 대도 게일↔SCN5 大盗賊ゲイル, C3↔SCN4 アートス国王)
- `align_jp_kr.py` 정렬 초안: 화자 매핑(수동 사전 + 가타카나→한글 음차 + 자모 fuzzy,
  119/130 해결) → DLL 단위 Smith-Waterman 국소 정렬(화자·본문 길이·숫자·인명 앵커
  점수) → 국소 재배정 패스. DOS 블록의 74~91% 매칭, `low_confidence`/`unmatched_kr`
  flags로 검토 대상 표시 → `out/align/ED1_SCN<n>.json`.
- **한계 (초안)**: PS1은 리메이크라 JP 블록이 DOS의 2배 이상(5,915 vs 2,825·ED1)이고
  같은 NPC의 상태별 변형 대사는 판본 간 순서가 달라, 의미 비교 없는 신호만으로는
  변형끼리 뒤바뀔 수 있음. 확정은 번역 이식 단계에서 LLM 의미 대조 + 인간 QA로.

### 재삽입 파일럿 — 인게임 한국어 확인 (2026-07-09, DuckStation)

- **길이 고정 모드 성공**: ED1SCN1 180블록 교체(블록 원위치·원길이 유지, 짧으면
  00패딩) → 시작 성 시녀 대사 「***」 화자명 포함 정상 표시. 인코딩(한글=한자슬롯 SJIS + 전각
  구두점)·폰트·조판 전 체인 인게임 검증 완료.
- **메시지 박스 실측**: 자동 줄바꿈이 ~14.5전각에서 개입 → 줄폭 WRAP=14 확정.
  페이지당 3줄 유지.
- **길이 재배치 모드 멈춤 — 근본 원인 규명 (emucap, 2026-07-09)**:
  텍스트 영역(0x0~0x13208) 안에 **대사 블록과 점프 테이블이 뒤섞여** 있다.
  emucap read BP로 멈춘 PC(0x8017DA5C)를 디스어셈블 → `lui at,0x8017` +
  `lw v0,0xffffad48(at)` + `jr v0` = 오프셋 0xAD48대 점프 테이블에서 코드 주소를
  읽어 점프하는 디스패처. 테이블 내용 확인: 0xB90·0xD48 등은 코드 주소 배열
  (`0x8017d69c`…), 대사와 인접. **재배치가 이 테이블을 밀어냄** → 코드의
  `lui+lw` 절대 참조가 옛 위치를 읽어 대사 텍스트를 코드 주소로 오독 → jr 폭주.
  놓친 이유: 재삽입기가 **lui+addiu/ori만** 스캔, `lui+lw` 데이터 테이블 참조
  **53건**(모두 순수 코드 포인터, text 포인터 0개)은 미발견.
- **앵커 기반 재배치로 해결 — 인게임 검증 완료 (emucap, 2026-07-09)**:
  `compute_anchors()`가 `lui+lw` 참조 테이블 범위를 앵커(35구간/15KB)로 잡고,
  이와 겹치는 블록은 pinned(원위치·원바이트 고정) 처리. 나머지 대사는 앵커 사이
  자유 구간에서만 재배치(`reflow_run`, 초과분은 성장폭 큰 것부터 제외). 앵커가
  안 움직여 `lui+lw`가 유효하게 유지된다.
  - **결과**: 예전 멈춤 지점을 통과해 부팅 성공, ED1 시작 성에서 한국어 표시
    (시녀·라이아스 확인). 아이덴티티 라운드트립(번역 0건 = 원본 바이트 동일)도
    통과 — 재배치 기계 정확성 증명.
  - **ED1 전량 일반화 (2026-07-09)**: SCN1~6 파라미터화(오버레이 base 0x8016A000
    전 씬 공통, 씬별 text_end는 scn_jp JSON에서). 한 이미지에 6씬 **1,024블록**
    이식(SCN1 233·2 227·3 164·4 147·5 179·6 74), 전 씬 아이덴티티 통과.
  - **사람 검수 오버라이드**(`align_overrides.json`): 자동매칭이 틀린 짝(시녀
