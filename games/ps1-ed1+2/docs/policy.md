⭐ **`呪文` 은 「주문」이다**(유저 개념 정정 2026-08-13). **마법 = 초자연 에너지 그 자체,
주문 = 그 마법을 발동시키는 명령어(spell).** 사이레스·프람·레스는 전부 **주문**이고
`呪文の書` 도 **주문책**이다.

- 시스템 UI 는 원래 그랬다(`전투의 주문`·`회복의 주문`) — **어긋나 있던 건 대사 쪽**이다.
  정발이 대사에서 `呪文` 을 거의 다 「마법」으로 옮겨 놨다(162곳 중 160곳).
- 교정은 **문안이 아니라 `fix_spacing`** 에 넣었다. 그래야 포인터 블록까지 덮인다 —
  정발 문안을 리포에 안 남기면서 전면 교정하는 유일한 길이다.
- ⚠ 예외 하나: **`마법의 물건`**(용의 알, 2곳)은 원문이 `魔法の品` 라 진짜 마법이다.
- **「정발 느낌을 살려 마법을 부분 허용」은 검토 후 기각**(유저 확정 2026-08-13).
  ED1 정발 **자체가 섞여 있다** — 11개 파일에서 둘이 공존하고 `H_100` 은 **한 줄 안에서**
  갈린다(`어느 주문이 배우고 싶은가?` → `누구의 마법책에 쓰도록 할까?`). 허용하려면
  「어디를 허용할지」 규칙이 필요한데 **정발에 그 규칙이 없다** — 향수가 아니라 흔들림을
  옮기는 게 된다. 결정타는 **2장 제목 카드**다: 우리도 정발도 `침묵의 주문` 이라 쓴다
  (`patch_gfx_cards` · 정발 `C_102`). 제목이 주문인데 대사에서 그걸 마법이라 부르고 있었다.
  ⇒ 주문 쪽에 UI·제목 카드·ED2 전편이 있고 마법 쪽엔 ED1 대사뿐이다.
- 필드 메뉴 `마법사용` 은 그대로 둔다 — 「마법을 쓴다」는 뜻이라 개념과 안 어긋난다.

⛔ **한때 「혼용이 정답」으로 적어 뒀다가 정정했다**(같은 날). 개념을 잘못 잡으면
규칙이 반대로 굳는다 — 그 사이에 SCN2 문안 열 곳을 「마법」으로 바꿨다가 되돌렸다.

⭐ **말줄임표는 `..` → 온점 하나, 3~9개 → 셋**(유저 확정 2026-08-13). 정발이 2~15개로
제각각이었다(2점 26 · 3점 307 · 4점 70 · 5점 18 …). 이것도 `fix_spacing` 규칙이다.
⚠ **10개 이상은 말줄임표가 아니라 「침묵 창」**이라 건드리지 않는다 — 원문도 중점을
그만큼 찍는다(우리 14점 18곳 ↔ JP 중점런 14). 전수 대조로 확인했다.

⭐ **같은 원문의 호칭은 한 표기로 모은다**(유저 확정 2026-08-13). ⚠ **「전하」가 틀린 게
아니다** — 왕족 높임말이라 「~님」과 둘 다 쓸 수 있다(유저 판정). 문제는 **원문 하나에
표기가 둘**인 것이었다:

    エリオンさま  101곳  →  에리온님 93 · 에리온 전하 14   ⇒ 「에리온님」으로 모았다
    ジェルマンさま·フラートさま  →  제르만 전하·프라토 전하  ⇒ 「~님」으로
    国王さま(아토스)  →  국왕 전하                        ⇒ 「국왕 폐하」로

⚠ 한때 「라누라 왕족의 전하는 그대로 둔다」고 적었는데, 세어 보니 **그쪽도 원문이 전부
`さま`** 였다 — 정발이 일관되게 고른 게 아니라 우리 안에서 갈린 것이었다.
⇒ **국왕은 「폐하」, 그 밖의 `さま` 는 「님」으로 모았다.** 다수(93:14)를 따른 것이지
「전하」를 배제한 게 아니다. `check_terms` 가 볼 수 있는 층이 아니니(호칭은 원문 낱말이
아니라 인물에 붙는다) 새 씬을 옮길 때 손으로 센다.

⚠ **개별 낱말의 편차는 여기 적지 않는다** — 지명·인명·아이템처럼 **항목이 계속 늘어나는 것**은
[jeongbal-deviations.md](jeongbal-deviations.md)(편차 대장)가 정본이고, **표기를 바꿀 때마다
그 문서에 추가할 의무**가 있다. 여기는 규칙, 저기는 사례다.

교정 규칙의 구현·함정은 `dos_spelling_fixes.json` 의 `_doc` 에 함께 적혀 있다.

## 재현성 — 배정 정본과 확정 락

**같은 입력이면 어디서 빌드하든 같은 산출물이 나와야 한다.** 이 프로젝트는 한때 그렇지
않았다 — 빌드 경로에 LaBSE 임베딩 + 헝가리안 배정이 있었고, 원작에 **글자까지 똑같은 JP
블록**이 있어(같은 대사를 하는 병사 여럿) 배정이 **정확한 동점**이 됐다. 승자는 부동소수
잡음이 정하니 머신마다 갈렸다. 구조·근거는 게임 [CLAUDE.md](../CLAUDE.md).

두 층이 각자 다른 것을 지킨다.

|               | 지키는 것                        | 파일                |
| ------------- | -------------------------------- | ------------------- |
| **배정 정본** | 어느 정발 엔트리를 쓸 것인가     | `align_map.json`    |
| **확정 락**   | 그 결과 **문안**이 안 바뀌었는가 | `locked_lines.json` |

```bash
#   → 바뀐 블록이 전부 의도한 것인지 눈으로 확인
python3 tools/lock_lines.py --unlock ED1SCN1 <eid …>
python3 tools/build.py
python3 tools/lock_lines.py --freeze ED1SCN1          # 신규만 늘고 "갱신 0" 이어야 정상
```

**"갱신 0"이 안전 신호다.** 갱신이 잡히면 의도하지 않은 대사가 같이 움직였다는 뜻이다.

### 상류 변경으로 확인분이 같이 바뀌었을 때 — `--relock`

맞춤법 일괄 교정·정발 사본 재지정처럼 **의도한 상류 변경**은 확인이 끝난 대사까지 같이
바꾼다. 그때 `--freeze` 를 쓰면 아직 확인 안 된 블록까지 정본으로 승격시키므로
`--relock <씬> <eid …> --why "<사유>"` 로 **해시만** 옮기고 그 자리를 `_requa` 재검수 대기에
적재한다(개수 불변).

⚠ **`--unlock` 을 먼저 하면 안 된다.** `--relock` 은 「이미 잠긴 블록」만 갱신하므로 풀린
자리에는 아무 일도 안 하고, 락이 사라진 채로 남는다(2026-08-11 실측 — 되돌려 다시 했다).

**`_requa` 를 비우는 기준은 「인게임에서 다시 봤다」가 아니라 「판정이 끝났다」**이다.
전/후 문안 대조와 JP 원문 대조로 맞다고 확정되면 `--requa-clear` 로 뺀다 — 그러지 않으면
목록이 수백 건으로 불어 아무도 안 본다. **화면을 봐야만 아는 것**(조판이 바뀐 자리)만 남긴다.

### ⚠ 절대 하지 말 것 — 검증기를 갱신기로 쓰는 것

`lock_lines.py --freeze` 와 `align_map.py --update` 는 **현재 계산값을 정답으로 승인**하는
도구다. 상태가 어긋난 채로 돌리면 **잡아야 할 드리프트를 조용히 덮는다.**

- **머신을 옮긴 직후에 돌리지 않는다.** 2026-08-03 실제로 `--freeze` 로 덮었다가, diff 에서
  출처 테이블이 갈린 것(`ED1/C_001 #10` → `ED1/C_009 #4`)을 보고 되돌렸다.
- 순서는 **빌드 먼저 → 락이 판정 → 필요하면 조치**다. 기준선을 만드는 명령과 확인하는
  명령을 같은 자리에서 돌리지 않는다.
- 정렬을 다시 돌리는 것은 **락 위반의 해법이 아니다.** 동점이라 재계산해도 같은 결과가
  나온다(실측 — 재생성 후 똑같은 24건이 해시까지 동일).

## ⭐ 번역 방침 — 정발을 살리되 고친다 (유저 확정 2026-08-12)

> "정발 퍼스트긴 하지만 **원문과 정발이 너무 다른 경우 원문을 정발 어투로 번역해서** 넣을까
> 해. (이스터에그 제외) 90년대에 번역된 작품이라 오역이 있을 수도 있고.
> **정발을 그대로 옮긴다 → 정발의 향수가 느껴지도록 정발을 살리되 오역은 고친다.**"
> "기왕 하는 거 **사람들이 더 잘 이해되도록** 문장 손보는 게 나을 것 같아."

**바뀐 것은 기준이지 지향이 아니다.** 여전히 정발이 저본이고, 90년대 문체(`~하시옵소서` ·
`~읍죠` · `~로군`)와 고유명사·어휘 선택은 그대로 간다. 다만 **정발을 옮기는 것 자체가
목적이 아니라, 정발의 맛이 나는 좋은 한국어판을 만드는 것**이 목적이 됐다.

| 대상                                     | 방침         |
| ---------------------------------------- | ------------ |
| **오역** — 뜻이 통째로 다름·시제·주체    | **고친다**   |
| **누락** — 원문에 있는 뜻이 정발에 없음  | **고친다**   |
| **뜻 반대** — 이식 차이로 분기가 다름    | **고친다**   |
| **캐릭터 개성** — 시점별 어투가 뭉개짐   | **되살린다** |
| **어색함** — 비문·읽기 어려운 조사·구성  | **고친다**   |
| **구조 불일치** — 정발 창 나눔이 안 맞음 | **고친다**   |
| **이스터에그** — 번역자의 창작·개그      | ✋ **보존**  |
| **90년대 문체·어휘**                     | ✋ **보존**  |
| 뜻이 맞고 표현만 다른 자리               | ✋ 정발대로  |

⚠ **정발 번역자가 넣은 것은 손대지 않는다** — 향수의 핵심이다. `subs`·`note` 가 걸린
자리는 사람이 이미 판단한 것이니 먼저 읽는다. 두 갈래가 있다:

- **이스터에그** — 복제 경고(`ED1SCN2 jp26`) · 퇴마록 개그(`T_131`·`T_132`). 재미로 넣은 것.
- **지역 신앙 「슈미님」** — 마스쿤 교회. 원문은 그냥 `我が教会に ようこそ。ご用件は
何ですかな？` 인데 정발이 **없는 종교를 만들어 넣었다.** 원문 대조로 한 번 되돌렸다가
  유저 판단으로 되살렸다(2026-08-12) — **"교회 기능도 없는데 이런 거라도 살리는 게 좋다."**
  ⇒ 원문에 없다고 다 지우면 정발판의 결이 통째로 빠진다. **원문 대조는 오역을 잡는
  도구이지, 저본의 창작을 지우는 근거가 아니다.**
  ⚠ 화면에 나가는 건 `ED1SCN2 jp365` 하나뿐이다 — 정발엔 마스쿤 교회에 여러 벌 있는데
  대응 블록이 없어 못 나간다.

**왜 바꿨나.** 정발 배정에는 **출구가 없는 자리**가 실재했다 — 원문 뜻이 정발에 아예 없으면
(`jp37` 의 `또 어질러져 있다`) 비슷한 걸 억지로 끌어오거나 보류하는 수밖에 없었고, 그
"비슷한 걸 끌어오기"가 곧 **오배정이자 캐릭터 개성을 지우는 짓**이었다. 원문은 감탄사 한
글자로 주인공을 가르는데(`ん!?` / `お!?` · `うーん` / `うーむ`) 아무 사본이나 가져오면 그게
뭉개진다. 실제 오역도 나왔다 — `jp826`(문장 전체가 다른 뜻) · `jp112`(시제·주체 뒤집힘).

⚠ **어긋나는 자리의 유형은 따로 모은다** — [mistranslation-patterns.md](../../../docs/reference/mistranslation-patterns.md)
(게임 무관. 다음 프로젝트에서 볼 자리를 좁히려고 남긴다).

⚠ **오역 판정은 우리가 한다 — 틀리면 정발보다 나빠진다.** 그래서 고친 자리는 반드시
`note` 에 **원문 근거**를 적고, 대본(`script_dump`)에서 `ours` 로 드러나게 둔다.
확정 락이 승인의 증거라는 아래 규율은 그대로다.

## 저작권 — 무엇을 리포에 두고 무엇을 포인터로 두는가 (유저 확정 2026-08-13)

기준은 **「정발과 같은가」가 아니라 「창작적 표현인가」**다. 같다는 이유로 전부 포인터로 밀면
리포만 읽기 어려워지고 얻는 게 없다.

| 대상                                                    | 어디에                       |
| ------------------------------------------------------- | ---------------------------- |
| **관용·상투 표현** — 인사·응대·확인 프롬프트            | `script/` 에 **그대로 둔다** |
| **번역자의 노력이 들어간 문장** — 어투·어순을 정한 결과 | **포인터**(`align_map`)      |
| 우리가 새로 쓴 문안                                     | `script/` (길이 무관)        |

**왜 상투구는 둬도 되는가.** 저작권은 창작적 **표현**을 보호하는데 `왕자님. 어서 오십시오.`
같은 자리는 원문을 옮기면 누가 해도 그 근처다 — **표현의 선택지가 없다.** 우리가 다시 써도
같은 말이 나오므로 잡아 봐야 고칠 수가 없다. 실제로 겹친 자리들이 그 꼴이었다:

    우리   `아니, 이거 왕자님. (인사말)`
    정발   `(인사말) 왕자님. 환영합니다.`   ← 문장은 다른데 인사말 조각이 겹쳤다

**포인터로 두는 것.** 반대로 서른 자 넘는 서술문 — 어떤 인물을 몰아내고 누가 왕위를 이어야
한다는 식의 긴 대사 — 은 겹칠 이유가 없다. 번역자가 어순·어미를 정한 결과라 실제로 글자
하나까지 같았다. ⚠ **예시를 그대로 옮겨 적지 말 것** — 이 문서도 게이트가 훑는다.

**게이트**는 `check_forbidden` 의 `scan_repo` 다(20자 임계). ⚠ **20자는 법적 경계가 아니라
기계적 선**이다 — 실측으로 그 위아래가 성격이 갈렸을 뿐이니, 애매하면 사람이 본다. 낮게
잡으면 상투구가 영구히 걸려 **늘 빨간불**이 되고 진짜 유출이 묻힌다.

⚠ **문안 파일만 훑으면 못 잡는다.** `subs` 의 찾을 문자열 · `note` 의 인용 · **조판 테스트
픽스처**에서 실제로 샜다(2026-08-13). 그래서 게이트가 `.py`·`.md` 까지 본다.

## 우리 문안(`ours`)을 쓸 수 있는 자리

**기본은 여전히 정발 포인터다.** 문장 테이블은 정발 원본에서 파생되고 리포엔 좌표만 남는다
(루트 CLAUDE.md 저작권 절). 위 방침이 `ours` 를 넓혔지만 **아무 데나 쓰라는 뜻은 아니다** —
정발 문안이 맞으면 정발을 쓴다. `ours` 는 **위 표의 「고친다」에 해당할 때** 쓴다.

⚠ **저작권상으로는 `ours` 가 늘수록 안전하다.** 규칙이 막으려는 건 정발 대본이 리포에 부분
복제되는 것인데 `ours` 는 우리 저작물이다. 단 **`note` 에 정발 문안을 인용하지 말 것** —
좌표(`T_330#6`)와 원문 근거만 적는다.

⚠ **지어낸 한국어는 QA 를 통과한다**(일본어로 두면 스스로 티가 나는 것과 다르다). 그래서
「고쳤다」는 판단은 반드시 기록에 남아야 한다 — `note` 의 원문 근거와 확정 락이 그 장치다.

### 해설(내레이션) — 색은 엔진이, 문체는 우리가 (2026-08-12)

**색은 대체로 손댈 필요가 없다.** 색을 정하는 곳이 셋인데 **둘이 텍스트 바깥**이다:

| 어디서             | 무엇이                                                  | 예                                                       |
| ------------------ | ------------------------------------------------------- | -------------------------------------------------------- |
| **콜사이트 인자**  | 엔진이 블록을 부를 때 색코드를 인자로 넘긴다            | `~가 동료가 되었습니다`(이름 주황·본문 초록) · 해설 초록 |
| 텍스트 바이트      | `COLOR_WRAP`(오버라이드 `color`)                        | jp303 등 **4곳뿐**                                       |
| 콜사이트 즉치 패치 | `SCN_ARG_PATCHES` — 원판 색 배치가 어긋난 자리를 고친다 | `jp280` 리더 교대                                        |

⚠⚠ **블록 바이트에 색코드가 없다고 「색이 안 나온다」고 읽으면 안 된다.** 대부분의 색이
텍스트 밖에 있어 **거의 모든 블록이 색코드 0으로 보인다** — 2026-08-12 에 그걸 근거로
「원판엔 색이 없다」·「`~가 동료가 되었습니다` 가 흰색으로 나간다」고 두 번 잘못 판정했다.
둘 다 화면에서는 멀쩡히 초록이었다. **색은 화면으로 확인한다.**

- 원본 블록 텍스트에 색코드가 든 것은 전 씬 **17개**(주황 9·초록 8)뿐이다.
- `SCN_ARG_PATCHES` 는 원판 자체가 어긋난 자리를 고친다 — `jp280` 은 원판이
  `세리오스=초록·본문=흰색` 이라 **이름 주황(2)·본문 초록(3)** 으로 뒤집었다(유저 2026-07-30).
- 우리가 색을 올릴 자리는 **원본도 흰색인데 해설로 읽히는 곳**뿐이다
  (`(정발 문안)` — 정발도 원판도 흰색이었으나 QA 때 넣었다).
- ⚠ `COLOR_WRAP` 은 **블록 전체**에 걸린다. 한 블록에 해설 창과 대사 창이 섞이면 못 쓴다.

**문체는 층이 둘이다 — 섞지 말 것**(유저 확정 2026-08-12).

|                    | 문체                 | 예                                                    |
| ------------------ | -------------------- | ----------------------------------------------------- |
| **해설**(내레이션) | **`~습니다` 높임말** | `그로부터 라이아스의 잔소리는 끝없이 계속되었습니다.` |
| **시스템 메시지**  | **평어체**           | `~는 보물상자를 열었다.` · `EP 500을 얻었다.`         |

정발이 그렇게 갈랐고, 성격이 달라서 맞는 구분이다 — 시스템 메시지는 **반복 노출되는 로그**라
간결해야 하고, 해설은 화자 없이 **이야기를 들려주는** 톤이다. 평어로 통일하면
`도구점은 휴업인 것 같다.` 처럼 관찰자 서술이 딱딱해진다.

⚠ **실측 사고** — 「해설은 높임말」을 시스템 메시지(`to_plain`)까지 적용했더니 문안이 길어져
**SCN6 정형 블록 10건이 `size` 로 탈락하고 화면에 일본어가 나갔다**(2026-08-12). 빌드는
성공했고 단위 테스트도 통과했다 — `check_scn_jp_left` 가 아니었으면 못 잡았다.
**문안 두 글자를 바꾸는 변경도 다른 씬의 블록을 통째로 떨어뜨릴 수 있다.**

### ⭐ ED1 에는 일본어가 한 톨도 남지 않는다 (유저 확정 2026-08-12)

> "이제 PS1 에서는 **일본어가 한 톨도 나오면 안 돼.** (ED2 제외)"

**옛 규칙은 폐기했다** — 「정발에서 못 찾겠으면 일본어로 두고 QA 에서 확인받는다」. 그건
`ours` 를 좁게 묶어 뒀을 때의 안전판이었고, 위 방침으로 **출구가 생겼으니 더는 필요 없다.**
못 찾으면 이제 **우리가 쓴다.**

- 대상은 **ED1 전부** — `ED1SCN*.BIN` · `ED.EXE` · `ED1MAIN.EXE` · `MONDLL` · 그래픽 · 오프닝.
  텍스트가 SCN 밖에도 있다는 걸 이 레포는 여러 번 잊었다.
- **ED2 는 제외**(아직 착수 전).

### 맞춤법 — 구어체는 그대로, 순수 오류만

> "**구어체는 유지하니까 완전 맞춤법/띄어쓰기/오타만** 잘 잡아보자."(유저 2026-08-12)

경계는 이미 `shared/text/spellcheck.py` 가 긋고 있다 — **A급(공백만 차이)은 반영**,
**B급(글자를 바꾸는 것)은 사람이 고른다.** 검사기는 문체까지 표준어로 미는데 그 오작동이
전부 글자를 바꾸는 쪽에 몰려서(`뵈는 듯 하옵니다`→`뵈는 듯합니다` · `빨랑`→`빨리`) 이
선이 실측으로 잘 듣는다.

주력 도구는 **`spellcheck_render`** — 정발 코퍼스가 아니라 **화면에 나갈 문안**을 본다
(우리 문안 포함). 정본으로 옮기고 나면 이쪽이 유일한 맞춤법 관문이 된다.

⚠ 파이프라인 치환(`dos_spelling_fixes`)은 **정발 원문의 결함을 메우던 층**이라 정본에는
거의 필요 없다. 특히 **부호를 덧붙이기만 하는 규칙은 끈다**(`spell_fix(punct=False)`) —
이미 온점이 있는 우리 문안에 걸려 `주시옵소서..` 가 됐다(실측 2026-08-12).

- 검사는 이미 있는 둘을 쓴다(층이 다르다) — **`check_scn_jp_left`**(SCN 오버레이 대사) ·
  **`check_jp_left`**(전투 코퍼스·이름 테이블·UI). 소스가 아니라 **빌드에서 나온 바이트**를
  보는 게 요점이다.
- ⚠ 이 규칙은 **미번역만 잡는 게 아니다.** 배정이 붙어도 게이트에서 빠지거나 정형 빌더가
  그 꼴을 못 알아보면 JP 가 그대로 나간다 — 두 도구가 그 층을 따로 본다.

**승인의 증거는 확정 락이다.** freeze 는 인게임 확인 뒤에만 하므로(아래 절), 락에 들어 있으면
유저가 화면에서 보고 통과시킨 것이다. 빌드는 이 기준으로 판정한다 —
note 가 "정발에 대응 없음"이라 말하는 `ours` 가 락에도 없으면 **빌드 실패**, 그 밖의 미확인
`ours` 는 경고. 그래서 **경고 수 = 아직 확인 안 된 손타이핑 수**다.

⚠ `ours` 도 `parse_kr` 안에서 `spell_fix` 를 지나간다 — 맞춤법 규칙은 손타이핑 문안에도
걸린다(2026-08-04 확인. "우회한다"고 오해했다가 정정).

## 빌드·검증 운용

- 테스트 이미지는 `work/build/Eiyuu Densetsu (KR).bin/.cue` **하나만** 유지한다.
- **실패한 빌드는 산출물을 무효화한다**(`*.failed` 리네임). 남은 낡은 이미지를 정상으로
  오해하고 조사하면 엉뚱한 결론이 나온다 — 실제로 겪었다.
- **인게임 확인은 유저 직접이 훨씬 빠르다.** 빌드 완료를 알리고 스크린샷으로 검증받는
  흐름을 기본으로 한다. emucap(mednafen)은 보조.
- ⚠ mednafen 은 디스크를 캐시한다 — **빌드 교체 후 reset 은 무효**다. 프로세스 kill + 재launch.
- ⚠ 캐릭터 이름은 **새 게임 시작 시점에 세이브로 복사**된다. 이름 관련 수정은 기존
  세이브로 확인되지 않는다(`로우` 가 `로` 로 나오던 건 이것 때문이었다).
- 📌 **QA 는 소리를 켜고 한다.** 효과음 깨짐은 화면상 무증상이라 텍스트 QA 로는 안 잡힌다.
- 조사 훅 진단: `JOSA_NOOP=1 python3 tools/patch_josa_hook.py` · `--selftest`.

## 인게임 결함을 만났을 때

1. **먹통·소프트락·이벤트 정지**면 코드 추적보다 **differential 빌드로 원인 계층을 이분**한다
   (`PILOT_TEXT_IDENTITY` · `PILOT_FIXED` · `PILOT_NOSPLICE` · `PILOT_IDENTITY` ·
   `PILOT_EXCLUDE_EIDS`). 구조 계약은 게임 [CLAUDE.md](../CLAUDE.md).
2. **"원판엔 없는 버그"로 보이면 원판 A/B 로 먼저 검증한다.** 원판에서도 재현되면 우리
   책임이 아니다(베르가 사령관 이벤트 후 메뉴 먹통이 그랬다).
3. **미번역·오배정이면 사유를 먼저 읽는다** — `work/derived/excluded_*.json` 이
   "왜 이 줄만 일본어인가"에 답한다. ⚠ 다만 **사유가 있어도 남겨 두지 않는다** —
   ED1 에 일본어를 남기지 않기로 했다(위 절).
4. 새로 알아낸 것은 [our-findings.md](../../../docs/reference/our-findings.md) 에 축적한다.

### 창 끝 종결부호 — 상시 규칙 (유저 확정 2026-08-06)

정발은 창 끝 온점을 자주 빠뜨린다. **문장이 온점 없이 끝나면 보고를 기다리지 말고 붙인다**
("모든 문장에 온점 누락이면 내가 말 안 해도 추가해줘"). 파이프라인이 자동으로 한다 —
`reinsert_kr_pilot.close_sentence`.

⚠ **연결어미를 종결로 착각하면 안 된다.** `…동생 말인데요`(jp1087)는 다음 창으로 이어지는
조각이라 온점을 찍으면 문장이 끊긴다. 그래서 `니다`·`십시오`·`았다/었다/겠다` 같은 **확실한
종결형만** 자동 처리하고, `…없지`·`…들어오지` 처럼 잘린 문장과 구별이 안 되는 것은 남긴다
(남은 7건은 인게임에서 판단).

### 정발 문안 vs 교정 — 경계 (유저 확정 2026-08-06)

> "정발에 신중하지만 **맞춤법·띄어쓰기·오타는 교정한다.**"

| 대상                      | 방침         | 예                                                          |
| ------------------------- | ------------ | ----------------------------------------------------------- |
| 문안(어휘·어투·문장 구성) | **정발대로** | `이곳은 도구가게입니다만` 을 통일하지 않는다                |
| 맞춤법·띄어쓰기           | 교정         | `도구점 입니다`→`도구점입니다` · `없을것`→`없을 것`         |
| 명백한 오타               | 교정         | `무레한`→`무례한` · `시끄러`→`시끄러워` · `저질럿`→`저질렀` |
| 종결부호 누락             | 교정(자동)   | `close_sentence` — 위 절                                    |
| 우리 슬라이스 오류        | 교정         | 매매 동사 뒤집힘 — `check_shop_verbs.py`                    |

⚠ **경계는 "정발이 그렇게 쓰려 했는가"다.** 어휘 선택은 의도일 수 있으니 두고, 오타·맞춤법은
의도가 아니니 고친다. ⚠ 교정은 전부 `dos_spelling_fixes.json` 의 낱말 쌍으로 한다 —
**문안을 통째로 교체하는 층은 쓰지 않는다**(남의 대사를 덮은 사고, devlog 2026-08-05).
