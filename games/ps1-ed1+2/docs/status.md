## 인게임 QA 하는 법 — 대조 체크리스트

유저 방침(2026-08-05): **순서대로 대조하며 플레이한다.** ⚠ 단 **전수 대조는 하지 않는다** —
손댈 이유가 있는 자리는 도구가 안다. 세그먼트(시점)마다 셋을 모아 준다:

```bash
python3 tools/segment_copy.py --checklist     # → work/review/PLAYTHROUGH.md   (시점 사본·미번역)
python3 tools/check_text_health.py --report   # → work/review/text_health.md   (구조 결함)
python3 tools/check_window_nl.py --suggest    # 창 앞 개행 결손(+ nl_after 제안·검산)
python3 tools/check_shop_verbs.py             # 상점 매매 동사 뒤집힘
python3 tools/sys_phrases.py                  # 시스템 문구 일원화 현황(JP 변형 전수)
python3 tools/check_variants.py               # 화자 변형 겹침(정발 한 엔트리 = 변형 여러 벌)
python3 tools/check_leader_variants.py --report  # **리더별 대사 변형**이 다 덮였는가
python3 tools/check_line_breaks.py --report      # 줄바꿈이 한 덩어리를 가른 자리(잔여)
```

⚠ **체크리스트 하나로는 못 잡는다**(유저 지적 2026-08-06 "playthrough 가 못 잡는 게 많다").
결함은 종류가 달라 검출기도 나뉜다 — 여섯을 같이 돌린다:

| 검출기              | 잡는 것                                                      |
| ------------------- | ------------------------------------------------------------ |
| `--checklist`       | 시점 사본 어긋남 · 미번역                                    |
| `check_text_health` | **정발 추출 결손** · 인접 블록 중복 · 2인 대사 **자리 목록** |

| `check_variants`    | **화자 변형(`\x06`/`\x07`)이 한 창에 겹쳐 나오는 자리**      |

## 남은 일 (우선순위)

### 0. ⚠ 씬 파일 = 장이 아니다 (기준 정정 2026-08-04)

`ED1SCN1` 은 "1장"이 아니라 **엘아스타·루디아·크루즈·베르가·네리아 지역 파일**이고, 그 지역을
**나중에 다시 방문했을 때의 상태**가 같이 들어 있다(아크담 몰락 후 개심한 병사·항로 재개 후
뱃사공·모험 후반 마법점 등). 그래서 **씬 100% 는 그 장만 플레이해선 도달할 수 없다.**

> **장을 닫는 기준 = 그 장에서 도달 가능한 블록 0건.** 후반 재방문분은 해당 장 QA 때 채운다.

목록은 `python3 tools/todo_untranslated.py [씬]` — 포인터 테이블·플레이트·빈 블록과
**판정 완료분**(`lock_lines.py --settled`)을 빼고 **손이 필요한 것만** 남긴다.
⚠ 확정 락은 _번역된_ 문안만 지키므로 "미번역이지만 확인 결과 문제없다"·"이 장에서 도달 안 함"은
락으로 못 남긴다 — 그래서 `--settled` 가 따로 있다(안 그러면 라운드마다 같은 블록이 또 뜬다).

### 1-0. ⏳ 정발 교정을 **저본 층으로** 올린다 — 2장 닫은 뒤 (계획 2026-08-07)

지금은 교정이 **배정 뒤**에 돈다(`parse_kr`: `resolve_dos_breaks` → `spell_fix` → 고유명).
그래서 `subs`/`pre_subs` 를 쓸 때 **교정 전 원문**을 겨냥해야 하는데 사람은 렌더된 문안을
보고 쓴다 — `무엇이든지 ` 로 썼는데 원본은 `무엇이{n}든지 ` 라 조용히 무변화가 된다
(2026-08-07 두 번 물렸다). 오류가 아니라 **아무 일도 안 일어나는** 게 문제다.

⚠ 급한 불(조용한 무변화)은 **빌드 경고로 이미 막았다** — 한 쌍도 안 맞으면 경고한다
(`sys_phrases` 가 박는 일원화 가드는 안 맞는 게 정상이라 제외). 죽은 치환 8건은 정리했고
이미지 sha1 이 안 변해 순수 정리임을 확인했다. 아래는 **구조 정리** 쪽이다.

**층을 가른다** — 옮길 것과 남길 것이 갈린다:

| 규칙                                            | 어디로    | 이유                                                                                                |
| ----------------------------------------------- | --------- | --------------------------------------------------------------------------------------------------- |
| `replace`(2,353쌍)·`space`·`titles` = 어휘 교정 | ⬆ 저본 층 | 엔트리 안에서 판단이 끝난다                                                                         |
| `resolve_dos_breaks`(`{n}` 해소·어절 붙임)      | ⬇ 그대로  | `{n}` 을 지우면 **슬라이스 인덱스가 흔들리고**, `subs`/`pre_subs` **14쌍이 `{n}` 을 직접 겨냥**한다 |
| come-again 절삭·종결부호 공백·HARD_NL·제어코드  | ⬇ 그대로  | 조립된 문안과 창 폭을 알아야 판단이 선다                                                            |

- ⚠ **원본을 지우지 말 것** — 추출 산출물에 `text`(교정) + `text_raw`(원본)를 같이 둔다.
  `읫`(C0CB 아티팩트)·`\x15m\x13`(수치 주입)·`가 버리다니슬슬`(문장 경계 결손) 셋 다
  raw 를 봐야 원인이 잡혔다.
- **수용 기준은 이미지 sha1 동일.** 순수 리팩터링이면 바이트가 안 변해야 한다.
  ⚠ 지금 `spell_fix` 는 `resolve_dos_breaks` **뒤**에 도는데(`space` 규칙이 붙은 형태를
  먼저 띄워야 한다) 순서가 바뀌는 셈이라 **여기서 diff 가 날 가능성이 제일 크다.**
- 검사기 입력은 이미 교정본이다(`dump_dos_corpus.normalize`) — 그 동기는 이미 충족돼 있다.
- **시점**: 2장 QA 중에는 하지 않는다(전 씬 바이트가 흔들리면 QA 수정과 안 갈린다).
  다른 판본(SS·PC98 …)으로 넓힐 때 저본 층이 깨끗한 값이 붙는다 — [ROADMAP](../../../ROADMAP.md).

⚠ **이 이벤트는 사본이 셋이고 `%s` 소스가 서로 다르다**(유저 재보고로 드러났다). 셋 다
같은 문장을 쓰지만 어느 자리에서 읽느냐로 갈린다:

| 사본             | 자리                        | `%s` 소스             |
| ---------------- | --------------------------- | --------------------- |
| 로우판           | `@0xFAA0` + `@0xFAA8`(지명) | 옆에 붙은 이름 리터럴 |
| **게일 재회 맵** | `@0x10884`(jp913~916)       | **캐릭터 레코드**     |
| 게일판           | `@0x10D84` + `@0x10D8C`     | 옆에 붙은 이름 리터럴 |

**캐릭터 레코드는 세이브에 저장된다.** 게일이 재합류할 때 이름이 레코드로 복사되는데,
옛 빌드에선 그 복사원이 위 일본어 리터럴이었다 → **그 구간에서 만든 세이브는 레코드 자체가
일본어**다(유저 카드 실측: 9번 한글 · **10번 일본어** · 11번 한글 — 탑 구간에서만 덮인다).
새 빌드엔 이미지 어디에도 `ゲイル` 바이트가 없어 그 복사가 다시 일어나지 않는다.
**9번(오염 전) 세이브로 유저 확인 완료** — 게일로 나온다.

⚠ 그래서 **옛 세이브 하나로 검증하면 안 고쳐진 것처럼 보인다.** 이 부류(세이브에 굳는 값)는
`our-findings.md` 의 "화면의 이름이 어디서 오는지" 절에 이미 경고가 있었는데
(`⚠ 3번은 세이브에 복사되는 값일 수 있다 → 새 게임으로 확인한다`) **그걸 안 따랐다.**

⚠ **정적 추적은 틀린 답을 가리켰다.** 디스어셈블로 `%s ← 0x801157AC + [0x80112B43]×0x6C`
(캐릭터 레코드 +0)까지 갔고 그 배열을 채우는 `strcpy` 소스(ED.EXE 0xF8DBC)는 이미 한글이라
"재현 안 될 것"이라 결론냈다. 실제로는 **사본마다 소스가 다른 것**을 못 본 것이었다 —
디스어셈블한 호출부는 셋 중 하나(게일 재회 맵)였다. 경위는 devlog.

⚠ **시스템 문구 색은 닫혔다** — `color` 오버라이드(색코드를 텍스트 바이트로 박는 방식,
`%c` 인자를 안 늘려 구조 계약 불변)로 jp868 을 초록 처리했다. 도구점 휴업 안내(jp164·191)와
같은 계열이다.

### 1-4. 🟢 줄 갈림 자동화 — 조판 규칙 둘 신설 (유저 제안 2026-08-09)

"한 줄에 나와야 뜻이 제대로 전달되는 경우가 꽤 많은데 일일이 눈으로 고치고 있다"에서 나왔다.
`krwrap` 의 고아 정리 자리에 규칙 둘을 더 붙였다 — **재배치라 글자·줄 수·바이트 불변**이다.

| 규칙              | 잡는 것                                            |
| ----------------- | -------------------------------------------------- |
| `_pull_auxiliary` | 본용언(`-아/어`)+보조용언 · `-지 못하다/않다`      |
| `_ADV_ORPHAN`     | 부사(왜·좀·더·안·못·다시) · 수관형사(몇·여러) 고아 |

전 씬 **95창**에서 발동. 잔여는 `python3 tools/check_line_breaks.py --report` — 현재 **77건**
(관형형+의존명사 33 · 부사 고아 20 · `-지` 부정 18 · 보조용언 6).

⚠ 잔여의 상당수는 **하드개행 보호 블록**(`protect_hard`)이라 자동으로 못 고친다 — 줄 경계가
작성자 지정이라 손대면 지정한 조판이 조용히 뒤집힌다. 사람이 `HARD_NL` 을 다시 놓아야 한다.
⚠ **조판 변화는 락·관측 대장이 안 잡는다**(둘 다 문안만 해시한다). 조판을 건드리면 검토표를
직접 떠서 본다.

### 1-4. 🟢 EP 획득 문구 — 전투와 한 벌로 통일 (유저 확정 2026-08-09)

`EP %d를 얻었다.` 한 벌로 맞췄다. **정발은 `포인트` 를 안 쓴다**(`Exp 500를 얻었다.`) —
JP 의 `ﾎﾟｲﾝﾄ` 를 살릴지 물었다가 정발 쪽으로 정했다. 따로 놀던 자리는 하나였다 —

- **마을 해방 보상**(SCN2 jp422)은 JP 가 `%d` 가 아니라 **하드코딩 리터럴**
  (`ＥＰ 500ﾎﾟｲﾝﾄ 獲得。`)이고 정발은 런타임 조립이라 대응 엔트리가 없다 → 자체 번역.
  미배정이던 시절엔 반각 가나가 한글 폰트로 그려져 `500ﾎﾟｲﾝﾄ 넌팀。` 으로 깨져 나왔다.

### 1-4. 🟢 상점 come-again 일원화 — `또 들러 주십시오.` (유저 확정 2026-08-09)

**JP 원판은 전 블록이 `また来てくださいね。` 하나**다(44블록 전수 동일). 갈린 건 정발 쪽이고
(시점 사본마다 `찾아`/`들러`), 우리 쪽 분포도 `들러` 30여 : `찾아` 4 였다. 지배형으로 맞췄다 —
**통일이 곧 원판 복원**이다.

⚠ 정발은 `또 `와 본문을 **다른 엔트리**로 갈라 놨다(앞 엔트리 꼬리가 x86 코드 블록이다).
뒤만 물면 `또` 가 빠진다 — 실제로 4블록이 그랬다(SCN2 jp95·118·367·450).
⚠ SCN1 jp123(루디아 도구점)은 락이 걸려 있어 `--unlock` 후 옮겼다(T_011#0 → 같은 마을
T_014#0 의 꼬리). **아직 재freeze 안 했다** — 인게임 확인 뒤 `lock_lines.py --freeze ED1SCN1`.
전 씬 `찾아` 끝인사 **0건**.

### 1-4. 🟢 마스쿤 폴스 보고 이벤트 — 소프트락 **해결** (2026-08-09)

`(정발 문안)`(SCN2 jp469) 뒤에서 멈췄다.
**대기 루프가 아니라 크래시**였다 — emucap 로 재현해 잡았다:

    ExcCode 4 (AdEL) · EPC = BadVAddr = 0x9420C50A (워드 정렬도 아님)
    → BIOS A0(0x40) SystemErrorUnresolvedException 무한 루프

즉 스크립트가 **쓰레기 주소로 점프**했다. 구조 계약은 멀쩡했다 — 빌드가 실제로 쓴 바이트로
SCN2 전 블록의 `%c`/`%s`/`%d` 를 원본과 대조해 **부족 0건**(초과 1건은 꼬리 잘림)을 확인했다.

**`PILOT_FIXED=1`(전 블록 원본 길이 고정) 빌드는 안 멈춘다** → 길이(위치) 계층 확정.
이 구간(jp464~)은 앵커 뒤에서 통째로 앞으로 당겨진다(jp470 이 −40B). 절대주소로 읽히는
스크립트가 있다는 뜻이다 — 크루즈 아침 자동이동과 같은 부류.

→ **`FIXED_RUNS["ED1SCN2"] = {470}`** 으로 그 런만 원본 길이에 묶었다. **문안 손실 0** —
길어진 14블록은 확장 영역으로 이주했다(제외 0건). 인게임으로 이벤트 끝까지 확인했다.

⚠ **조사 중 딴 결함을 하나 잡았다** — jp473 이 재삽입을 포기하고 일본어로 남아 있었다.
정발 `T_125#27` 이 **4페이지 × `\x06` 화자 변형**을 한 엔트리에 담고 있어 통째로 물면 창이
4개가 되는데 JP 는 1창이라 `build_from_template` 가 포기한다(모드 ③). `27#0.0` 으로 슬라이스.

### 1-4. 🟢 리더별 대사 변형 감사 — 1·2장 **의심 0건** (2026-08-08)

**`tools/check_leader_variants.py`**(신설). PS1 은 같은 자리를 리더별로 **다른 블록**에 두는데
(`セリオス: お前だな!!` · `リュナン: き、きさまだな!!` · …), 한 블록만 빠지거나 두 블록이 같은
정발 변형을 물어도 **그 리더로 플레이할 때만** 드러난다 — 다른 리더로 지나가면 영영 안 보인다.
실제로 구엔의 탑에서 둘 다 걸렸다(`ん!?`/`お!?` 가 둘 다 `오 !?` · `어떻게 이런곳에서.` 가
세리오스판에만).

    묶음 62개 · 의심 21개 — SCN1 0 · SCN2 0 · SCN3 4 · SCN4 8 · SCN5 9 · SCN6 0

⚠ **1·2장은 깨끗하다.** 3~5장 의심은 대부분 **아직 회수 안 한 묶음**(통째로 미배정)이고,
SCN3 의 `T_250#5` 겹침은 **정발에 변형이 셋뿐**(하게체=세리오스·류난 공용)이라 정상이다 —
겹침 자체는 오류가 아니라서, 묶음의 다른 멤버는 다른 좌표인데 일부만 겹칠 때만 의심으로 올린다.
