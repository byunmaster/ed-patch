## 시작하기 — 첫 명령은 빌드다

```bash
cd games/ps1-ed1+2
python3 tools/build.py        # → work/build/Eiyuu Densetsu (KR).bin/.cue
```

**통과하면 그대로 작업을 시작하면 된다.** 머신이 바뀌었든 파생물이 낡았든 상관없다 —
배정 정본(`align_map.json`)이 커밋되어 있어 **어디서 빌드하든 바이트 동일한 이미지**가 나온다.
LaBSE·torch 도 필요 없다(정렬 파일을 전부 지우고 빌드해 sha1 일치를 확인했다).

**`work/` 는 통째로 지워도 된다** — 원본 덤프(`extract_scn.py` · `extract_dos_kr.py`)는
`build.py` 가 매번 새로 뜬다(둘 합쳐 1.3초). `rm -rf work/` 후 재빌드로 sha1 동일 확인
(2026-08-09). 낡은 덤프를 안고 오는 사고를 막으려고 그렇게 바꿨다 — 경위는
[devlog.md](devlog.md).

빌드가 **확정 락 위반**으로 멈췄다면 문안이 바뀐 것이다. 절차는 [policy.md](policy.md).

## 인게임 QA 하는 법 — 대조 체크리스트

유저 방침(2026-08-05): **순서대로 대조하며 플레이한다.** ⚠ 단 **전수 대조는 하지 않는다** —

python3 tools/sys_phrases.py                  # 시스템 문구 일원화 현황(JP 변형 전수)
python3 tools/check_variants.py               # 화자 변형 겹침(정발 한 엔트리 = 변형 여러 벌)

## 남은 일 (우선순위)

### 0. ⚠ 씬 파일 = 장이 아니다 (기준 정정 2026-08-04)

`ED1SCN1` 은 "1장"이 아니라 **엘아스타·루디아·크루즈·베르가·네리아 지역 파일**이고, 그 지역을
**나중에 다시 방문했을 때의 상태**가 같이 들어 있다(아크담 몰락 후 개심한 병사·항로 재개 후
뱃사공·모험 후반 마법점 등). 그래서 **씬 100% 는 그 장만 플레이해선 도달할 수 없다.**

> **장을 닫는 기준 = 그 장에서 도달 가능한 블록 0건.** 후반 재방문분은 해당 장 QA 때 채운다.

목록은 `python3 tools/todo_untranslated.py [씬]` — 포인터 테이블·플레이트·빈 블록과
**판정 완료분**(`lock_lines.py --settled`)을 빼고 **손이 필요한 것만** 남긴다.
⚠ 확정 락은 _번역된_ 문안만 지키므로 "미번역이지만 확인 결과 문제없다"·"이 장에서 도달 안 함"은
락으로 못 남긴다 — 그래서 `--settled` 가 따로 있다(안 그러면 라운드마다 같은 블록이 또 뜬다).

### 0-1. 🔴 오배정 전수조사 — 진행 중 (2026-08-11)

**오배정은 화면만 봐선 못 잡는다**(유저 지적) — 그 자체로 자연스럽기 때문이다. 그래서

| ------------------------- | ---------------------------------------------------------------------------- |

정지다 — 2·3장 QA 를 끝낸 뒤에 붙는다.

### 1-0. ⏳ 추출기 잔여 조각 둘 — 급하지 않다 (2026-08-08)

본체(오퍼랜드 ②③ · gap 꼬리 ①)는 닫혔고 화면에 새는 글자는 **0** 이다. 남은 건 둘.

| 남은 것                                          | 규모                                                                                   | 왜 미뤘나                                                                                                                                                                                                                                                                                         |
| ------------------------------------------------ | -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `` `N `` 인자 슬롯이 화면에 그대로 나온다        | **3블록** — SCN3 jp426·jp461(`` `1 받았습니다``) · SCN3 jp1128(`` `3 들어있었습니다``) | `` `1 ``·`` `3 `` 은 DOS 의 **인자 자리**(PS1 의 `%s` 에 해당)다. 지우면 아이템명이 통째로 빠지고, `%s`(NAME_SENT)로 매핑하면 서식 개수가 바뀌어 게이트를 건드린다. jp1128 은 지금 `fmt_drop` 으로 빠져 있어 **오히려 고쳐질 가능성**이 있는데, 확인하려면 배틀 슬롯 계약(1-2)을 먼저 알아야 한다 |
| `\x11`~`\x16` 이 **제어 범위 오퍼랜드**도 먹는지 | 미조사                                                                                 | 지금은 **뒤가 ASCII 일 때만** 먹는다(`OPERAND1_ASCII`). 제어 범위까지 먹이면 종료자를 삼켜 메시지가 합쳐질 위험이 있고, 지금 화면에 새는 건 없다                                                                                                                                                  |

⚠ 둘 다 **인게임에 보이는 손해가 없다**(첫째는 3블록뿐, 둘째는 0). 배틀 문안 전환(1-2) 때
같이 본다.

### 2. 창 계약으로 막힌 잔여

ED1 전체 제외 **4건**(회수 전 49건 — 페이지 갭 회수 + 추출기 수정으로 `fmt_excess` 는 0 이 됐다).
`size` 3(SCN1 jp1362 · SCN3 jp1126·jp1130) + `fmt_drop` 1(SCN3 jp1128) — 2026-08-11 실측.
1번과 같은 뿌리라 함께 다뤄진다. 사유는 `work/derived/excluded_*.json`.

### 3. 대사 속 지명 표기 — 미결정 (급하지 않음)

HUD 는 슬롯 제약 때문에 **붙여 쓰고**(`크루즈마을`), 대사 본문은 **정발 그대로 띄운다**
(`크루즈 마을`). 유저 확정(2026-08-04): 대사는 유지, HUD 만 예외. 사유·수치는
[jeongbal-deviations.md](jeongbal-deviations.md).

맞추고 싶어지면 대사 쪽 **68블록**(락 25건 포함)을 치환하면 된다 — 실측해 둔 수치다.
2장 QA 중 실제로 거슬리는지 보고 판단한다.

> ⚠ 미치환 지명이 남았는지는 **바이트 카운트로 판정하면 안 된다.** 지명 치환은 새 위치에 쓰고
> 참조를 바꾸는 방식이라 **원본 JP 바이트가 그대로 남는다**(빌드본에 29곳). 인게임으로 볼 것 —
> ED1 1장 구간(크루즈마을·루디아·네리아항구)은 확인 완료.

### 5. ED2 전체 미착수

배정 정본에 ED2 9씬이 들어와 있지만 재삽입·QA 는 시작하지 않았다.
⚠ ED2 씬10~13 은 대응 KR 테이블이 0건으로 잡힌다(씬 규칙 미대응 또는 덤프 누락) — 착수 시 먼저 볼 것.

## 유저 손이 필요한 것

- 🔴 **`kr/ed1-ch2` 는 `main` 위로 리베이스돼 있다**(2026-08-10, 두 번). `origin/kr/ed1-ch2` 에
  올리려면 **force-push 가 필요하다** — 푸시는 유저 몫이라 손대지 않았다.
  되돌릴 백업 브랜치 둘: `kr/ed1-ch2-prerebase` · `kr/ed1-ch2-prerebase2`. 확인 끝나면 지운다.
  ⚠ 히스토리에 **문서만 남은 쌍둥이 커밋**이 있다(제목이 `main` 의 `…덤프를 빌드가 만들게` 와
  같다) — `main` 이 코드 몫을 갖고 이쪽은 문서 몫만 남았다. 제목 정리는 미결.
- **커밋은 순서대로 쌓는다**(유저 확정 2026-08-10) — 장별로 한 커밋씩, QA 반영은 그 장의
  **다음 커밋**으로. 과거 커밋에 끼워 넣지 않는다(같은 JSON 을 뒤 커밋들이 계속 고쳐 충돌하고,
  "무엇을 언제 알았는지"가 무너진다).
- 외부 의존물은 **2026-08-09 기준 전부 최신**이다 — emucap 0.14.1 · create-kr-patch 1.2.1 ·
  patch-template. ⚠ **emucap 을 올린 세션에는 Claude Code 재시작이 필요하다**(MCP 서버가
  메모리에 물려 있어 구 바이너리로 붙어 있다).
- ⚠ **이 머신엔 emucap 어댑터(에뮬레이터 바이너리)가 없다.** 인게임 확인은 맥
  (DuckStation)에서 한다. 여기서 돌리려면
  `sh vendor/emucap/adapters/mednafen/build.sh` + BIOS 배치 —
  [machine-setup.md](../../../docs/machine-setup.md) ③.
- `vendor/emucap` 의 "수정된 파일 3개"(`adapters/desmume-nds/patches/*.patch`)는 **해소됐다**
  — 우리가 고친 게 아니라 CRLF 변환 탓이었고, 그 경로만 변환을 끄면 끝난다(2026-08-09).
  절차는 [machine-setup.md](../../../docs/machine-setup.md) ②.
