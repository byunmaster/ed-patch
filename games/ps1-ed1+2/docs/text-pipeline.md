## 0. 먼저 알아야 할 것 — 구조 계약

엔진은 블록의 **텍스트가 아니라 구조**를 계약으로 읽는다. 아래 장치는 전부 **`%c`·`%s`·`%d`
개수를 안 바꾸도록** 설계돼 있다. 이 셋을 건드리면 증상이 오타가 아니라 **소프트락**이다.

| 게이트           | 조건                        | 뜻                                                  |
| ---------------- | --------------------------- | --------------------------------------------------- |
| `window_deficit` | 재조립본 `%c` **<** 원본    | 종단을 못 만나 뒤 데이터까지 읽는다(치명)           |
| `fmt_drop`       | `%s`/`%d` **<** 원본        | 인자 소비가 모자라 어긋난다                         |
| `fmt_excess`     | `%s`/`%d` **>** 원본        | **없는 인자를 소비**해 인자열이 통째로 밀린다(치명) |
| `ctrl_seq`       | 원본 제어런을 재현 못 함    | 인라인 헤더 미재현 — 색·화자 오배정 방지            |
| `anchor_overlap` | 블록이 포인터 테이블과 겹침 | 이동 금지 대상                                      |

`fmt_excess` 는 2026-08-01 에 추가됐다. 그전엔 **`<` 만 보고 `>` 를 안 봐서** 잠재 소프트락이
전 씬 14블록 잠복해 있었다.

⚠ **빌드 로그의 `경고:` 줄을 매번 확인할 것.** 오버라이드가 조용히 실패하면 그 블록은 일본어로
남는데, 화면만 봐서는 "아직 미번역"과 구분이 안 된다.

### ⚠ 위 게이트가 다 초록인데 화면에 원문이 남는 길 — 색 구간 (`check_jp_leak`)

원문이 `%c<아이템명>%c<나머지>` 로 **색 구간**을 쓰는 자리가 있다. 우리 문안이 그 경계에
안 맞으면 조립기가 **못 채운 구간의 원문을 그대로 둔다** — `%c` 수도 `%s` 수도 원본과 같아
**위 게이트가 전부 통과한다**(ED2 49블록 실측 2026-08-15).

```
%c切符%cを 渡しました。%c  +  "표를 건넸습니다."   →  %c자符%c표를 건넸습니다.%c
%c切符%cを 渡しました。%c  +  "표{p}를 건넸습니다."  →  %c표%c를 건넸습니다.%c   ✅
```

**고치는 법은 원문 구조를 따라가는 것이다** — 색 구간 경계마다 `{p}` 를 둔다. 문안을
바꾸거나 구조와 싸울 일이 아니다(루트 `CLAUDE.md` 「구조와 싸우기 전에 구조를 따르는 안」).

⚠ **화면을 봐도 못 알아챈다.** 한자 슬롯을 한글로 덮어썼으므로 남은 원문은 「엉뚱한 한글」로
렌더된다 — `密造酒` 가 `密짚숌` 으로 보이니 오타처럼 읽힌다. 검출기도 그래서 축이 둘이다:
슬롯 **밖** 코드(`leaked`)만 세면 `密` 은 잡고 `造酒` 는 놓치므로, **원문 raw 와 2글자 이상
연속 일치**(`shared_runs`)를 함께 본다.

```bash
python3 tools/check_jp_leak.py         # 체인 등록분(ED1) — check.sh 게이트
python3 tools/check_jp_leak.py --ed2   # ED2 씬
```

---

⚠ **창은 블록 단위가 아니다.** 엔진은 `%c` 를 만나야 창을 지우므로, `%c` 없이 끝난 블록은
**다음 블록과 한 창에 이어 붙는다.** 조판은 블록 하나를 창 하나로 보고 줄 수를 지키니, 각자
규칙을 지켜도 합쳐서 넘칠 수 있다(무기점 이름1+본문6=7줄 실측). JP 는 같은 자리가 3줄이라
**원본에선 안 드러난다** — 한국어가 길어져서만 생기는 결손이다. `check_tail_cut` 이 센다.
⚠ 이렇게 이어지는 블록 쌍은 **정발 한 문장을 나눠 담아야 한다** — 각자 고르면 앞부분이 겹쳐
같은 인사가 두 번 나온다(도구점 실측).

## 1. 배정 — 어느 정발 문안을 쓸 것인가

`align_overrides.json` 의 블록 항목. 기본형은 `{"table": …, "entry_id": …}`.

### `chain` — 정발 엔트리의 일부만 쓰기

정발 1엔트리가 PS1 여러 블록으로 쪼개져 있을 때 쓴다. 표기법은 **누적**된다:

| 형식         | 뜻                              |
| ------------ | ------------------------------- |
| `"12"`       | 엔트리 전체                     |
| `"12~1"`     | **`\x06` 상태/화자 변형** 1번만 |
| `"12#2"`     | `{p}` 페이지 2번만              |
| `"12#2.3"`   | 그 페이지의 문장 3번만          |
| `"12#2.3-"`  | 문장 3번부터 끝까지             |
| `"12#2.3-5"` | 문장 3~5                        |

**정발이 여러 대사를 한 엔트리에 몰아두는 방식이 셋**이고, 각각 다른 장치로 푼다:

| 정발 쪽 구조           | 뜻                                                        | 푸는 법                                   |
| ---------------------- | --------------------------------------------------------- | ----------------------------------------- |
| `\x06` 로 이어붙임     | 같은 NPC 의 **상태/화자 변형** (한 엔트리에 6개까지 실측) | `chain: ["12~3"]`                         |
| `\x03` 로 이어붙임     | **단계 진행** 대사(말을 걸 때마다 다음 토막)              | `pre_subs` 로 `\x03`→`{p}` 후 페이지 선택 |
| `{p}`·문장 경계 어긋남 | 페이지/문장이 PS1 블록 경계와 안 맞음                     | `#p` · `#p.s` 슬라이스                    |

⚠ **`\x06` 를 그냥 지우면(옛 관례 `subs: [["\\x06",""]]`) 전 변형이 한 창에 쏟아진다.**
정발이 `\x06` 를 쓰는 엔트리는 204개(7.2%)이고 그중 상당수가 아직 미사용 상태다.

### `ours` — 정발에 대응이 없을 때

리메이크 신규 대사 등. **우리 문안**이므로 정발 문법에 맞춰 새로 쓴다. 넣기 전에
**전 정발 풀 LaBSE 재탐색**으로 정말 없는지 확인할 것 — 짧은 대사는 유사도가 안 나와서
있는데도 못 찾는다(한 어절 응답이 0.53 실측).

### `exclude` — 오배정을 물리기

⚠ **번역이 아니라 "이 배정은 틀렸다"는 표시**다. `jp_open` 이 이걸 "번역됨"으로 세던 버그가
있었고(2026-07-31 수정), 그 탓에 해당 블록이 후보 풀에 영영 안 올라왔다.

## 2. 자구 교정

| 키         | 적용 시점            | 쓰임                                                             |
| ---------- | -------------------- | ---------------------------------------------------------------- |
| `pre_subs` | **체인 슬라이스 전** | `{n}`→`{p}`·`\x03`→`{p}` 처럼 **페이지 경계를 새로 만드는** 교정 |
| `subs`     | 체인 슬라이스 **후** | 문구 보정, 제어코드 제거                                         |

⚠ **`subs` 로는 페이지를 못 만든다.** 슬라이스가 먼저 돌아 `#1` 이 빈 문자열이 되고
`본문 없음` 으로 **조용히 실패**한다(경고는 찍힌다). 그때 쓰는 게 `pre_subs`.

### ⚠ 제어바이트는 자리에 따라 뜻이 다르다

`\x10` 은 루드라 `T_320` 에서 **주입 코드**(`\x10의 천` → `드래곤의 천`)인데, 같은 바이트가
**페이지 선두에서는 화자 전환 마커**다(`\x10그렇습니다`). `subs` 로 통째 치환하면
`드래곤그렇습니다` 가 된다 — **뒤따르는 글자까지 묶어**(`\x10의`) 겨냥한다.

### ⚠ 치환 규칙은 이름창에 안 닿는다 — `NAME_CANON`

화자는 본문이 아니라 **DOS 블록 헤더**에서 오고(`extract_dos_kr.block_fields`), 화자 마크업
`{spk}…{/spk}` 은 `spell_fix` 보다 **먼저 잘려 나간다.** 그래서 표기 통일을 치환 규칙으로만
하면 본문은 고쳐지는데 **이름창만 옛 표기로 남는다**(`젤만`, 2026-08-11 실측).
이름 정본은 `reinsert_kr_pilot.NAME_CANON` 이고 `parse_kr` 이 화자를 돌려줄 때 적용한다.

### 전역 교정 — `dos_spelling_fixes.json`

`replace` 는 **전 씬 전역**이라 복제 사본까지 한 번에 잡는다. 정발 오타·띄어쓰기는 대개
여러 곳에 복제돼 있어서(한 규칙이 50곳 넘게 잡은 사례 다수) 블록 단위 `subs` 보다 이쪽이 맞다.
`titles`(인명+직함 띄어쓰기)·`space`·`names_extra` 도 같은 파일.

## 3. 조판(줄바꿈·폭)

- 창 폭 **14.0슬롯** · 창당 **6줄 하드 리밋**. 한글/전각 = 1슬롯, 공백·반각 부호 = 0.5.
  - ⭐ **꼬리가 반각 부호면 14.5슬롯까지** — 「온점 매달기」(2026-08-28). 엔진 한계는 사실
    **29열**(전각 2열·반각 1열 = 14.5슬롯)인데 `prewrap`·드로어가 「전각이 삐져나갈까 봐」
    마지막 열을 통째로 예약하고 있었다. `patch_hang_punct.py` 가 그 가드를 **글자 폭
    조건부**로 바꾸고, `reinsert_kr_pilot._hang_merge` 가 그 덕에 안 갈려도 되는 줄을
    도로 붙인다(실측 384줄). 꼬리 부호는 `HANG_TAIL = ".,!?)\"'"`.
  - 🔴 **셋이 한 몸이다** — 훅 둘(prewrap·드로어) + `_hang_merge`. **하나만 켜면 지금보다
    나빠진다**(엔진이 부호만 다음 줄로 꺾는다 — 2026-07-19 실측이 그 상태였다).
- 반각 부호는 `HALF_PUNCT = ".,!?()"`.
  ⚠ **`~` 를 넣지 말 것** — SJIS 반각 `0x7E` 는 물결이 아니라 **오버라인(‾)** 이라 윗줄
  일자로 렌더된다(2026-08-01 실측). 전각 `～` 가 커 보여도 그게 맞다.
- 곧은 따옴표(`"`·`'`)는 **폰트에 글리프가 없다** → `parse_kr` 이 곡선 따옴표로 정규화한다.
  안 하면 그 페이지를 무는 블록이 통째로 `encode` 탈락한다.

### `dos_break_fixes.json` 의 `line_overrides`

`[고유구절, 개행넣은구절]`. `\n` 이 **하드 개행 마커(HARD_NL)** 로 바뀌어 리플로우가 못 지운다.

⚠ 함정 셋 — 전부 실측으로 데었다:

1. 마커는 `parse_kr` 의 **'선두 opcode 노이즈 절삭' 허용목록**에도 있어야 한다. 빠지면 앞
   부호와 함께 잘려 **강제개행이 조용히 무시**된다.
2. `krwrap` 의 고아 정리는 `protect_hard` 일 때 **건너뛴다**. 안 그러면 어절을 하드 개행
   너머로 끌어내린다.
3. **공백 패딩으로 밀어내려 하지 말 것.** `wrap` 이 `text.split()` + `" ".join()` 으로
   **모든 유니코드 공백을 ASCII 하나로 정규화**한다(전각 공백·NBSP 포함). 구조적으로 불가능.

⚠ 페이지 경계에서는 **한글 없는 조각이 버려진다**(`_kr_pages`). 부호만 남는 조각에 하드
개행을 넣으면 조각째 사라진다 — 조각에 한글이 있어야 산다.

## 4. 화자·이름

### 화자 결정

`accept_pair` 는 **화자 일치를 유사도보다 강한 신호**로 쓴다. 단 **정발 엔트리가 자기
`{spk}` 를 가질 때만** 그 화자를 증거로 본다 — 없으면 앞 엔트리에서 물려받은 것이라
이 엔트리의 증거가 아니다(우리 정발 추출본엔 짝 안 맞는 `{spk}` 잔여가 122블록 있다).

규칙은 **비대칭**이다. 대칭으로 만들면 low_sim 구제분이 같이 죽는다:

- 화자 일치 → 상속이어도 채택
- 자기 `{spk}` 가 있는데 불일치 → 기각(확실한 반증)
- **상속 화자 불일치 → 거부권 없음**, 유사도 기준으로 판정

화면에 엉뚱한 화자가 뜨면 `speaker` 키로 명시하면 된다(오버라이드는 이 관문을 우회한다).

### `name_plate` — 헤더 자리가 **없는** 블록에 이름 넣기

원본 `%c`=1 이라 `%c이름%c` 헤더 쌍이 없는데 화면엔 이름이 떠야 할 때. 색코드+이름+개행을
**텍스트 바이트로 직접** 박는다 — `%c` 를 안 늘리므로 계약 불변.

```json
"name_plate": "사령관"              // 기본 색 (2=주황, 복귀 1=흰색)
"name_plate": [2, "사령관", 1]      // 색 직접 지정
```

**색코드 실측: `2`=주황(화자 이름) · `3`=초록 · `1`=흰색 복귀.**

### `fold_name` — 이름창을 본문 줄로 접기

JP 가 이름을 헤더 줄로 띄우는데 정발은 한 줄로 뽑을 때. `[[이름창 인덱스, 조사], …]`.

### `chain` 의 `+` — 앞 항목에 **이어 붙인다**

체인은 원래 **페이지 단위**다(`chain_text` 가 항목마다 `{p}` 를 붙인다). 그런데 정발이
**한 문장을 엔트리 여러 개에 걸쳐** 둔 자리가 있다 —
`T_042#10~12` = `…사시는게` + `좋{n}을 것` + `입니다.`

```json
"chain": ["10#0.2-", "+11", "+12#0.0"]
```

⚠ 이게 없어서 `subs` 로 **정발 문장을 지어 넣고** 있었다(2026-08-06 회수). 커밋되는 파일에
문안이 남는 문제이기도 했다. (후보를 세던 `check_text_health` 는 2026-08-12 에 걷어냈다 —
번역 정본에서는 우리가 문장을 통째로 쓰므로 「정발 추출 결손」이라는 층이 없다.)

⚠ `"".join` 이라 이음매에 공백이 없다 — 필요하면 `subs` 로 한 글자만 되살린다
(`["게좋", "게 좋"]`). 정발이 단어 중간에서 줄을 바꾼 것도 같이 걷는다(`["좋{n}을", "좋을"]`).

### `nl_after` — 창 뒤 강제 개행

원본이 **인라인 이름 창 앞**에 두는 개행을 복원한다. 기존 `nl_wins`(창 **앞** 개행)는
본문 창에만 걸려 이름 창엔 못 쓰므로, 앞 본문 창의 꼬리에 넣는 방식이다.

⚠ **창 인덱스를 눈으로 세지 말 것** — 템플릿 토큰 기준이라 어긋난다.
`build_from_template` 를 직접 호출해 인덱스를 훑어 찾는다.

**2인 대사(정발 `\x09\x02`)가 한 줄에 붙는 증상이 이것이다**(jp701 실측 2026-08-06).
채우기가 본문 창의 내용을 갈아 끼우며 골격의 창 끝 개행을 잃어 다음 인라인 이름 창
(`%c로우%c`)이 앞 줄에 붙는다. `nl_after: [본문창]` 로 복원한다.
⚠ 이때 `subs [["\x09\x02","{p}"]]` 를 **같이 둬야** 한다 — 빼면 `\x09` 가 `%s` 로 나가
`fmt_excess` 에 걸려 블록이 통째로 제외되고 화면에 일본어가 뜬다.
(전수를 뽑던 `check_text_health` 는 2026-08-12 에 걷어냈다 — 2인 대사는 정본에서 `{p}` 로
창을 갈라 쓰면 되니 *자리 목록*이 따로 필요 없다.)

### ⛔ 문장 **안**의 이름 색 — 원본이 슬롯을 준 자리만 가능

정발은 `\x09\x03`(이름 주입 + 색)으로 문장 중간의 이름을 물들인다. PS1 에서 그게 되려면
**원본 블록이 그 자리에 `%c이름%c` 쌍을 갖고 있어야** 한다. 색은 `%c` 가 소비하는 **콜사이트
인자**로 주입되기 때문이다.

- `1:293` — 원본 `%c` 쌍 있음(`%c`=5) → 색 정상 재현 ✅
- `1:548` — 원본이 이름을 **평문**으로 씀(`%c`=1) → **불가.** 넣으려면 `%c` 를 늘려야 하고
  그건 구조 계약 위반이다. 원판도 그 자리는 색이 없다.

**강제 색상 장치를 만들게 되면** 이 케이스를 같이 검토한다(유저 결정 2026-08-02) — 다만
`%c` 를 안 늘리는 방법(텍스트 바이트 직접 삽입)이 문장 중간에서도 되는지가 관건이다.

### `color` — 블록 전체 색

`[on, off]` 또는 `on`. 색코드를 텍스트 바이트로 직접 박으므로 `%c` 인자를 안 늘린다.
해설(내레이션) 블록에 쓴다.

### `inject_pairs` — 0x5C 이스케이프 글자

팔콤 툴체인이 둘째 바이트가 `0x5C` 인 SJIS 글자를 `%c%c`+인자로 주입하는 자리.
`[[raw오프셋, 주입바이트hex], …]`. `SCN_ARG_PATCHES` 와 세트로 쓴다.

## 9. 막혔을 때

1. **빌드 로그의 `경고:` 와 `제외` 사유부터 본다.** 대부분 여기서 갈린다.
2. 구조 의심이면 원본과 `%c`/`%s` 개수를 직접 센다 — `build_from_template` 를 직접 호출해
   후보 바이트를 뽑아 원본 raw 와 비교하는 게 가장 빠르다.
3. 인게임 먹통·메뉴 잠김 등은 코드 추적보다 **differential 빌드로 이분**한다:
   `PILOT_FIXED=1`(블록 무이동 — 재배치 격리) → `PILOT_TEXT_IDENTITY=1`(대사만 끔) →
   `PILOT_IDENTITY=1`(번역 0건). `PILOT_SCN=ED1SCNn` 으로 씬을 좁힌다.
4. 어투가 흔들리면 **DOS 정발을 띄워 참고한다**(`scripts/emu/dosbox.sh ed1`). ⚠ 이제 정발은
   저본이 아니라 **참고 자료**다 — 맞춰야 할 대상이 아니라 향수의 기준이다.

## 10. 외부 맞춤법 검사기로 전수 교정

정발 문안의 띄어쓰기·오타를 스크린샷 나올 때마다 반응적으로 잡으면 끝이 없다. 코퍼스를
통째로 외부 검사기에 돌려 **치환쌍**을 뽑고 `dos_spelling_fixes.json` 의 `replace` 로 회수한다.

```bash
python3 tools/spellcheck_render.py --report   # **화면에 나갈 문안**을 검사(우리 문안 포함)
python3 tools/spellcheck_render.py --apply    # A급(공백만)만 반영
```

엔진은 **`shared/text/spellcheck.py`**(게임 무관 — 분류·diff·보고서). 판정 근거·함정은 엔진
docstring 이 정본이다.

⚠ **정발 코퍼스 쪽(`dump_dos_corpus`·`spellcheck_corpus`)은 걷어냈다**(2026-08-12). 정발
원문을 교정하던 층인데 번역 정본으로 옮기면서 대상이 우리 문안이 됐다 — 볼 곳은
`spellcheck_render` 하나다.
⚠ **부호를 덧붙이기만 하는 치환 규칙은 정본에 안 건다**(`spell_fix(punct=False)`). 정발에
빠진 온점을 메우려던 규칙이라, 이미 온점이 있는 우리 문안에 걸면 `주시옵소서..` 가 된다.

### 방침 — A급은 검사기를 신뢰한다 (유저 확정 2026-08-02)

한글패치 스킬 1.2.0 은 "맞춤법 같은 언어 휴리스틱은 **사람 검토 후보로만**" 이라고 한다.
우리는 **표본 감사로 근거를 만들어 자동 채택**하기로 했다 — 2,275쌍에서 무작위 60개를 읽었다:

|             |                                                               건수 |
| ----------- | -----------------------------------------------------------------: |
| 정확        |                                                                 56 |
| 명백한 오류 | 2 (`없는뎁쇼`→`없는 뎁쇼` 어미 분리 · `되는대로`→`되는 대로` 부사) |
| 경계 사례   |                                                    2 (틀리진 않음) |

**오류율 3.3%**(전체 환산 약 75건). 감수하는 근거는 셋 — ① 치환은 조판·인코딩·크기 게이트를
그대로 통과하므로 **구조 위험이 0**이다(최악이 "띄어쓰기가 조금 이상함"), ② `replace` 한 줄
지우면 되돌아간다, ③ 인게임 QA 에서 눈에 띄면 그때 뺀다.

⚠ 대사가 아닌 **UI·아이템 라벨처럼 슬롯이 빠듯한 곳에는 이 표를 적용하지 않는다**
(공백 하나가 +0.5슬롯이라 잘린다).

⚠ 정발 코퍼스를 사전 대신 쓰지 말 것 — 코퍼스 자체가 틀린 붙임을 갖고 있어서(그래서 고치는
중이다) "붙은 형태가 코퍼스에 있으니 떼면 안 된다" 식 필터는 **41.9% 오탐**이 났다.

### 어투를 지키는 선 — `공백만 차이`

검사기는 문체까지 표준어로 밀어버린다. 다행히 그 오작동이 **글자를 바꾸는 쪽에 몰린다**:

| 급  | 판정                      | 예                                                    |
| --- | ------------------------- | ----------------------------------------------------- |
| A   | 공백만 다름 → 자동 채택   | `무찌를수`→`무찌를 수` · `네녀석들`→`네 녀석들`       |
| B   | 글자가 바뀜 → 사람이 판단 | `듯 하옵니다`→`듯합니다`(고어체 소멸) · `빨랑`→`빨리` |

A급에서도 셋을 더 뺀다 — **보조용언 붙이기**(`듯 하오`→`듯하오`, 띄어 씀이 원칙),
**부호 옆 공백**(조판 관할), **문맥 의존 짧은 낱말**(`한번`).

⚠ 한글은 음절이 한 코드포인트라 `"줄".startswith("주")` 가 **거짓**이다(어간 `주`+어미 =
종성만 채워짐). 보조용언 판정은 **종성을 뗀 초성·중성**으로 맞춘다.

### 덤프의 함정 — 제어코드가 인자를 감싼다

`\x0F$\x0D` · `\x10d\x11` · `` `1 `` 처럼 **인자를 감싸는** 코드가 있다. 양끝만 지우면
가운데 인자가 본문으로 남아 검사기가 그걸 낱말로 오해하고 조사까지 붙인다
(`` `1 무찌를 `` → `1을 무찌를` 실측). 감싼 채로 통째로 걷어내야 한다.

### 우리 번역은 따로 안 돌려도 된다

`align_overrides` 의 `ours` 는 `parse_kr` → `spell_fix` 를 그대로 타므로 **A급을 반영하면
같이 고쳐진다**(실측 23건). 코퍼스에 없을 뿐이다. 반면 `textmap/*` 은 그 경로를 안 타는데,
규칙 2306쌍을 대봐도 걸린 게 1건뿐이라 개별 수정이 낫다 — 아이템·메뉴 라벨은 슬롯이
빠듯해 공백 하나(+0.5슬롯)에 잘린다.

### 정식 추출기가 없는 타이틀

**`shared/text/ksc_scan.py`** 가 바이너리에서 KSC-5601 문장을 직접 긁는다. 치환쌍만 필요하니
블록 구조가 없어도 된다(ED3 실측 26,492문장). ⚠ cp949 전체를 받으면 임의 바이너리가 한글로
디코드되므로 **완성형(선두 0xB0~0xC8)** 으로 좁힌다. ED4 는 LZ 압축이라 해제기가 먼저다.

## 부록. 핵심 상수·구조 (영구 참조)

옛 HANDOFF 의 "핵심 지식" 절을 옮겨 왔다. 자주 되묻게 되는 값들이다.

- **ED.EXE**: LBA 257. RAM = file − 0x800 + 0x80010000. mednafen `ram` 오프셋 = `& 0x1FFFFF`.
- **`%c` 의 정체**: 창 구분자가 아니라 **제어 인자 escape**(색상 등). 데미지 조립부
  `sprintf(buf, "%c%s%c…", 2, 이름, 1)` 로 확증 — `%c` 에 색코드(2=ON, 1=OFF)가 인자로 들어간다.
  조판 시 제어 토큰 위치를 옮기면 색이 문장 중간에서 바뀐다 → **템플릿 채우기**로 골격 보존.
- **구조 계약(소프트락 방지)**: 엔진은 블록당 **`%c` 세그먼트 수 · `%s`/`%d` 수**를 원본대로
  읽는다. 부족하면 과잉읽기로 소프트락(1장 탈출 먹통의 원인). 재조립본이 부족하면 번역 제외.
- **`%s` 이름 주입 소스**: ED.EXE 0x800 이 아니라 **SCN 오버레이의 널종단 이름 사본**
  (전투 HUD 몬스터명 사본과 같은 계열). `patch_sys_ui.CHAR_NAMES` 가 처리한다.
- **공간(오버레이 확장)**: SCN 파일을 `DUMMY.;1` 영역으로 재배치 + ISO 디렉토리 레코드 패치
  (엔진이 SCN 을 ISO 경로로 로드). `work/derived/scn_layout.json` 매니페스트로 새 LBA 전달.
  ⚠ 도너 풀 `reinsert.DONOR_RUNS` 는 조사 훅 배치용 2런(0xBF5DC/0xC105C)을 **주석 예약 제외**로
  유지해야 한다.
- **HUD 지명 소스**: SCN 오버레이 맵 세그먼트 헤더 = `[포인터테이블] + [지명 널종단] + [%c 대사]`.
- **값 메뉴 정렬**: 값 X = 라벨 렌더폭 + 갭. KR 라벨을 JP 원본 렌더폭에 패딩
  (`patch_sys_ui.VALUE_PAD`). 정렬값은 바이트수 × 3.
- **MIPS 손인코딩 함정**: `andi` rs 필드, load-delay 슬롯 — 디스어셈블 + 시뮬로 검증할 것.

## 좌표는 문안과 **별개로** 틀린다 — `chain` 함정 넷

> `jeongbal-matching` 스킬을 걷어내며 건져 온 것(2026-08-19). 정발 **대조·채택** 절차는
> 자체 번역 전환으로 없어졌지만, **`align_overrides` 의 좌표 장치는 그대로 쓴다** —
> ED2 가 아직 체인으로 돌고 ED1 에도 체인 블록이 남아 있다. 전부 실측이다.

- ⚠ **같은 문장이라고 같은 좌표가 되는 게 아니다.** 시점 사본마다 엔트리 번호가 다르다.
- ⚠ **제어부호로 시작하는 조각은 본문이 빈다** → 빌드가 「본문 없음」으로 죽는다.
  `pre_subs` 로 앞을 걷어낸다.
- ⚠ **한 페이지를 통째로 받으면 두 문장이 한 창에 붙어 `ctrl_seq` 로 탈락한다** →
  **문장 둘을 체인 항목 둘**로 준다(`["24#4.0", "24#4.1"]`).
- ⚠ 한 문장이 엔트리 둘로 갈린 자리(`응? 그 ` + `이상은 …`)는 체인 `+` 로 잇되 **앞 조각을
  페이지 통째**(`#0.0-`)로 받는다 — `#0.0` 이면 `응?` 만 붙는다.
- ⚠ `\x0A`·`\x07`·`\x06` 은 **문장 경계가 아니라 페이지 경계**다 → `pre_subs` 로 `{p}`.

**문안이 안 바뀌어야 하는 변경은 「렌더 일치」로 판정한다.** 상류(추출기·교정 규칙·파서)를
건드릴 때 그게 유일하게 확실한 조건이다 — 실제로 18건이 그래서 되돌아왔다. 반대로 **문안이
바뀌는 판정**은 렌더로 못 하고 **JP 를 읽어서** 정한다.
