# 대사 텍스트 처리 — 장치 레퍼런스

**"지금 무엇을 언제 쓰나"** 를 모은 문서다. "왜 이렇게 됐나"의 경위는 devlog 쪽에 있다:
`josa-hook-devlog.md`(조사 훅) · `ch1-qa-devlog.md`(1장 QA) · `npc-binding-devlog.md`(NPC 바인딩).

⚠ 이 문서는 커밋된다 — **문장급 문안(팔콤 일문·만트라 한국어)은 적지 않는다.** 블록 id 와
구조로만 기술한다(CLAUDE.md 저작권 규칙).

---

## 0. 먼저 알아야 할 것 — 구조 계약

엔진은 블록의 **텍스트가 아니라 구조**를 계약으로 읽는다. 아래 장치는 전부 **`%c`·`%s`·`%d`
개수를 안 바꾸도록** 설계돼 있다. 이 셋을 건드리면 증상이 오타가 아니라 **소프트락**이다.

| 게이트           | 조건                        | 뜻                                                  |
| ---------------- | --------------------------- | --------------------------------------------------- |
| `window_deficit` | 재조립본 `%c` **<** 원본    | 종단을 못 만나 뒤 데이터까지 읽는다(치명)           |
| `fmt_drop`       | `%s`/`%d` **<** 원본        | 인자 소비가 모자라 어긋난다                         |
| `fmt_excess`     | `%s`/`%d` **>** 원본        | **없는 인자를 소비**해 인자열이 통째로 밀린다(치명) |
| `ctrl_seq`       | 원본 제어런을 재현 못 함    | 인라인 헤더 미재현 — 색·화자 오배정 방지            |
| `anchor_overlap` | 블록이 포인터 테이블과 겹침 | 이동 금지 대상                                      |

`fmt_excess` 는 2026-08-01 에 추가됐다. 그전엔 **`<` 만 보고 `>` 를 안 봐서** 잠재 소프트락이
전 씬 14블록 잠복해 있었다.

⚠ **빌드 로그의 `경고:` 줄을 매번 확인할 것.** 오버라이드가 조용히 실패하면 그 블록은 일본어로
남는데, 화면만 봐서는 "아직 미번역"과 구분이 안 된다.

## 1. 배정 — 어느 정발 문안을 쓸 것인가

`align_overrides.json` 의 블록 항목. 기본형은 `{"table": …, "entry_id": …}`.

### `chain` — 정발 엔트리의 일부만 쓰기

정발 1엔트리가 PS1 여러 블록으로 쪼개져 있을 때 쓴다. 표기법은 **누적**된다:

| 형식         | 뜻                              |
| ------------ | ------------------------------- |
| `"12"`       | 엔트리 전체                     |
| `"12~1"`     | **`\x06` 상태/화자 변형** 1번만 |
| `"12#2"`     | `{p}` 페이지 2번만              |
| `"12#2.3"`   | 그 페이지의 문장 3번만          |
| `"12#2.3-"`  | 문장 3번부터 끝까지             |
| `"12#2.3-5"` | 문장 3~5                        |

**정발이 여러 대사를 한 엔트리에 몰아두는 방식이 셋**이고, 각각 다른 장치로 푼다:

| 정발 쪽 구조           | 뜻                                                        | 푸는 법                                   |
| ---------------------- | --------------------------------------------------------- | ----------------------------------------- |
| `\x06` 로 이어붙임     | 같은 NPC 의 **상태/화자 변형** (한 엔트리에 6개까지 실측) | `chain: ["12~3"]`                         |
| `\x03` 로 이어붙임     | **단계 진행** 대사(말을 걸 때마다 다음 토막)              | `pre_subs` 로 `\x03`→`{p}` 후 페이지 선택 |
| `{p}`·문장 경계 어긋남 | 페이지/문장이 PS1 블록 경계와 안 맞음                     | `#p` · `#p.s` 슬라이스                    |

⚠ **`\x06` 를 그냥 지우면(옛 관례 `subs: [["\\x06",""]]`) 전 변형이 한 창에 쏟아진다.**
정발이 `\x06` 를 쓰는 엔트리는 204개(7.2%)이고 그중 상당수가 아직 미사용 상태다.

### `ours` — 정발에 대응이 없을 때

리메이크 신규 대사 등. **우리 문안**이므로 정발 문법에 맞춰 새로 쓴다. 넣기 전에
**전 정발 풀 LaBSE 재탐색**으로 정말 없는지 확인할 것 — 짧은 대사는 유사도가 안 나와서
있는데도 못 찾는다(한 어절 응답이 0.53 실측).

### `exclude` — 오배정을 물리기

⚠ **번역이 아니라 "이 배정은 틀렸다"는 표시**다. `jp_open` 이 이걸 "번역됨"으로 세던 버그가
있었고(2026-07-31 수정), 그 탓에 해당 블록이 후보 풀에 영영 안 올라왔다.

## 2. 자구 교정

| 키         | 적용 시점            | 쓰임                                                             |
| ---------- | -------------------- | ---------------------------------------------------------------- |
| `pre_subs` | **체인 슬라이스 전** | `{n}`→`{p}`·`\x03`→`{p}` 처럼 **페이지 경계를 새로 만드는** 교정 |
| `subs`     | 체인 슬라이스 **후** | 문구 보정, 제어코드 제거                                         |

⚠ **`subs` 로는 페이지를 못 만든다.** 슬라이스가 먼저 돌아 `#1` 이 빈 문자열이 되고
`본문 없음` 으로 **조용히 실패**한다(경고는 찍힌다). 그때 쓰는 게 `pre_subs`.

### 전역 교정 — `dos_spelling_fixes.json`

`replace` 는 **전 씬 전역**이라 복제 사본까지 한 번에 잡는다. 정발 오타·띄어쓰기는 대개
여러 곳에 복제돼 있어서(한 규칙이 50곳 넘게 잡은 사례 다수) 블록 단위 `subs` 보다 이쪽이 맞다.
`titles`(인명+직함 띄어쓰기)·`space`·`names_extra` 도 같은 파일.

## 3. 조판(줄바꿈·폭)

- 창 폭 **14.0슬롯** · 창당 **6줄 하드 리밋**. 한글/전각 = 1슬롯, 공백·반각 부호 = 0.5.
- 반각 부호는 `HALF_PUNCT = ".,!?()"`.
  ⚠ **`~` 를 넣지 말 것** — SJIS 반각 `0x7E` 는 물결이 아니라 **오버라인(‾)** 이라 윗줄
  일자로 렌더된다(2026-08-01 실측). 전각 `～` 가 커 보여도 그게 맞다.
- 곧은 따옴표(`"`·`'`)는 **폰트에 글리프가 없다** → `parse_kr` 이 곡선 따옴표로 정규화한다.
  안 하면 그 페이지를 무는 블록이 통째로 `encode` 탈락한다.

### `dos_break_fixes.json` 의 `line_overrides`

`[고유구절, 개행넣은구절]`. `\n` 이 **하드 개행 마커(HARD_NL)** 로 바뀌어 리플로우가 못 지운다.

⚠ 함정 셋 — 전부 실측으로 데었다:

1. 마커는 `parse_kr` 의 **'선두 opcode 노이즈 절삭' 허용목록**에도 있어야 한다. 빠지면 앞
   부호와 함께 잘려 **강제개행이 조용히 무시**된다.
2. `krwrap` 의 고아 정리는 `protect_hard` 일 때 **건너뛴다**. 안 그러면 어절을 하드 개행
   너머로 끌어내린다.
3. **공백 패딩으로 밀어내려 하지 말 것.** `wrap` 이 `text.split()` + `" ".join()` 으로
   **모든 유니코드 공백을 ASCII 하나로 정규화**한다(전각 공백·NBSP 포함). 구조적으로 불가능.

⚠ 페이지 경계에서는 **한글 없는 조각이 버려진다**(`_kr_pages`). 부호만 남는 조각에 하드
개행을 넣으면 조각째 사라진다 — 조각에 한글이 있어야 산다.

## 4. 화자·이름

### 화자 결정

`accept_pair` 는 **화자 일치를 유사도보다 강한 신호**로 쓴다. 단 **정발 엔트리가 자기
`{spk}` 를 가질 때만** 그 화자를 증거로 본다 — 없으면 앞 엔트리에서 물려받은 것이라
이 엔트리의 증거가 아니다(우리 정발 추출본엔 짝 안 맞는 `{spk}` 잔여가 122블록 있다).

규칙은 **비대칭**이다. 대칭으로 만들면 low_sim 구제분이 같이 죽는다:

- 화자 일치 → 상속이어도 채택
- 자기 `{spk}` 가 있는데 불일치 → 기각(확실한 반증)
- **상속 화자 불일치 → 거부권 없음**, 유사도 기준으로 판정

화면에 엉뚱한 화자가 뜨면 `speaker` 키로 명시하면 된다(오버라이드는 이 관문을 우회한다).

### `name_plate` — 헤더 자리가 **없는** 블록에 이름 넣기

원본 `%c`=1 이라 `%c이름%c` 헤더 쌍이 없는데 화면엔 이름이 떠야 할 때. 색코드+이름+개행을
**텍스트 바이트로 직접** 박는다 — `%c` 를 안 늘리므로 계약 불변.

```json
"name_plate": "사령관"              // 기본 색 (2=주황, 복귀 1=흰색)
"name_plate": [2, "사령관", 1]      // 색 직접 지정
```

**색코드 실측: `2`=주황(화자 이름) · `3`=초록 · `1`=흰색 복귀.**

### `fold_name` — 이름창을 본문 줄로 접기

JP 가 이름을 헤더 줄로 띄우는데 정발은 한 줄로 뽑을 때. `[[이름창 인덱스, 조사], …]`.

### `nl_after` — 창 뒤 강제 개행

원본이 **인라인 이름 창 앞**에 두는 개행을 복원한다. 기존 `nl_wins`(창 **앞** 개행)는
본문 창에만 걸려 이름 창엔 못 쓰므로, 앞 본문 창의 꼬리에 넣는 방식이다.

⚠ **창 인덱스를 눈으로 세지 말 것** — 템플릿 토큰 기준이라 어긋난다.
`build_from_template` 를 직접 호출해 인덱스를 훑어 찾는다.

### ⛔ 문장 **안**의 이름 색 — 원본이 슬롯을 준 자리만 가능

정발은 `\x09\x03`(이름 주입 + 색)으로 문장 중간의 이름을 물들인다. PS1 에서 그게 되려면
**원본 블록이 그 자리에 `%c이름%c` 쌍을 갖고 있어야** 한다. 색은 `%c` 가 소비하는 **콜사이트
인자**로 주입되기 때문이다.

- `1:293` — 원본 `%c` 쌍 있음(`%c`=5) → 색 정상 재현 ✅
- `1:548` — 원본이 이름을 **평문**으로 씀(`%c`=1) → **불가.** 넣으려면 `%c` 를 늘려야 하고
  그건 구조 계약 위반이다. 원판도 그 자리는 색이 없다.

**강제 색상 장치를 만들게 되면** 이 케이스를 같이 검토한다(유저 결정 2026-08-02) — 다만
`%c` 를 안 늘리는 방법(텍스트 바이트 직접 삽입)이 문장 중간에서도 되는지가 관건이다.

### `color` — 블록 전체 색

`[on, off]` 또는 `on`. 색코드를 텍스트 바이트로 직접 박으므로 `%c` 인자를 안 늘린다.
해설(내레이션) 블록에 쓴다.

### `inject_pairs` — 0x5C 이스케이프 글자

팔콤 툴체인이 둘째 바이트가 `0x5C` 인 SJIS 글자를 `%c%c`+인자로 주입하는 자리.
`[[raw오프셋, 주입바이트hex], …]`. `SCN_ARG_PATCHES` 와 세트로 쓴다.

## 5. 조사 훅 (런타임)

병기(`은(는)`·`이(가)`·`을(를)`)를 실행 중에 정확 조사로 다시 쓴다. 이름이 런타임에
주입되므로 조판 시점에는 종성을 알 수 없어서 필요하다.

훅은 **세 지점**이고 전부 같은 `josa_fix` 를 부른다(병기가 없으면 무동작이라 멱등):

| 훅  | 지점     | 대상                                                               |
| --- | -------- | ------------------------------------------------------------------ |
| 1   | assemble | 메시지 조립 경로                                                   |
| 2   | prewrap  | 자동 개행 삽입기 — **개행이 조립보다 먼저** 결정되므로 여기도 필요 |
| 3   | drawstr  | 단문 직접 그리기 경로(파티 합류 등)                                |

배치는 ED.EXE 의 0런 2곳. ⚠ **VAB 헤더 패딩이라 여유가 4B 뿐**이다 — 루틴을 키우면
사운드 뱅크를 침범한다. 진단 스위치: `JOSA_NOOP` · `JOSA_NOPREWRAP` · `JOSA_NODRAWSTR` ·
`--selftest`. 경위는 `josa-hook-devlog.md`.

## 7. 막혔을 때

1. **빌드 로그의 `경고:` 와 `제외` 사유부터 본다.** 대부분 여기서 갈린다.
2. 구조 의심이면 원본과 `%c`/`%s` 개수를 직접 센다 — `build_from_template` 를 직접 호출해
   후보 바이트를 뽑아 원본 raw 와 비교하는 게 가장 빠르다.
3. 인게임 먹통·메뉴 잠김 등은 코드 추적보다 **differential 빌드로 이분**한다:
   `PILOT_FIXED=1`(블록 무이동 — 재배치 격리) → `PILOT_TEXT_IDENTITY=1`(대사만 끔) →
   `PILOT_IDENTITY=1`(번역 0건). `PILOT_SCN=ED1SCNn` 으로 씬을 좁힌다.
4. 정발과 미묘하게 다르면 **DOS 정발을 나란히 띄운다**(`scripts/dosbox.sh ed1`).
   짧은 대사는 LaBSE 가 구조적으로 약해 자동으로는 못 잡는다.

## 8. 외부 맞춤법 검사기로 전수 교정

정발 문안의 띄어쓰기·오타를 스크린샷 나올 때마다 반응적으로 잡으면 끝이 없다. 코퍼스를
통째로 외부 검사기에 돌려 **치환쌍**을 뽑고 `dos_spelling_fixes.json` 의 `replace` 로 회수한다.

```bash
python3 tools/dump_dos_corpus.py                 # 정발 대사 전문 덤프(work/review, 커밋 금지)
python3 tools/spellcheck_corpus.py ED1 ED2       # 검사 → 보고서 + 치환쌍
python3 tools/spellcheck_corpus.py ED1 ED2 --apply   # A급만 replace 에 반영
```

엔진은 **`shared/text/spellcheck.py`**(게임 무관 — 분류·diff·보고서). 여기 어댑터는
코퍼스 수집과 반영 대상만 정한다. 판정 근거·함정은 엔진 docstring 이 정본이다.

### 어투를 지키는 선 — `공백만 차이`

검사기는 문체까지 표준어로 밀어버린다. 다행히 그 오작동이 **글자를 바꾸는 쪽에 몰린다**:

| 급 | 판정 | 예 |
| -- | ---- | -- |
| A | 공백만 다름 → 자동 채택 | `무찌를수`→`무찌를 수` · `네녀석들`→`네 녀석들` |
| B | 글자가 바뀜 → 사람이 판단 | `듯 하옵니다`→`듯합니다`(고어체 소멸) · `빨랑`→`빨리` |

A급에서도 셋을 더 뺀다 — **보조용언 붙이기**(`듯 하오`→`듯하오`, 띄어 씀이 원칙),
**부호 옆 공백**(조판 관할), **문맥 의존 짧은 낱말**(`한번`).

⚠ 한글은 음절이 한 코드포인트라 `"줄".startswith("주")` 가 **거짓**이다(어간 `주`+어미 =
종성만 채워짐). 보조용언 판정은 **종성을 뗀 초성·중성**으로 맞춘다.

### 덤프의 함정 — 제어코드가 인자를 감싼다

`\x0F$\x0D` · `\x10d\x11` · `` `1 `` 처럼 **인자를 감싸는** 코드가 있다. 양끝만 지우면
가운데 인자가 본문으로 남아 검사기가 그걸 낱말로 오해하고 조사까지 붙인다
(`` `1 무찌를 `` → `1을 무찌를` 실측). 감싼 채로 통째로 걷어내야 한다.

### 우리 번역은 따로 안 돌려도 된다

`align_overrides` 의 `ours` 는 `parse_kr` → `spell_fix` 를 그대로 타므로 **A급을 반영하면
같이 고쳐진다**(실측 23건). 코퍼스에 없을 뿐이다. 반면 `textmap/*` 은 그 경로를 안 타는데,
규칙 2306쌍을 대봐도 걸린 게 1건뿐이라 개별 수정이 낫다 — 아이템·메뉴 라벨은 슬롯이
빠듯해 공백 하나(+0.5슬롯)에 잘린다.

### 정식 추출기가 없는 타이틀

**`shared/text/ksc_scan.py`** 가 바이너리에서 KSC-5601 문장을 직접 긁는다. 치환쌍만 필요하니
블록 구조가 없어도 된다(ED3 실측 26,492문장). ⚠ cp949 전체를 받으면 임의 바이너리가 한글로
디코드되므로 **완성형(선두 0xB0~0xC8)** 으로 좁힌다. ED4 는 LZ 압축이라 해제기가 먼저다.
