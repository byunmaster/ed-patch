## 9. ED2 오프닝(OPEN2.EXE) — 이식 조건이 다 섰다 (2026-08-14)

**동영상 EXE 넷은 같은 코드가 일정하게 옮겨진 것이다.** 코드 영역을 32B 창으로 훑어 델타를
투표시켰다 — **OPEN2 −0x1A4**(61%) · END1 −0x4(60%) · END2 −0x1AC(60%). 나머지가 안 맞는
건 코드 안의 절대주소가 그만큼 달라지기 때문이고, 오히려 그게 「옮겨졌다」는 증거다.

ED1 오프닝 한글화(`patch_opening_font.py`)의 다섯 조각이 **전부 델타 자리에 있다**:

| 조각                                        | OPEN1     | OPEN2     | 확인                              |
| ------------------------------------------- | --------- | --------- | --------------------------------- |
| 폰트베이스 획득부(`jal`/`nop`/`addu s0,v0`) | `0xC684`  | `0xC4E0`  | 구조 동일, `jal` 대상만 다름      |
| PC0 훅 스텁 자리(저작권 문자열)             | `0x15C14` | `0x15A70` | **바이트까지 동일**               |
| 압축 폰트 임베드 자리                       | `0x15CE0` | `0x15CE0` | 같은 자리(0런)                    |
| 전각 advance A                              | `0x13370` | `0x131CC` | 명령 동일                         |
| 전각 advance B                              | `0x13750` | `0x135AC` | `lw` 오프셋만 다름(데이터 포인터) |

**폰트도 든다.** ED2 오프닝은 26줄 · **고유 음절 137**(ED1 은 50줄 · 208)이라 네이티브
4,110B → 압축하면 2.6KB 안팎이고, `0x15CE0` 이후 0런이 **3,664B** 다(ED1 은 4,084B).
⚠ 공간이 ED1 보다 **420B 좁다** — ED1 폰트(3,988B)를 그대로 옮기면 **안 들어간다.**
반드시 ED2 문안으로 다시 구워야 한다.

문안은 이미 있다 — `textmap/opening_ed2.json`(정발 26줄,
`originals/kr/dos-ed2/OPENING.EXE 0x99102~` 파생).

### 🔴 남은 것 — 구현과 검증

1. **`patch_opening_font.py` 를 게임별로 연다.** 지금은 OPEN1 상수가 모듈 전역이고
   `main()` 안에도 주소가 박혀 있다(411줄). 델타를 받아 다섯 자리를 옮기면 된다.
2. **자유 RAM 검증** — OPEN1 은 런타임 폰트 자리(`0x80080000`)와 스텁 자리를 **에뮬레이터
   RAM 덤프**로 확인해서 잡았다. OPEN2 는 오프닝 동안 메모리 사용이 다를 수 있다.
   ⚠ 이 레포엔 전례가 있다 — **「0런이 3중 검증을 통과해도 사운드 뱅크 안일 수 있다」**
   (효과음이 조용히 깨졌다). 정적 판정으로 끝내지 말 것.
3. **손인코딩 스텁 검산** — 옮긴 뒤 `verify_asm` 으로 연속 디코드 + 지연 슬롯 확인.
   과거 스텁 오타 둘에 반나절을 썼다.

⚠ **틀렸을 때 증상이 검은 화면·소프트락**이라 확인 비용이 크다. 그래서 시스템 UI·전투를
먼저 넣었다(되돌리기 쉽고 확인이 쉽다).

## 12. SCN — 정본에 직접 쓰되, 정발 후보를 옆에 둔다 (2026-08-14)

**자동 승격은 안 된다.** 사람이 검증한 `ED2SCN1` 104건을 정렬기 제안과 대조했다:

| 정렬기                        | 좌표 일치 | 문안 동일(좌표만 다름) | 문안도 다름 | **화면 기준** |
| ----------------------------- | --------: | ---------------------: | ----------: | ------------: |
| 구조(`align_jp_kr`)           |        15 |                      — |           — |       **14%** |
| 의미(`align_semantic`, LaBSE) |        58 |                      4 |          38 |       **62%** |

⚠ **「좌표가 다르다」가 곧 오류는 아니다** — 정발엔 같은 문안이 여러 표에 복제된 시점 사본이
있어 다른 표를 가리켜도 화면은 같다. 그걸 갈라야 진짜 정확도가 나온다(4건이 그랬다).

62%도 자동 승격엔 부족하다. 틀리는 38%가 **엉뚱한 대사**다 — `jp22` 는 라우엘의 「또
빠져나가려 하지 마십시오」 자리에 「무리하지 않도록 조심하십시오」를 물어 온다.

### ⚠ 도구를 지우면 그 도구가 만들던 것도 같이 지워진다

처음엔 구조 정렬기 수치(14%)만 보고 **「배정을 버린다」고 판단할 뻔했다.** ED1 정본을 만든
건 의미정렬인데 그 도구는 도구 정리(83 → 55) 때 지워져 있었고, **유저가 「의미정렬이 뭐냐,
데비안에선 못 하냐」고 물어서야 되짚었다.** torch 는 데비안에서 그냥 받아진다(CPU 휠).
`tools/align_semantic.py` 를 되살렸다(게임 인자로 트랙을 제한하도록 고쳐서).

### 그래서 이렇게 간다

**정본(`script/ED2SCN*.json`)에 우리 문안을 직접 쓴다.** 다만 번역할 때 **정발 후보를 옆에
둔다** — 62%가 맞으므로 어투·어휘를 살리는 데 충분히 값이 있다. 후보가 맞으면 그 표현을
쓰고, 아니면 정발 어투로 새로 쓴다. 블록 대 엔트리로 묶지 않으니 **한 칸 밀림 사고가
구조적으로 안 난다.**

⚠ 파이프라인은 손댈 게 없다 — `_load_script()` 가 `script/*.json` 을 파일명으로 집어 씬을
만든다. `script/ED2SCN1.json` 을 두고 빌드하니 그대로 이미지에 들어갔다.

## 11. 전투 문안 — 남은 건 조사 훅이 여는 문이다 (2026-08-14)

`patch_ed2_battle.py --plan` 의 「번역 없음 342」를 갈라 보니 **전투·시스템은 32건뿐**이고
나머지 **310건은 프롤로그·챕터·이벤트 대사**였다. 즉 전투 트랙에 남은 일은 작고, 310건은

32건은 옮겼다(제자리 60 → **90**).

### ⚠ 넘침 50건의 원인은 하나다 — 조사 병기

원문 `は` 는 2바이트인데 우리 `은(는)` 은 **6바이트**다. 넘치는 자리를 늘어놓으면 부족분이
대부분 +1~+3바이트라 **병기가 곧 원인**이다:

```
は目がさめた。      14B → `은(는) 깨어났다.` 18B   슬롯 16B
```

ED1 은 **동적 조사 훅**으로 이 4바이트를 회수한다(`patch_josa_hook.py`). ED2 에는 없다.

⚠ **이식은 별도 프로젝트다.** 훅은 858줄의 손인코딩 MIPS 이고 `ED.EXE` 의 전투 텍스트
조립 함수와 **그 실행파일의 자유 공간**(VAB 헤더 패딩)에 묶여 있다. ED2 로 옮기려면
①ED2.EXE 의 대응 함수 ②ED2.EXE 안의 안전한 0런 ③주소 재인코딩 이 셋을 다시 해야 하고,
⚠ **0런은 3중 검증을 통과해도 사운드 뱅크 내부일 수 있다**(효과음이 조용히 깨진다).
게다가 런타임 코드라 **인게임 검증 없이는 못 닫는다.**

문안을 줄여서 맞추는 길도 있지만, 그러면 ED1 과 표기가 갈린다(같은 문자열을 공유한다).

## 8. ED2.EXE 시스템 문자열 — 구획 넷 · 590건 (번역 완료, 소재만 남긴다)

`ED2.EXE`(LBA 756, 872,448B)를 SJIS 널종단으로 훑어 구획을 특정했다. 잡음(바이너리가
한자로 디코드되는 것)은 「가나가 있거나 한자 3자 이상」으로 걸렀다.

| 구획              | 건수 | 내용                                                                       |
| ----------------- | ---: | -------------------------------------------------------------------------- |
| `0x00800–0x00F44` |  128 | 파티 이름(アトラス·ランドー·フローラ·シンディ) · 무기/방어구/도구 · 주문서 |
| `0x03D7C–0x0BBEB` |  261 | 전투·시스템 메시지 · 창고 주인 · 관광선 가이드 · 나라 이름 · 메모리카드    |
| `0x99C8E–0x9A54E` |  137 | 메뉴 · 전투 커맨드 · 전투 설정 · 지명 두 벌(플레이트 16B · 이름 14B)       |
| `0xD4868–0xD4B46` |   56 | 시나리오 전용 아이템(ナイフ·布の服·光の杖·切符·密造酒 …)                   |

⚠ **문안만 넣으면 글자가 안 나온다** — 한글 폰트는 `reinsert_kr_pilot` 이 **ED.EXE 에만**
굽는다(`hangul_map.slot_ed_offset`). ED2.EXE 는 자기 폰트를 갖게 했고(`font_map.FONT_BASE`),
**OPEN2·END1·END2 는 아직 없다** — 오프닝·엔딩을 이식할 때 폰트 자리부터 찾아야 한다.

⚠ **파티 메뉴는 ED.EXE 와 사본 관계다**(`patch_sys_ui` 주석, `ED2.EXE 0x99C84`).
공유가 아니라 사본이라 같은 자리를 두 번 고쳐야 하고, 갈리면 한 디스크가 두 말을 한다.

## 13. 조사 훅 — ED2 이식 조건이 다 섰다 (2026-08-15)

전투 문안 넘침 50건의 단일 원인은 **조사 병기**다(`은(는)` 6B). ED1 은 런타임 훅이 병기를
줄여서 이 문제가 없다 — **같은 훅을 ED2.EXE 에 붙이면 50건이 통째로 풀린다.**

조건 셋을 정적으로 다 확인했다:

| 조건        | 결과                                                                          |
| ----------- | ----------------------------------------------------------------------------- |
| 훅 지점 셋  | ✅ 도출 — `HOOK 0x80089A8C` · `PREWRAP 0x80089798` · `DRAWSTR 0x800805BC`      |
| 워크버퍼    | ✅ `0x800F1718`, 줄 stride **66 — ED1 과 같다**                               |
| 글리프 슬롯 | ✅ 같은 체계(`font_map.FONT_BASE` 는 폰트 **위치**만 다르다) → 비트테이블 재사용 |
| 배치 자리   | ✅ VAB 헤더 패딩 **508B 짜리 16곳**(`vab.safe_len` 실측) — ED1 과 같은 수법     |

도출은 `tools/check_josa_sites.py` 가 매번 다시 한다 — ED1 훅 지점의 명령어 열을 **주소를
마스크해** 시그니처로 삼고 ED2.EXE 를 훑는다. 세 지점 다 **후보가 정확히 하나**다.

**구현은 끝났다**(2026-08-15) — `patch_josa_hook.SITES` 가 게임별 표고, `site(게임)` 이
파생값(복귀 지점·RAM 주소·원명령)까지 채운다. `build_and_patch(ed, "ED2")` 가 그대로 돈다.
`--selftest` 가 두 게임 모두 **조립·배치 예행**을 통과시킨다(원명령 대조 · VAB 파형 침범
검사 포함). ⚠ ED1 경로는 **바이트 하나 안 변한다**(빌드 sha1 A/B 로 확인).

🔴 **남은 것은 켜는 것과 인게임 확인뿐이다.** `build.py` 체인에서 ED2.EXE 에도
`build_and_patch(..., "ED2")` 를 부르면 된다. 안 켠 이유는 하나다 — 훅이 틀리면 증상이
**크래시**라(ED1 도 구판 훅이 죽은 이력) 에뮬레이터가 붙는 자리에서만 켜야 한다.
