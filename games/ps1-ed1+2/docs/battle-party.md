# 전투 파티 구조체 · 레벨업 판정 · 전멸 판정 (정적 역추적, 11-03)

레벨업·전멸 화면을 현재 롬에서 찍기 위한 좌표 모음. **디스어셈블만으로 도출했고 에뮬로는 아직 안 읽었다** —
첫 촬영 차례에 `runner3/play.py --dump` 로 대조한다(아래 「검증」). 원판 `ED.EXE`(LBA 257)·`ED2.EXE`(LBA 756)를
PS-X EXE 헤더(로드 `0x80010000`, 파일 오프셋 = 주소 − `0x80010000` + `0x800`)로 읽었다.

## 한 줄 결론

- 파티 구조체는 **배열이 둘**이다 — 영구 배열 **B**(필드·메뉴·저장이 보는 것)와 전투 사본 **A**(전투 중 갱신되는 것). 한 칸 **0x6C 바이트 × 4**(0x1B0).
- 전투 시작 때 **B → A** 를 통째 복사하고, 이긴 뒤 **A → B** 로 되쓴다(졌을 때는 되쓰지 않는다).
- 10-31 에 쓴 `0x80108B30+0x6c×k` 는 **파티가 아니다** — 장면 인터프리터가 쓰는 게임 상태 바이트(참조 1,300여 곳, 저장 구간 `0x80108B00..`)였다. 그래서 써도 전투가 안 따랐다.

| | B (영구) | A (전투 사본) | 복사 |
|---|---|---|---|
| **ED1** `ED.EXE` | `0x80115758 + 0x6C·k` | `0x801661A8 + 0x6C·k` | B→A `0x80055F5C`(전투 편성 `0x80055EAC` 안) · A→B `0x80047354`(승리) · `0x8004F208`(이벤트 전투 승리) 외 |
| **ED2** `ED2.EXE` | `0x800F0FE8 + 0x6C·k` | `0x8013D670 + 0x6C·k` | B→A `0x8004AC6C` · `0x8006A438` · A→B `0x8003AA98`(승리) 외 |

저장은 B 를 첫 `0x1B0` 바이트로 직렬화한다(ED1 `0x800989E4`, 루틴 `0x80098A60..` 가 전역을 `0x80099534(주소, 버퍼, 길이)` 로 하나씩 쓴다).
전투 사본 A 는 저장되지 않는다.

## 필드 (A·B 공통, 한 칸 안의 오프셋)

| 오프셋 | 형식 | 뜻 | 근거 |
|---|---|---|---|
| +0x00 | u8 | 상태 비트 — **0x80 = 전투불능(죽음)** | 승리 보상·전멸 판정이 `& 0x80` 으로 건너뜀 |
| +0x02 | u8 | **레벨** (1~98) | 레벨업 루틴이 `+1`, 판정 함수 인자 |
| +0x04 | u32 | 현재 HP | 레벨업 뒤 갱신 표시·HP 막대 갱신 (`0x80080FA8` 등) |
| +0x08 | u32 | 최대 HP | 레벨업이 `+= 증가분×2` (`0x8007FABC`) |
| +0x0C | u32 | 현재 MP | |
| +0x10 | u32 | 최대 MP | 레벨업이 `+= 증가분` |
| +0x1C | u32 | **경험치** (상한 `0xFFFFFF`) | 보상 루틴이 더하고 판정이 읽음 |
| +0x20 · +0x24 | u32 | 공격력 · 방어력 (장비로 재계산, `0x80082FB8`) | |
| +0x28~0x2B | u8 | 능력 증가분 등(레벨업 때 읽음) · +0x28..0x30 은 장비 번호도 겸함 | 정확한 쓰임은 미확정 |
| +0x3F~0x53 | u8 | 상태이상·이름 등. **+0x54 부터 이름** (`%s` 가 가리킴) | 승리 메시지가 `A+0x54` 를 이름으로 출력 |
| +0x46 | u8 | 0 이 아니면 전멸 판정·보상에서 **빠진 칸**(부재 멤버) | 판정 루틴 |

ED2 도 +0x00·+0x02·+0x04·+0x08·+0x1C 는 같다(`lbu`/`lw` 접근 패턴이 같고 판정 함수·경험치 표가 바이트 단위로 같다).
나머지 칸(+0x0C 이후)은 ED1 만 읽었다.

⚠ 10-31 devlog 의 「레벨 +0x0a · HP×10 +0x0c · 경험치 +0x24」는 틀린 좌표를 기준으로 한 값이라 **무효**(올바른 오프셋은 위 표, 기준이 +8 어긋남).

## 레벨업 판정

- **보상 루틴** ED1 `0x80043A8C(결과)` — 결과 1 = 승리, 2 = 패배. 승리 쪽은 ① 돈(`0x801086B8`) 가산 ② 칸마다 `exp += 몫` (몫 = `0x800983E4(총 경험치 0x80108AC0)`, 상한 `0xFFFFFF`) ③ 칸마다 `while 판정(exp, 레벨) == 1 && !(+0 & 0x80) : 레벨업(k)`. 죽은 칸·부재 칸(`+0x46`)은 건너뛴다. ED2 는 같은 구조(`0x8003A2A8..`, 판정 호출 `0x8003A808`).
- **판정** ED1 `0x8007F88C(exp, 레벨)` · ED2 `0x8005CCC0` — 레벨 0 이거나 99 이상이면 `0x42`, `exp > 0xFFFFFE` 이면 0, 아니면 `exp >= 임계값(레벨)` 일 때 1.
- **임계값** ED1 `0x8007F6BC(레벨)` · ED2 `0x8005CAF0` — 증가 표 44칸(u32, ED1 `0x80018F7C` · ED2 `0x80015098`, 두 표가 같다)의 **앞 `레벨`칸 합**. 레벨 ≥ 44 는 앞 43칸 합 + `(레벨−43) × 표[41]`(= 57949).

```
표 = 20 40 56 78 108 148 201 271 363 483 638 836 1087 1402 1795 2280 2873 3591 4453 5477
     6682 8085 9702 11545 13623 15939 18489 21262 24239 27390 30677 34051 37456 40827 44093 47180
     50011 52512 54612 56250 57375 57949 57949 57949
임계값(1)=20 · (2)=60 · (3)=116 · (5)=302 · (10)=1768 · (20)=26200 · (43)=804098 · (98)=3991293
```

- **레벨업 실행** ED1 `0x80043928(칸)`: 「<이름>은 레벨업했다」 메시지(문자열 `0x8001413C`) → `0x8004781C`(장비 재계산 `0x80082FB8`) → `0x8007FABC`(레벨 +1, 최대 HP += g₀×2, 최대 MP += g₁, g = +0x28/+0x29) → 능력치 창(`0x800A3D58`).
- 레벨업 직전 상태 만들기: 레벨 L, 경험치 `임계값(L) − 1`, 승리하면 몫 ≥ 1 이 더해져 오른다. 여러 번 보려면 `임계값(L)+임계값(L+1)` 쯤을 준다(`--over`).

## 전멸 판정

- ED1 `0x800444EC` — 칸 0~3 에서 `+0x46 == 0` 이고 `!(+0 & 0x80)` 인 칸이 하나라도 있으면 0(생존), 없으면 1(전멸). **HP 가 아니라 +0 의 0x80 비트**를 본다 — HP 0 이 되면 어딘가에서 그 비트를 세우는 것으로 보이나 그 쓰기 지점은 미확인.
- 호출: 전투 단계 함수 ED1 `0x80047290..`(승리 `0x800445E8` → 보상 1, 아니면 패배 `0x800444EC` → 보상 2). 패배 보상(`0x80043A8C(2)`)은 「…는 전투에서 패했다」 메시지(`0x800141A4`)를 낸다.
- 승리 판정 `0x800445E8`: 적 칸(`0x8015F925 + 0x40·k`, 개수 `0x801088F2`)이 전부 0 이면 승리.

## 촬영 시나리오 (runner3)

`.local/work/inbox/ps1-ed1+2/battle-run/runner3/party.py` 가 `--poke` 문자열을 만든다. `play.py` 는 `--poke` 를 **조우 전에** B 에 쓰고(전투 시작이 B→A 로 복사한다), `--dump` 로 조우 직후 B·A 의 레벨·HP·경험치·상태를 찍는다.

```
P=$(python3 party.py levelup ED1 --level 5 --members 0)          # 레벨 5, 경험치 301 → 승리 시 레벨업
python3 play.py --game ED1 --state <필드 상태> --enc <약한 조우> --poke "$P" --dump --keys <공격 열>
P=$(python3 party.py wipe ED1)                                   # 전원 HP 1 → 적의 첫 공격에 쓰러진다
```

- 검증(다음 차례 첫 일): ① `--dump` 의 A 값이 poke 한 B 값과 같은가(복사 확인) ② 레벨업: 승리 뒤 「레벨업」 메시지·능력치 창 ③ 전멸: 패배 메시지와 게임 오버 연출. 한 곳이라도 어긋나면 위 표의 해당 오프셋부터 의심한다.
- 미확정 둘: HP 가 정말 +0x04 의 원시값인가(표시 ×10 여부는 안 읽음) · 죽음 비트를 세우는 지점. 전멸이 HP 1 로 안 일어나면 +0 에 `0x80` 을 B 에 직접 쓰는 길도 있다(필드에서 죽은 멤버 상태와 같다).
