`tools/narrow_claims.py` 신설. 상세는 HANDOFF 참조. 근거는 **창 수(W) = PS1 구조 계약**이고,

## 2. ⚠ 소프트락 — 게이트가 한쪽만 보고 있었다

유저가 **진행 불가**(대사가 안 넘어감 + 쓰레기 글자)를 보고했다. 원인:

`build_block` 의 구조 계약 게이트 둘이 오래도록 **`<`(원본보다 적을 때)만** 검사했다 —
`window_deficit`(`%c`)·`fmt_drop`(`%s`/`%d`). **넘치는 건 안 봤다.**

`jp245` 는 원본 `%s` 가 0개인데 정발의 `\x09`(이름 주입)가 `%s` 를 만들어 1개가 됐다. 원본은
그 자리에 **리터럴 인라인 헤더**(`%c<이름>%c`)를 쓴다. 엔진이 **없는 인자를 소비**하며 인자열이
통째로 밀려 쓰레기 글자가 뜨고 흐름이 멈췄다.

대칭 게이트 `fmt_excess` 를 넣으니 **전 씬 14블록**이 걸렸다 — 전부 같은 지뢰:
`SCN1 245·548·699·701 / SCN2 402·521·614·617·622 / SCN3 247 / SCN4 568 / SCN5 1117·1149 /
SCN6 54·124`.

### 되살리는 법 (jp245 로 확립)

막힌 블록은 **원본 구조를 그대로 재현**하면 살아난다. 게이트를 우회하는 게 아니다:

| 장치                    | 용도                                                                                                                                          |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `subs: [["\\x09", ""]]` | 정발 이름 주입이 원본의 **리터럴** 헤더 자리에 올 때 **제거**. 이름은 템플릿의 인라인 헤더가 채운다 — 리터럴로 *치환*하면 이름이 두 번 나온다 |
| `speaker`               | `\x09` 를 지우면 화자 해석이 실패하므로 명시                                                                                                  |
| `nl_after`              | 원본이 인라인 이름 창 **앞**에 두는 개행 복원                                                                                                 |

결과 `%c`=5·`%s`=0 으로 원본과 정확히 일치. 나머지 13블록도 같은 조합으로 살릴 수 있을 것이다.

⚠ `nl_after` 의 창 인덱스는 **눈으로 세면 안 된다**(템플릿 토큰 기준이라 어긋난다).
`build_from_template` 를 직접 호출해 인덱스를 훑어 찾는다.

### 7-1. `subs` 는 페이지를 만들지 못한다 → `pre_subs`

치환은 **슬라이스 뒤에** 돈다. 그래서 `subs` 로 `{p}` 를 넣어 페이지를 쪼개려 하면 이미 늦었고,
`#1` 이 빈 문자열이 돼 `본문 없음` 으로 조용히 탈락한다. 슬라이스 **전에** 도는 `pre_subs` 를
새로 팠다(13건). ⚠ 경고는 찍히고 있었는데 내가 grep 을 안 했다 — 침묵이 아니라 내가 안 본 것.

### 7-2. 인라인 이름 헤더 — 지울 것이냐 채울 것이냐

정발은 이름을 `\x09`(이름 주입)로 넣는데 PS1 은 블록에 따라 둘로 갈린다. **반대로 하면 이름이
두 번 나오거나 아예 빠진다.**

- **템플릿이 이미 이름 창을 채우는 블록**(`jp245`) → `\x09` 를 **지운다**. 안 지우면 중복.
- **이름이 본문 텍스트인 블록**(`jp548`) → `\x09` 를 **이름으로 치환**한다.
- ⚠ 이때 뒤따르는 `\x03` 까지 **같이** 소비해야 한다. 남기면 그 자리가 공백으로 렌더돼
  조사가 떨어진다(`게일 이라고` → `게일이라고`).

### 7-3. 게일 동료 문구가 일본어였던 이유 — 이스케이프 오타

`ED1SCN1.559` 의 `subs` 가 `\x09\x02` 를 지우려 했는데 정발 `T_031` 의 실제 바이트는 `\x09\x03`
이었다. 매칭이 조용히 실패 → `\x09` 잔존 → **창 수 계약 불일치(1≠2)로 템플릿 경로가 탈락** →
원본 일본어가 그대로 나갔다. 로우(`jp317`)와 동형으로 맞춰 회수.

**교훈: 오버라이드를 복붙할 때 제어 바이트는 표마다 다르다.** 치환이 안 먹으면 조용히 원문이
나가므로, `subs` 를 쓸 땐 대상 문자열이 실제로 존재하는지 먼저 확인한다.

### 7-4. 강제 개행은 조판이 아니라 데이터로

`모두들, 크루즈 마을이 안전해.` 는 **14.5슬롯**이라 14슬롯 한계를 넘는다(정발은 온점이 없어
딱 14.0 이었다). 온점을 빼는 대신 `dos_break_fixes.json` 의 `line_overrides` 로 하드개행을
넣어 3줄로 잡았다 — `HARD_NL` 은 `protect_hard` 를 켜 문장 리플로우가 못 지운다.

### 7-5. 인라인 이름 색상은 현재 불가

`#126`(본문 중간 이름에 주황). 정발에는 색 제어가 없고 우리 파이프라인에도 **강제 색상 장치가
없다**. 유저 판단으로 보류 — 장치를 만들면 같이 적용한다.

### 7-6. 반각 부호 함정 (2건)

SJIS 반각(JIS X 0201) 은 ASCII 가 아니다. `~`(0x7E)는 `‾`(윗줄)로, `-` 도 일자 대시로 렌더된다.
`HALF_PUNCT` 에 넣기 전에 **실제 글리프를 확인**한다. 현재 안전 집합은 `.,!?()` 뿐.

### 7-7. 사령관 이벤트 후 메뉴 불가 — **원판 버그**(우리 것 아님)

베르가 사령관을 쓰러뜨리고 게일이 합류한 뒤, 필드에서 `✕` 를 눌러도 메뉴가 안 열린다.
이동은 정상이라 "이벤트가 건 메뉴 잠금이 안 풀린" 모양새 — 재삽입이 이벤트 종료 경로를
끊었나 의심할 만하다. **차분 빌드 대신 JP 원판으로 같은 지점을 재현했더니 원판도 똑같이
막혔다**(2026-08-02, mednafen). 확인한 것:

- 화면 sha 완전 동일 → 입력이 아예 안 먹음. 방향키 이동·카메라 스크롤은 정상.
- 같은 맵 안에서는 12칸 이상 걸어 나가도 동일. `✕` 뿐 아니라 `△` 도 무반응.
- 이벤트 전에는 `✕` 로 메뉴가 열린다(양쪽 다) → 버튼 매핑 문제가 아니다.
- **맵을 넘어가면 풀린다** — 한 화면 아래 「베르가 광산남서」로 나가면 `✕` 정상(KR 확인).

즉 팔콤 PS1판 자체의 결함이고, **그 맵 한정 · 맵 로드가 잠금을 대신 푼다**. 진행 차단이
아니라 원판도 이대로 출시된 흠집이다.

**고치려다 접은 기록(유저 판단: 간단하면 고치고 복잡하면 넘어간다)** — 잠김 2표본 ×
풀림 3표본(같은 맵 1 + 다른 맵 2)으로 5중 RAM diff 를 걸었다. `L1==L2 && A==B==E &&
L1!=A` 조건이라 위치·HP·골드·파티구성·맵데이터가 전부 상쇄되는데도 후보가 **4,692B /
2,177구간**에서 안 줄었다. 플래그다운 단일바이트 33개 중 유력 후보(`0x80112E45`)를
직접 써 봐도 안 열렸고, 포인터형 후보는 전부 스택(`0x801FFxxx`)이었다.

⇒ **"메뉴 금지 플래그 한 개"가 아니다.** 차이가 넓게 퍼져 있고 맵 로드로만 풀린다는 건
**이벤트 스크립트 VM 이 그 이벤트를 아직 물고 있는 상태**(정상 종료를 못 하고 이동만
양보)에 가깝다. 맵 로드가 VM 을 초기화하니 그때 풀린다. 고치려면 SCN 옵코드 레벨에서
종료 경로를 손봐야 하고 실패 증상이 소프트락이라 위험 대비 이득이 나쁘다 — [mod] 트랙
과제로 미룬다. **다음에 붙는다면 데이터 플래그 탐색이 아니라 필드 상태머신부터.**

재현이 애매한 인게임 이상은 **차분 빌드보다 원판 대조가 먼저다** — 여기서는
`PILOT_TEXT_IDENTITY` 한 판(빌드 2분 + 재플레이)을 통째로 아꼈다.
