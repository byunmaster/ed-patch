### ⭐ 교훈 — 확정분은 계산에서 빼내야 한다

인게임에서 통과했던 대사가 자꾸 **조용히 딴 대사로 바뀌었다**. 뿌리는 하나다 —
**정렬·배정 결과가 소스가 아니라 매 라운드 재계산되는 파생물**이고, 그 파생물은
`work/`(gitignore)라 **머신을 안 따라간다**. 집→회사로 옮겨 복구하다 정본을 초안으로 덮었다.

- **`align_jp_kr.py` 를 인자 없이 돌리면 의미정렬 정본을 덮어쓴다** ← 이번 사고의 직접 원인.
  이제 `align_semantic` 이 `generator` 표식을 남기고 `align_jp_kr` 가 덮어쓰기를 **거부**한다.
- **전역 최적 배정은 기존 짝까지 흔든다**(`assign_pages` Hungarian, 문턱 0.75→0.62 특히).
- **대책 = 확정 락**(`tools/lock_lines.py`). **ED1SCN1 928건 freeze 완료.**
  문안 해시가 달라지면 **빌드가 실패**한다. 커밋되는 `locked_lines.json` 이라 머신을 따라간다.
- **락은 검증만으론 부족하다 — 되씌워야 한다**(2026-08-03(3) 추가). 검증만 하던 시절엔
  머신을 옮기면 **빌드가 서고 앞으로 못 나갔다**(재계산으로는 복원 불가). 이제
  `apply_lock_src` 가 락의 좌표를 정렬 결과에 되씌운다 — 복원 27건으로 빌드가 다시 통과했고,
  해시가 전부 맞았다는 건 **회사 문안이 그대로 재현됐다**는 뜻이다.

```bash
python3 tools/lock_lines.py --status              # 현황
python3 tools/lock_lines.py --freeze ED1SCN2      # 그 씬 QA 끝나면
python3 tools/lock_lines.py --unlock ED1SCN1 331  # 의도적으로 고칠 때만
```

⚠ 락 검증은 `load_translations` 안에 있다 — 관리 도구는 `LOCK_BYPASS=1` 로 우회한다
(안 그러면 락이 깨졌을 때 **복구 도구까지 잠긴다**, 실측 교착).

### 🔴 남은 것 (우선순위)

1. **SCN2~6 커버리지** — 최대 과제. 씬별 인게임 QA 를 돌고 **끝날 때마다 freeze**.
   제외가 가장 많은 곳은 SCN2(27건: `size` 20 · `fmt_excess` 5 · `ctrl_seq` 2)로,
   `size` 가 압도적이라 **정발 문장이 창 용량을 넘는 쪽**부터 손보면 회수가 크다.
2. **`anchor_overlap` 잔여 3건**(SCN3 ×1 · SCN5 ×2) — SCN1 분은 회수 완료(`e49d905`).
   포인터 테이블과 대사가 한 블록이라 핀 고정되는 부류다. 앵커는 블록 **앞부분**만 덮으므로
   뒤 텍스트를 **제자리·같은 길이**로 덮어쓰면 절대참조가 유효하다. 구현 자리는 `rebuild()` 의
   `if b["pinned"] and b["eid"] in translations` 분기.
3. **소니아 화자창 앞 `ソ` 잔재** — JP 블록이 `%c%c%cニア%c` 구조다(`ソ`=0x835C 를 printf
   인자 두 개로 우회한 원판의 dame-moji 처리). `%c` 개수가 인자 스트림과 묶여 있어 그냥
   못 지운다 — **인자 정렬을 먼저 확인**할 것. 상세는 `docs/ch1-qa-devlog.md`.
4. **HUD 접미 폭** — `[지명]+[접미]` 합계가 14B 한계다(`베르가 광산`+`입구`=15B). 공백을 넣으면
   잘리고, 반각 공백은 전각 경계를 깨 `++` 가 뜬다. **폰트 폭 축소 후에나 띄어쓰기 가능**.
   상세는 `docs/reference/our-findings.md`. 같은 건으로 「クルスの村」 미치환 인스턴스 잔여.
5. **B급 교정 2,352건** 수동 검토 (`work/review/corpus/ED*_spell_report.md`).
6. 오버라이드 조용한 실패 4건(SCN2 jp933/942/952 · SCN3 jp694 "화자 없음").
7. 창 계약으로 막힌 잔여 — `fmt_excess` 9 · `fmt_drop` 8 · `ctrl_seq` 6.
8. 화자 미해결 잔여 `アグニージャ`·`ギュリゲス`·`フラート` — `ロー`와 같은 증상(음차가
   화자창에 그대로 나감)이 날 수 있다. 1장 밖이라 미룸.

### 3c. ✅ 효과음 깨짐 — 완전 해결 (07-29)

**조치**: `DONOR_RUNS = []`(빈 리스트). 오버레이 확장만으로 이주가 전부 수용돼(**ED도너
사용 0B**) **번역 손실 없음** — 수정 빌드가 유저 검증 진단 빌드와 **바이트 동일** 확인.
경위·재발 방지 기준은 [our-findings.md](../../../docs/reference/our-findings.md) "빈 공간" 절.

**✅ 조사 훅 배치도 해소(07-29)** — 재배치 없이 끝났다. VAB는 `[헤더(미사용 슬롯 0 패딩)]`
뒤에 `[파형(ADPCM)]`이 오는 구조이고 **깨지는 건 파형뿐**이다(각 VAG의 첫 16B가 무음이라 0런 탐색에
삼켜졌던 것). 실측: 도너 14개는 파형을 16~20B씩 침범, **josa 루틴은 8B 침범**, 테이블+스텁은
침범 0. ⇒ josa_fix의 **지연 슬롯 3곳을 채워 12B 축소**(516→504B)하니 헤더 패딩 안에서 끝난다.

- 한계 상수화 + assert: `JOSA_SAFE`/`DATA_SAFE` = **파형 시작 직전까지(각 508B)**.
  ⚠ 런 크기(524B)를 한계로 쓰면 안 된다 — 그게 이번 사고의 형태였다.
- 검증: 셀프테스트 7케이스(MIPS 인터프리터로 실제 바이트 실행) 통과 + 빌드본의
  **VAB 파형 95,216B가 원본과 바이트 동일**함을 전수 확인.
- 재검증법: `pBAV` 스캔 → 뱅크별 헤더크기 `32+128*16+512*nprog+512` → 파형 시작 산출.
- ⭐ **도너 풀은 97% 되살릴 수 있다(미검증, 항목 2용)**: 폐기한 14런을 **파형 직전까지로 캡**하면
  7,344B → **7,112B**(런당 16~20B만 포기, 손실 3.2%). VAB 16개가 각각 ~508B의 미사용 헤더
  패딩을 갖고 있고, 조사 훅 2런이 그 패딩에서 정상 동작하는 게 실증이다. **단 헤더 패딩
  안전성은 josa 2런으로만 확인됐으므로, 되살릴 때 "파형 직전 캡" 빌드로 소리 확인 1회 필수.**
- ⚠ **커버리지 확대 시 공간**: 씬 확장 영역은 이미 SCN1 기준 96%(`0x129E9/0x13208`). 항목 2가
  진행되면 공간이 모자란다 — 그때 **뱅크 밖** 도너를 새로 검증해 확보할 것.
- 📌 **QA는 소리를 켜고 할 것** — 이 버그는 화면상 아무 이상이 없어 텍스트 QA로는 안 잡힌다.

- 카지노/이벤트성 문자열이 더 있을 수 있음. SJIS 전수 스캔으로 한자 포함 잔여 목록화 후 배정.

### 5. ✅ 게임 자체 조판 메시지 char-wrap — #2/#3 완료·인게임 검증됨 (07-28)

**공통 뿌리**: 게임이 런타임에 조립하는 메시지(도구사용 "[화자]는 [아이템]을(를) 사용했다" 등,
우리가 pre-wrap 안 하는 것)를 **글자 단위로 폭에서 끊는다**(단어 인식 X) + 병기가 아직 "을(를)"
(3슬롯)인 상태로 폭 계산(조사훅 해결 前). 셋 다 **정발에도 있던 현상**.

- **#1 줄머리 공백** ⬜ 미해결(우선순위 낮음): 자동 줄바꿈 시 줄머리 공백을 안 먹어 렌더됨.
  정발도 발생 — 유저 확인 07-28.
- **#2 단어 중간 분할** / **#3 불필요 개행** ✅ **해결·인게임 검증됨**(07-28, 유저: 횃불·요슈아의
  눈 도구사용에서 조사·개행 모두 정상).

**⭐ 원인 확정 + 훅 2 구현(2026-07-28, capstone 정적 RE — 라이브 불필요):**

개행은 우리가 짚었던 `0x800AD3A8`(그리기 단계)이 아니라 **그보다 앞선 `0x800ACE18`**에서
결정된다. 전체 파이프라인(호출 순서 = 데이터 흐름):

```
0x800B1D50 strcpy(fp+0x18, msg)      호출자 스택 128B 사본
0x800B1D60 jal 0x800ACE18            ★자동 개행 삽입기(글자단위·29열) — 0x0A를 끼워 제자리 재작성
0x800B1D7C jal 0x800B1E58            0x0A로만 분할 → 워크슬롯(0x801190B0+k*66)  ↳ 훅 1이 여기 끝
0x800B1DF0 jal 0x800B2410 → 0x800AD3A8   줄마다 그리며 남은 초과분만 재차 개행
```

- 훅 1(`0x800B2054`)은 **개행이 이미 정해진 뒤**라 폭 계산이 미해결 병기로 이뤄졌다:
  `세리오스은(는) 횃불을(를) 사용했다` = **34열 > 29** → "…사/용했다"(유저 재현과 일치).
  해결 후 `세리오스는 횃불을 사용했다` = **28열 ≤ 29** → 무개행.
- **훅 2 = `0x800B1D60`의 `jal` 타깃 1워드 교체** → 스텁이 `josa_fix(a0, 128, zero-guard)` 후
  `j 0x800ACE18` 꼬리호출(ra 유지). 원명령 재현·지연 슬롯 처리 불필요(지연 슬롯이 원래 nop).
  대상이 호출자 전용 스택 사본이고 결과는 **항상 짧아지며**, prewrap·assemble 모두 `strlen`을
  다시 재므로 오버플로·길이 불일치가 없다. 훅 1과 멱등 중복(둘 다 같은 `josa_fix` 호출).
- ⚠ **이전 RE 오류 정정**: `0x800B245C`는 `0x800B1E58` 내부가 아니라 별개 함수 `0x800B2410`.
  `0x800AD3A8`의 `a2`는 원문이 아니라 **워크슬롯 줄** — "a2 소스 라이브 확인" 항목은 잘못된
  질문이었다(그래서 삭제). `0x800ACE18`의 호출자는 전수 스캔 결과 `0x800B1D60` 하나뿐.
- ⚠ **"capstone 미설치"는 스테일** — 5.0.7 설치돼 있다.
- 검증: `--selftest`에 **MIPS 미니 인터프리터** 신설(어셈블된 바이트를 실제 실행해 파이썬 시뮬과
  바이트 비교 — 인코딩 오류를 잡는다) 7케이스 + 빌드 후 **디스크에서 다시 꺼낸 바이트**로 재실행.
  실패 시 `JOSA_NOPREWRAP=1`(훅 2만 제외) / `JOSA_NOOP=1`(훅 1 무력화)로 계층 이분.

**⚠ 훅 2가 안 닿는 곳**: 상점(도구점) 프롬프트는 이 체인을 안 탄다(훅 1이 `해독초은 (는)`을 못
잡은 07-27 QA가 근거 — 훅 2는 같은 체인 한 단계 앞일 뿐). 대신 **문안을 조사가 필요 없게** 짜뒀다
— **살 때 `…이군요`**, **팔 때 `… 값은 %d Gold가…`**(`shop_price_build`, 조사를 고정 명사 '값'에
붙여 아이템명 무관). **런타임 이름 뒤에 조사를 두지 않는 어순이 훅보다 싸고 확실** — 되돌리지 말 것.
`0x800A9A60`(단문 직접 그리기, 메뉴·상태창 라벨 ~45곳)도 훅 밖이라 같은 원칙을 적용한다.

⭐ **차단 해제됨 — DuckStation 메모리카드→emucap 로드 워크플로**(2026-07-28 확립):

- DuckStation `.mcd`와 mednafen `.mcr`는 **둘 다 표준 PSX 128KB raw** → 호환. 복사만 하면 emucap이
  유저 세이브를 그대로 로드(로드 메뉴에 뜸). **원본 .mcd는 건드리지 말 것**(FROM만 복사).
- 경로: `cp "~/Library/Application Support/DuckStation/memcards/…(Japan)_1.mcd" \
"~/.mednafen/sav/Eiyuu Densetsu (KR).eb5fceade0b3cda486dd8f20b0f1fab1.0.mcr"` (백업 후).
  현재 유저 세이브 **9개**(엘아스터~네리아 항구). **유저가 새 세이브 만들면 다시 복사**(스냅샷). ⚠ **복사 순서**:
  mednafen이 종료 시 인메모리(구) 카드로 덮으니 **프로세스 kill → 재복사 → 재기동**(실행 중 복사 후 kill하면 유실).
- **부팅→로드 절차(2026-07-28 실전 확인)**: 타이틀 START → 영웅전설 I(circle) → 오프닝 START 스킵 → 메뉴에서
  **이어하기**(right→circle) → LOAD "**슬롯1**"(circle; 저해상도에서 倉庫로 오독 주의, 슬롯2는 빈 카드) → 세이브
  리스트 9개 → 선택(circle) → 예(circle). **버튼: cross=메뉴열기/취소, circle=확인.** 로드 후 도구사용:

  사용 트리거 실패) → **유저가 emucap 창에서 직접 아이템 사용**이 가장 확실. BP `0x800AD3A8`로 소스 포착.

## 핵심 지식 (영구 참조)

- **ED.EXE**: LBA 257. RAM = file − 0x800 + 0x80010000. mednafen 'ram' 오프셋 = & 0x1FFFFF.
- **`%c`의 정체**: 창 구분자가 아니라 **제어 인자 escape**(색상 등). 데미지 조립부
  `sprintf(buf, "%c%s%c…", 2, 이름, 1)`로 확증 — `%c`에 색코드(2=ON,1=OFF)가 인자로 들어간다.
  블록 조판 시 제어 토큰 위치를 옮기면 색이 문장 중간에서 바뀐다 → **템플릿 채우기**로 골격 보존.
- **구조 계약(소프트락 방지)**: 엔진은 블록당 **`%c` 세그먼트 수·`%s`/`%d` 수**를 원본대로 읽는다.
  부족하면 과잉읽기로 소프트락(1장 탈출 먹통의 원인). 재조립본이 부족하면 번역 제외.
- **%s 이름 주입 소스**: ED.EXE 0x800이 아니라 **SCN 오버레이의 널종단 이름 사본**(전투 HUD의
  몬스터명 사본과 같은 계열). patch_sys_ui.CHAR_NAMES가 처리.
- **공간(오버레이 확장)**: SCN 파일을 DUMMY.;1 영역으로 재배치 + ISO 디렉토리 레코드 패치
  (엔진이 SCN을 ISO 경로로 로드). work/derived/scn_layout.json 매니페스트로 새 LBA 전달. 도너 풀
  `reinsert.DONOR_RUNS`는 조사 훅 배치용 2런(0xBF5DC/0xC105C)을 **주석 예약 제외** 유지 필수.
- **HUD 지명 소스**: SCN 오버레이 맵 세그먼트 헤더([포인터테이블]+[지명 널종단]+[%c 대사]).
- **값 메뉴 정렬**: 값 X = 라벨 렌더폭 + 갭. KR 라벨을 JP 원본 렌더폭에 패딩(patch_sys_ui VALUE_PAD).
- **MIPS 손인코딩 함정**: andi rs 필드, load-delay 슬롯 — 디스어셈블+시뮬로 검증.
- **정발 우선**: 정발에 있는 건 다 이식(이스터에그 포함), 없는 것만 정발 문법으로 신규 번역.
  문안 변경은 사전 보고. 재사용 기법은 `docs/reference/our-findings.md`에 축적.
