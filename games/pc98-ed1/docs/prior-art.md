**같은 게임·같은 기종의 완성된 영문 패치**가 있다(유저 제보 2026-08-30).
https://github.com/nleseul/ds6_pc98_trans — Python, **Unlicense(퍼블릭 도메인)**.

🔴 **문안은 안 본다.** 우리 방침은 JP 원문 직역이고(루트 ROADMAP 「기본 방침」), 남의 번역을
저본으로 삼으면 그 해석의 오류까지 물려받는다. 저자 본인이 _"My Japanese is still fairly
mediocre"_ 라고 적어 뒀다. 가져오는 건 **구조 지식과 하네스 설계**뿐이다.

## 무엇이 확인되나

## 🔴 갈리는 자리 — 폰트

그쪽은 **영문이라 반각 ANK 로 끝난다.** CGROM 글리프를 읽어 오는 헬퍼(`0x8a49`, 0x50B)를
NASM 으로 다시 써서 **반각 폭으로 접어 넣는 것**이 전부다.

우리는 한글 2,350자를 **디스크에서 싣어야** 한다 — 같은 루틴을 후킹하지만 「ROM 에서
읽기」를 「우리 표에서 읽기」로 바꾸는 것이라 **작업이 그쪽보다 크다.** 그쪽 코드가 답을
주는 게 아니라 **후킹이 성립한다는 증거**를 준다.

## ⚠ 컨테이너가 다르다 — 지문이 안 맞는다

그쪽 원본은 **NFD** 덤프이고 우리 소장본은 **d88** 이다. README 의 sha1 세 개는 우리
`tools/common.py` 의 것과 **당연히 다르다**(같은 디스크의 다른 담는 그릇).
그쪽 파일 오프셋 산식(`addr - 0x4000 + 0x13e10`)도 NFD 레이아웃의 것이라 **그대로 못 쓴다** —
우리 좌표는 `common.read_d88()` 의 평면 이미지 기준이다.
