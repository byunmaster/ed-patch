# pc98-ed1 작업 방침 — 결정과 근거

⚠ **여기엔 pc98 고유의 것만 둔다.** 세계관·인물·표기·한국어 문장 규약은 이미 정본이 있고,
베끼면 두 벌이 되어 어긋난다(루트 CLAUDE.md 「DRY — 지식은 한 곳, 나머지는 포인터」).

| --------------------------------- | ------------------------------------------------------- |
| 표기 **데이터**(원문→우리 표기)   | `shared/glossary/eiyuu.json`                            |
| 표기 **판정 규칙**                | `docs/naming.md` ⭐ 정본 데이터와 어긋나면 **규칙이 이긴다** |
| 인물·관계·말투                    | `games/ps1-ed1+2/docs/ed1-story-bible.md` — **같은 게임이다** |

| RPG 델타(부호 매핑·물음표·화자)   | 스킬 `rpg-translate` — **문안을 쓰기 전에 연다**        |
| 이 게임의 경위·시행착오           | `devlog.md` · 현재 상태는 `status.md`                   |

🔴 **PS1 ED1 은 같은 작품이다.** 인물 대장을 새로 쓰지 않는다. 다만 **문안은 공유하지
않는다** — 창 규격이 달라서다(아래). 사전(`line_dict.json`)은 **씨앗**이지 정본이 아니다.

## 창 규격 — 실측 (2026-09-06)

원문 13,143블록의 줄을 표시 폭(전각=2칸)으로 재서 얻었다.

| 값                   | 실측                                   |
| -------------------- | -------------------------------------- |
| **창 폭**            | **36칸** (원문 줄의 95.4%가 36칸 이하) |
| **페이지당 줄**      | **4줄** (원문 5,883페이지 중 5줄이 49) |
| 줄바꿈               | **엔진이 공백에서 자동으로 접는다**    |

🔴 **그래서 우리 문안에 36칸 넘는 줄이 있어도 결함이 아니다** — 엔진이 접는다.
인게임으로 확인했다(라이아스 대사가 「…기다리고 / 계시옵소서…」로 어절에서 접혔다).
⚠ 진짜 위험은 **페이지당 줄 수**다. 접은 뒤 4줄을 넘는 페이지가 우리 정본에 4건 있는데,
원문에도 5줄 페이지가 49건이라 **넘침 자체는 원판 사양**으로 본다.

## 문자 — 무엇을 쓸 수 있나

- 🔴 **JIS 구 `0x40`~`0x58` 은 한글이 차지했다.** 그 대역의 한자를 문안에 쓰면 화면에
  **엉뚱한 한글**이 나온다. `tools/check_glossary.py`·빌드가 아니라 **문안 자체**를 봐야
  하는 축이라, 전수 점검을 해 뒀다(2026-09-06: 걸리는 문자 **0**).
- ✅ 반각 ASCII 는 그대로 나온다(CGROM). 전각 `…『』「」` 도 대역 밖이라 안전하다.
- **숫자는 반각으로 통일한다**(2026-09-06 판정). 27줄이 반각이고 4줄만 전각이었다 —
  우리 창이 36칸이라 반각이 유리하고, 무엇보다 **한 문안에 두 꼴이 섞이면 결함**이다.
- **인용은 「」**. 곱은따옴표 `”` 는 여는 꼴과 닫는 꼴이 같아 인용으로 못 쓴다.

## 시스템 층 — 메뉴·HUD·표·전투 메시지 (2026-09-06)

🔴 **시나리오와 규칙이 다르다.** 시나리오는 `0F` 무조건 점프로 런을 밖으로 뺄 수 있지만,
시스템 문안은 **실행 파일의 데이터 영역**이라 통로가 없다 — **제자리에, 원본 길이 안에서만**
쓴다(`tools/patch_sys.py`). 길이가 곧 계약이라 게이트가 되읽어 대조한다.

| 자리                    | 예산                       | 비고                                  |
| ----------------------- | -------------------------- | ------------------------------------- |
| 아이템 표(`0x3f09~`)    | 14B(7자) · stride 0x14     | **우측정렬** — 앞을 반각 공백으로 채운다 |
| 주문 표(`0x485c~`)      | 8B(4자) · stride 0x0b      |                                       |
| HUD 라벨(`0xa7f1~`)     | 7B · stride 0x07           | `ＥＰ`·`あと` 류                      |
| 메뉴·설정               | 문자열마다 다르다          | 전각 공백으로 **열을 맞춘다** — 그 꼴을 지킨다 |
| 전투·주문 메시지        | 문자열마다 다르다          | 런타임에 이름과 이어 붙는다           |

### 🔴 조사를 병기하지 않는다 — **예산이 안 된다**

`rpg-translate` §⑥ 은 앞말이 런타임 주입이면 `을(를)` 병기가 옳다고 한다. 맞는 말이나
**여기선 7바이트짜리 사치다** — 「は眠っている。」의 예산이 14B 인데 「은(는) 잠들었다.」가
16B 다. ⇒ **조사가 변하지 않는 꼴로 다시 짓는다.**

    は眠っている。 →  잠들어 있다.      (주격을 아예 안 쓴다)
    には効かなかった。 → 에게는 안 통했다.  (「에게」는 받침을 안 탄다)
    の攻撃 →  공격                     (「의」도 뺀다 — 6B 안에 못 들어간다)

전투 로그라 주어가 앞에 붙어 있어 **조사 없이도 읽힌다.** 이게 이 게임의 기본값이다.

### 슬롯 편차 대장 — 칸이 모자라 정본과 갈린 자리

`docs/naming.md` 가 「플랫폼 제약으로 갈린 것(슬롯·폭)은 그 게임의 편차 대장에」라고
정해 둔 자리다. **셋뿐이고 전부 14B 아이템 칸을 한 글자 넘겼다.**

| 원문         | 공용 정본       | 우리(칸)       |
| ------------ | --------------- | -------------- |
| `聖なる杖`   | 성스러운 지팡이 | **성스런 지팡이** |
| `ダイヤの杖` | 다이아의 지팡이 | **다이아 지팡이** |
| `ギルモアの虹` | 길모아의 무지개 | **길모아 무지개** |

⚠ 문안(대사)에서는 **정본 표기를 그대로 쓴다** — 편차는 칸에 갇힌 자리만이다.

## 칸 표 — 지명 목록 둘 (2026-09-06)

같은 지명 목록이 **두 벌** 있고 규격이 다르다. 둘 다 **칸 단위로** 넣는다 — 통째로 채우면
정렬이 통째로 깨진다.

| 어디                       | 규격                                   | 다루는 곳                    |
| -------------------------- | -------------------------------------- | ---------------------------- |
| `program:0x497c` (613B)    | 머리 13B + **12B(6칸) × 50**, 가운데   | `patch_sys.py` 의 `table`    |
| 시나리오 `10.00.20:0x14da` | **14B + 종결자 `07`, × 46**, 가운데     | `patch_scn.py` 의 `CELL_TABLES` |

🔴 **일반 런처럼 다루면 안 된다** — 밖으로 빼면 칸이 비고, 「틈」을 쓰면 이름이 왼쪽에
붙는다. 그래서 **제자리에 가운데 정렬**로 넣고 점프를 안 쓴다.
🔴 **표기는 「붙임」이다** — 여기는 HUD·표 층이라 접미를 붙인다(`크루즈마을`). 대사에서는
같은 곳을 띄워 쓴다(`크루즈 마을`). `docs/naming.md` 「접미는 층마다 다르다」 그대로다.
⇒ 정본 항목은 `layer: "table"` 로 표시하고, `check_glossary.py` 의 「우리 안에서 갈림」 축은
**표 층을 빼고** 본다 — 안 그러면 규칙대로 넣은 표가 결함으로 잡힌다.
⚠ 구조를 **사전조건으로 검사한다** — 칸마다 종결자가 제자리에 없으면 그 자리에서 죽는다.
⚠ 덤퍼가 못 보는 칸 둘은 표 선언의 `kr` 로 직접 채운다 — 하나는 런이 칸보다 앞에서
시작하고, 하나(`竜の卵`)는 **순수 한자라 가나 필터가 버린다.**

⇒ 46칸·50칸 모두 한글이고, 전부 6칸 안에 들어간다(지명 접미를 띄워도 들어간다).

## ⭐ PS1 ED1 은 **저본이지 정본이 아니다** (유저 확정 2026-09-06)

ED1 은 PS1 판이 유일하게 1회차 인게임 QA 를 마치고 main 에 머지돼 있다(`ada1a54e`).
그 문안을 **참고**하되, **PS1 이 이 기종의 일본어 원문과 다르면 원문을 따른다** —
추가·삭제·의역·기종 고유 대사가 있다.

🔴 **우리 구조가 이미 그렇게 만든다.** 사전(`games/ps1-ed1+2/line_dict.json`)의 열쇠가
**원문 해시**라(`shared/text/line_key`), 사전이 걸렸다는 건 곧 **PC-98 원문과 PS1 원문이
글자까지 같다**는 뜻이다. 다르면 애초에 안 걸리고, 그 자리는 **PC-98 원문을 보고 새로
옮긴다.** ⇒ 「PS1 을 베끼다 원문과 어긋난다」가 구조적으로 안 일어난다.

⚠ 그래도 **사람이 손댈 때는 원문을 본다** — `payload` 가 내는 검토표에는 PC-98 원문이 들어
있고, PS1 문안은 참고로도 안 붙인다(`rpg-translate` §2-2 의 「다른 문안을 보면 오염된다」).
⚠ PS1 이 QA 로 문안을 고치면 `seed --refresh` 로 받는다. 우리가 판정한 줄(`by=human`)은
안 건드린다.

## 번역 흐름

```sh
python3 tools/translate.py seed --refresh   # 사전이 고친 것 받기 (by=human 은 보호)
python3 tools/translate.py payload NAME     # 남은 것을 긴 것부터 검토표로 (⚠ work/review/ 밖으로 안 낸다)
#   → 번역 (rpg-translate 를 먼저 연다)
python3 tools/translate.py apply NAME       # 구조 계약(<PAGE>/<WAIT> 수) 대조하며 정본에 반영
sh ../../scripts/check.sh                   # 게이트
```

⚠ **전투 영역에는 재삽입 경로가 없다** — `patch_scn.py` 는 시나리오 영역만 본다.
거기 줄을 번역해도 화면에 안 나온다(`translate.py stat` 이 그 수를 찍는다).

## 오프닝 — PS1 정본과 나란히 놓고 다시 썼다 (2026-09-06, 유저 지적)

유저가 인게임에서 첫 줄을 짚었다. 대조해 보니 오프닝 26줄이 PS1 정본(1회차 QA 완료본)과
**통째로 갈려 있었다.** 방침대로 다시 썼다 — **낱말·문장 꼴은 PS1**(`games/ps1-ed1+2/textmap/opening.json`),
**PC-98 원문이 PS1 원문과 실제로 다른 자리만 원문.**

⚠ **PS1 의 원문은 이 트리에 없다**(`originals/jp/ps1-ed1+2` 를 안 링크했고, textmap 은
`k`=슬롯오프셋 + `ours`=우리 문안 + `sha`=한국어 가드라 JP 를 안 담는다). 그래서 대조는
**PC-98 원문 ↔ PS1 한국어**로 했다 — PS1 문안이 우리 원문을 그대로 옮긴 자리면 그 낱말을
쓰고, 우리 원문에만 있는 내용이면 원문을 살렸다.
