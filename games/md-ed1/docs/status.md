## 한 줄 요약

**재삽입 경로가 끝까지 열렸다.** 씬 모듈 225개의 문안 스트림을 파서가 뿌리(lea)부터 제어코드
오프셋까지 따라가 2,742개로 갈랐고(화자 태그 1,423/1,437 도달), 재조립기가 **원본 바이트는 제자리에
두고 스트림만 끝에 다시 써** 변위를 돌린다. 첫 대사를 8B 늘려 재조립·재압축·재배치한 롬이 원본 블록
자리를 지운 채로 대사와 다음 장면까지 정상이었다(7절). 글꼴은 표 교체 + 글리프 교체로 끝난다.
남은 본진은 **한글 글리프 자리 결정**(유저) · 미도달 14 스트림 · 평문(메뉴·시스템) 분모다.

### 2. LZ 코덱 — 디컴프레서 `$0C9E~$0DEE` 이식, 왕복 검증

블록 = `[LE16 길이-1][00][플래그8][스트림]`. 플래그 워드(LE16, LSB 부터)와 데이터가 섞인 LZSS —
리터럴 / 거리 8비트 / 거리 13비트, 길이 부호 2~269(단항+3비트+바이트), 거리 1 = RLE(14~4,109),
거리 0 = 끝. 정본은 [`tools/lz.py`](../tools/lz.py) 머리말. 색인 접근은 `$0C60`(a1=색인, d0=번호).
`archives.py --check` 가 225+110+… 블록의 **디코더 끝 == 헤더 길이**를 매번 확인하고, 실물 블록
재압축 왕복도 본다. ⚠ 인코더는 탐욕 매칭이라 원본보다 **~3.5% 크다**(script 35: 2,492 → 2,579B) —
자리가 빠듯해지면 최적 파싱으로 바꾼다.

### 3. 대본 — 씬 모듈 225개 (헤더 + 68000 코드 + 이벤트 + SJIS 문안)

```
모듈 헤더 12B(BE16 ×6): [a][b][코드 시작=0x0A|0x0C][d][e] …   (a·b·d·e 뜻은 미확정)
코드: movem … pc 상대 lea 22개 / 절대 $FF1Axx~$FF1Cxx(게임 변수) 21개 — 위치 독립
문안: 1E 화자 04 · 01 개행 · 05 페이지 · 00 끝 · 07 · 09 xx · 0E xx(변수 삽입) · 10~15 xx xx ·
      FE xx(글자 폭) · FF xx(줄 간격) · 02·03·08·0C·0F·1A·1C … (렌더러 `$9FA0` 표 참조)
```

- 덤프 실측: 블록 225 · 출력 663,896B · SJIS 런(4자↑) **115,465자** · 화자 태그 1,437 · 화자 123종
  (兵士 192 · 男 120 · 道具屋 82 · 神父 81 · 女 77 · 老人 71 …). 첫 대사(侍女)는 블록 35.
- 제어코드 표는 렌더러 `$9FA0` 에 있다 — 인자 길이 표 `$9FE2`(53개) · 핸들러 오프셋 `$A018`.
  `00`~`1F` 직접, `EB`~`FF` 는 −0xCB. 인자: `09` 1 · `0C` 2 · `10~15` 2 · `16` 10 · `ED` 4 ·
  `EE~F1` 1 · `F2 F3 F6` 2 · `F4 F8 F9` 3 · `FC~FF` 1. `06` = 페이지 대기(끝과 같은 −1 반환).
- **소비자 연결(확정)**: 씬 로더 `$18460` — 맵 ID 표 0x134DDC(BE16 × 225, `FFFF` 끝)에서 ID 를
  찾은 **자리**가 씬 번호(`$FF343C`) → `lea $134FA0,a1 / lea $FF6650,a2 / jsr $C60` 으로 블록을
  **RAM 0xFF6650** 에 푼다(`$2038A` 도 같은 식으로 다시 푼다). 침실(첫 대사)은 **블록 104**.
  한도: 엔진이 0xFFA650 을 다음 버퍼로 잡으므로 **모듈 ≤ 16,384B**(실측 최대 11,562B).
- **모듈 안 문안 = 스트림**(정본 [`tools/scene.py`](../tools/scene.py)). 코드가 `lea x(pc),a1` +
  `movea.w #85E3/85E2/85DC/85E4/0403/8421/8422/04B3,a5` 로 엔진 메시지 함수(전부 `$60A0`, 창 종류만
  다름)를 부르고, `$60A0` 은 렌더러 `$978C` 를 **한 번** 부른다 ⇒ **00·06·07 이 스트림의 끝**
  (00 창 닫기 · 06 반환 · 07 개행+대기+반환), **05 는 페이지 넘김**(계속). 스트림 안 오프셋 제어코드
  (기준 = 첫 인자 자리): `0F hhll` goto · `10 hhll` call(렌더 재귀 — 화자 머리 `1E 侍女 04 07` 을
  서브루틴처럼 공유; `10 8644` 는 $FF3644 동적 문자열) · `15 hhll` 모듈 코드 호출(hh≥80 엔진 함수) ·
  `F2/F3 hhll` 셀 비교/설정 · `F5`/`FB` 셀 쓰기(상대/절대, 가변 길이) · `11/12 xxxx`·`F8 xx` 조건부
  3B 건너뜀(뒤의 goto). `09 00` = 주인공 화자. 그 밖은 렌더러 표 `$9FE2` 의 인자 길이로 raw.
  ⚠ `lea x(pc),a1` 뒤에 `46DF` 만 오는 529건은 **자료 포인터**다(문안으로 오인해 옮기면 코드가 깨진다).
- **재조립 방침(확정, PoC 통과)**: 원본 바이트(코드·자료·셀)는 **전부 제자리**, 도달 가능한
  스트림을 **모듈 끝에 다시 쓰고** 뿌리 lea 변위와 goto/call 오프셋·표 항목만 돌린다. 옮긴 스트림의
  옛 자리는 0 으로 지운다(RLE 로 거의 공짜, 문안을 두 벌 들지 않는다). 셀·코드 참조는 새 자리 기준
  상대값만 재계산. 항등 재조립이 225블록에서 다시 파싱해 같고 최대 11,829B.
  **용량**: 원본 압축 378,286B → 항등 재조립·재압축 396,889B(우리 인코더 +3.5% 포함). 가용 = 아카이브
  자리 378,286 + 꼬리 81,058 = **459,344B**(색인 오프셋은 어디든 된다) ⇒ 한글이 일본어 바이트의
  ~115% 까지 든다. 넘치면 인코더 최적 파싱(−3~5%)이나 작은 빈 공간(0x1918D2 6KB · 0x054214 3KB) 순.
  **표 참조**(블록 83·84 — `lea T(pc),a6; move.w (a6,d2.w),d2; lea 0(pc),a6; lea (a6,d2.w),a1`, 항목 =
  모듈 시작 기준 BE16, 선택지 4개씩)도 뿌리로 잡고 재조립 때 항목을 다시 쓴다.
  ⚠ 남은 **미도달 12**(화자 태그 기준, 블록 92·103·115·117·122·141·151×2·174·176·181·223)는 전부
  `00`/`05`/`06` 로 끝난 스트림 **바로 뒤**에 붙어 있고 어떤 lea·표·goto 도 가리키지 않는다 —
  죽은 문안으로 본다(제자리 유지, 번역 안 됨). 인게임에서 그 장면이 나오면 이 판단을 뒤집는다.
  ⚠ `15`/`10` 의 엔진 특수값 판정은 상위 니블 8(`$A32E`) · 정확히 8644(`$A2AE`) — 음수 오프셋
  (0x9000~)을 상위비트로 가르면 되참조 호출을 놓친다(한 번 놓쳤다).
- 전투 아카이브(110블록)에도 문안이 있다 — 몬스터 이름(スラッグＡ…)·전투 메시지. 별도 분모.

### 4. 글꼴 — 롬 안 14×14 1bpp, 채움 + 테두리 두 면

리소스 색인 0x1A54D2(12B × 6, 자기 기준 오프셋: 표 · 표 끝 · 서술자). 서술자 4B `01 0E 0E 1C`
= 두 면 · 14×14 · 28B → 스트라이드 56B. 정본은 [`tools/font.py`](../tools/font.py).
**둘째 면 = 첫 면의 8방향 팽창 − 첫 면**(あ 로 196/196 일치) — 한글 글리프는 채움만 그리면 테두리는
기계로 만든다.

| # | 표                   | 자수  | 형상            | 글리프              | 무엇                                   |
| - | -------------------- | ----- | --------------- | ------------------- | -------------------------------------- |
| 0 | 0x1A551A (SJIS 2B)   | 1,459 | 14×14 28B×2면   | 0x1A62D2~0x1BA1FA   | 전각: 기호·숫자·영문·가나·**한자 1,2xx** |
| 1 | 0x1A6080 (`00 xx`)   | 131   | 8×14 14B×2면    | 0x1BA1FE~0x1BB052   | 반각 ASCII + 반각 가나(0xA1~0xDF)      |
| 2 | 0x1A6186             | 40    | 8×8 8B×2면      | 0x1BB056~0x1BB2D6   | 반각 소형(숫자·영문)                   |
| 3 | 0x1A61D6             | 38    | 8×12 12B×2면    | 0x1BB2DA~0x1BB66A   | 반각 중형(숫자·영문)                   |
| 4 | 0x1A6222 (SJIS 가나) | 86    | 12×12 24B×2면   | 0x1BB66E~0x1BC68E   | **가타카나만**(ァ~ヴ + 기호) 12×12 — 이름 입력용으로 추정 |
| 5 | —                    | 0     | —               | 0x1BC68E            | 빈 리소스(끝 표식)                     |

- 조회 `$9BA0`: d1=0 이면 1B 표(리소스는 `$9BAC` 의 `lea $1A54D2` 기준 색인), d1=1 이면 SJIS 표.
  표를 0x40B 보폭으로 조탐색한 뒤 32항목 역방향 정탐색 → 색인 × 56 + 글리프 시작 = 주소.
  ⇒ **표를 한글 코드(정렬)로 갈고 글리프를 같은 형식으로 두면 코드 수정 없이 먹는다.**
  🔴 자리: 한글 2,350 × 56 = 131,600B. 한자 자리(리소스 0 통째 81,704B) + 꼬리 빈 공간 81,058B
  = 162,762B 로 들어가지만 **두 조각**이라 리소스를 둘로 갈라야 한다(색인은 6개까지 슬롯이
  있다). 아니면 4MB 확장. 판단은 「남은 일」 4.
- 렌더러: SJIS 코드를 `$9838~`(`$985A` 에서 바이트를 읽는다)에서 모아 `$9B32` → 글리프를 타일로
  굽는다. 글자 폭 `$FF2014`(`FE xx`, 대사 14) · 줄 간격 `$FF2015`(`FF xx`).

### 5. 창 규격 (PoC 롬 실측 + 창 서술자 2026-09-05)

메시지 함수 넷(85DC/E2/E3/E4 → `$60A0`, d0 = 0~3)은 같은 창 서술자(`$63FC`, 0x30B → `$FFFE52`)를
쓴다: `00 00 | 00 90 | 00 E0 | 00 50 | 02 00 | 08 08 | 01 01 01` = y 144 · **폭 224px** · 높이 80 ….
`$FF2020` 비트7 이 서면 `$642C`(y 184 · 224 × 40 = 2줄 창), `$FF1853` 비트6(전투?)이면 `$2165A`
(y 176 · **312 × 48**). 뜻은 폭·높이만 확정, 나머지 필드는 미해석.

대사창: **화자 줄 + 본문 3줄**, 본문 한 줄 **18칸**(안쪽 218px ÷ 피치 12px — `$9802` 가 창 종류에
`$FF2014 = 0x0C` 를 준다. 글리프는 14px 지만 12px 로 겹쳐 찍는다), 줄 간격 16px. 반각 공백은 약 5px.
**자동 줄바꿈이 없다** — 18칸을 넘기면 오른쪽이 조용히 잘린다(「。」 이 잘렸다, `poc2_dialog.png`).
줄바꿈은 `01`, 페이지는 `05` 가 정한다 ⇒ 조판기(krwrap)가 18칸·3줄 예산으로 미리 갈라야 한다.
오프닝 자막은 별도 드라이버(피치 14px, 한 줄 16자). 타이틀 메뉴(はじめから)는 블록 0 의 스트림이
`FE 10`(피치 16) → `FE 0C` 로 찍는다.

```
SEGA 화면 → start(after 600) → 타이틀(はじめから/つづきから) → start(after 300)

```

- 세이브스테이트: `work/emu/title.mcs`(타이틀) · `opening.mcs` · `dialog1.mcs`(첫 대사) ·
  `start.mcs`(침실, 조작 가능).
- 메모리 타입 `cpu`(24비트 전체 — 롬 0~, RAM 0xFF0000~) · `ram`(64KB) · `vram` · `cram` …
  ⚠ 레지스터 값은 십진이다 — `A4=16718440` 은 0xFF1A68 이지 0xFF1668 이 아니다(한 번 틀렸다).
- BP 는 `cpu` 로 건다. 쓰기 BP 는 **값 필터**(`value`/`value_len`)가 먹는다. 리셋 직후 초기화 루틴
  (`$10744`)이 RAM 을 쓸어 쓰기 BP 가 한 번 헛돈다 — 탭이 `press` 단계에서 끊기니 다시 탭한다.
- `disassemble` MCP 는 스키마 오류로 죽는다 — capstone(`.venv`)으로 롬을 직접 푼다.

## 남은 일 (순서대로)

1. **한글 글리프 자리 결정**(유저 판단) — 4MB 는 SRAM 겹침으로 **그냥은 안 된다**(7절). 남은 길:
   (a) 리소스 0 을 한자 슬롯(1,459칸) + 꼬리 빈 공간(1,447칸) 둘로 갈라 2,350자 전부 — 조회가 리소스
   단위라 렌더러의 리소스 선택(`$9B74~`, d1=0/1)에 한 갈래를 더해야 한다(코드 수정 소량),
   (b) 한자 슬롯 하나에 **번역문이 쓰는 한글만**(빈도 부분집합 ≤1,459자) — 코드 수정 0, 대신 조판
   게이트가 미수록 글자를 빌드 실패로 막아야 한다(루트 「화면에 나가는 바이트」), (c) `$A130F1`
   토글로 SRAM 코드를 감싸고 4MB — 모드 수준 위험. 추천은 (b) 로 시작해 모자라면 (a).
   조사(종성) 훅은 PS1 과 같은 구조로 `0E` 삽입 코드나 렌더러에 건다.
2. **창 종류별 규격** — 메시지 함수 넷(d0=0~3)의 창 서술자(`$63FC` 0x30B 복사)에서 폭·줄 수를 읽어
   조판 예산표를 만든다. 대사창은 18칸 × 3줄로 실측됐다.
3. **평문 문안 분모** — 0x003000~0x008000 · 0x01F000~0x035000 평문(시스템·전투·메뉴·미니게임·장
   제목·이름)과 전투 아카이브의 이름 표. 코드 사이에 박혀 있어 **길이 고정**이 될 수 있다.
4. 오프닝 자막(0x16224~) — 평문, `FF FF` 머리 · 한 줄 16자. 별도 표.
5. 추출·번역 정본 설계 — 스트림 단위(블록·시작 오프셋)로 `textmap` 을 만들고 조판(18칸·3줄)을
   빌드 게이트에 건다(루트 「화면에 나가는 바이트를 게이트로」).
