### 3. 파일 구조와 포인터 — 재삽입의 핵심

파일 = `[지명 헤더 12B][SH-2 코드][텍스트]` 가 **지역 단위로 여러 번** 반복된다.
PS1(0xC 부터 바로 텍스트)과 여기가 다르다.

텍스트 참조는 **SH-2 리터럴 풀의 BE32 절대 주소**다. 로드 베이스는 파일군마다 고정:

| 파일군             | 로드 베이스  |
| ------------------ | ------------ |
| `ED.BIN`·`ED2.BIN` | `0x06028000` |
| `ED1SCN*.BIN`      | `0x060D0000` |
| `ED2SCN*.BIN`      | `0x060B8000` |
| `ED2MON*.BIN`      | `0x060E0000` |

**전 파일에서 `%c` 블록 포인터 커버리지 100%**(ED2SCN04 는 대사 자체가 없음).
즉 텍스트를 옮기면 **가리키는 BE32 를 같이 고치면 된다** — 숨은 참조가 없다는 뜻이다.
덤프 JSON 의 `ptr_at` 이 각 문자열을 가리키는 모든 포인터 위치를 담고 있다.

⚠ 화자만 건너뛴 중간 지점을 가리키는 포인터가 실재한다(예: `ED1SCN01` 0x312 는
0x308 블록의 본문 시작). 블록을 통으로 옮기면 **이런 부분 포인터도 같이 옮겨야 한다.**

### 5. 폰트 — 축이 사실상 해결됐다

정본은 [`tools/font.py`](../tools/font.py). 실측 지오메트리:

| 파일                 | 크기     | 글리프                             | 용도                        |
| -------------------- | -------- | ---------------------------------- | --------------------------- |
| `11KANJI.FON`        | 96,250B  | 4,375 × 22B (16×11 저장, 획 11×11) | **본편 대사 — 여기가 전부** |
| `11ASCII.FON`        | 2,805B   | 255 × 11B (8×11)                   | 본편 반각                   |
| `KANJI.FON`          | 249,792B | 7,806 × 32B (16×16)                | **`TITLE.BIN` 전용**        |
| `ASCII/KANA.FON`     | 4,096B   | 256 × 16B (8×16)                   | 본체 미참조                 |
| `/OPENEND/KANJI.FON` | 249,792B | 위와 동일 사본                     | 오프닝/엔딩 모듈용          |

코드로 확정한 사실 (`ED.BIN` 기준, `ED2.BIN` 도 **동일 함수·동일 파일**을 쓴다):

- 로드는 LWRAM 고정 주소 — `11KANJI.FON`→`0x20280000`, `11ASCII.FON`→`0x20298000`.
  둘 사이 여유는 **2,048B(글리프 93자)뿐**이라 파일 크기를 늘리지 않는 게 안전하다.
- SJIS→JIS 변환은 표준(`0x0607D600`), 글리프 인덱스는 **`(구-1)*94 + (점-1)`**
  (`0x0607D6AA~`, ×22 로 오프셋). 가나·기호·한자가 **한 배열**이다.
  → **PS1 의 미해결 난제(가나 블록 커스텀 인덱싱 `0x800AE768`)가 새턴엔 존재하지 않는다.**
  루틴은 `font.game_index()` 가 그대로 재현한다(상수 실측: cmp `0xDF` · add `-129`) —
  우리 인코더가 게임과 어긋나면 **빌드도 테스트도 통과하는데 화면만 깨지므로** 검산기를 뒀다.
  전 4,375 슬롯 왕복 대조 **불일치 0**.
- ED1·ED2 가 **같은 폰트 파일 하나**를 공유한다 → PS1 처럼 폰트를 두 벌 구울 필요가 없다.

**한글 삽입 방법** — PS1 과 같은 수법인데 대상이 EXE 가 아니라 파일이라 훨씬 싸다:

1. 원본 텍스트가 실제로 쓰는 글리프는 **1,413 종**뿐 → **여유 슬롯 2,962**.
2. 그 슬롯에 한글 비트맵을 굽고, 문안은 그 슬롯의 **SJIS 코드로 인코딩**한다
   (`font.sjis_of_index()`).
3. `11KANJI.FON` **파일만 교체**한다. 크기 유지 → 로드 주소·코드 무수정.

⚠ **여유 2,962 를 다 쓸 수 있다고 보면 안 된다.** 구성이 갈린다:

| 구간               | 슬롯  | 성격                                                                                                                 |
| ------------------ | ----- | -------------------------------------------------------------------------------------------------------------------- |
| 한자 ku16~47       | 1,761 | **여기부터 쓴다** — 원본이 이미 쓰던 코드라 게임의 모든 경로가 통과                                                  |
| 미정의·기호 ku1~15 | 1,201 | 표준 코덱으로 인코딩 불가(803 개는 cp932 디코드도 안 됨) + **창 폭 계산·반각 판정이 이 코드를 어떻게 보는지 미검증** |

`font.free_slots()` 가 **한자 구간을 먼저** 준다(빈 글리프가 많은 쪽은 오히려 위험한 쪽이다).
그래서 실질 예산은 **1,761 자**인데, PS1 번역 정본이 지금 쓰는 한글은 **1,048 종**이라
완역해도 들어갈 공산이 크다. ⚠ 넘치면 그때 미정의 구간을 여는데, **인게임 검증이 선행**이다.

**타이틀·오프닝·엔딩(16×16)은 Neo둥근모로 간다** (유저 확정 2026-08-21). `KANJI.FON` ·
`/OPENEND/KANJI.FON` 은 **무압축 32B/글리프**라 잉크 행 제약이 없고 셀이 16×16 이라
neodgm 이 네이티브로 들어간다(축소 없음 = 도트 안 뭉갬). 빈 슬롯이 이미 **1,001개**고
크기를 유지하니 로드 경로도 안 건드린다. 기준·근거는 `shared/fonts/README.md`.
⚠ 라이선스는 OFL — 전문 동봉 + 예약 이름(`Neo둥근모`) 미사용. Galmuri 도 OFL 이라 새로
지는 의무는 없다.

✅ **텍스트가 맞다 — 확인했다**(2026-08-21). 화면에서 본 문구를 이미지 전량에서 찾으니
`/TITLE.BIN` 에 **평문 SJIS** 로 있었다. 그림이 아니므로 폰트 교체 + 문안 재삽입이 먹는다.
자세히는 아래 7절.

**본편 대사 폰트: Galmuri11** (`shared/fonts/Galmuri11.bdf`, 오픈 라이선스, 11px 설계).
PS1 파이프라인 `games/ps1-ed1+2/tools/hangul_font.py` 의 `convert_chars()` 출력이
**22B(11행×16bit)로 새턴 셀과 그대로 일치**한다 — PoC 로 「영」 렌더까지 확인했고
획이 11×11 안에 정확히 수납된다. 즉 폰트 도구는 새로 쓸 게 없고 **재사용**이다.

| 명시 개행으로 **끝난** 줄이 최대 **42.5슬롯**    | 그 폭의 창은 없다 → 엔진이 접는다         |
| 한 창 안에 **14슬롯 줄 + 41슬롯 줄**이 섞인다 67 | 작가가 앞줄만 끊고 나머지를 흘렸다        |
| **공백 없는 41슬롯 토큰**이 있다                 | 공백 단위가 아니라 **글자 단위**로 접는다 |

즉 원문의 `\n` 은 **화면 줄이 아니라 작가의 문단 힌트**다. 대부분(2,662창)은 13~14.5에서
손으로 끊었고, 265창은 20슬롯 넘게 통째로 흘려 엔진에 맡겼다.

🔴 **그래서 우리 문안도 개행을 다 넣을 필요가 없다** — 오히려 넣으면 엔진 개행과 겹쳐
이중으로 접힌다. 재삽입 조판은 「krwrap 으로 끊어 넣기」가 아니라 **「엔진 폭 안에서
넘치지 않게 총량만 지키기」**가 된다.

**폭·행 수는 실행에서 읽었다** — mednafen/saturn 으로 띄워 `ED1SCN01:16`(첫 대사, 시녀)을
화면에서 픽셀로 쟀다:

| 값             | 실측                                                                                         |
| -------------- | -------------------------------------------------------------------------------------------- |
| 글리프 advance | **전각 12px** (「ますよ。」 셀 22·34·46·58). 반각 공백은 5px — 그 밖의 반각 글자 폭은 미확인 |
| 창 안쪽        | x 16..201 · y 147..228                                                                       |
| 글자 원점      | x=22 · 첫 행 y=150 · 행 피치 12px                                                            |
| **창 폭**      | **전각 15자 = 180px** (22 + 15×12 = 202 = 안쪽 끝)                                           |
| **창 행 수**   | **6행** — 화자 이름이 1행, **본문 5행**                                                      |

그 화면이 곧 엔진 개행의 증거다(⚠ 원문은 싣지 않는다 — 좌표로 본다. `ED1SCN01:16`).
그 블록은 이름창 뒤에 **한 줄 25.5슬롯**이 통째로 오고 그 뒤에 명시 개행이 하나 있는데,
화면에는 **세 줄**로 나왔다:

| 화면 줄 | 폭       | 왜 거기서 끊겼나                          |
| ------- | -------- | ----------------------------------------- |
| 1       | 14.5슬롯 | 다음 글자를 얹으면 15.5 → 폭 15 를 넘는다 |
| 2       | 11슬롯   | 원문의 명시 개행                          |
| 3       | 4슬롯    | 나머지                                    |

1행이 **낱말 한복판**에서 끊긴 것이 결정적이다 — 앞뒤가 한 어절인데 갈렸으니
공백 단위가 아니라 **글자 단위**로 접는다.

✅ **정적 코퍼스와 맞물린다** — 원문 전량을 폭 15 로 접으면 본문이 **최대 정확히 5줄**이고
초과가 0 이다. 반대로 폭 13 이면 73창이 넘친다. 위아래에서 계약이 잠겼다.

🔴 **재삽입 조판 계약: 전각 15자 · 본문 5행 · 엔진 자동 개행(글자 단위).**
우리가 넣을 것은 **문단 개행뿐**이고, 줄 끊기는 엔진에 맡긴다. 지켜야 하는 건
「줄 폭」이 아니라 **「창당 총량이 5줄을 안 넘는가」**다 — PS1 조판기(krwrap)를 그대로
가져다 쓰면 안 되는 이유가 여기다.

### 6-1. 🔴 문안 길이 제약 둘 — **문안을 쓸 때마다 걸린다**

조판(6절)과 별개로, 시스템/전투 문안에는 **바이트로 재는 칸**이 둘 있다. 넘기면
빌드도 테스트도 통과하고 **화면만 조용히 깨진다.** 둘 다 게이트가 본다.

**① 한 줄 예산 29B** — 줄 나누기 함수(`ED 0x0607CD64` · `ED2 0x06064158`)의 `mov #29,r12`.
바이트 단위라 전각 한 글자가 2칸이다. 넘치면 조각이 갈리고 **낱말 한복판에 흰 네모**
(「이어서 더 있음」 표시)가 남는다.

    색코드 1B + 이름(세리오스 8B) + 색코드 1B + 조사 2B + 본문 ≤ 29B

⚠ 조사 병기(`은(는)`)는 **접힌 뒤 2B 로 센다** — 훅이 나누기보다 먼저 돌기 때문이다
(2026-08-27). 이름이 긴 몬스터(데스 가디언A 12B)는 어차피 넘치니 완전히는 못 막는다.

- ✅ `은(는) 방어했다.` 21B · `은(는) 방어에 들어갔다.` 28B
- ❌ `은(는) 방어자세를 취했다.` 30B · `은(는) 방어 자세를 취했다.` 31B

**② 고정 길이 복사** — 문자열을 언롤로 **정확히 N바이트** 퍼 나르는 자리(ED 10 · ED2 13).
N 이 원본 문자열에 딱 맞춰 박혀 있다. 우리 문안이 1바이트만 길어도 **NUL 이 잘려 직전
내용이 화면에 이어진다**(유저 캡처의 「7격」).

    원본이 NUL 까지 넣던 자리 → 우리 것도 `길이 + 1 ≤ 칸`
    원본이 NUL 없이 꽉 채우던 고정 폭 필드(이름 등) → `길이 ≤ 칸`
    ⚠ **우리 것이 짧은 건 결함이 아니다** — NUL 이 함께 복사돼 목적지가 거기서 끊긴다

`tools/check_fixed_copy.py` 가 전수로 본다. 회심/통한(14B)만은 제약이 커서 **NUL 종단
루프로 코드를 갈았다**(`tools/patch_crit_copy.py`) — 거기만 길이가 자유롭다.
⚠ **편마다 원본이 다르다** — `しかし `(ED, 칸 8B) vs `しかし`(ED2, 칸 7B). JP 키가 갈려
있으니 정본에서 따로 쓴다.

#### 지명은 정본이 다르다 — `shared/glossary`

메뉴 라벨은 같은 JP 가 자리마다 다른 말이 되지만(`強さ` = 상태/강함/힘) 지명은 안 그렇다.
그래서 표+색인이 아니라 **평탄한 JP→KR** 로 옮긴다 — 대사·오프닝과 표기가 하나로 가고
목록을 손으로 들 필요도 없다. 못 찾으면 **실패한다**(한 칸만 일본어여도 화면에서 튄다).

🔴 **화면에 뜨는 지명은 `ED.BIN` 표가 아니라 씬 파일 머리다.** 표를 넣고도 HUD 가 그대로
일본어여서 알았다(2026-08-24). 씬 파일은 `[지명 헤더][SH-2 코드][텍스트]` 가 지역마다
반복되고 그 헤더가 화면에 간다 — 499곳 · 78파일 · 87종.
자리는 **SH-2 프롤로그**(`2F 86 2F 96 2F A6` = R8~~R10 푸시)로 잡는다. 그 프롤로그는 평범한
함수에도 있어서(1,473곳) **앞 12~16B 가 지명 정본에 있을 때만** 헤더로 친다.
⚠ 필드는 4바이트 정렬(이름 + 널 + 패딩)이고 **마지막 바이트가 `09` 인 꼴**이 있다 —
뜻을 모르니 원본 값을 그대로 남긴다.
⚠ 반각 가나 표(`ED.BIN` 0x84CCE~~ `ｴﾙｱｽﾀ`·`ﾍﾞﾙｶﾞM`)는 **내부 키다.** 지명처럼 보여도 안 건드린다.

#### 값이 붙는 표는 JP 폭에 맞춰 채운다

엔진이 값 X 를 **`라벨 렌더폭 + 행별 고정 갭`** 으로 잡고 그 갭은 **JP 폭 기준으로 박혀**
있다. 한글 라벨이 좁으면 값이 그만큼 왼쪽으로 밀려 열이 어긋난다(유저 QA 2026-08-24 —
상태·전투설정·시스템 창). PS1 이 RAM 실험으로 규명해 둔 것과 같다
(`ps1-ed1+2/tools/patch_sys_ui.py:VALUE_PAD`). 정본 `pad_to_jp` 에 적힌 표는 라벨을
JP 렌더폭까지 전각 공백으로 채운다.
⚠ 한글이 더 넓은 행이 있으면(`전투의 주문` 11 > `戦いの呪文` 10) 표 전체를 그만큼 함께
민다 — 행간 상대만 맞으면 열은 맞는다.

#### 챕터 카드 — 문자열 열 자리 + 그림 판 열두 장 (둘 다 완료)

`章`+`完` 을 가진 문자열 10장을 정본(`cards`)으로 넣었다. 자리는 손으로 안 적고 JP 제목으로
짝짓는다. 제목은 **원문 번역**이고 PS1 과 한 벌이다(`ps1-ed1+2/tools/patch_gfx_cards.py:CARDS`),
`完`→`끝`.
🔴 **화면 아래 상시 표시되는 챕터 판은 이 문자열이 아니다** — 넣고도 `第１章 王子の旅立ち`
그대로였다. 그건 `/SCR1.2D`·`/SCR2.2D` 안의 **그림**이고, 아래 10절에서 닫았다.

#### SAVE/LOAD·본체 RAM 문구 — 74 자리

`본체 RAM`·`카트리지 RAM`·저장/로드 확인·초기화 안내 등 고유 30 종이 **74 자리**에 흩어져
있다(한 파일 안에 여러 번, 편마다 또 한 벌). 하나만 고치면 어떤 화면에서만 일본어가 남는다.
🔴 **PS1 문안을 그대로 못 쓴다** — PS1 은 메모리카드, 새턴은 본체/카트리지 RAM 이라 문구가
다르다. 어투와 용어(로드·저장·기록)만 `patch_sys_ui.MSGS` 에 맞췄다.
⚠ **접미로 맞춘다** — 문구 앞에 BE32 포인터가 붙어 한 런을 이루는 자리가 많다
(`\x06\x0b華…ゲームの記録が ありません。`). 통째 비교로는 놓치고, 앞을 다시 인코딩하면
포인터가 깨진다. 뒤에서 맞추고 **앞은 원본 바이트 그대로** 이어 붙인다.
⚠ **긴 것부터 맞춘다** — `ロードに失敗しました` ⊂ `ロードに失敗しました。` 처럼 짧은 쪽이
긴 쪽의 부분 문자열인 자리가 있다.

#### 값 열은 채우지 않는다 — 폭 채우기 폐지

### 10. `SCR*.2D` — 화면 그래픽. 챕터 판은 닫혔다 (2026-08-24)

HUD 인명·`あと`·하단 챕터 판이 **전부 여기 그림으로** 들어 있다. 정본은
[`tools/dump_scr.py`](../tools/dump_scr.py), 재삽입은
[`tools/patch_gfx_cards.py`](../tools/patch_gfx_cards.py).

    0x00  "SEGA SATURN SCR\0"
    0x20~ 구획 표 — 16B 씩 `[오프셋 BE32][크기 BE32][0 8B]`
      구획0  패턴 네임 테이블 : 16B 머리 + 64×64 × BE16
      구획1  문자 데이터      : 16B 머리 + **8bpp · 8×8 셀**(셀 하나 64B)
      구획2  팔레트           : 16B 머리 + 256색 RGB555 BE (⚠ **R 이 하위 5비트**)
      구획3  0 으로 찬 칸     : 미사용

| 파일      | 크기     | 셀    | 팔레트           |
| --------- | -------- | ----- | ---------------- |
| `SCR1.2D` | 105,268B | 1,458 | SCR2 와 **같다** |
| `SCR2.2D` | 100,648B | 1,388 | 〃               |

**셀 색인 ↔ VDP2 문자 번호**: `charno = 0x1000 + 2×셀` (실기 대조로 확정).
0x1000 은 파일 머리 0x18 의 BE16 과 짝이고, 2 를 곱하는 건 문자 번호 단위가 32B 인데
8bpp 셀이 64B 라서다.

**어디에 뭐가 있나** (셀 색인, SCR1 = ED1 · SCR2 = ED2)

      0~ 255   기본 맵 — 금색 프레임 · 우측 패널 · 판 바탕
    256~1023   **챕터 판 여섯 장** — 한 장이 24×5 셀(192×40), **스트라이드 128**

⚠ 기본 맵은 일부만 쓴다 — 나머지는 게임이 **런타임에 패턴 이름을 바꿔 끼운다.**
⚠ **한때 4bpp 라 적었는데 틀렸다**(정정 2026-08-24). 4bpp 로 조립해도 워터마크가 읽혀서
확증한 줄 알았지만 실기 VDP2 는 8bpp·8×8 로 읽는다. 🔴 **「조립해 보니 읽힌다」는
포맷의 증거가 못 된다** — 실기 레지스터(`get_video_state`)가 정본이다.

##### 챕터 판 열두 장 — 넣고 인게임 확인까지 끝났다

`tools/patch_gfx_cards.py --apply` 하나로 SCR1 여섯 + SCR2 여섯이 들어간다. 문안 정본은
`script/ui.json:cards` 열둘이고 **순서가 곧 판 번호**다(SCR1 여섯 → SCR2 여섯).
⚠ `cards` 는 **장 목록**이라 열둘인데 문자열 카드는 열뿐이다 — ED2 의 序章·終章 은 그림
판으로만 있다. 그래서 `card_rows` 는 「정본에 있는데 디스크에 없다」를 실패로 안 친다.

**깨끗한 바탕**: 원본엔 글자 없는 판이 없다. 판 열둘이 바탕을 공유하므로 화소마다
**글자 아닌 값의 최빈값**을 고르면 복원된다 — 남는 구멍이 27화소뿐이라 최근접으로 메운다.
⚠ 동점은 **작은 색인**으로 깬다(결정성). 글자 자리는 열두 장이 똑같다 — 1행 잉크 y 4~~18 ·
2행 y 21~~35 · 가운데 x 96 · 최대 폭 168.

##### 잔량 라벨 `あと` → 남다 — `/FRAME.DAT` 0x1080 (2026-08-24)

🔴 **`SCR*.2D` 가 아니다.** 패널엔 `EP` 가 구워져 있지만, 시스템 메뉴에서 EP 표시를
「남다」로 바꾸면 게임이 **NBG0 비트맵**(숫자·게이지를 그리는 그 층)에 라벨을 그린다.
그 원본이 `/FRAME.DAT` — **HUD 스프라이트 시트**다(숫자 두 벌 · 상태이상 한자 · 게이지 · `あと`).

    자리    0x1080 · 스트라이드 16B · 10행(0행은 빈 줄, 잉크 1~9행) · 쓰는 폭 12px
    색      39 남색 바탕 / 35 청록 본문 / 36·37 음영

            일반 폰트가 안 들어간다. 음영은 (+1,+1), 창 밖은 자른다(옆 스프라이트 보호)

**어떻게 짚었나** — 실기에서 표시를 「남다」로 바꾼 뒤 NBG0 비트맵에서 그 12×10 화소를

✅ **인게임 확인 완료** — 시스템 → EP → 남다 로 바꾸면 HUD 가 `세리오스 남다 20` 으로 뜬다.

##### ⚙ 메뉴를 실기에서 몰 때 (조작 정본)

- **한 칸 이동 = `input_control pulse_while_running` + `frames: 2`.** 길게 잡으면
  자동반복이 걸려 **목록 끝까지 달려가 클램프**된다(16프레임 이상이면 무조건 끝).

  ✅ **초록 상자 = 지금 입력을 받는 창 · 하늘색 상자 = 부모 창의 잔상.**

#### 11. 고유명사 표 다섯 — 516칸 (2026-08-24)

문안은 **공용 고유명사 정본**(`shared/glossary`)이 내고 `patch_ui.py` 엔 **자리만** 적는다
(`NAME_TABLES`) — 두 이식판이 같은 이름을 쓰게 하는 유일한 길이다.

🔴 **칸 하나씩 제자리에 맞추면 34칸이 넘친다**(`궁극의 지팡이` 15B > 12B). 그런데 표는

**정본에 없던 것들은 규칙으로 흡수한다** — 손으로 안 적는다:

- **변종 접미** `Ａ~Ｅ` → 밑말 + 반각 `A~E`(`スライムＢ` = 슬라임B). 정본이 네 배로 안 는다.
- **`〜の書`** → 밑말 + `의 서`(주문서 23종).
- **반각 가나·중점**(`ｷｬﾘｵﾝ ｸﾛｰﾗｰ`·`ﾃﾞｽ･ｶﾞｰﾃﾞｨｱﾝ`)은 대조할 때만 눕힌다(NFKC + 중점·공백 제거).

**해결 방식 내역**(516칸 실측) — 정본 직접 323 · 변종 접미 168 · `〜の書` 23 ·
반각/중점 정규화 2 · 그대로 3. 규칙은 회귀 테스트 `tools/tests/test_names.py` 가 못 박는다.
전체 대조표는 `work/review/names.md` 로 뜬다(사람이 훑는 용도).
⚠ 사람이 읽는 판은 **`docs/reference/manual-items-spells.md`** 다 — 정본에서 다시 뜬다
(`scripts/dump_manual.py`). 정본을 고쳤으면 **매뉴얼도 다시 뜬다.**

⚠ **`ＭＧ１４`·`ＭＧ１５`·`ＭＧ２２` 는 그대로 둔다** — 내부 자리표시자다(`NAME_SKIP`).

## 이 층에서 물린 함정 넷

1. **한글은 cp932 로 인코딩이 안 된다** — 안 쓰는 글리프 슬롯에 배정하고 그 SJIS 로 적는다.
   슬롯 정본은 `hangul_map.json`(커밋). ⚠ 자동 갱신하지 않는다 — 낡은 이미지의 폰트와 어긋난다.
2. **반각을 섞으면 레코드 길이가 깨진다**(42B 고정). 원본은 전부 전각이라 렌더러가 반각을
   어떻게 보는지도 미검증이다. 그래서 **로마자·숫자·부호도 슬롯에 배정**하고 셀 가운데에
   그린다 — 보기엔 반각, 바이트는 전각.
3. 🔴 **저장은 역순, 정본은 화면 순서**다. 그대로 색인해 **화면에 결말이 먼저** 나왔다.
   ⚠ 증상이 「깨짐」이 아니라 「순서가 이상함」이라 캡처를 대충 보면 넘어간다.
4. **검증 치환(`--as`)으로 슬롯 정본을 갱신하면 안 된다** — 계획이 그 치환 문안에만 맞게
   좁아져(346→280) 정상 빌드에서 글자가 사라진다. `--refresh` 와 같이 못 쓰게 막았다.

#### 12. 시스템 메시지 — ✅ **전투 문안 전량** (540종 / 686자리, 2026-08-24)

정본은 **sha1 키**다(`script/system.json`) — 원문 평문을 커밋에 안 남긴다(루트 CLAUDE.md
「저작권」). 그래서 **자리도 손으로 안 적는다**: 파일의 문자열을 훑어 해시로 붙인다.

🔴 **PS1 문안을 복사해 오지 않는다.** 그쪽 전투 문안(`textmap/battle`)은 **정발 유래**라
사전(`line_dict`)에서 일부러 뺀 것이다(4절). → 새턴에서 새로 썼고, 나중에 **PS1 으로
역수출**하면 그쪽 구멍도 닫힌다.

**조사는 두 갈래다.**

| 앞말이            | 언제 정해지나 | 어떻게                                                |
| ----------------- | ------------- | ----------------------------------------------------- |
| 런타임 인자(`%s`) | 그릴 때       | **병기**(`은(는)`)로 적고 **조사 훅**이 접는다 (13절) |
| 구운 이름         | 빌드 때       | `shared/text/josa.attach` 로 **정적으로** 고른다      |

출현·대결 98줄이 뒤엣것이다(`<몬스터>[の群れ]が現れた。`) — 이름은 `shared/glossary`,
조사는 정적. 초안 생성기는 **일회성**이고 결과는 정본에 박았다(레포 제1 원칙).
⚠ **`과(와)` 는 훅이 모른다** — 기계어가 쌍 셋(은/는·이/가·을/를)을 상수로 안다.
런타임 이름에 `과(와)` 가 필요해지면 루틴을 늘려야 한다.

##### 제자리로는 안 들어간다 — 자리 풀에 다시 깐다

병기와 한글 폭 때문에 제자리로는 안 들어간다. 전부 포인터 참조라 자리를 옮길 수 있고,
**자기 칸 전부 + 이름 표를 다시 깔고 남은 꼬리**를 한 풀로 묶는다.
🔴 **재배치 단위는 「포인터가 가리키는 자리」다.** 한 런에 문자열이 둘 이상 0 없이 붙어
있고 포인터가 중간을 가리키는 자리가 있다 — 우리 글 앞에서 **가장 가까운 포인터 대상**을
잡아야 앞말을 안 끌고 간다.
🔴 **붙어 있는 칸은 합친다.** 배정이 칸을 못 넘으므로, 안 합치면 총량이 남는데도 조각이
작아 큰 문안이 갈 데가 없다(실측 ED2 가 **256B 를 남기고** 25B 하나를 못 넣고 죽었다).
🔴 **포인터가 없는 자리는 못 옮긴다** — 코드가 절대주소로 집는다. 제자리에 박고, 넘치면
실패시킨다(686 중 1자리: `ED.BIN` 0x26CF8).
⚠ **풀 전체를 먼저 0 으로 덮는다** — 옮긴 자리에 옛 일본어가 남으면 다른 포인터가 그걸
가리키고 있을 때 조용히 살아난다. 큰 것부터 넣는다(first-fit decreasing).

##### 정본에 넣기 전 통과해야 하는 가드 넷 (`patch_ui.py`)

셋은 **실패로 배운 것**이다 — 넷 다 자동 실패다.

1. **고정폭 표(`dump_ui.TABLES`) 구간은 안 본다** — 포인터가 첫 칸만 가리키고 나머지는
   색인이라 옮기면 메뉴가 통째로 밀린다.
2. **`_no_jp_prefix()`** — 접미로 맞추므로 짧은 조각(`が現れた。`)을 넣으면 이름이 구워진
   자리(`スライムが現れた。`)까지 걸리고 **앞말이 일본어로 남는다.** 그런 자리는 조각이
   아니라 **통짜로** 적는다.
3. **`_no_double_owner()`** — 카드·문구는 **제자리**에, 시스템 메시지는 **풀에** 깐다.
   같은 문자열을 양쪽 정본에 적으면 나중 쪽이 앞엣것을 덮는다(24자리 실측).
4. **되읽기는 포인터를 따라간다** — 자리를 옮겼으니 그게 정본이다.

**남은 것** — 본편 대사(씬 파일)와, ED/ED2 본체에 남은 비전투 문자열.

#### 13. 동적 조사 훅 — ✅ 섰다 (2026-08-24)

`patch_josa_hook.py`. 그리기 루틴을 부르는 **BE32 리터럴 여섯**을 우리 루틴으로 바꾼다 —
**코드는 한 바이트도 안 고친다**. 루틴은 버퍼를 훑어 병기(`조사A(조사B)`)를 만나면 앞
음절의 받침으로 하나를 골라 **4바이트를 왼쪽으로 당기고**, 끝나면 원래 루틴으로 tail-jump.

- 자리: 참조 0 인 2,560B 0런(`ED.BIN` 0x7E708 · `ED2.BIN` 0x63CC8) + `MARGIN` 0x40.
  🔴 **0런이라고 다 빈 자리가 아니다** — 1,301B 짜리 런들은 참조가 23곳이었다(사운드 뱅크).
- 받침 표는 **바이트 배열**이다 — SH-2 엔 가변 시프트가 없어 비트맵을 못 읽는다.
  구간은 **슬롯 정본에서 유도**한다(`josa.code_span()`) — 상수로 박았다가 새 글자 하나에 깨졌다.
- 검산 셋: `sh2.verify`(연속 디코드 + 지연 슬롯) · **SH-2 인터프리터 회귀 테스트**(기계어를
  실제로 돌려 기준 구현 `josa.fix_buffer` 와 **바이트까지** 대조) · 되읽기(참조 여섯).
- 실기: 브레이크포인트로 **진입 확인**. ⚠ 아직 **화면에서 접히는 걸 눈으로 못 봤다**
  (전투가 짧아 병기가 든 줄이 잘 안 나온다). RAM 전량 훑기로 **적재 이미지 밖에는 병기가
  하나도 없다**는 것까지는 봤다.
