# originals/

원본 게임 데이터. **전부 gitignore** — 클론 후 직접 소장본에서 채워야 도구가 동작한다.
여기 있는 건 어떤 트랙에서도 **읽기 전용**이다. 실행·패치 검증은 항상 사본
(`.local/cache/dosbox/<game>`)이나 각 게임의 빌드 출력(`games/<게임>/work/`)에 대고 한다.

## 이 머신에서는 **심볼릭 링크**다 (2026-09-15)

SSD 여유가 없어(89% → 58%) **원본 실체를 HDD 소장 컬렉션에 두고 파일마다 링크**를 건다.
도구는 경로가 그대로라 **한 줄도 안 바뀐다.**

```
originals/<지역>/<플랫폼>-ed<N>/<파일>  →  /mnt/originals/<기종>/<게임>/<파일>
  예) originals/jp/ps1-ed1+2/Legend of Heroes I & II, … .bin
        → /mnt/originals/PS1/Legend of Heroes I & II, … .bin
```

- **링크는 파일 단위다**(폴더 단위가 아니다). 게임 폴더는 우리 규약을 유지하고, **파일 이름은
  덤프 표준 그대로**(redump·No-Intro) 둔다 — 그 이름이 출처와 검증 상태를 담기 때문이다.
- ⚠ **HDD 가 안 붙으면 링크가 깨진다.** 조용히 틀리는 게 아니라 **눈에 띄게 실패**하므로
  그게 낫다. 마운트는 호스트(LXC) 몫이다 — `docs/machine-setup.md`.
- 🔴 **옮기기 전 sha1 전수 대조를 했고 3,869개가 전부 일치했다.** 크기·이름만 보면 안 된다 —
  실측으로 **크기가 같은데 내용이 다른 것**이 나왔다(`win-ed1` 의 옛 HDD 사본, 표본 20 중 2).
- 새 원본을 넣을 땐 **HDD 에 두고 링크를 건다.** 레포 쪽에 실체를 두면 이 규칙이 조용히 무너진다.

## 폴더 규약

```
originals/<지역>/<플랫폼>-ed<작품번호>/
```

- **지역**: `kr`(국내 정발) · `jp`(일본 원판) · `us`(북미판). 같은 작품이라도 판본이
  다르면 완전히 다른 원본이라 지역을 1단으로 뺐다.
- **플랫폼**: `dos` `win` `ps1` `ss` `pce` `md` `sfc` `msx` `pc88` `pc98` `x68k` `fmt` `psp`.
- **작품번호**: 합본은 `+`로 잇는다(`ps1-ed1+2`). `ed12`는 "twelve"로 읽혀 배제.
- 같은 지역·플랫폼에 재판/이판본이 있으면 접미어를 붙인다(`dos-ed1-jewel`).
- `games/<이름>/`은 이 규약에서 **지역만 뺀 이름**을 쓴다 — `games/ps1-ed1+2`는
  `originals/jp/ps1-ed1+2`를, `games/dos-ed2`는 `originals/kr/dos-ed2`를 타깃으로 한다.
  어느 지역을 타깃으로 하는지는 각 게임의 도구(`tools/common.py` 등)가 명시한다.

## 현재 소장분

### kr/ — 국내 정발판 (만트라 DOS / 윈도우)

한글패치 트랙의 **고유명사 표기 대조용**(번역은 일본 원판에서 한다 — 2026-08-18 자체 번역 전환)이자,
정발 복원 트랙의 **패치 대상**이다.

| `dos-ed1/`       | 영웅전설 I (만트라 DOS)    | `SINDLL/*.DLL`  |

### us/ — 북미판

(우리 `originals/us/` 는 비어 있다. TurboGrafx-CD 영어판(`TGXCD1029`)은 **소장 중**이지만
HDD 컬렉션의 `PCE/` 에 두고 여기로 링크하지 않는다.)

🔴 **공식 영어판을 번역 참고용으로 쓰지 않는다**(마스터 판단 2026-09-15) — 그 시절 콘솔 영문화가
**고유명사를 통째로 갈아서**(캐릭터·지명) 줄 정렬부터 안 되고, 남는 건 「저쪽은 이 문장을 어떻게
읽었나」 정도인데 분량 대비 값이 낮다. 우리에겐 **정발(DOS)** 이라는 훨씬 가까운 저본이 있고,
ED1 은 이미 거의 닫혔다. ⚠ 저작권 축도 같다 — 공식 영문 문안도 원저작물이다.

## 구할 것 (2026-08-18 정찰 기준 · 2026-09-15 갱신)

✅ **2·3 은 들어왔다**(2026-09-15) — PC-98 ED3 은 **플로피 11장**(`d88`/`hfe`/`mfi`/`scp` 네 형식)과
**RENEWAL CD**(17트랙, 데이터 1 + 오디오 16)를 **둘 다** 갖췄고, ED4 는 **CD(DIC 덤프)+HDI** 다.
🔴 **그래서 ED3 은 저본이 둘이다** — 아래 2번 경고가 이제 실제 판정 과제가 됐다.
⚠ ED3 의 `.d88` 에는 `[Copy Aid 98 II]` 가 붙어 있다(복제방지를 우회한 변환본) — 원반과 바이트가
같지 않을 수 있고, 같은 폴더의 `.scp`(플럭스)가 원본 근거다.
⚠ **1 은 아직**이다 — PC-98 ED2 는 `.hdi` + `hfe`/`scp` 는 있는데 **`.d88` 이 없다**(플럭스에서
변환하면 되지만 아직 안 했다).



1. **PC-98 ED2 플로피(.d88)** — 지금 것은 설치 HDI 라 원본 지문이 성립 안 한다.
   2HD 예상 3~5장. 도착 검증: MAP 25·MON 201·CHR 75 를 `kr/dos-ed2` 와 바이트 대조
   (현 HDI 는 301/301 동일) + `TEXT.BZH` 가 HDI 판과 같은지 확인.
2. **PC-98 ED3 (일본판)** — 만트라 dos-ed3 의 직계 원본(`ED3_98.CFG` 증거).
   ⚠ 원판 FD(1994, 11장)와 **RENEWAL CD(1996)는 다른 빌드** — 구분해서 취급.
3. **PC-98 ED4 (일본판)** — FD/CD 1996-05-24 동시 발매라 아무거나. 도착하면
   `kr/dos-ed4` 의 `DATA*.DAT` 와 파일 대조로 판본 판별.
4. PC-9801 **98NOTE 전용판 ED1** (1990-06-23, 별도 SKU) — 있으면 좋은 정도.

## 보관 규칙

- CD 이미지는 **참조되는 트랙 파일만** 남긴다 — `.chd` 등 중복/변환 포맷은 제거
  (재생성 가능). `.cue`/`.mds`/`.m3u`가 참조하는 데이터 파일과 짝을 맞춰 보관.
- 파일명은 원본(redump/No-Intro 등) 그대로 유지 — 도구가 정확한 이름을 참조한다
  (예: `jp/ps1-ed1+2`는 `common.py`의 `ORIG_BIN`/`ORIG_CUE`가 파일명을 하드코딩).
- 빌드 출력·분석 산출물은 각 게임의 `work/` — 여긴 원본만.
