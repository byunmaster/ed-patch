# RPG 대사 번역·검수

## 0. 이 스킬은 **델타**다 — 규칙을 여기 다시 쓰지 않는다

한국어 문장 QA 의 일반론은 **이미 있고 우리도 설치해 뒀다.** 여기 베껴 두면 두 벌이 되어
서로 어긋난다(레포 설계 원칙 DRY: 「지식은 한 곳, 나머지는 포인터」).

| 저본                                                 | 무엇이 거기 있나                                                                               |
| ---------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `kr-patch-qa` 의 `LOCALIZATION_QA_STANDARD.md`       | §3 화자·청자·어투 · §4 한국어 문장(부호·띄어쓰기·조사·**일본어 번역투 자연화**) · §5 줄바꿈·폭 |
| `create-kr-patch` `strategy/translation-workflow.md` | 번역 에이전트 배정 · 보호 정보 · 생성/검토/승인 분리 · 대량 치환 승인                          |
| 그 게임의 `games/<게임>/docs/policy.md`              | **그 게임이 확정한 것** — 표기·문체 등급·창 폭·유저 판정 대장                                  |

⇒ **번역투·띄어쓰기·조사·기본 부호는 위 표준을 읽는다.** 아래는 그 표준에 **없거나 우리가
뒤집은 것**만이다.

## 1. 🔴 우리가 뒤집은 기본값 — 이걸 모르고 표준을 따르면 문서와 싸운다

| 축             | 표준 기본값                            | 이 레포                                    |
| -------------- | -------------------------------------- | ------------------------------------------ |
| 대화 끝 마침표 | **생략**(`알겠습니다.` → `알겠습니다`) | **일관 추가** — 정발이 들쭉날쭉해 통일했다 |
| 부호 뒤 공백   | 명시 없음                              | 트랙마다 다르다 → 그 게임 `policy.md`      |

⚠ 게임마다 또 갈릴 수 있다. **표준을 그대로 적용하기 전에 그 게임의 `policy.md` 를 본다.**

## 2. 시작 전 셋 — 안 하면 되돌아온다

1. **그 게임의 정본을 연다** — `policy.md`(방침) · `*-story-bible.md`(인물·관계·말투) ·
   고유명사 정본 · `docs/naming.md` 류의 표기 규약.
2. 🔴 **기존 한글판(정발·유출본)이 있으면 번역 갈래에서 열지 않는다.** 옮겨 적는 것 자체가
   저작권 문제이고, **같은 세션에서 앞서 읽었으면 문맥이 이미 오염된다** — 번역은 그 문안을
   본 적 없는 **별도 에이전트**에게 넘긴다(우리 구현: `tools/rewrite_payload.py`).
   검수 갈래에서 대조용으로 여는 건 별개다.
3. ⚠ **판정이 이미 끝났는지 먼저 본다** — 도구 주석 · `policy.md` 결정 대장 · 상태 문서.
   실측: 유저가 확정한 표기를 모르고 **두 번 되돌렸다**(`ブラムナ` 주문/몬스터 구분 ·
   전투 꼬리 개행). 늘 같은 자리를 다시 판정하면 검수가 진도를 못 낸다.

## 3. 갈래 A — 번역(새로 쓴다)

0. 🔴 **앞뒤 문맥을 먼저 읽는다**(유저 확정 2026-08-29). 한 블록만 보고 옮기면 어투가
   틀린다 — 상대가 누구인지, 방금 무슨 말이 오갔는지, 그 대답인지 새 화제인지에 따라
   **경어 등급도 종결 부호도 달라진다.** 이 스킬의 판정 기준 태반이 「앞뒤를 봐야 갈린다」
   라는 꼴인 것도 그래서다(④ 문장 끝 · ③ 물음표 · ① 문체).
1. **화자와 청자를 잡는다.** 문체는 문장이 아니라 **관계**가 정한다(§4-①).
2. **경어 등급은 원문을 따른다** — 원문이 `ございます` 계면 하옵니다체, `です·ます` 면 합쇼체.
   ⚠ 한 장면 안에서 오르내리게 하지 말고 **우세한 층**으로 고른다.
3. **블록 앞뒤 창을 같이 읽는다**(§4-④). 한 블록이 한 문장이 아니다.
4. **창에 들어가는지 확인한다**(§5). 문안을 늘리면 블록이 **조용히 탈락**하는 엔진이 있다.
5. **같은 원문이 다른 데도 있는지 본다**(§4-③) — 있으면 같이 쓴다.

## 4. 갈래 B — 검수: RPG 델타 축 일곱

### ① 화자 — **관계**가 문체를 정한다

표준 §3.2 위에 RPG 특유의 것 셋을 얹는다.

- 🔴 **역할군(병사·신부·상점·현자)은 마을마다 다른 사람이다.** 개체끼리 말투가 갈리는 게
  **정상**이고, 「같은 원문=같은 문안」 검사가 여기서 오탐을 쏟는다.
  실측: 한 번의 검수에서 163블록이 이 예외에 걸렸고, 통일했으면 마을 색이 사라질 뻔했다.
  ⇒ **판정을 내렸으면 적어 둔다.** 안 적으면 다음 점검에서 또 후보로 뜬다.
- **지켜야 하는 건 하나 — 한 인물 한 문체.** 등급이 상대·상황에 따라 오르내리는 건 정상이고
  (왕 앞 / 부하 앞), 같은 등급 안에서 하오체↔하세요체를 넘나드는 것이 결함이다.
- ⚠ **말투를 인물끼리 통일하지 않는다.** 인물마다 다른 게 정상이다.
- ⚠ **어투 선택이 성별·연령 통념과 부딪히면 그 게임 문서의 판정을 따른다**
  (실측 판정: 여성 인물에 하오체를 쓰지 않는다 — 우아함·멸시는 정중형으로도 낸다).
- 🔴 **인물 대장과 문안이 갈리면 원문의 문체를 따른다**(유저 확정 2026-09-06).
  대장은 **요약**이고 원문이 1차 자료다 — 실측: 후보 68 중 **59가 이 규칙으로 정상 판정**
  됐고 실제 결함은 하나였다. 갈리는 데엔 대개 이유가 있다(**시점**: 왕자인 줄 모를 땐
  반말, 알고 나선 존댓말).
- ⚠ **대장에 없는 관계가 있다 — 검수는 문안과 대장을 같이 채운다.** 실측: 「딸에게는
  하소체」가 아버지 항목에만 있고 어머니 항목엔 없어 판정 근거가 비어 있었다(문안도 실제로
  어긋나 있었다, 4블록).
- 🔴 **인사 감탄사를 호격으로 옮기면 관계가 뒤집힌다.** `やあ`(가벼운 인사)를 `야` 로
  옮기면 한국어에선 **아랫사람을 부르는 호격**이 된다 — 왕자가 스승 노인을 `야` 라고
  부르는 꼴이 됐다(실측 6곳). `여어`·`이런` 처럼 **감탄사로** 받는다. 같은 부류 `おい`·`ねえ`.

### ② 일본식 부호 → 한국식 — **표준에 매핑표가 없다**

⚠ **표의 오른쪽 칸은 「되는가」이지 「해야 하는가」가 아니다.** 폭·바이트가 유리해도
화면에서 나쁘면 안 쓴다 — 부호는 글자와 **무게가 맞아야** 읽힌다.

| 일본식            | 한국식                    | 비고                                                                                                                                                                                                                   |
| ----------------- | ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `。` `、`         | `.` `,`                   | 반각을 낼 수 있으면 반각이 폭·용량 모두 유리                                                                                                                                                                           |
| `「…」` `『…』`   | **살린다**(한국어도 쓴다) | ⚠ 폰트에 반각 코너 브래킷(`｢｣`)이 있어도 **화면으로 판정한다** — 실측(PS1 2026-08-30): 글리프는 멀쩡히 나오는데 괄호만 반 칸이라 한글과 무게가 안 맞아 되돌렸다. 글리프 존재는 **증명하고** 쓰되, 쓸지는 눈으로 정한다 |
| `・` (가운뎃점)   | `,` 또는 공백             | 나열이면 쉼표. 이름 구분이면 그 게임 표기 규약을 따른다                                                                                                                                                                |
| `・・・` `。。。` | `…` 한 글자               | JP 는 점 세 개를 여러 꼴로 쓴다 — 한 글자로 모은다                                                                                                                                                                     |
| `！？`            | `?!`                      | **순서가 한국어와 반대다**                                                                                                                                                                                             |
| `～`              | `~` 또는 뺀다             | 장음 흉내는 한국어에서 과해지기 쉽다 — 의성어면 살린다. **범위**(`3～5`)는 그대로 물결표다                                                                                                                             |
| `”…”` (같은 짝)   | `‘…’` / `“…”`             | 🔴 **원문은 여닫이가 같은 글자**인 경우가 많다 — 한국어는 방향을 가른다. 겹낫표 **안**의 인용이면 작은따옴표다                                                                                                          |
| 전각 `（）`       | 반각 `()`                 |                                                                                                                                                                                                                        |
| `！！`            | `!!`                      | **살린다** — 감정 강도는 원문 것이다                                                                                                                                                                                   |

⚠ **전역 치환하지 않는다.** `「」` 가 비석·간판·인용문 연출인 자리가 있고, 그건 한국어에서도
따옴표가 맞다. 후보를 세고 사람이 판정한다.

🔴 **따옴표는 「어느 글자를 쓰나」가 먼저다** — 세 함정이 겹쳐 있다(PS1 실측 2026-09-06).

1. **ASCII `"`·`'`(0x22·0x27)는 1바이트 폰트에서 여닫이가 같은 모양으로 그려진다.**
   빌드도 검사기도 통과하고 **화면에서만** 드러난다.
2. **방향을 살리려면 전각 짝**(SJIS `‘’“”` = 0x8165~68)**을 쓴다.** 대개 원본 폰트에
   글리프가 살아 있다 — ⚠ 단 **한글 재배정이 그 자리를 덮었는지** 먼저 확인한다.
3. **전각은 두 칸을 먹는다** — 인용구가 줄을 넘어 `‘빛의 / 엘리베이터’` 로 **갈린다.**
   강제 개행으로 잡는다.

### ③ 원문이 생략한 물음표를 되살린다 — **표준에 없다**

표준 §4.1.6 은 `?!…` 를 「**보존**한다」고만 한다. 그런데 일본어는 의문에 `？` 를 자주 안
쓴다(`〜のか。` `〜かい。` `〜だろう。`) — **한국어는 물음표가 없으면 의문으로 안 읽힌다.**

실측(ED1+ED2): 원문이 `？` 없이 의문으로 끝나는 블록 **263**, 그중 우리 문안에 `?` 가 없는
것 **158**.

⚠ **전부 오류는 아니다.** 셋을 뺀다:

- **수사의문문** — `도망칠 수 있을 것 같으냐!!` (답을 요구하지 않는다)
- **바람·추측의 `かな`** — `사람이 더 와 주면 좋으련만.`
- **자문** — 혼잣말로 굴리는 물음

⇒ 기준은 하나: **상대의 답을 요구하면 `?`.**

🔴 **원문이 `？` 대신 `！！` 를 고른 자리는 그 연출을 보존한다.** 문법은 의문형인데 원문이
느낌표로 닫았으면(`本当ですか！！`) 그건 「묻는다」가 아니라 「놀란다」다 — 한국어도
`정말입니까!!` 로 간다. ⚠ 이걸 놓치면 후보가 부풀어 아닌 것까지 고치게 된다
(실측: 후보 158 중 다섯이 이 자리였고, 하마터면 다 물음표로 바꿀 뻔했다).
⚠ 덤프에서 부호가 **이스케이프로 보일 수 있다**(`\x21\x21`) — 디코드한 글자만 보고
「느낌표 없음」으로 판정하면 틀린다.

### ④ 블록은 문장이 아니다 — 창이 이어진다

RPG 메시지는 창(세그먼트) 단위로 잘려 있어 **한 블록이 문장 중간에서 끝난다.**

- 문장 끝 부호·물음표·문체 판정은 **다음 블록이 새 이름창을 여는가**를 봐야 결론이 난다.
  이어지는 중간이면 부호가 없는 게 정상이다.
- ⚠ 원문 조각만 보고 규칙을 돌리면 낚인다 — 실측: 소유격 `の` 로 끝난 블록을 의문 종결로
  세어 오탐 37건이 나왔다.
- 검수 도구를 짤 때 **블록 구조를 입력에 넣는다.** 안 넣으면 그 도구는 조용히 틀린다.

### ⑤ 같은 원문 = 같은 문안 — 예외는 둘뿐

원작은 같은 대사를 여러 곳에 복제해 둔다. 경로가 달라지면 **같은 NPC 가 마을마다 다른 말을
한다.** 블록마다는 다 멀쩡해서 여러 마을을 돌기 전엔 안 드러난다.

- 갈려도 되는 자리: **화자가 다르다**(①의 역할군) · **시점이 다르다**(1장엔 못 알아보고
  2장부터 알아보는 설정 등).
- ⚠ **「화자 라벨이 비었다」를 「화자가 다르다」로 세지 말 것.** 라벨은 자주 비어 있어
  (실측 33%) 그 오판이 넓다.
- ⚠ **한쪽에 판정 근거를 적었으면 사본에도 퍼뜨린다.** 실측: 주석에 이미 근거가 있는데 다른
  자리에 안 퍼져 두 종이 갈린 채 남아 있었다.

### ⑤-b 한 블록이 **여러 자리에 나간다** — 조사를 공통분모로 잡는다

⑤가 「같은 원문이 여러 블록에 복제돼 있다」면, 이건 반대다 — **블록이 하나인데 스크립트가
여러 번 참조한다.** 문안을 자리마다 다르게 줄 수가 없다.

실측(PS1 ED1 보스 유언, 2026-09-01) — `人間ごときに ･･･` 는 EXE 에 **한 번만** 있는데 두
문장에 다 나온다:

    ① おれが      人間ごときに やられるとは…          `に` = 수동의 행위자
    ② 人間ごときに 世界の破滅を  食い止めることは できぬ  `に` = 가능의 주체

🔴 **일본어에서는 안 걸린다** — `に` 가 두 역할을 겸하니 같은 덩이를 재사용해도 자연스럽다.
**한국어 조사는 대개 한 역할만 한다**(`에게` 는 행위자만) 그래서 그대로 옮기면 한쪽이
비문이 되거나 **뜻이 뒤집힌다**(②를 `에게` 로 두면 「인간에게서 오는 파멸」로 읽힌다).

**푸는 법 — 공유 블록은 고정하고 주변을 맞춘다.**

1. 그 블록이 **몇 자리에 나가는지** 먼저 센다. 표시 순서를 눈으로 보고 판단하면 틀린다
   (실측: 창 넷만 보고 「앞 문장 소속」이라 단정했다가 유저가 두 번 나온다고 잡아 줬다).
2. **모든 자리에서 자연스러운 조사**를 고른다. 그게 공통분모다.
3. **나머지 창을 그 조사에 맞춰 고쳐 쓴다** — 공유가 아닌 창은 자유롭다.
   `에게` 를 살리려면 뒤를 피동으로(`저지당할 일은 없다`) 두면 ①②가 같은 자리에 놓인다.

⚠ **원작이 안 쪼개도 됐던 걸 우리는 쪼개야 한다.** 정발(구 한국어판)은 이걸 안 넘고 두 자리에
같은 말을 써 둘째 문장을 비문으로 뒀다 — **같은 함정에 두 번 빠진 셈**이니, 옛 번역이 그렇게
돼 있으면 그 자리가 바로 이 부류다.

### ⑥ 의성어·조사·숫자

- **의성어는 원문 꼴을 지킨다** — 마디 수, 촉음(`ッ`)=받침 ㅅ. **인물을 가르는 표지**라
  통일하면 개성이 사라진다(실측: 노인 웃음으로 여성 악역 웃음까지 덮어 네 블록을 망쳤다).
- **조사 병기(`을(를)`)는 변수 자리에만.** 앞말이 **런타임 주입**이면 병기가 옳고,
  **리터럴**이면 빌드 시점에 받침을 아니 풀어 둔다.
  ⚠ **리터럴로 보인다고 리터럴이 아니다** — 상점 프롬프트처럼 원문에 기본값이 박혀 있어도
  실제로는 주입인 자리가 있다. 그 블록이 **어느 빌더에 등록되는지**가 진짜 축이다.
- **영문·숫자·단위는 원본 그대로** 두는 게 기본이다(그 게임 방침 확인).

## 5. 기계가 보는 축 — **검출기를 짜기 전에 여기부터 본다**

🔴 오늘의 교훈: 「일본어가 화면에 남는다」를 직접 스윕해 44종을 냈는데, 그 축엔 이미 도구가
있었고 돌려 보니 **0**이었다. **중복 검출기는 규칙이 갈려 조용히 틀린다.**

그 게임에 아래 축의 도구가 있는지 먼저 센다(`ls tools/check_*.py` 류). 없으면 만든다.

| 축                    | 무엇을 보나                                         |
| --------------------- | --------------------------------------------------- |
| 원문 잔존             | 화면에 나가는 **바이트**에 원문이 남았나            |
| 같은 원문 갈림        | ⑤ — 화자·시점 예외를 같이 판정                      |
| 어투 혼용             | 한 창 안 존대↔해라체 · 원문 경어 → 우리 해라체      |
| 화자 이름창           | 이름창에 남의 이름이 뜨나                           |
| 고유명사              | 정본 표기가 문안에 들어갔나                         |
| 조사                  | 받침 불일치 · 변수 뒤 고정 조사 · 고정 명사 뒤 병기 |
| 문장 끝 부호          | 화자의 **마지막 창**에 종결 부호가 있나(④)          |
| 의성어                | 원문 꼴 유지                                        |
| 창 폭·줄 수·꼬리 잘림 | 조판이 화면에 들어가나                              |
| 맞춤법                | **화면에 나갈 문안**을 본다(소스가 아니라)          |
| 표시 속성(색·강조)    | 같은 **부류**(아이템 이름 · 설명)가 같은 색인가     |

⚠ **초록불이 「없다」가 아니다.** 그 도구가 **무엇을 읽는지** 확인한다 — 실측: 로더가 키
하나만 긁어 152문자열이 통째로 안 보이는데 내내 ✅였다.
⚠ **게이트가 그 도구를 부르는지도 본다** — 실측: 검사기 38 중 18을 게이트가 안 불렀다.

🔴 **후보가 뜨면 문안보다 검출기를 먼저 의심한다.** 실측(2026-09-06): 화자 말투 후보 68 중
**실제 결함은 하나**였고, 그 한 회차에 검출기가 **세 번** 틀렸다. 셋 다 한국어·RPG 특유의
자리라 다음 게임에서도 같은 데를 밟는다.

1. **창을 문장으로 셌다**(④) — 블록 구조를 입력에 안 넣으면 그 도구는 조용히 틀린다.
2. **문체 등급표에 의문형이 빠졌다** — `입니다` 만 넣고 `입니까`·`겁니까` 를 빠뜨려
   합쇼체 의문문이 통째로 「등급 없음」이 됐다. **평서·의문·청유·명령을 다 넣는다.**
3. **의존명사 띄어쓰기를 못 봤다** — 한국어는 `란도 씨` 처럼 **띄어 쓴다.**
   `이름+접미` 로 붙여 찾으면 0 이 나온다.

💡 **한국어 문안에 `\b` 를 쓰지 않는다** — 한글도 단어문자라 `\bfoo\b` 가 조사 앞
(`align이`)에서 안 걸린다. `(?<![A-Za-z0-9_])…(?![A-Za-z0-9_])` 로 쓴다.

🔴 **규칙을 세우기 전에 세는 단위를 가른다 — 반각/전각 · 부류 · 블록이 아니라 문구.**
한 주에 넷을 밟았다: **전각** `！` 넷만 세어 「JP 는 부호를 안 쓴다」로 규칙을 세웠는데
반각 `!!` 가 556 이었다(그만큼의 강세를 조용히 지웠다) · 같은 문구가 25자리에 복제된 것을
**블록으로** 세어 색 다수결이 뒤집혔다. ⇒ 세기 전에 **무엇을 세고 있는지** 먼저 적는다.

## 6. 끝내는 법

1. 그 게임의 커밋 전 게이트를 돌린다(빌드 + 검사).
2. **문안을 의도적으로 바꿨으면 조판 지문·확정 락을 갱신한다.** 안 바꿨는데 떴으면
   **공용 코드를 의심한다**(다른 게임 작업이 흘러들어온 것이다).
3. **판정을 남긴다** — 「갈려도 되는 자리」·「유저가 확정한 것」은 적어야 다음 점검에서
   다시 판정하지 않는다.
4. 인게임 확인은 사람 몫이다. **기계로 닫을 수 있는 축을 먼저 다 닫고** 넘긴다.

## 7. 새 게임에 처음 붙일 때

이 스킬은 **게임 문서가 있다고 전제**한다. 없으면 넷을 먼저 만든다 — 그 전엔 검수 결과를
믿을 수 없다.

1. **표기 정본** — 인명·지명·아이템(단어 수준이라 저작권 대상이 아니다).
2. **인물·관계·말투 대장** — 누가 누구에게 어떤 등급으로 말하나.
3. **문체 방침** — 시스템 메시지 층, 대화 층, 뒤집은 기본값(§1).
4. **창 규격** — 폭·줄 수·부호가 반각으로 나오나. ⚠ 이게 없으면 §5 조판 축이 못 돈다.
